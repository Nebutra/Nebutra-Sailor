# Brand Meta-Replacement Governance — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collapse the ~5 uncoordinated brand sources of truth into ONE human-edited config (`DEFAULT_BRAND` in `scripts/brand-types.ts`) from which `pnpm brand:apply` derives every downstream representation (DTCG `core.json` color scales → `styles.css`, `metadata.ts`, app SEO/JSON-LD/PWA/RSS/legal/marketing surfaces, i18n catalogs, favicons/OG images, runtime per-tenant logo). A single `brand:apply` run must propagate a rebrand end-to-end, and a shrink-only governance ratchet must guarantee the ~3,000 existing literals can only ever decrease.

**Architecture:** One human-edited source (`DEFAULT_BRAND`) → `brand:apply` derives `core.json` (color SSOT) + `metadata.ts` (identity object) → Style Dictionary regenerates `styles.css` → apps/packages import the generated `@nebutra/brand` object and `@nebutra/brand/metadata-helpers` instead of hardcoding strings → i18n catalogs use ICU placeholders injected at request time → asset generators rasterize from the brand logo + palette → runtime sidebar reads tenant-uploaded logo via a lightweight GET route → a config-driven `governance.config.json` + `scripts/governance/*.mjs` engine (mirroring the existing repository-seam ratchet) flags any new raw brand literal and forces on-touch migration of the 203 seeded offenders. No new source of truth is introduced — every layer collapses toward `DEFAULT_BRAND`.

**Tech Stack:** TypeScript (strict), Vitest (`vitest.arch.config.ts` for architecture guards), Biome (no `console.log` — scripts use `process.stdout.write`/`process.stderr.write`), Style Dictionary 4, next-intl, Next.js 16 Metadata/MetadataRoute, `@resvg/resvg-js` + `sharp` + `png-to-ico` (favicon generation), Satori/`next/og` (OG images), Prisma via `@nebutra/repositories`/`@nebutra/db` seam for core domains, pnpm workspaces (`minimumReleaseAge:1440` — mature/caret deps only). Commit straight to `main` in frequent small commits.

## Requirements & Audit Findings

A completed 3-agent audit established the broken multi-SSOT reality (treat as fact, but re-read files to quote exact code before editing):

1. **Dual color SSOT.** The real runtime color source is `packages/design/design-tokens/tokens/core.json` (self-described DTCG SSOT — see its `$description` at line 3) → Style Dictionary (`packages/design/design-tokens/style-dictionary.config.mjs`, `pnpm --filter @nebutra/design-tokens build`) → `packages/design/tokens/styles.css`. But `packages/design/brand/src/metadata.ts` (auto-generated by `pnpm brand:apply` from `DEFAULT_BRAND` in `scripts/brand-types.ts`) carries a **second, unused copy** of the same colors. `brand:apply` (`scripts/brand-apply.ts` main(), confirmed at lines ~385-390 — `copyCustomAssets → updateBrandMetadata → updatePackageScopes → updateREADMEs → updateEnvTemplate`) **never touches `core.json`**. So editing `DEFAULT_BRAND.colors` changes `metadata.ts` but does NOT change the shipped CSS. Silent drift.

2. **~3,102 literal "Nebutra"/"云毓智能" occurrences across apps.** App SEO/title/manifest/JSON-LD/RSS/legal/marketing surfaces are hardcoded; **none import the brand metadata object.** A governed scan (apps + commerce + integrations/email, excluding tests/stories/previews and the brand/tokens packages) yields **203 offender files** today.

3. **Dead asset paths.** `copyCustomAssets` writes to a non-existent `packages/brand/assets` (post-2026-05 layout migration left it at `packages/design/brand/assets`); `faviconAssets` in `metadata.ts` declares 5 paths but only `favicon.ico` exists; `manifest.ts` declares `/icons/*.png` paths with no `public/icons/` directory.

4. **i18n identity hardcoded.** 7 next-intl catalogs (`apps/landing-page/messages/*.json`) hardcode brand identity (en=54 lines, zh=56, de=56, es=56, fr=55, ja=57, ko=57). A pre-existing spelling drift exists: `brand.nameFullEn` = "Wuxi Nebutra **Intelligent** Technology Co., Ltd." vs catalog `companyNameEnglish` = "Wuxi Nebutra **Intelligence** Technology Co., Ltd."

5. **Runtime per-tenant logo unwired.** `Organization.logo String?` exists (`schema.prisma:134`) and an upload route exists, but the sidebar `BrandLogo` never renders it; `logo/route.ts` still carries dead `as unknown` casts guarded by a stale `TODO(#126 schema)`.

**Chosen approach — Option B ("complete skeleton + convergence ratchet").** Build the full single-config architecture + generators + arch guards in one coherent pass; migrate the 203 existing literals **on-touch** via a shrink-only ratchet that **mirrors the existing repository-seam pattern** (root `governance.config.json` + `scripts/governance/*.mjs` engine + thin wrapper; create-sailor ships these). Do NOT invent a parallel mechanism. Never design a new source of truth — collapse toward ONE.

### Critical correctness invariants

- All hex written to `core.json` is **lowercased** (`hex.toLowerCase()` → `#0033fe` not `#0033FE`).
- `nebutra-neutral` has **no `"0"` key** in `core.json` (`NeutralColorScale.0`="#ffffff" is brand-types-only → maps to `color.white`). `deriveColorNodes` iterates `COLOR_SCALE_STEPS = ["50",...,"950"]` only for all three scales.
- `nebutra-neutral` carries a scale-root `$description`; `deriveColorNodes` copies it from `existingCore.color["nebutra-neutral"]["$description"]`. Build it as `{ $description, ...steps }` (description first) to preserve key order.
- `nebutra-blue`/`nebutra-cyan` 500-stop carries leaf-level `$description` + `$extensions` (display-p3). For the 500-step, spread the existing on-disk node and replace `$value`; if `p3Overrides` is set, override `$extensions`.
- JSON key-order stability: `updateCoreJson` spreads `existingCore` then overlays only the three scales → V8 preserves insertion order → `JSON.stringify(updated, null, 2) + "\n"` is idempotent. The idempotency test catches any regression.

## Convergence (on-touch ratchet)

The ~3,000 literals (203 governed offender files) shrink monotonically via the shrink-only allowlist in `governance.config.json → brandLiterals.allowlist`, exactly mirroring the established `repositorySeam` ratchet:

1. **Seed once (Phase 8).** All current offenders are listed in `brandLiterals.allowlist`. CI passes because every offender is grandfathered.
2. **New literals fail immediately.** Any new file (or a previously-clean file gaining a raw `Nebutra`/`nebutra.com`/`#0033FE` literal) is in `detected` but not `allowlist` → `newViolations` non-empty → `pnpm lint` exits 1 in the new CI "Governance lint guards" step. The author must route through `@nebutra/brand/metadata` (`brand.name`, `brand.domains.*`) or token vars (`var(--brand-primary)`/`var(--brand-accent)`) — never hardcode.
3. **On-touch migration shrinks the list.** When an engineer edits any allowlisted file for any reason, they replace its literals with brand imports/tokens AND delete its allowlist entry in the same PR. If they migrate but forget to remove the entry, the engine's `fixedButListed` check (`allowlist − detected`) fails the build with "no longer contain raw brand literals — remove them from brandLiterals.allowlist (the list is shrink-only)". The list can therefore only ever shrink.
4. **Escape hatch for genuine exceptions.** Files that legitimately cannot use CSS vars (e.g. `apps/web/src/app/global-error.tsx`, which renders outside the root layout) add a top-level `// @brand-exempt: <reason>` comment, which the engine honors — these stay correct without bloating the allowlist permanently.
5. **Permanent exemptions** (stories, `__tests__`, previews, the brand/tokens packages themselves) live in `knownExemptPatterns`, not the allowlist — they are intentionally illustrative or are the source of truth itself.
6. **Scaffold inheritance.** Because the engine reads `governance.config.json` (no hardcoded monorepo paths) and lives under `scripts/governance/`, `create-sailor` ships it into every scaffolded project with an **empty** allowlist — new projects start with zero brand debt and the ratchet enforces single-source brand identity from day one.

End state: as files are touched over time, `brandLiterals.allowlist` drains toward `[]`, at which point every brand identity reference in the codebase flows from the single `DEFAULT_BRAND` source through `brand:apply` and `@nebutra/brand` — and a full white-label rebrand is one `pnpm brand:apply` run.
