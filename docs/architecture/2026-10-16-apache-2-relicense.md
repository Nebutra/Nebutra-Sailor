## Why

- **The vision is adoption.** Sailor's goal is to be what coding agents reach for by default.
  FSL's competing-use clause read as stingy and was the first objection on every channel that
  checks licences (HN on fair source; linux.do 开源推广 requires full open source).
- **It lets us say “open source” and be right.** Apache-2.0 is OSI-approved. FSL is not, so every
  surface had to say “source-available” and a few still said “open source” incorrectly.
- **One licence instead of three.** The FSL repo / MIT packages / MIT scaffold split needed an
  explainer table on every surface and a `LICENSE-UPSTREAM-REFERENCE.md` in every scaffold.
- **Apache over MIT:** an explicit patent grant and a `NOTICE` mechanism, which suits a codebase
  companies build products on; it remains permissive.

## Consequences

- Versions released before 2026-10-16 keep the licences they shipped with — those grants were
  irrevocable. Every new commit and every new npm version is Apache-2.0.
- `tests/architecture/release-surface.test.ts` enforces `"license": "Apache-2.0"` and an
  Apache-2.0 `LICENSE` file on every publishable package; `license-policy.json` records
  Apache-2.0 as the project licence (dependency allow/deny list unchanged: copyleft dependencies
  stay forbidden).
- `create-sailor` writes the Apache-2.0 `LICENSE` and a `NOTICE` into every project; the scaffold
  marker's licence tier becomes `apache-2.0` (readers still accept the legacy `mit-scaffold` and
  `independent` values).
- Copy may call Sailor **open source (Apache-2.0)** / **开源（Apache-2.0）**. “Source-available”
  and FSL wording are retired on live surfaces; dated records (ADRs, reports, changelogs) are
  left as written.
