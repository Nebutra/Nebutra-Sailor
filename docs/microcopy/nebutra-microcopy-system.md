# Nebutra Microcopy System

**创业文化微文案与彩蛋系统 · 唯一权威版 · The Cultural Layer Writing Bible**

> 一份方法论，不是一本句子集。
> 它的目的不是提供一千条文案，而是提供一台能持续生产一千条文案、且每一条都像出自同一个人之手的机器。

---

## 核心定义

Nebutra 的微文案系统，不是提示用户完成操作，而是在用户从 idea 到 company 的过程中，用中美创业文化的隐喻、仪式感和彩蛋，持续告诉他：**你真的可以创立一家了不起的公司。**

> 用户不是在用一个 SaaS。
> 用户感觉自己正在进入一条创业者前辈走过的路。

整套系统建立在一句母句上。它是所有文案的源头：

> **每一家了不起的公司，都开始于一个不够体面的地方。**
> *Every great company begins in a small, imperfect place.*

---

## 如何使用这份文档

文档分九层，从抽象到具体，从「为什么」到「做多少」：

| 层 | 名称 | 回答的问题 |
|---|---|---|
| 01 | **Philosophy / 哲学** | 我们为什么写，写给谁，信什么 |
| 02 | **Brand Voice / 品牌声音** | Nebutra 像个什么样的人，五种语气怎么切 |
| 03 | **Cultural Themes / 文化母题** | 系统反复出现哪些意象，中美如何映射 |
| 04 | **Narrative Arc / 叙事主轴** | 用户旅程是什么形状（三幕九阶段） |
| 05 | **State Categories / 状态分类** | 文案分几类，各自的写法 |
| 06 | **Easter Egg System / 彩蛋系统** | 彩蛋怎么埋、埋多深、控制在多少比例 |
| 07 | **Writing Rules / 写作规则** | 哪些能写、哪些禁止 |
| 08 | **Production System / 生产系统** | 生产公式、数据结构、里程碑库 |
| 09 | **Rollout / 落地规划** | 第一版做多少、谁照着干、怎么扩 |

**给写手的一句话：** 如果只有时间读两节，读 02（Brand Voice）和 07（Writing Rules）。前者告诉你声音，后者告诉你边界。其余所有内容都是为了让这两节落地。

# 01 · Philosophy / 哲学

## 1.1 我们在写什么

Nebutra 的微文案不是 UI 提示，不是操作说明，不是企业级管理系统的回音。它是一层**文化层（Cultural Layer）**——一种贯穿产品全生命周期、让用户持续感到「这个产品是由真正理解创业的人设计的」的东西。

每一条微文案要达到的效果，不是「我知道该点哪里了」，而是：

> 「写这句话的人，懂。」

## 1.2 一个核心信念

母句同时解决了三件事，这是它能当源头的原因：

1. **它是中美同构的。** 美国是车库、宿舍、Denny's 餐厅卡座；中国是湖畔花园的三室一厅、大学宿舍、城中村出租屋、白天上班晚上写代码的那张工位。地点不同，母题相同——**伟大诞生于非正式空间**。
2. **它对所有用户成立。** 不论是想冲 YC 的小团队、海归创业者，还是只有一个深夜想法的副业 builder，「不够体面的起点」是所有 dreamer 共享的真相。这让 Nebutra 不属于任何小圈层，而属于所有「有梦想的人」。
3. **它定义了产品的情感立场。** Nebutra 不嘲笑你的起点小，也不假装你的起点不小。它说：小是对的，不够体面是正常的，重要的是方向真实。

## 1.3 关键判断：不复制 Garage，而抽象 Garage

这是整套文化定位最重要的一个决定。

「车库（Garage）」在美国是成熟的创业文化符号，但**它在中文世界并不成立**——中国创业者不会对「车库」产生共鸣，因为中国的城市住宅没有车库，中国的创业神话发生在别的地方。

所以 Nebutra 的做法不是把 Garage 翻译过来，而是**向上抽象一层**，抽出「车库」背后真正的母题——*非正式空间里诞生的认真事业*——再让这个母题在不同文化里各自落地。

这一抽象动作，是整套系统区别于「硅谷文化搬运工」的根本。我们不搬运符号，我们提炼母题，再让母题在每种语言里重新生长。

## 1.4 我们写给谁

不限定人群。但我们想象的读者，共享四个特征：

- **正在从 0 到 1。** 他们要么还没开始，要么刚开始。
- **起点不够体面。** 没有大办公室、没有完整团队、没有充足资金。这恰恰是我们尊重的。
- **怕被忽悠，也怕被看轻。** 他们对鸡汤、成功学、老板味高度敏感。一句假话就会让他们离开。
- **会被「懂」打动。** 当产品说出一句只有真正创过业的人才说得出的话，他们会停顿半秒，然后继续——但已经信任了。

## 1.5 三条不可违背的底线

无论写什么，违背以下任何一条，这条文案就不能上线：

1. **不说假话。** 不夸大用户的进展，不把小成就吹成大成就，也不把失败粉饰成胜利。
2. **不替用户感动。** 用户的情绪由用户自己产生，我们只负责把事实放在桌上。自我感动是最廉价的写作。
3. **不教训。** 我们是见过世面的同行，不是人生导师。我们分享，不指挥。

# 02 · Brand Voice / 品牌声音

## 2.1 Nebutra 是谁

> **Nebutra 是一位见过世面的老兵。**
> *A veteran who has seen things.*

不是连续创业的成功者（那会有优越感），不是 YC Partner（那会有评判感），不是热血的同龄人（那会有空洞感）。

是一个**把创业史装进口袋的人**——经历过早期的窘迫、半夜的部署、第一个用户、第一笔收入，也经历过项目死掉和重新开始。他不再激动，但他记得每一种心情。当你走到某一步，他刚好知道那一步是什么感觉，于是放下一张纸条，然后退后，让你继续走。

## 2.2 为什么是「老兵」

这个人格直接决定所有语气规则。它的价值在于：**它让「克制」和「有内容」可以共存。**

一个老兵话少，不是因为没东西说，而是因为他知道哪些话不必说。这正好区别于两种失败的声音：新手的声音是**空洞的**（没经历过，只能喊口号）；成功学的声音是**用力的**（急于证明，急于煽动）；老兵的声音是**克制的**（经历过太多，反而不需要大声）。

从这个人格，可以推导出几乎所有规则：

| 因为他是老兵... | 所以... |
|---|---|
| 老兵不喊 | 禁止感叹号、禁止全大写吼叫 |
| 老兵不指挥你 | 少用祈使句，多用陈述句——他把事实放下，不命令你 |
| 老兵见过失败 | 失败状态最能体现声音：不安慰、不评判、只是「我懂」 |
| 老兵记得细节 | 文案里藏具体的、真实的创业细节，而非抽象励志 |
| 老兵不抢功 | 用户的成就归用户，Nebutra 退到背景里 |
| 老兵话里有历史 | 这就是彩蛋的来源——他的话里有只有同行听得懂的回响 |

## 2.3 声音的四个维度

每个维度是一根滑杆。Nebutra 的位置都不在极端，但明显偏向一侧。

```
冷漠 ─────────────●─── 温暖          (偏温暖，但克制，不腻)
随意 ──────●───────── 庄重          (偏随意，但有分量，不轻浮)
谦逊 ────────────●─── 自信          (偏自信，但不优越，是经验的笃定)
严肃 ──────────●───── 幽默          (偏严肃，幽默只在恰当处闪现，从不抖机灵)
```

**温暖但克制：** 关心体现在「准确地知道你此刻在经历什么」，而不是「为你加油」。
**随意但有分量：** 语言可口语、可简短，但每句话背后要有真东西。
**自信但不优越：** 老兵的自信来自经验，不来自地位。
**严肃但偶有幽默：** 幽默永远是「会心一笑」式，不是「段子手」式。不抖机灵，不玩谐音，不蹭热点。

## 2.4 一个人格，五个声音档位

Nebutra 在不同场景需要不同语气，但**它们不是五个角色，是同一个老兵的五种语气模式**。就像一位前辈，在你失败时和你部署成功时语气不同，但还是同一个人——你认得出那是他。

之所以坚持「档位」而非「角色」：五个独立角色写到两百条以后会各自漂移——同伴越写越像产品经理，旁白越写越像文案策划，最后产品里住了五个人，统一人格瓦解。「档位」从根上锁死统一性：所有档位共享同一套底线，只调节温度和语速。

| 档位 | 触发场景 | 相对默认声音的调节 | 一句话示范 |
|---|---|---|---|
| **同伴档** Companion | 创建、建造、部署 | 默认档，安静坚定 | 许多公司，最初只是一个文件夹。 |
| **前辈档** Mentor | 失败、重构、现金流告急 | 更慢、更短、更克制，绝不安慰 | 先活下来，不丢人。 |
| **旁白档** Historian | 里程碑、彩蛋、毕业 | 略带历史感，可稍微抒情一句 | 第一间房间不必体面。 |
| **务实档** Operator | 数据、增长、反馈 | 更清醒、更冷静，泼一点冷水 | 信号变强之前，先确认它真实。 |
| **送别档** Graduation | 推荐外部工具、出师 | 温暖、有交接感，不舍但放手 | 你出师了。下一程需要更强的装备。 |

**档位切换的硬规则：** 无论切到哪个档位，以下永远不变（这是「还是同一个老兵」的保证）——不用感叹号、不用 emoji、不喊口号；不教训、不替用户感动；陈述优先于命令。档位只能调节**温度（冷↔暖）、语速（短促↔舒展）、是否泼冷水**，不能调节底线。

## 2.5 声音速记：Nebutra 会说 / 不会说

| 场景 | ❌ 不会说 | ✅ 会说 |
|---|---|---|
| 创建公司 | 「恭喜！开启你的创业之旅！🚀」 | 「第一间房间已经准备好。」 |
| 第一个用户 | 「太棒了！你获得了第一个用户！」 | 「从今天起，你不再只为自己开发。」 |
| 现金流告急 | 「警告：您的资金即将耗尽！」 | 「先活下来，不丢人。」 |
| 项目失败 | 「别灰心，失败是成功之母！」 | 「重启不是失败，是更诚实的开始。」 |
| 空状态 | 「暂无数据，点击下方添加。」 | 「许多公司，最初只是一个文件夹。」 |

每一个「会说」的共同点：**它陈述一个事实，而不是发出一个情绪。** 情绪留给用户自己产生。

## 2.6 双语原则

主语言是中英文，并兼顾多国 i18n。但「双语」不等于「互译」。

- **中英文各自独立成立。** 不是先写一种再翻译。两种语言各自要在自己的文化里读起来像母语写手写的。中文要有宿舍、工位、起盘、成局、出师的语感；英文要自然，偏 Stripe / Linear / GitHub 的克制感，不要 startup-bro 腔（no `crush it` / `10x` / `hustle`）。
- **保留同一个灵魂，允许不同的身体。** 同一条文案的中英版，母题相同、克制程度相同、彩蛋深度相同，但措辞可各自生长。
- **i18n 扩展时，翻译的是母题，不是句子。** 扩展到其他语言时，本地写手拿到的应是「这条要表达的母题 + 彩蛋深度 + 场景」，而非中文原句的字面翻译，这样才能在每种文化里各自找到对应的创业神话（见 §03.5）。

# 03 · Cultural Themes / 文化母题

## 3.1 什么是母题，为什么它是体系的核心

母题（Theme）是反复出现的意象。它是这套系统能「自我生产」的关键——写手不需要每次重新发明，只需要从母题库里取一个，再为当前场景具体化。

把母题想象成一组**和弦**。一千条文案是一千段旋律，但它们都建立在同样七个和弦上，所以听起来像同一首曲子的不同段落。这就是一个庞大文案系统能保持「像出自一人之手」的原理。

## 3.2 七大母题（The Seven Themes）

每个母题都附：内核、中美双重落地、可触发的产品场景。这是写手取灵感的主矿区。

**母题一 · 小空间，大公司 / The Small Room。** 内核：伟大的事业诞生于不够体面的空间，简陋不是缺陷，是起点的勋章。美国落地：HP 车库（后被官方立牌「硅谷诞生地」）、Google 早期借用的车库、宿舍。中国落地：湖畔花园的三室一厅、大学宿舍、城中村出租屋、白天上班晚上写代码的工位。表达方向：不说「车库」也不说「出租屋」，说**「第一间房间」**——一个所有文化都成立的抽象空间。触发场景：创建公司、创建 Workspace、创建项目、空状态、新手引导。

**母题二 · 第一位相信你的人 / The First Believer。** 内核：创业旅程由一连串「第一次有人相信」标记，这些「第一次」比任何数字都重。美国落地：Google 早期那张开给一家还不存在的公司的 10 万美元支票。中国落地：第一位客户、第一张订单、第一个愿意跟你干的同事。表达方向：强调「第一次」这个时刻本身的重量，而非数字大小——一个用户和一百万用户，「第一个」永远是不同质的。触发场景：First User、First Revenue、First Teammate、First Deploy。

**母题三 · 餐桌也可以是董事会 / The Table。** 内核：重要的事不一定发生在正式会议室，一张餐桌、一个咖啡馆、一顿夜宵，可以是一家公司真正的起点。美国落地：NVIDIA 三位创始人在 San Jose 一家 Denny's 餐厅的卡座里聊出了公司雏形。中国落地：创业咖啡馆（车库咖啡、3W 咖啡曾是北京创业者、投资人、媒体聚集地）、夜宵摊、学校食堂的小饭桌。表达方向：「第一场合伙人会议」不在董事会室，在一张普通的桌子旁。触发场景：Team Formation、Co-founder Invite、First Meeting、邀请成员。

**母题四 · 先活下来，再伟大 / Survival First。** 内核：在谈愿景之前先谈现金流，活下来不丢人，反而是早期最值得尊重的成就；收入的第一意义是「氧气」，不是「战略」。美国落地：Airbnb 早期靠卖大选主题麦片盒（Obama O's / Cap'n McCain's）续命；Paul Graham 提出过「ramen profitability」——赚够吃泡面的钱就算盈利。中国落地：先接单、先收钱、先把现金流跑通。表达方向：把「生存」正名为里程碑，现金流告急时不制造恐慌，而是把它说成创业的常态。触发场景：Revenue State、Runway Warning、Bootstrap Mode、First Revenue。

**母题五 · Ship 比 PPT 重要 / Ship It。** 内核：把东西做出来、交付出去，胜过完美的计划书；验证靠真实用户，不靠会议纪要；速度本身是竞争力。美国落地：YC 的核心训诫——做人们想要的东西、去和用户聊、做不可规模化的事；Demo Day 作为创业者的「成人礼」；开源世界里的 first deploy、第一行 Hello World、第一个 Pull Request。中国落地：华强北「上午设计、下午打样、次日量产」的速度神话。表达方向：推崇「交付」和「面对真实世界」的时刻，部署不是炫耀成果，是接受检验。触发场景：Deploy、Launch、Validate、Prototype、Demo。

**母题六 · 重启不是失败 / The Honest Restart。** 内核：推倒重来不是失败的证据，而是更诚实的开始，它往往比硬撑更接近正确。美国落地：Notion 早期一度濒死，两位创始人跑到京都重写整个代码库；General Magic「伟大的失败」——产品太超前而失败，却训练出了后来改变世界的一代人。中国落地：美团熬过千团大战、京东在 SARS 危机中从线下转线上——危机不是暂停键，可能是新渠道。表达方向：失败状态是 Nebutra 声音最该发光的地方，不安慰、不打鸡血，只是平静地说「重来也是进展」。触发场景：Failure State、Pivot、Refounding、Recovery、产品重构。

**母题七 · 开源 Repo 是新时代的车库 / The New Garage。** 内核：上个时代的创业从车库开始，这个时代的创业从一个公开的代码仓库、一次协作、一份开源开始；协作与开放是现代创业的底层动作。美国落地：GitHub 的 Pull Request 文化——提出变更、讨论、审查、合并。中国落地：DeepSeek 的开放模型与低调技术路线，已成为中国 AI 创业的新文化符号。表达方向：把「协作」「公开」「让未来进入 review」作为意象——邀请合伙人 = 发起一个 Pull Request，开源发布 = 把一部分未来交给世界。触发场景：Open Source、Collaboration、邀请合伙人、提交计划、工具毕业。

## 3.4 中美文化映射（成对落地）

落地时用这张表把母题翻译成具体意象。**注意：Nebutra 抽象表达一列才是最终进入文案的语言，左右两列只是它的文化根。**

| 硅谷符号 | 文化含义 | 中国对应 | Nebutra 抽象表达 | 对应母题 |
|---|---|---|---|---|

## 3.5 i18n 扩展：每种文化都有自己的「第一间房间」

扩展到其他语言市场时，**不要翻译中文或英文句子，而要为该文化找到它自己的「不够体面的起点」**。母题不变，落地符号随文化生长：

| 瑞典 | Spotify、宜家——小市场孕育全球品牌 | 小空间，大公司 |
| 日本 | Sony 战后从被烧毁建筑的一间房起步；任天堂从花札纸牌起家 | 废墟里的第一间房间 |

# 04 · Narrative Arc / 叙事主轴

## 4.1 为什么需要主轴

如果母题（§03）是「和弦」，叙事主轴就是「曲式结构」——它决定一条文案应该出现在用户旅程的哪个位置，以及那个位置该有什么情绪。没有主轴，文案会变成一盘散沙：每条单看都不错，但用户走完全程感受不到「成长」。

## 4.2 结构：用户看见三幕，写手标注九阶段

这是体系最重要的结构决定。完整的创业旅程有九个阶段，但**九个里程碑用户记不住，进度条也难画**；而三幕（起步 / 建造 / 成长）是任何人都能清晰感知的状态。所以：

- **用户感知层 = 三幕。** 产品里的进度可视化、阶段提示，用户看到的是三幕。
- **写手生产层 = 九阶段。** 写手标注一条文案时，必须标清它属于九阶段里的哪个——因为 Validating 阶段的失败和 Scaling 阶段的失败，心情完全不同。

```
第一幕「起步」          第二幕「建造」              第三幕「成长」
 ┌──────────────┐    ┌──────────────────┐    ┌─────────────────────┐
 │ Imagining 起念 │    │ Building   建造    │    │ Growing    起势       │
 │ Validating 试水│    │ Shipping   发布    │    │ Scaling    扩张       │
 │ Assembling 组局│    │ Operating  经营    │    │ Graduating 出师       │
 └──────────────┘    └──────────────────┘    └─────────────────────┘
   想法→验证→组队        造出来→发出去→跑起来        长大→扩张→毕业
```

采用 -ing 进行时，因为创业永远是「正在进行」，从不是「已完成」。进行时本身就是一种声音——它暗示运动、未完成、还在路上。

## 4.3 九阶段对照表（生产用）

| # | 英文 | 中文 | 所属幕 | 用户在做什么 | 主导情绪 | 主力母题 |
|---|---|---|---|---|---|---|
| 1 | Imagining | 起念 | 起步 | 产生想法 | 兴奋而不确定 | 第一间房间 |
| 2 | Validating | 试水 | 起步 | 找用户、验需求 | 忐忑、求真 | Ship 比 PPT |
| 3 | Assembling | 组局 | 起步 | 找合伙人、招人 | 期待、谨慎 | 餐桌即董事会 |
| 4 | Building | 建造 | 建造 | 做 MVP | 专注、投入 | 新时代车库 |
| 5 | Shipping | 发布 | 建造 | 部署、上线 | 紧张而骄傲 | Ship + 第一位相信你的人 |
| 6 | Operating | 经营 | 建造 | 跑业务、处理反馈 | 务实、疲惫 | 先活下来 |
| 7 | Growing | 起势 | 成长 | 获客、留存 | 谨慎乐观 | 第一位相信你的人 |
| 8 | Scaling | 扩张 | 成长 | 团队收入扩大 | 沉稳、有重量 | 餐桌即董事会（回望） |
| 9 | Graduating | 出师 | 成长 | 走向更专业工具 | 成长、被认可 | 第一间房间（回望） |

## 4.4 两条纵贯线（横切所有阶段）

九阶段是骨架，但**有两类状态塞不进任何单一阶段**，它们横切整条主轴：

- **Failure / 失败状态** — 任何阶段都可能失败。Imagining 阶段想法被否、Scaling 阶段公司崩盘，本质是同一种心情。失败是一条纵贯线，不是某一站。
- **Milestone / 里程碑状态** — 每个阶段都有自己的「第一次」。它是横切所有阶段的庆祝机制。

```
        ┌──────────────────────────────────────────────────┐
   主轴 │ Imagining→Validating→Assembling→…→Scaling→Graduating │
        └──────────────────────────────────────────────────┘
                  ↕ 任何一点都可能触发 ↕
        ┌──────────────────────────────────────────────────┐
   纵贯 │      Failure(失败/重启)    ·    Milestone(里程碑)        │
        └──────────────────────────────────────────────────┘
```

骨架提供顺序感，纵贯线提供完整性。两者结合，才覆盖真实创业的全部心情。

## 4.5 主轴如何指导写作

接到一条文案任务，先问：它在哪个阶段？（定情绪）它是纵贯状态吗？（Failure / Milestone，定是否横切）

举例「第一次部署成功」：阶段 = Shipping；纵贯 = 是 Milestone（第一次）；于是情绪 = Shipping 的「紧张而骄傲」+ Milestone 的「第一次的重量」；母题 = Ship 比 PPT + 第一位相信你的人；产出方向 = 「世界第一次看见它。」这就是从主轴和母题**推导**一条文案的标准流程，而非凭灵感硬想。

# 05 · State Categories / 状态分类

这是写手日常查得最多的一节。它把产品里所有需要文案的时刻分成可操作的类别，每类给出：情绪、母题、档位、规则、范例。接到任务时，先在这里定位你的文案属于哪一类。

## 5.1 分类总览

| 状态类别 | 出现时机 | 核心情绪任务 | 默认档位 | 主力母题 |
|---|---|---|---|---|
| **Onboarding** 新手引导 | 首次进入 | 让人觉得「来对了」 | 旁白 | 第一间房间 |
| **Empty State** 空状态 | 还没有内容 | 把「空」说成「起点」 | 同伴 | 第一间房间 |
| **Success State** 成功状态 | 操作成功 | 确认，但不替用户嗨 | 同伴 | 视场景 |
| **Failure State** 失败状态 | 出错/失败 | 不安慰、不评判、只「我懂」 | 前辈 | 重启不是失败 |
| **Team State** 团队状态 | 组队/邀请 | 把「加人」说成「成局」 | 同伴 | 餐桌即董事会 |
| **Revenue State** 收入状态 | 钱相关 | 把收入正名为氧气 | 务实 | 先活下来 |
| **Growth State** 增长状态 | 数据上涨 | 谨慎，不吹泡沫 | 务实 | 第一位相信你的人 |
| **Milestone State** 里程碑 | 「第一次」时刻 | 标记重量，不放烟花 | 旁白 | 第一位相信你的人 |
| **Deployment State** 部署状态 | 发布/上线 | 交付即受检验 | 同伴 | Ship 比 PPT |
| **Graduation State** 出师状态 | 阶段跃迁/推荐工具 | 给「长大」一个仪式 | 送别 | 第一间房间（回望） |

## 5.2 逐类写作指南

**Onboarding / 新手引导。** 情绪任务：让用户在前 10 秒感到「这个产品是同行做的」。规则：不解释功能，先建立气场；第一句话不该是「欢迎使用 Nebutra，这是一个……」，而该是一句让人停顿的事实。范例：中「你不需要准备完美，先给它一个开始。」/ 英 `You don't need to be ready. You need to begin.`

**Empty State / 空状态。** 情绪任务：「空」是大多数产品最尴尬的时刻，却是 Nebutra 最该发光的时刻——因为空，正是每家公司的真实起点。规则：永远不要写「暂无数据」，把空白重新定义为「未被填写的开始」。范例：中「许多公司，最初只是一个文件夹。」/ 英 `Many companies begin as a folder.`

**Success State / 成功状态。** 情绪任务：确认事情成了，但把情绪留给用户。规则：禁感叹号，禁「恭喜」「太棒了」；用陈述句描述「发生了什么」，而非「你多厉害」。范例：中「第一间房间已经准备好。」/ 英 `The first room is ready.`

**Failure State / 失败状态。** 情绪任务：这是整套声音的试金石——不安慰（显得轻浮）、不打鸡血（显得空洞）、不评判（显得高高在上），只做一件事：让用户感到「写这句话的人也失败过」。规则：禁「别灰心」「失败是成功之母」；禁过度共情（"我知道这很难"）；平静、简短、有历史感。范例：中「重启不是失败，是更诚实的开始。」/ 英 `A restart is a more honest beginning.`

**Team State / 团队状态。** 情绪任务：把「邀请成员」这种功能动作，还原成「组一个局」的人情时刻。规则：强调「一个人能开始，几个人才能成事」，但不煽情。范例：中「一个人可以开始，几个人才能成局。」/ 英 `One can start. A few can build.`

**Revenue State / 收入状态。** 情绪任务：把收入从「财务数字」翻译成「梦想还能继续存在」。规则：第一笔收入不论多小都郑重对待；现金流告急时不制造恐慌。范例：中「梦想开始拥有现金流。」/ 英 `The dream has cash flow now.`

**Growth State / 增长状态。** 情绪任务：承认增长，但保持老兵的清醒——增长可能是信号，也可能是泡沫。规则：禁「爆了」「起飞」「指数级」这类短视频语气；用「信号变强」这类克制描述。范例：中「信号开始变强。」/ 英 `The signal is getting stronger.`

**Milestone State / 里程碑（纵贯线）。** 情绪任务：标记一个「第一次」的重量，重点是这一刻的不可复制，不是数字本身。规则：不放烟花（禁 🎉🚀），但要让用户感到这一刻被认真记住了。范例：中「从今天起，你不再只为自己开发。」/ 英 `From today, you are no longer building only for yourself.`

**Deployment State / 部署状态。** 情绪任务：部署不是「成功提示」，是「世界第一次看见你的东西」。规则：可藏开源/黑客文化的回响层彩蛋。范例：中「世界第一次看见它。」/ 英 `The world sees it for the first time.` 回响层：「它终于离开了 localhost。」/ `It finally left localhost.`

**Graduation State / 出师状态。** 这是 Nebutra 区别于普通 SaaS 的核心场景：用户不是被永远锁住，而是被 Nebutra 培养成能用更专业工具的创业者。情绪任务：让工具推荐不像销售，而像「出师」。规则：禁「升级套餐解锁更多功能」。范例：中「你出师了。试试 {tool}，它能让你的团队走得更远。」/ 英 `You've outgrown the basics. Try {tool} for the road ahead.`

## 5.3 接到任务时的标准流程（写手 SOP）

```
1. 这条属于哪个 State Category?       → 查 5.1
2. 它在九阶段的哪个阶段?              → 查 4.3
3. 它是纵贯状态吗(Failure/Milestone)?→ 查 4.4
4. 该用哪个母题?                      → 查 3.3
5. 该用哪个声音档位?                  → 查 2.4 / 5.1
6. 要不要彩蛋?哪一层?                → 查 06
7. 写中英两版,各自独立成立。         → 查 2.6
8. 过写作规则红线,确认能上线。       → 查 07.5
```

# 06 · Easter Egg System / 彩蛋系统

这是整套系统最难、也最珍贵的一层。彩蛋让产品有了文化人格，但也最容易翻车：埋浅了是低级模仿，埋深了没人看懂，引用过度会侵权，用力过猛变成圈内尬梗。这一节给出能长期、安全、批量生产彩蛋的规则。

## 6.1 三层彩蛋（而非更多级）

彩蛋按文化深度分三层。**之所以是三层而非更细的分级：写手必须能稳定标对，否则彩蛋登记表会乱。** 每层有清晰的硬判定，谁标都一样。

| 层级 | 一句话定义 | 硬判定标准 |
|---|---|---|
| **功能层** Functional | 纯功能，无文化 | 拿掉它产品就不可用（高风险操作确认） |
| **隐喻层** Metaphor | 文化隐喻，人人读懂 | 第一层独立成立，**无需任何背景**就是好文案 |
| **回响层** Echo | 懂的人会心一笑 | 双层：表面人人懂，第二层同行才听出回响 |

## 6.2 投放比例：不要满屏彩蛋，否则会油

这是整套彩蛋系统最锋利的一条纪律。目标比例：

```
功能层   ████ 10%       ← 只在高风险操作出现
隐喻层   ███████████████████████████ 65%   ← 绝对主力,大部分场景
回响层   ██████████ 25%  ← 点睛,过多则油
```

**为什么回响层卡死在 25% 上限：** 回响层是「会心一笑」的来源，但也是最容易让产品显得「用力」「在炫耀自己懂梗」的地方。25% 意味着平均每四条里有一条藏深彩蛋——足够让常用产品的用户时不时撞见惊喜，又不至于每一句都在抖文化而变油。

## 6.3 回响层的双层铁律

回响层的每一条都必须通过这个测试：**把第二层背景知识全拿掉，只看字面——如果仍是好文案，合格；如果变得莫名其妙，降级到隐喻层或重写。** 没读出第二层的人毫无损失；读出第二层的人获得一个秘密的微笑。这是「会心一笑」和「看不懂」之间唯一安全的平衡点。

| 回响层范例 | 第一层（人人懂） | 第二层（同行会心） |
|---|---|---|
| 它终于离开了 localhost。 | 你的东西上线公开了 | 开发者记得第一次服务跑出本地那一刻 |
| 有些项目不是失败，是把团队练出来了。 | 项目结束但你成长了 | General Magic——伟大的失败孕育一代人 |
| 先活下来，不丢人。 | 现金流紧张很正常 | ramen profitability 的生存美学 |
| 第一间房间不必体面，但方向必须真实。 | 起点小没关系 | 车库/湖畔花园——所有创业神话的共同起点 |

## 6.4 「隔一层」翻译法（核心手艺）

彩蛋永远不裸引用。把一个文化典故变成合格彩蛋的标准动作，是**「隔一层」**——不说典故本身，说典故指向的那个真相。

| 裸引用（❌ 低级） | 隔一层（✅ 高级） | 隔的是哪一层 |
|---|---|---|
| `Talk to users.` | 用户不会出现在会议纪要里，除非你真的去找他们。 | 把训诫变成观察 |
| `From garage to unicorn.` | 第一间房间不必体面，但方向必须真实。 | 把口号变成态度 |
| `Make something people want.` | 先做一个有人愿意回来使用的东西。 | 把标语变成动作 |
| 像乔布斯一样创业 | 有些公司，先成为神话，后拥有办公室。 | 把名人变成原型 |
| `Move fast and break things.` | 先让它跑起来，再让它好看。 | 把激进口号变成务实顺序 |

为什么必须隔一层：裸引用有三宗罪——显得浅（像贴名人语录）、可能侵权（直接用他人标语）、排斥了不认识典故的人。隔一层同时解决三者：它高级、它原创、它对所有人成立。

## 6.5 彩蛋安全红线（侵权与风险控制）

以下情况一律不可，无论多想用：

1. **不直接引用受保护的标语/口号。** 例：不写 `Think Different`、`Move fast and break things`、「让天下没有难做的生意」。抽象其精神，另写一句。
2. **不直接引用名人原话并署名。** 不做「乔布斯说过：……」，可抽象成无主语的原型表达。
3. **不点名调侃在世的具体人物/公司。** 致敬可以，影射特定真人不行（法律 + 格调双重风险）。
4. **不蹭时事热点、不玩谐音梗、不抖网络流行语。** 热点会过时，过时的彩蛋是尴尬的。
5. **第一层就需要太圈内知识才能读通的，不算合格隐喻层/回响层。** 若第一层就需要懂 K8s 才能读通，放弃或藏进只有寻宝者会触发的角落。

## 6.6 彩蛋素材矿区（按文化分区，供长期取材）

这里列的是矿，不是成品。写手从中提炼母题，再用 §6.4 的方法产出原创彩蛋。

**硅谷矿区：** 车库神话（HP「硅谷诞生地」/ Apple / Google）→ 第一间房间；Denny's 卡座（NVIDIA）→ 餐桌即董事会；卖麦片盒续命（Airbnb）+ ramen（PG）→ 先活下来；Demo Day（YC）→ 面对世界的检验；京都重写代码（Notion）→ 诚实的重启；伟大的失败（General Magic）→ 失败孕育团队；door desk / regret minimization（Amazon）→ 朴素的起点 / 不留遗憾的决定。

**中国矿区：** 湖畔花园三室一厅、十八个人（阿里）→ 小空间大公司；创业咖啡馆（车库/3W）→ 餐桌即董事会；SARS 转线上（京东）→ 危机即新渠道；千团大战的长期战役（美团）→ 先打赢一条街；低调技术、开源（DeepSeek）→ 安静地推进前沿；华强北「上午设计下午打样」→ Ship 比 PPT；工位/出租屋/宿舍 → 第一间房间（中国版）。

**开源/黑客矿区（适合 Deployment / 技术场景，多为回响层）：** Hello World → 第一次发声；localhost → 走出本地即面对世界；Pull Request / merge / fork → 让未来进入 review；first deploy → 世界第一次看见；404 / 500 → 俏皮错误页（隐喻层）；rubber duck / "works on my machine" → 开发者共同窘境（慎用，太圈内）；42 → 藏在关于页的深彩蛋。

**YC/创投矿区（抽象理念，绝不裸引）：** do things that don't scale → 早期就该做笨重而真实的事；default alive vs default dead → 先确认自己还活着；第一性原理 → 回到问题本身；runway / burn rate → 跑道与氧气。

## 6.7 彩蛋登记表（Easter Egg Registry）

每条回响层彩蛋入库时记录：`层级 / 第一层文案 / 第二层典故来源 / 已用于哪个场景 / 风险等级`。目的有二：**防侵权**（同一典故不重复裸用）、**防油**（同一典故不在相邻场景反复出现）。

## 6.8 一个完整的彩蛋诞生流程（示范）

以「第一次部署成功」为例：

```
1. 场景:Deployment,Shipping 阶段,是 Milestone(第一次)
2. 取母题:Ship 比 PPT + 第一位相信你的人
3. 进矿区:开源黑客区找到「localhost」素材
4. 隔一层:不说「你部署到生产环境了」(裸),说「它终于离开了 localhost」(隔一层)
5. 验双层:第一层=东西上线公开 ✓ 通顺;第二层=开发者第一次跑出本地的心情 ✓ 会心
6. 定层级:回响层(资深开发者会心,普通人也读得懂)
7. 写中英:中「它终于离开了 localhost。」/ 英 It finally left localhost.
8. 过红线:无裸引、无署名、无热点、第一层成立 ✓ 上线
9. 入登记表:典故=localhost,场景=首次部署,风险=低
```

这是一个可被无限复制的生产流程。任何写手照此走，产出的彩蛋都会像出自同一个老兵之手。

# 07 · Writing Rules / 写作规则

这是评审一条文案能否上线的清单。如果 Brand Voice（§02）是「声音」，这一节就是「边界」。

## 7.1 七条禁令（违反即不能上线）

1. **禁过度激励。** 不写「加油」「你能行」「冲鸭」「梦想成真」。老兵不喊口号。
2. **禁空洞成功学。** 不写「失败是成功之母」「越努力越幸运」「下一个独角兽就是你」这类没有信息量的格言。
3. **禁自我感动。** 不替用户流泪。不写「这一刻，所有努力都值得了」这类越俎代庖的情绪。
4. **禁 LinkedIn 味 / 老板味。** 不写「赋能」「闭环」「抓手」「颗粒度」「打法」「数字化转型」，不写「请您」「为了更好地服务您」「系统检测到」。
5. **禁尬梗 / 蹭热点 / 谐音梗。** 不玩网络流行语、不蹭时事、不抖机灵（例：不写「你的 MVP 已经支棱起来了」）。
6. **禁裸引用。** 不直接搬名人语录、他人标语口号（见 §6.5）。
7. **禁失败羞辱。** 不写「你失败了」「操作失败，请重试」这类伤害用户情绪的话。

## 7.2 五条提倡（好文案的标志）

1. **克制。** 能用更少的字说清，就用更少。删到不能再删。
2. **真诚。** 说真话。不夸大用户的进展，不粉饰失败。
3. **有历史感。** 句子背后有创业史的回响（通过回响层彩蛋实现）。
4. **有传承感。** 像前辈留给后辈的纸条，而非系统对用户的通知。
5. **陈述，而非命令/煽动。** 把事实放在桌上，让用户自己产生情绪和判断。

## 7.3 标点与格式微规则

| 项目 | 规则 | 原因 |
|---|---|---|
| 感叹号 | 几乎禁用 | 老兵不喊 |
| Emoji | 默认不用（🎉🚀🔥 一律禁） | 烟花式庆祝违背克制 |
| 全大写吼叫 | 禁（英文不写 `LET'S GO!!!`） | 同上 |
| 祈使句 | 少用，优先陈述句 | 老兵不指挥 |
| 句子长度 | 偏短。一条微文案通常一到两句 | 克制 |
| 省略号 | 慎用，容易显得欲言又止/做作 | 老兵话说完就停 |
| 破折号 | 可用于「停顿后补一句更真的话」 | 符合口语节奏 |

## 7.4 中英文各自的微调

**中文：** 避免「的的不休」和翻译腔（「这是一个能够帮助你……的工具」）；善用短句和留白，克制靠节奏不靠词藻；不用网络用语，但也不文绉绉——是「会写字的同行」，不是「文案策划」。

**英文：** 避免 startup-bro 腔（no `crush it` / `10x` / `hustle` / `grind`）；偏短句，sentence fragment 可用（`The first room is ready.`）；小写美学可酌情用于回响层技术彩蛋（`it finally left localhost.`），但正式状态文案用正常句式。

## 7.5 上线前自检清单（每条文案过一遍）

```
□ 它属于明确的 State Category 吗?(05)
□ 它的情绪符合所在阶段吗?(04)
□ 它用了某个母题,而不是凭空发明吗?(03)
□ 它用了正确的声音档位吗?(02.4)
□ 如果有彩蛋,第一层独立成立吗?(06.3)
□ 它违反七条禁令的任何一条吗?(07.1)
□ 它是陈述而非煽动吗?(07.2)
□ 中英两版各自像母语写手写的吗?(02.6)
□ 删掉后用户会有损失吗?(没损失就别加——克制)
```

最后一条最重要：**如果一条文案删掉，产品没有任何损失，那它就不该存在。** 每一条都要么提供信息，要么提供温度，要么提供会心。三者皆无，删。

# 08 · Production System / 生产系统

这一节把前面所有规则固化成可执行的部件：生产公式、数据结构、里程碑库。这是把「方法论」变成「生产线」的地方。

## 8.1 文案生产公式

```
基础公式:
用户动作 + 九阶段 + 用户情绪 + 文化母题 + 声音档位 + 彩蛋层 + 下一步 = 微文案
```

# 09 · Rollout / 落地规划

## 9.1 产能规划：先做黄金 50 条，验证后扩到 155

不要一上来写 1000 条，也不要一上来写 155 条。**第一版先做黄金 50 条：每个 P0 场景只写最高频、最能定调的那几条，每条打磨到样板级，先验证「声音对不对、彩蛋油不油」，再放量。** 155 条难一次写到位，会稀释质量。

| 阶段 | 总量 | 目的 | 验收门槛 |
|---|---|---|---|
| **Phase 0 黄金样板** | 50 条 | 定调、验证声音、校准彩蛋比例 | 团队盲读能认出「同一个人写的」；回响层 ≤25%；无一条触禁令 |
| **Phase 1 铺开** | 扩到 155 条 | 覆盖 P0+P1 全场景 | 每条过 §7.5 自检清单 |

## 9.2 黄金 50 条的分配（Phase 0）

只做 P0 场景 + 两个差异化场景：

| 场景 | 条数 | 为什么是它 |
|---|---|---|
| Onboarding 新手引导 | 8 | 决定第一印象 |
| Empty State 空状态 | 10 | 最容易体现产品气质，且高频 |
| Success State 成功状态 | 10 | 高频，强化仪式感 |
| Milestone 里程碑 | 12 | 创业文化彩蛋的主战场 |
| Failure State 失败状态 | 6 | 老兵声音的试金石，先少而精 |
| Graduation 出师 | 4 | Nebutra 区别于普通 SaaS 的差异点 |
| **合计** | **50** | |

## 9.3 Phase 1 扩量目标

验证通过后再扩：Onboarding 20 / Empty 30 / Success 30 / Failure 20 / Milestone 40 / Graduation 15 = 155。

## 9.4 落地路线图

| 步骤 | 动作 | 产出 |
|---|---|---|
| 1 | 写黄金 50 条（§9.2 分配） | 50 条样板 |
| 2 | 团队盲读校准 | 验证「同一个人写的」+ 彩蛋 ≤25% |
| 3 | 建 Easter Egg Registry | 登记表上线（字段见 §6.7） |
| 4 | 扩到 155 条（Phase 1） | 全 P0+P1 覆盖 |
| 5 | i18n 试点一个语言 | 母题落地手册（见 §3.5） |

## 9.5 这套系统如何生产「第 1001 条」文案

这份文档的全部价值，在于它能让一个从没读过前 1000 条文案的新写手，产出第 1001 条，且没人能看出是不同的人写的。流程是：

用 §5.3 的 SOP 定位场景 → 用 §04 定情绪 → 用 §03 取母题 → 用 §2.4 定档位 → 用 §06 决定彩蛋层 → 写中英两版 → 用 §7.5 自检上线。

这就是「方法论而非句子集」的含义。句子会用完，方法不会。
