Status document — updated as claims are corrected. Last verified: 2026-07-30.
Ratchet: `tests/architecture/doc-claims-drift.test.ts` — **GREEN** (19 assertions), with a
16-entry shrink-only allowlist carrying the decision-blocked items (see "Ratchet status").
Scope: `CLAUDE.md`, `README.md`, `apps/design-docs/content/docs/**`,

Build artifacts (`.next`, `storybook-static`, `dist`, `node_modules`) excluded from every search.

## Why this file exists

Four doc claims were found actively wrong on 2026-07-29, and each had already caused a defect
because somebody followed it:

1. `CLAUDE.md` called `packages/design/tokens/styles.css` the SOURCE OF TRUTH in three places and
   told readers to edit it. It is a build artifact —
   `packages/design/tokens/scripts/sync-styles.mjs` copies over it — so edits vanished silently.
2. `CLAUDE.md` described `@nebutra/theme` as a "CSS-only multi-theme engine (data-theme attribute,
   6 oklch themes)" with presets `neon/gradient/dark-dense/minimal/vibrant/ocean`. Those were
   deleted in 2026-07; `packages/design/theme/README.md` says not to reintroduce them.
3. `CLAUDE.md`'s Rebranding step 3 pointed at `packages/design/theme/themes.css`, now five generated
   lines aliasing `keyframes.css`.
4. `apps/design-docs/content/docs/{en,zh}/how-to-use.mdx` showed `bg-[var(--background)]` under a
   "Good" heading. `--background` holds bare HSL channels, so that form invalidates the whole
   declaration and the browser discards it.

All four are fixed. This is the worklist for everything else of the same shape.

`[ratchet: fixed]` — all five rows now carry the real counts. Only the `design/` row was in the
original audit; the other four were found by the ratchet.

**`README.md` is itself a generated file** — `scripts/brand-apply.ts` renders it from
`README.template.md`, as `tests/architecture/readme-template-drift.test.ts` documents and enforces
(same for `README.zh-CN.md` and `README.ja.md`). The first correction to these counts was made in
the rendered file and disappeared: the next render restored the stale numbers from the untouched
template. This is finding #1 of "Why this file exists" recurring on a file nobody had classified as
generated.

Fixed on 2026-07-30 in `README.template.md`, then re-rendered with `pnpm brand:apply`. The rows now
read `# N pkgs — e.g. …` rather than presenting a partial list as complete, which drops the
hand-typed name list as a second drift surface (the assertion checks `N`).

Two consequences worth carrying forward:

- The ratchet now checks the **template and** the rendered file, and its failure message says to fix
  the template. Checking the rendered file alone was also the cause of a real flake: the sibling
  drift suite runs `brand:apply` and restores afterwards, so `README.md` is briefly the freshly
  rendered version mid-suite, and the assertion passed in isolation while failing in the full run.
- `README.md` / `README.zh-CN.md` / `README.ja.md` are **not** in the test's `GENERATED_FILES` list.
  They cannot be, as written: that check does a substring match, and `README.md` is a suffix of
  every package README path, none of which are generated. Anchoring the match to a repo-relative
  path would let the three root READMEs join the list — worth doing, listed under "Still open".

### Decision-blocked (allowlisted, 16 entries)

Held in `MISSING_PACKAGE_ALLOWLIST` (14) and `UNRESOLVED_SUBPATH_ALLOWLIST` (2) in
`tests/architecture/doc-claims-drift.test.ts`, in the same shape as
`repositorySeam.allowlist` in `governance.config.json`: sorted, committed, **shrink-only**.
Anything not on a list fails; an entry that stops matching also fails, so fixing a page means
