## Authentication methods

The Nebutra API supports two authentication methods:

| Method | Use case |
|--------|----------|
| **API Key** | Server-to-server, CLI tools, CI/CD pipelines |
| **Bearer Token (JWT)** | User-facing requests from your frontend or mobile app |

## API Key authentication

API keys are long-lived credentials tied to an organization (not a user). They are prefixed with `nbk_live_` in production and `nbk_test_` in test mode.

Pass the API key in the `Authorization` header:

```http
GET /api/v1/projects HTTP/1.1
Authorization: Bearer nbk_live_xxxxxxxxxxxxxxxxxxxx
```

### Create an API key

In the dashboard: **Settings → API Keys → Create Key**

Or via the API:

```typescript
const key = await nebutra.apiKeys.create({
  orgId: "org_123",
  name: "Production CI",
  scopes: ["project:read"],
  expiresAt: new Date("2027-01-01"),
});
// key.secret → shown ONCE, store securely
```

### API key scopes

API keys can be scoped to a subset of your organization's permissions. Always use the minimum scopes required (principle of least privilege).

See [Permissions](/concepts/permissions) for the full scope reference.

### Rotate an API key

```typescript
const newKey = await nebutra.apiKeys.rotate("key_123");
// Old key is immediately invalidated
```

### Revoke an API key

```typescript
await nebutra.apiKeys.delete("key_123");
```

Revoked keys return `401 Unauthorized` immediately.

## Bearer token (JWT) authentication

JWTs are issued by your auth provider (Clerk or Better Auth) after a user signs in. They are short-lived (typically 1 hour) and automatically refreshed client-side.

```http
GET /api/v1/projects HTTP/1.1
Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...
```

### Token contents

```json
{
  "sub": "user_2a8bXXXXXXXXX",
  "org_id": "org_2a8bXXXXXXXXX",
  "org_role": "org:member",
  "scopes": ["project:read", "project:create"],
  "plan": "pro",
  "iat": 1743427200,
  "exp": 1743430800
}
```

### Verify a token in your backend

```typescript
import { verifyToken } from "@nebutra/sdk/server";

const payload = await verifyToken(token, {
  apiKey: process.env.NEBUTRA_API_KEY!,
});

// payload.userId, payload.orgId, payload.scopes
```

## Security best practices

<Warning>
  - Never expose API keys in client-side code, browser URLs, or version control
  - Use environment variables for all secrets
  - Rotate API keys regularly (at least annually)
  - Use scoped keys — never give a key `OWNER`-level access unless necessary
  - Set expiration dates on API keys used in automated workflows
</Warning>
