Nebutra sends transactional emails through the `@nebutra/email` package. Templates are built with [React Email](https://react.email) and delivered via [Resend](https://resend.com). All six system email templates are included out of the box.

## Architecture

```
┌──────────────────────────────────────┐
│    Server Action / API Route /       │
│    Background Job / Webhook          │
└──────────────┬───────────────────────┘
               │ email.send({ to, template, data })
┌──────────────▼───────────────────────┐
│         @nebutra/email               │
│  getEmailProvider() → Resend client  │
│  Renders React Email template →      │
│  HTML + plain-text                   │
└──────────────┬───────────────────────┘
               │ Resend API (HTTPS)
┌──────────────▼───────────────────────┐
│              Resend                  │
│  Transactional delivery, logs,       │
│  domain verification, webhooks       │
└──────────────┬───────────────────────┘
               │ SMTP delivery
┌──────────────▼───────────────────────┐
│         Recipient inbox              │
└──────────────────────────────────────┘
```

Template rendering happens in your application process before the email is sent to Resend. React Email components compile to HTML and a plain-text fallback automatically.

## Built-in templates

| Template key | Subject | When it is sent |
|--------------|---------|-----------------|
| `welcome` | Welcome to Nebutra | After a new user signs up and their account is ready |
| `api-key-created` | Your new API key | After an API key is generated for an organization |
| `quota-warning` | You've used 80% of your [metric] quota | When metered usage reaches 80% of the plan limit |
| `quota-exceeded` | You've exceeded your [metric] quota | When metered usage exceeds 100% of the plan limit |
| `team-invite` | [inviter] invited you to join [org] | When a user is invited to join an organization |
| `password-reset` | Reset your password | When a user requests a password reset link |

## Quick start

```typescript
import { getEmailProvider } from "@nebutra/email";

const email = await getEmailProvider();

// Welcome email
await email.send({
  to: user.email,
  template: "welcome",
  data: {
    userName: user.name,
    orgName: org.name,
    dashboardUrl: "https://app.nebutra.com/dashboard",
  },
});

// Quota warning
await email.send({
  to: adminEmails,
  template: "quota-warning",
  data: {
    orgName: org.name,
    metric: "api_calls",
    used: 8100,
    limit: 10000,
    percentage: 81,
    upgradeUrl: "https://app.nebutra.com/billing",
  },
});

// Team invite
await email.send({
  to: invitee.email,
  template: "team-invite",
  data: {
    inviteeName: invitee.name ?? invitee.email,
    inviterName: inviter.name,
    orgName: org.name,
    inviteUrl: `https://app.nebutra.com/invites/${invite.token}`,
    expiresAt: invite.expiresAt.toISOString(),
  },
});
```

## Environment variables

| Variable | Required | Description |
|----------|----------|-------------|
| `RESEND_API_KEY` | Yes | Resend API key — starts with `re_` |
| `EMAIL_FROM` | Yes | Sender address, e.g. `Nebutra <noreply@mail.nebutra.com>` |

<Warning>
`RESEND_API_KEY` is a secret. Never commit it to source control. Add it to Vercel environment variables or your secrets manager.
</Warning>

## Resend dashboard

The [Resend dashboard](https://resend.com) provides:

- **Logs** — delivery status, bounces, and opens for every email
- **Domain verification** — DNS records to verify your sending domain
- **API keys** — create and rotate keys
- **Webhooks** — receive delivery events in your application

<Note>
Resend requires a verified sending domain before you can deliver to recipients outside your Resend account. See [Providers](/email/providers) for domain verification steps.
</Note>
