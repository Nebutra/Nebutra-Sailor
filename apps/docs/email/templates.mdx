Email templates live in `packages/email/src/templates/`. Each template is a React Email component that accepts a typed `data` prop and renders to HTML and plain text.

## Template reference

### `welcome`

Sent after a new user's account is created.

**File:** `packages/email/src/templates/welcome.tsx`

```typescript
await email.send({
  to: user.email,
  template: "welcome",
  data: {
    userName: string,       // Display name, e.g. "Alex Chen"
    orgName: string,        // Organization name, e.g. "Acme Corp"
    dashboardUrl: string,   // Full URL to the user's dashboard
  },
});
```

---

### `api-key-created`

Sent when an API key is generated for an organization.

**File:** `packages/email/src/templates/api-key-created.tsx`

```typescript
await email.send({
  to: adminEmail,
  template: "api-key-created",
  data: {
    userName: string,       // Name of the user who created the key
    orgName: string,        // Organization name
    keyName: string,        // Human-readable key name, e.g. "Production Key"
    keyPrefix: string,      // First 8 chars of the key for identification, e.g. "sk_live_"
    createdAt: string,      // ISO 8601 timestamp
    manageUrl: string,      // URL to the API keys settings page
  },
});
```

---

### `quota-warning`

Sent when metered usage reaches 80% of the plan limit.

**File:** `packages/email/src/templates/quota-warning.tsx`

```typescript
await email.send({
  to: adminEmails,          // string | string[]
  template: "quota-warning",
  data: {
    orgName: string,        // Organization name
    metric: string,         // Metric ID, e.g. "api_calls", "storage_gb"
    used: number,           // Current usage value
    limit: number,          // Plan limit value
    percentage: number,     // Usage percentage (0–100)
    upgradeUrl: string,     // URL to the billing/upgrade page
  },
});
```

---

### `quota-exceeded`

Sent when metered usage exceeds 100% of the plan limit.

**File:** `packages/email/src/templates/quota-exceeded.tsx`

```typescript
await email.send({
  to: adminEmails,          // string | string[]
  template: "quota-exceeded",
  data: {
    orgName: string,
    metric: string,
    used: number,
    limit: number,
    upgradeUrl: string,
  },
});
```

---

### `team-invite`

Sent when a user is invited to join an organization.

**File:** `packages/email/src/templates/team-invite.tsx`

```typescript
await email.send({
  to: invitee.email,
  template: "team-invite",
  data: {
    inviteeName: string,    // Invitee's name or email if name unknown
    inviterName: string,    // Name of the person who sent the invite
    orgName: string,        // Organization the invitee is joining
    inviteUrl: string,      // One-time invite acceptance URL
    expiresAt: string,      // ISO 8601 expiry timestamp
  },
});
```

---

### `password-reset`

Sent when a user requests a password reset.

**File:** `packages/email/src/templates/password-reset.tsx`

```typescript
await email.send({
  to: user.email,
  template: "password-reset",
  data: {
    userName: string,       // User's display name
    resetUrl: string,       // Password reset URL with token
    expiresInMinutes: number, // Link validity, e.g. 60
    ipAddress: string,      // IP address of the request (security info)
  },
});
```

## Customizing a template

Templates are React Email components — edit them like any other React component.

<Steps>
  <Step title="Locate the template file">
    Templates are in `packages/email/src/templates/`. For example, to edit the welcome email:

    ```
    packages/email/src/templates/welcome.tsx
    ```
  </Step>

  <Step title="Edit the component">
    React Email provides layout primitives from `@react-email/components`:

    ```tsx
    import {
      Body,
      Button,
      Container,
      Head,
      Heading,
      Html,
      Preview,
      Section,
      Text,
    } from "@react-email/components";

    interface WelcomeEmailProps {
      userName: string;
      orgName: string;
      dashboardUrl: string;
    }

    export function WelcomeEmail({ userName, orgName, dashboardUrl }: WelcomeEmailProps) {
      return (
        <Html>
          <Head />
          <Preview>Welcome to Nebutra, {userName}!</Preview>
          <Body style={{ fontFamily: "sans-serif", backgroundColor: "#f8fafc" }}>
            <Container style={{ maxWidth: "600px", margin: "0 auto" }}>
              <Heading>Welcome to {orgName}</Heading>
              <Text>Hi {userName}, your account is ready.</Text>
              <Section>
                <Button href={dashboardUrl}>Open Dashboard</Button>
              </Section>
            </Container>
          </Body>
        </Html>
      );
    }
    ```
  </Step>

  <Step title="Preview your changes">
    Start the preview server to see changes live in a browser:

    ```bash
    pnpm --filter @nebutra/email dev
    # Opens at http://localhost:3100
    ```
  </Step>
</Steps>

## Adding a new template

<Steps>
  <Step title="Create the template component">
    Add a new file in `packages/email/src/templates/`:

    ```tsx
    // packages/email/src/templates/invoice-paid.tsx
    import { Body, Button, Container, Html, Text } from "@react-email/components";

    export interface InvoicePaidEmailProps {
      userName: string;
      orgName: string;
      invoiceId: string;
      amount: string;     // formatted, e.g. "$99.00"
      invoiceUrl: string;
    }

    export function InvoicePaidEmail(props: InvoicePaidEmailProps) {
      return (
        <Html>
          <Body>
            <Container>
              <Text>Hi {props.userName}, invoice {props.invoiceId} for {props.amount} has been paid.</Text>
              <Button href={props.invoiceUrl}>View Invoice</Button>
            </Container>
          </Body>
        </Html>
      );
    }
    ```
  </Step>

  <Step title="Register the template">
    Export the new template from the template registry:

    ```typescript
    // packages/email/src/templates/index.ts
    export { InvoicePaidEmail, type InvoicePaidEmailProps } from "./invoice-paid";
    ```

    Then register it in the template map:

    ```typescript
    // packages/email/src/provider.ts
    import { InvoicePaidEmail } from "./templates/invoice-paid";

    const templates = {
      // ... existing templates
      "invoice-paid": InvoicePaidEmail,
    } as const;
    ```
  </Step>

  <Step title="Add TypeScript types for the data payload">
    Add the new template's data type to the `EmailTemplateData` discriminated union so `email.send()` is fully type-safe.

    <Warning>
    TODO: Document the exact location of the `EmailTemplateData` union type once the `@nebutra/email` type system is finalized.
    </Warning>
  </Step>

  <Step title="Preview and test">
    ```bash
    pnpm --filter @nebutra/email dev
    ```

    Navigate to your new template in the preview sidebar and verify it renders correctly in both desktop and mobile viewports.
  </Step>
</Steps>

<Warning>
Test all templates before deploying to production. A broken template will cause `email.send()` to throw at runtime. See [Testing](/email/testing) for the recommended test approach.
</Warning>
