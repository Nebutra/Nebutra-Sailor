## 概述

Nebutra 是一个包含 7 个应用和 33 个 packages 的 **Turborepo monorepo**，共享统一的设计系统、类型安全的 API 契约和运行时令牌系统。每个组件均可独立部署和替换。

```
浏览器 / 移动客户端
        │
        ▼
┌─────────────────────────────┐
│       Vercel 边缘网络        │  (CDN、WAF、DDoS 防护)
└─────────────┬───────────────┘
              │
    ┌─────────┴─────────┐
    │                   │
    ▼                   ▼
┌────────────┐   ┌──────────────┐
│ landing-   │   │   web 应用   │  Next.js 16 (App Router)
│ page       │   │ app.nebutra  │  认证后的仪表板
└────────────┘   └──────┬───────┘
                        │ fetch / Server Actions
                        ▼
              ┌──────────────────┐
              │   API 网关        │  Hono + OpenAPI
              │ api.nebutra.com  │  认证中间件、RBAC、限流
              └────────┬─────────┘
                       │
          ┌────────────┼────────────┐
          │            │            │
          ▼            ▼            ▼
   ┌────────────┐ ┌─────────┐ ┌──────────┐
   │  Supabase  │ │  Redis  │ │  AI      │
   │ PostgreSQL │ │ (缓存)   │ │  服务代理 │
   │ + pgvector │ │         │ │          │
   └────────────┘ └─────────┘ └──────────┘
```

## 应用一览

| 应用 | URL | 框架 | 用途 |
|-----|-----|------|------|
| `landing-page` | `nebutra.com` | Next.js 16 | 公开营销网站、更新日志、路线图 |
| `web` | `app.nebutra.com` | Next.js 16 | 认证后的 SaaS 仪表板 |
| `api-gateway` | `api.nebutra.com` | Hono + Node | REST API、认证、RBAC、限流 |
| `studio` | `studio.nebutra.com` | Sanity v4 | 内容管理 |
| `storybook` | `ui.nebutra.com` | Storybook 8 | 组件库文档 |
| `design-docs` | 内部 | Fumadocs | 内部设计系统文档 |
| `docs` | `docs.nebutra.com` | Mintlify | 本文档站点 |

## 核心 Packages

| Package | 描述 |
|---------|------|
| `@nebutra/ui` | 组件库——Radix + Lobe UI + 布局原语 |
| `@nebutra/tokens` | 运行时 CSS 设计令牌——主题化的单一可信来源 |
| `@nebutra/permissions` | RBAC/ABAC 引擎——CASL（进程内）或 OpenFGA（Zanzibar） |
| `@nebutra/queue` | 消息队列——QStash（Serverless）或 BullMQ（Redis） |
| `@nebutra/tenant` | 多租户上下文——AsyncLocalStorage + RLS |
| `@nebutra/metering` | 使用量计量管道——ClickHouse 实时聚合 |

## 请求流程

每个 API 请求都经过以下链路：

```
请求
  │
  ├─ 1. Vercel WAF        (IP 白名单、限流规则)
  │
  ├─ 2. Hono 中间件
  │     ├─ CORS           (来源验证)
  │     ├─ 认证            (通过 Clerk / Better Auth 验证 JWT)
  │     ├─ 租户            (解析 orgId → 租户上下文)
  │     ├─ RBAC           (路由的权限范围检查)
  │     └─ 限流            (通过 Redis 实现每租户配额)
  │
  ├─ 3. 路由处理器         (业务逻辑)
  │
  └─ 4. 响应              (JSON 封装: { success, data, error })
```

## 提供商替换模式

Nebutra 中的每个基础设施依赖都可以通过环境变量替换：

```bash
AUTH_PROVIDER=better-auth   # 或 "clerk"
QUEUE_PROVIDER=bullmq       # 或 "qstash" | "memory"
SEARCH_PROVIDER=typesense   # 或 "meilisearch" | "algolia"
PERMISSIONS_PROVIDER=openfga # 或 "casl"
```

应用代码不变——只需修改环境变量。
