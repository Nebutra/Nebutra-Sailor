---
title: 数据库提供商
description: 将 Nebutra 连接到 Neon 或 Supabase — 每个提供商的环境变量、连接池和迁移设置。
---

Nebutra 开箱即用支持两个托管 PostgreSQL 提供商。两者都与 Prisma v7、pgvector 和 RLS 完全兼容。无论选择哪个提供商，应用程序代码完全相同 — 只有连接字符串不同。

<Note>
Neon 和 Supabase 都是 PostgreSQL。`pnpm db:migrate` 生成的迁移在任一提供商上均可不加修改地使用。
</Note>

<Warning>
**不支持**基于 MySQL 的提供商（PlanetScale、Railway MySQL）。Nebutra 依赖 pgvector 和原生 PostgreSQL RLS — 两者都需要 PostgreSQL。TODO：记录自托管 PostgreSQL 设置文档。
</Warning>

<Tabs>
  <Tab title="Neon（默认）">
    Neon 是默认提供商。它是一个无服务器 PostgreSQL 平台，具有分支、自动暂停和慷慨的免费套餐。内置 PgBouncer 连接池。

    ### 为什么选择 Neon

    - **分支** — 为每个功能分支或 PR 创建隔离的数据库分支，零数据复制成本
    - **无服务器** — 空闲时自动缩减到零；休眠数据库不收取计算费用
    - **自动暂停** — 免费套餐数据库在 5 分钟不活动后暂停，约 500 毫秒内恢复
    - **pgvector** — 在所有 Neon 数据库上默认启用

    ### 连接字符串格式

    Neon 为每个数据库提供两个 URL：用于运行时查询的连接池 URL（通过 PgBouncer），以及用于迁移的直接 URL。

    ```
    # 连接池 — 用于所有应用程序查询
    postgresql://USER:PASSWORD@ep-XXXXXX.us-east-2.aws.neon.tech/neondb?sslmode=require&pgbouncer=true

    # 直接连接 — 仅用于迁移
    postgresql://USER:PASSWORD@ep-XXXXXX.us-east-2.aws.neon.tech/neondb?sslmode=require
    ```

    ### 环境变量

    ```env .env
    # 运行时查询（通过 PgBouncer 连接池）
    DATABASE_URL="postgresql://USER:PASSWORD@ep-XXXXXX.us-east-2.aws.neon.tech/neondb?sslmode=require&pgbouncer=true"

    # 仅迁移（直接连接 — 绕过连接池）
    DIRECT_URL="postgresql://USER:PASSWORD@ep-XXXXXX.us-east-2.aws.neon.tech/neondb?sslmode=require"
    ```

    ### schema.prisma 数据源

    ```prisma packages/db/prisma/schema.prisma
    datasource db {
      provider  = "postgresql"
      url       = env("DATABASE_URL")
      directUrl = env("DIRECT_URL")
    }
    ```

    ### 通过 PgBouncer 的连接池

    Neon 的 PgBouncer 以**事务模式**运行 — 连接仅在单个事务期间保持，然后归还到连接池。这使得少量实际 PostgreSQL 连接可以支持数千个并发应用程序连接。

    <Warning>
    PgBouncer 事务模式不支持跨事务持久的 `SET` 语句（例如用于 RLS 的 `SET LOCAL`）。Nebutra 的 `withRls` 在事务内部设置租户变量，这与事务模式连接池兼容。
    </Warning>

    ### 开发用数据库分支

    从 Neon 控制台或 CLI 创建分支，为功能分支获取架构的隔离副本：

    ```bash
    # Neon CLI
    neon branches create --name feature/new-model --parent main
    ```

    每个分支都有自己的 `DATABASE_URL`。在本地 `.env` 或 Vercel 的每分支环境变量设置中设置它。
  </Tab>
  <Tab title="Supabase">
    Supabase 是一个 PostgreSQL 平台，提供托管控制台、内置认证、存储和实时订阅。连接池由 Supavisor 提供。

    ### 为什么选择 Supabase

    - **托管控制台** — 在 Supabase Studio UI 中浏览表、运行 SQL 和查看 RLS 策略
    - **Supavisor** — 支持 RLS 所需 `SET LOCAL` 语句的会话模式连接池
    - **pgvector** — 作为一流扩展提供，可从控制台启用
    - **存储** — 与数据库同置的 S3 兼容对象存储（由 `@nebutra/uploads` 使用）

    ### 启用 pgvector

    在运行迁移之前，从 Supabase 控制台启用 pgvector 扩展：

    **控制台 → 数据库 → 扩展 → 搜索 "vector" → 启用**

    或通过 Supabase SQL 编辑器：

    ```sql
    CREATE EXTENSION IF NOT EXISTS vector;
    ```

    ### 连接字符串格式

    Supabase 为每个项目提供连接池 URL（Supavisor）和直接 URL：

    ```
    # 通过 Supavisor 连接池（会话模式 — 支持 SET LOCAL）
    postgresql://postgres.PROJECTREF:PASSWORD@aws-0-us-east-1.pooler.supabase.com:5432/postgres

    # 直接连接（用于迁移）
    postgresql://postgres:PASSWORD@db.PROJECTREF.supabase.co:5432/postgres
    ```

    ### 环境变量

    ```env .env
    # 运行时查询（通过 Supavisor 连接池）
    DATABASE_URL="postgresql://postgres.PROJECTREF:PASSWORD@aws-0-us-east-1.pooler.supabase.com:5432/postgres"

    # 仅迁移（直接连接）
    DIRECT_URL="postgresql://postgres:PASSWORD@db.PROJECTREF.supabase.co:5432/postgres"
    ```

    ### schema.prisma 数据源

    ```prisma packages/db/prisma/schema.prisma
    datasource db {
      provider  = "postgresql"
      url       = env("DATABASE_URL")
      directUrl = env("DIRECT_URL")
    }
    ```

    ### 通过 Supavisor 的连接池

    Supabase 的 Supavisor 支持**事务模式**（端口 6543）和**会话模式**（端口 5432）。使用**会话模式**（上方连接池 URL 中的端口 5432）确保 RLS 的 `SET LOCAL` 语句正常工作。

    <Warning>
    如果在事务模式（端口 6543）下使用 Supavisor，`SET LOCAL` 用于 RLS 时将不会在同一逻辑请求的各语句之间持久。使用 Supabase 且依赖 `withRls` 时，始终使用会话模式（端口 5432）。
    </Warning>

    ### 使用 Supabase 运行迁移

    迁移与 Neon 完全相同：

    ```bash
    pnpm db:migrate
    ```

    Prisma 使用 `DIRECT_URL` 执行 DDL 语句，使用 `DATABASE_URL` 执行所有其他查询。
  </Tab>
</Tabs>

## 选择提供商

| 标准 | Neon | Supabase |
|------|------|----------|
| 免费套餐 | 慷慨（0.5 GB 存储，1 计算单元） | 慷慨（500 MB 数据库，2 GB 带宽） |
| 分支 | 是 — 每个分支独立数据库 | 否 |
| 托管控制台 | 基础版 | 功能完整的 Studio UI |
| 连接池 | PgBouncer（事务模式） | Supavisor（会话 + 事务模式） |
| 内置认证 | 否（使用 Clerk / Better Auth） | 是（如需要） |
| 内置存储 | 否（使用 `@nebutra/uploads`） | 是（S3 兼容） |
| pgvector | 默认启用 | 作为扩展提供 |
| 自动暂停 | 是（免费套餐） | 是（暂停的项目） |

<Tip>
如果团队严重依赖每个 PR 的数据库环境，选择 Neon 的分支功能。如果希望有一个单一的可视化控制台来检查表和运行 SQL，Supabase Studio 非常出色。
</Tip>

## 常见问题

<AccordionGroup>
  <Accordion title="上线后可以切换提供商吗？">
    可以。由于两个提供商都是标准 PostgreSQL，切换只需对数据进行 `pg_dump` / `pg_restore` 并更新 `DATABASE_URL` 和 `DIRECT_URL` 环境变量。不需要任何应用程序代码更改。
  </Accordion>
  <Accordion title="为什么需要两个连接字符串？">
    连接池（PgBouncer、Supavisor）将许多应用程序连接多路复用到少量真实的 PostgreSQL 连接上。它们不支持迁移期间使用的 DDL 语句（如 `CREATE TABLE` 或 `ALTER TABLE`）。`DIRECT_URL` 绕过连接池，使 Prisma 能够安全地运行迁移。
  </Accordion>
  <Accordion title="支持自托管 PostgreSQL 吗？">
    支持，但需要额外设置。您需要确保安装了 pgvector，配置连接池（推荐 PgBouncer），并为迁移提供直接 URL。目前没有针对自托管 PostgreSQL 的自动化设置脚本。

    <Warning>TODO：记录包含 pgvector 安装和 PgBouncer 配置的自托管 PostgreSQL 设置指南。</Warning>
  </Accordion>
  <Accordion title="免费套餐的连接数限制如何？">
    Neon 和 Supabase 的免费套餐都有连接数限制（通常为 100-200 个总连接）。在免费套餐上连接池是必不可少的 — 在无服务器部署中永远不要将 `DATABASE_URL` 设置为直接连接字符串，因为每次函数调用都会消耗一个连接。
  </Accordion>
</AccordionGroup>
