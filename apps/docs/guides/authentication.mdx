## Auth providers

Nebutra supports two auth providers, switchable via a single environment variable:

| Provider | Best for | Notes |
|----------|----------|-------|
| **Clerk** | Production — hosted auth with UI components | Default. Managed dashboard, MFA, social login |
| **Better Auth** | Self-hosted or compliance-sensitive deployments | Open source, runs in your infrastructure |

```bash
# .env
AUTH_PROVIDER=clerk       # or "better-auth"
```

## Clerk setup

### 1. Install Clerk

```bash
pnpm add @clerk/nextjs
```

### 2. Add environment variables

```bash .env
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_live_xxxxxxxxxxxx
CLERK_SECRET_KEY=sk_live_xxxxxxxxxxxx
CLERK_WEBHOOK_SECRET=whsec_xxxxxxxxxxxx
```

### 3. Wrap your app

```tsx app/layout.tsx
import { ClerkProvider } from "@clerk/nextjs";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <ClerkProvider>
      <html lang="en">
        <body>{children}</body>
      </html>
    </ClerkProvider>
  );
}
```

### 4. Add the auth proxy

```typescript proxy.ts
import { clerkMiddleware, createRouteMatcher } from "@clerk/nextjs/server";

const isPublicRoute = createRouteMatcher(["/", "/sign-in(.*)", "/sign-up(.*)"]);

export default clerkMiddleware(async (auth, req) => {
  if (!isPublicRoute(req)) {
    await auth.protect();
  }
});

export const config = {
  matcher: ["/((?!_next|favicon.ico).*)"],
};
```

### 5. Read auth in Server Components

```typescript app/dashboard/page.tsx
import { auth, currentUser } from "@clerk/nextjs/server";

export default async function DashboardPage() {
  const { orgId } = await auth();
  const user = await currentUser();

  if (!orgId) redirect("/create-org");

  return <Dashboard userId={user?.id} orgId={orgId} />;
}
```

## Token verification (API Gateway)

The Hono API gateway verifies tokens on every protected request:

```typescript
// Handled automatically by Nebutra's auth middleware
app.use("/api/*", clerkMiddleware());

app.get("/api/projects", async (c) => {
  const { userId, orgId } = c.get("auth");
  // userId and orgId are verified and safe to use
});
```

## JWT claims

Every verified token includes:

```json
{
  "sub": "user_2a8bXXXXXXXXX",
  "org_id": "org_2a8bXXXXXXXXX",
  "org_role": "org:admin",
  "org_slug": "acme",
  "scopes": ["project:read", "project:create", "project:update"],
  "plan": "pro",
  "iat": 1743427200,
  "exp": 1743430800
}
```

The `scopes` claim is set by Nebutra's RBAC layer at token issuance time.

## Session management

- **Session duration**: 7 days by default (configurable in Clerk Dashboard)
- **Token refresh**: Automatic client-side refresh via Clerk's SDK
- **Revocation**: Revoking a session invalidates all active tokens for that session immediately

## Multi-factor authentication

MFA is enforced at the org level. Admins can require MFA for all members via **Settings → Security → Require MFA**.

Supported factors:
- TOTP (Authenticator apps: Authy, 1Password, Google Authenticator)
- SMS OTP
- Passkeys (WebAuthn)

## Sign-in / Sign-up UI

Nebutra ships pre-built sign-in and sign-up pages:

```typescript app/sign-in/[[...sign-in]]/page.tsx
import { SignIn } from "@clerk/nextjs";

export default function SignInPage() {
  return (
    <div className="flex min-h-screen items-center justify-center">
      <SignIn />
    </div>
  );
}
```

## Organization creation flow

After sign-up, users without an organization are redirected to the org creation flow:

```typescript app/create-org/page.tsx
import { CreateOrganization } from "@clerk/nextjs";

export default function CreateOrgPage() {
  return <CreateOrganization afterCreateOrganizationUrl="/dashboard" />;
}
```

<Warning>
  Without this page, users who sign up will have `orgId: null` in their auth token and will be redirected back to the landing page in an infinite loop. Always implement the org creation flow.
</Warning>
