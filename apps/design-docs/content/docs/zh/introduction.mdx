## 这个系统是什么

Nebutra Design System 是面向 AI-native SaaS 产品的受治理 UI 平台。它沉淀应该在 Nebutra 应用之间共享的决策：token 语义、primitive API、组合规则、可访问性契约和对外 registry 分发。

它不是设计灵感库。只有当一个界面能减少产品差异、给下游开发者更好的 API，或把重复生产模式沉淀成可复用契约时，它才属于这里。

## 设计原则

| 原则 | 落地含义 |
| --- | --- |
| Token 真相高于视觉记忆 | 运行时 UI 消费 `@nebutra/tokens/styles.css`；组件示例不能硬编码漂移色。 |
| 公开 API 高于 DOM 穿透 | 消费者通过 variants、props 和文档化 slots 扩展；不针对内部子节点选择器写样式。 |
| 原生语义优先 | 优先使用原生元素和成熟 primitive。行为由 Base UI、自研逻辑或其他底层负责时，文档必须明确写出。 |
| 产品密度高于装饰堆叠 | SaaS 表面应该克制、可扫描、精密。动效和视觉效果只有在澄清状态或层级时才成立。 |
| Storybook 与 docs 收敛 | Stories 证明状态，docs 解释契约。两者不一致时，必有一方过期。 |

## Package Map

| Package | 角色 |
| --- | --- |
| `@nebutra/tokens` | 运行时 CSS 变量、theme provider、light/dark token 语义。 |
| `@nebutra/ui` | 公共 UI package，包含 primitives、components、layout、patterns、hooks 和 utils。 |
| `@nebutra/icons` | Nebutra 图标门面，产品 UI 优先使用 Geist icons。 |
| `@nebutra/brand` | VI 和品牌识别的源数据，不直接参与应用运行时样式。 |

## 分发路径

Nebutra 应用内部使用 package import：

```tsx
import { Button, Input } from "@nebutra/ui/primitives";
```

只有给外部项目安装 standalone copy 时才使用 registry：

```bash
npx shadcn@latest add https://ui.nebutra.com/r/button.json
```

两种路径下，package source 和 MDX docs 仍然是设计权威。
