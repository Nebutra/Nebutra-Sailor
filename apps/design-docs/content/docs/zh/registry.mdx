# Registry

Registry 是公开 `@nebutra/ui` 原语和 docs preview 的分发层。它从 `/registry.json` 和 `/r/:name.json` 暴露可安装 manifest，但契约来源仍然是 package source、tokens、MDX docs 和 Storybook stories。

## 这个页面负责什么

- 把 docs 信息架构连接到公开 registry 分发面。
- 明确产品文档和可安装 registry manifest 的边界。
- 防止 registry JSON 反过来成为设计权威。

## 用法

当你需要 registry-visible component 的安装命令或原始 manifest 时，进入 registry 页面。

[打开 Registry](https://ui.nebutra.com/registry)

## 治理规则

- `packages/design/ui/scripts/build-registry.ts` 负责公开组件 manifest。
- `apps/design-docs/scripts/build-registry.mjs` 负责 preview-demo manifest。
- Registry docs 必须有匹配 MDX 页面；视觉组件必须有真实 preview；并且必须有同名 Storybook 覆盖或显式 Storybook metadata。
- 例外不是通用 allowlist 流程；如果未来重新引入覆盖债务，必须带 owner、reason、expiry。
- 发布 registry 变更前运行 `pnpm --filter @nebutra/design-docs prebuild`。
