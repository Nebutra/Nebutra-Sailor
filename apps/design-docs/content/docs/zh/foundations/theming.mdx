## 概览

> 本页此前记录的是归属于 `apps/docs-hub` 的 `createTheme()` / `DesignSystemProvider` /
> `generateMarketingCSSVars()` API。这些在仓库中并不存在——`apps/docs-hub` 从未是一个真实的
> app，`@nebutra/ui` 中也没有任何这些导出。本页现在记录的是真实上线的主题机制。

主题被拆分到三个包中，各自职责清晰：

| 层级 | 包 | 职责 |
|---|---|---|
| 运行时 token（SSOT） | `@nebutra/tokens` | `styles.css`（CSS 变量）+ `ThemeProvider`/`useTheme`（浅色/深色模式） |
| 语言切换 | `@nebutra/theme` | Brand Package + `applyLanguage()` + `skins.css`，作用域为 `html[data-brand]` |
| 组件桥接 | `@nebutra/ui` | `NebutraThemeProvider` —— 用同一套 token 包裹 Lobe UI |

## 运行时 token —— `@nebutra/tokens`

`@nebutra/tokens` 是运行时设计 token 的唯一真源。在应用根部导入一次生成后的样式表：

```css
@import "@nebutra/tokens/styles.css";
@import "@nebutra/tokens/recipe.css";
```

`styles.css` 声明了：

- 品牌色阶（`--nebutra-blue-*`、`--nebutra-cyan-*`）
- 12 档功能色阶（`--neutral-1..12`、`--blue-1..12`、`--cyan-1..12`）
- 语义变量（`--primary`、`--background`、`--border` 等），以**裸 HSL 三元组**的形式声明——落在颜色位置时需要包裹（`hsl(var(--border))`），或改用语义化 Tailwind 工具类。原因见 [Nebutra Tokens](/zh/docs/foundations/nebutra-tokens)。
- 通过 `:root` / `.dark` 实现浅色/深色模式
- Display-P3 广色域，带 sRGB 回退
- Tailwind v4 `@theme` 集成

`styles.css` 本身是**生成产物**——可编辑的源文件见 [Nebutra Tokens](/zh/docs/foundations/nebutra-tokens)。

### `ThemeProvider` / `useTheme` —— 浅色/深色模式

```tsx
import { ThemeProvider, useTheme } from "@nebutra/tokens";

// 应用根部
<ThemeProvider attribute="class" defaultTheme="system" enableSystem>
  <App />
</ThemeProvider>;

// 树内任意组件
function ThemeToggle() {
  const { resolvedTheme, setTheme } = useTheme();
  return (
    <button type="button" onClick={() => setTheme(resolvedTheme === "light" ? "dark" : "light")}>
      Current: {resolvedTheme}
    </button>
  );
}
```

这是 `next-themes` 的手写替代实现（prop 和 hook 命名保持一致，可直接迁移），而非对其的重新导出——
`next-themes@0.4.x` 会在 Client Component 内渲染一个内联 `<script>`，React 19 + Next.js 16（Turbopack）
现在会对此报警。该 provider 拆分为客户端 `ThemeProvider`（运行时状态、跟随系统）并写入 cookie，使
Server Component 能通过 `next/headers` 的 `cookies()` 读取已解析的主题，并直接把 class 注入
`<html>`——没有内联脚本，没有 FOUC。

**`ThemeProviderProps`：**

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `attribute` | `"class" \| "data-theme"` | `"class"` | 设置在 `<html>` 上的 DOM 属性 |
| `defaultTheme` | `"light" \| "dark" \| "system"` | `"system"` | 初始偏好 |
| `enableSystem` | `boolean` | `true` | `theme === "system"` 时跟随操作系统偏好 |
| `storageKey` | `string` | `"theme"` | localStorage / cookie 键名 |
| `children` | `ReactNode` | — | 应用子树 |

**`useTheme()` 返回值：**

| 属性 | 类型 | 说明 |
|---|---|---|
| `theme` | `"light" \| "dark" \| "system"` | 原始用户偏好 |
| `resolvedTheme` | `"light" \| "dark"` | 实际应用的主题 |
| `systemTheme` | `"light" \| "dark"` | 操作系统层面的偏好 |
| `setTheme` | `(theme) => void` | 命令式切换偏好 |

应用根部只包裹一次 `ThemeProvider`。通过 `useTheme()` 读取和切换模式——不要独立管理主题状态。

## 语言切换 —— `@nebutra/theme`

`@nebutra/theme` 是独立的可选层：全局产品外观切换（例如 Create Center / 多租户 SaaS 中让租户选择
整套设计语言）。它**不是**浅色/深色模式——那是上面的 `@nebutra/tokens`。

> **已移除（2026-07）：** `[data-theme]` 下的 78 种 oklch “mood” 预设（`neon`、`gradient`、
> `dark-dense`、`minimal`、`vibrant`、`ocean`）。它们会双写产品外观、观感通用，且与 carrier 模型冲突。
> 不要重新引入。

```css
@import "@nebutra/theme/skins.css"; /* 多语言，作用域为 html[data-brand] */
```

```ts
import { applyLanguage, clearLanguage, LANGUAGE_REGISTRY } from "@nebutra/theme";

applyLanguage("vanta", { persist: true }); // 内置 Brand Package
clearLanguage(); // 回到 factory token
```

内置目录（`id` → 证明的方向）：`factory`（默认 SSOT）、`linear`、`gsap`、`raycast`、`vercel`、
`vanta`、`stripe`、`notion`。用 CLI 查看：

```bash
nebutra theme list
nebutra theme inspect vanta
```

## 组件桥接 —— `@nebutra/ui`

`@nebutra/ui` 中的部分组件（源自 Lobe UI / Ant Design）需要自己的主题 context。
`NebutraThemeProvider` 用同一套品牌 token 包裹该 context——它不替代 `@nebutra/tokens` 的
`ThemeProvider`。

```tsx
import { NebutraThemeProvider } from "@nebutra/ui";

<NebutraThemeProvider appearance="auto" defaultAppearance="light">
  <App />
</NebutraThemeProvider>;
```

**`NebutraThemeProviderProps`：**

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `appearance` | `"dark" \| "light" \| "auto"` | `"auto"` | 强制某一模式，或跟随 `defaultAppearance` |
| `defaultAppearance` | `"dark" \| "light"` | `"light"` | `appearance === "auto"` 时的回退值 |
| `children` | `ReactNode` | — | 子树 |

## 应做 / 禁止

**应做**：在应用根部只导入一次 `@nebutra/tokens/styles.css`，且要在任何组件样式之前。

**应做**：使用 `@nebutra/tokens` 的 `useTheme()` 读取和切换浅色/深色模式。

**应做**：裸 HSL 三元组的语义 token（`--background`、`--border` 等）在落入颜色位置时始终用
`hsl(...)` 包裹——未包裹的 `var(--border)` 会使整条声明失效，浏览器会静默丢弃它。

**禁止**：不要手动编辑 `packages/design/tokens/styles.css`——它是 generated（生成）产物，构建会覆盖任何手改。
改动请编辑 `packages/design/design-tokens/tokens/` 下的 DTCG 源文件。

**禁止**：把 `@nebutra/theme` 的 `applyLanguage()` 当作普通的浅色/深色模式切换来用——那是整套产品
外观的切换，不是模式开关。

**禁止**：嵌套多个 `ThemeProvider` 实例。根部单一 provider 应治理整棵树。
