## 概览
主题层负责控制设计 token 在运行时如何传递给组件。它分成两个清晰职责：

1. **应用主题**：通过 `createTheme()` + `DesignSystemProvider` 驱动产品 UI 的浅色/深色模式。
2. **营销 token 注入**：通过 `generateMarketingCSSVars()` 为落地页 surface 注入变量。

Token 源自 `default.ts`（Primer baseline），可在 `brand.ts` 中通过 `BrandOverrides` 覆盖；营销扩展位于 `marketing.ts`。

## 应用主题

### `createTheme(mode, overrides?)`

位于 `apps/docs-hub/design-system/src/theme/brand.ts`。

```ts
import { createTheme } from "@nebutra/ui/theme/brand";

// 无覆盖的浅色主题（Primer 默认值）
const theme = createTheme("light");

// 深色主题
const darkTheme = createTheme("dark");

// 带品牌覆盖的浅色主题
const brandTheme = createTheme("light", {
  colors: {
    accent: {
      fg: "#0033FE",
      emphasis: "#002ad4",
      muted: "rgb(0 51 254 / 0.4)",
      subtle: "rgb(0 51 254 / 0.1)",
    },
  },
  typography: {
    fontFamily: {
      normal: '"BrandFont", var(--font-geist-sans), "Geist", sans-serif',
      mono: '"BrandMono", var(--font-geist-mono), "Geist Mono", ui-monospace, monospace',
      display: '"BrandDisplay", var(--font-geist-sans), "Geist", sans-serif',
    },
  },
  radii: {
    lg: "16px",
    xl: "24px",
  },
  shadows: {
    brand: "0 0 40px rgb(0 51 254 / 0.25)",
  },
});
```

**签名：**
```ts
function createTheme(
  mode: "light" | "dark",
  overrides?: BrandOverrides
): DefaultTheme
```

**`BrandOverrides` 接口：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `colors` | `Partial<semanticColorsLight>` | 覆盖语义颜色 token |
| `typography.fontFamily.normal` | `string` | 正文 / UI 字体栈 |
| `typography.fontFamily.mono` | `string` | 代码 / 等宽字体栈 |
| `typography.fontFamily.display` | `string` | Display / hero 字体栈 |
| `radii` | `Partial<typeof defaultTheme.radii>` | 圆角覆盖 |
| `shadows` | `Record<string, string>` | 命名阴影扩展 |

### 预置主题

直接导出两个预置主题：

```ts
import { lightTheme, darkTheme } from "@nebutra/ui/theme/brand";
```

两者都是 `DefaultTheme` 对象，即未应用品牌覆盖的 Primer 语义 token。

### `DesignSystemProvider`

<Info>
`DesignSystemProvider` 是设计系统和 React 应用的集成点，通过 context 下发当前主题。
</Info>

```tsx
import { DesignSystemProvider } from "@nebutra/ui";

// 默认模式：跟随系统偏好
<DesignSystemProvider>
  <App />
</DesignSystemProvider>

// 强制浅色模式
<DesignSystemProvider defaultMode="light">
  <App />
</DesignSystemProvider>

// 强制深色模式
<DesignSystemProvider defaultMode="dark">
  <App />
</DesignSystemProvider>
```

**Props:**

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `defaultMode` | `"light" \| "dark" \| "system"` | `"system"` | 初始颜色模式 |
| `theme` | `DefaultTheme` | `lightTheme` | 来自 `createTheme()` 的自定义主题对象 |
| `children` | `ReactNode` | — | 应用子树 |

### `useDesignSystem` Hook

在 `DesignSystemProvider` 内的任意组件中读取当前主题和模式切换方法。

```tsx
import { useDesignSystem } from "@nebutra/ui";

function ThemeToggle() {
  const { mode, setMode, theme } = useDesignSystem();

  return (
    <button onClick={() => setMode(mode === "light" ? "dark" : "light")}>
      Current: {mode}
    </button>
  );
}
```

**返回值：**

| 属性 | 类型 | 说明 |
|---|---|---|
| `mode` | `"light" \| "dark"` | 当前颜色模式 |
| `setMode` | `(mode: "light" \| "dark") => void` | 命令式切换模式 |
| `theme` | `DefaultTheme` | 完整解析后的主题对象 |

## 营销 Token 注入

营销 token 不属于主题 context。它们是注入到页面级别的 CSS 自定义属性。

### `generateMarketingCSSVars()`

位于 `apps/docs-hub/design-system/src/theme/marketing.ts`。

```ts
import { generateMarketingCSSVars } from "@nebutra/ui/theme/marketing";

// 返回 CSS 自定义属性声明字符串
const cssVars = generateMarketingCSSVars();
```

生成的属性：

```css
/* Marketing Spacing */
--marketing-section-sm: 64px;
--marketing-section-md: 96px;
--marketing-section-lg: 128px;
--marketing-section-xl: 160px;
--marketing-hero-min-height: 100vh;
--marketing-content-max-width: 1200px;

/* Marketing Radii */
--marketing-radius-sm: 8px;
--marketing-radius-card: 16px;
--marketing-radius-card-lg: 24px;
--marketing-radius-xl: 32px;
--marketing-radius-button: 9999px;

/* Marketing Transitions */
--marketing-transition-fast: 150ms ease;
--marketing-transition-default: 200ms ease;
--marketing-transition-smooth: 300ms cubic-bezier(0.4, 0, 0.2, 1);
--marketing-transition-emphasized: 400ms cubic-bezier(0.4, 0, 0.2, 1);
--marketing-transition-slow: 500ms cubic-bezier(0.4, 0, 0.2, 1);
```

在任意营销 surface 的页面布局中注入它：

```tsx
// apps/landing-page/src/app/layout.tsx
import { generateMarketingCSSVars } from "@nebutra/ui/theme/marketing";

export default function Layout({ children }) {
  return (
    <html>
      <head>
        <style>{`:root { ${generateMarketingCSSVars()} }`}</style>
      </head>
      <body>{children}</body>
    </html>
  );
}
```

### 完整营销 Token 映射

```ts
import { marketingTokens } from "@nebutra/ui/theme/marketing";
// marketingTokens.spacing
// marketingTokens.typography
// marketingTokens.gradients
// marketingTokens.effects
// marketingTokens.radii
// marketingTokens.transitions
// marketingTokens.zIndex
```

渐变和效果 token 值见 [Color foundation](/zh/docs/foundations/brand-colors)。营销排版预设（`display`、`headline`、`subheadline`、`featureTitle`、`cardText`、`label`）见 [Typography](/zh/docs/foundations/typography)。

## Z-Index 尺度（营销）

| Token | 值 | 层级 |
|---|---|---|
| `marketingZIndex.background` | −1 | 装饰背景 |
| `marketingZIndex.base` | 0 | 默认内容 |
| `marketingZIndex.elevated` | 10 | Hover 状态卡片 |
| `marketingZIndex.sticky` | 100 | 粘性页头 |
| `marketingZIndex.nav` | 1000 | 导航栏 |
| `marketingZIndex.dropdown` | 1100 | Dropdown / Popover |
| `marketingZIndex.modal` | 1200 | Modal / Dialog |
| `marketingZIndex.toast` | 1300 | Toast / Notification |
| `marketingZIndex.tooltip` | 1400 | Tooltip |

## 应做 / 禁止

**应做**：在应用顶层只包裹一次 `DesignSystemProvider`。

**应做**：使用 `useDesignSystem()` 读取和切换当前模式，不要独立管理主题状态。

**应做**：只在营销页面布局中调用 `generateMarketingCSSVars()`，不要放进应用 shell。

**禁止**：在共享 UI 组件中导入 `marketingTokens`，它只属于营销 surface 代码。

**禁止**：用硬编码 HEX 覆盖语义 token。应使用带 `BrandOverrides` 的 `createTheme()`。

**禁止**：嵌套多个 `DesignSystemProvider`。根部单一 provider 应治理整棵树。
