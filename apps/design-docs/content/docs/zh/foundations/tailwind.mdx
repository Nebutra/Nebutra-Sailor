## 概览
`@nebutra/ui` 提供 Tailwind preset，把设计 token 暴露为 Tailwind utility classes。preset 中的颜色、间距、圆角、阴影、字体与动画值都来自和 React 组件一致的 token 来源，保证两套系统同步。

Source: `packages/design/ui/src/tailwind.preset.ts`

```ts
import nebutraPreset from "@nebutra/ui/tailwind.preset";
```

preset 导出以下对象：

| 导出 | 类型 | 说明 |
|---|---|---|
| `nebutraColors` | Object | primary、secondary、neutral 与语义颜色 |
| `nebutraSpacing` | Object | 命名间距尺度（xs → 3xl） |
| `nebutraBorderRadius` | Object | 圆角尺度（none → full） |
| `nebutraShadows` | Object | 层级阴影（sm → xl） |
| `nebutraTypography` | Object | 字体族与字号尺度 |
| `nebutraAnimations` | Object | 命名 CSS 动画简写 |
| `nebutraPreset` | Object | 完整组合 preset（默认导出） |

## 设计依据

Tailwind CSS 4 支持 CSS-native 配置。与其在每个 app 维护独立 `tailwind.config.ts`，Nebutra 通过 preset 集中管理所有 token 决策。应用接入 preset 后即可使用全部 token，无需重复声明。

preset 与设计系统 token（`default.ts`、`brand.ts`）保持近距离维护，但不是直接 re-export。它采用更符合 Tailwind 的结构，为 class 生成优化，而不是为主题上下文优化。

<Info>
Tailwind CSS 4 中通过 CSS `@source` 直接导入样式，不再强依赖 JS 配置文件。见下方安装章节。
</Info>

## 使用准则
### Tailwind CSS 4（CSS 优先）

```css
/* app/globals.css */
@import "tailwindcss";
@import "@nebutra/tokens/styles.css";
@source "../../../packages/design/ui/src";
```

### Tailwind CSS 3（配置式）

```ts
// tailwind.config.ts
import { nebutraPreset } from "@nebutra/ui/tailwind.preset";
import type { Config } from "tailwindcss";

export default {
  presets: [nebutraPreset],
  content: ["./src/**/*.{ts,tsx}"],
} satisfies Config;
```

### 程序化访问

当你需要在 TypeScript 中读取 token 值，而不是使用 Tailwind class 时：

```ts
import { nebutraColors, nebutraSpacing } from "@nebutra/ui/tailwind.preset";

const brandBlue = nebutraColors.primary[500]; // "#0033FE"
const sectionPadding = nebutraSpacing["2xl"];  // "3rem"
```

## 应做 / 禁止

**应做**使用 preset，而不是在每个 app 的 Tailwind config 中重新定义设计 token。

**应做**在 utility classes 中引用语义颜色 token（`primary`、`secondary`、`success`、`error`），而不是基于 raw hex 的临时色阶名。

**禁止**在单个 app 的 Tailwind config 中添加一次性颜色值。需要新增时，把它提升到 preset 的 `nebutraColors` 并补充文档。

**禁止**对同一属性混用 Tailwind utility class 和 inline `style={{ color: "#..." }}`。这会制造 specificity 冲突，并削弱 token 系统。

**禁止**在生产应用运行时代码中导入 `nebutraPreset`。它是构建期配置产物，不是运行时依赖。
