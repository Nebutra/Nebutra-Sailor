## 属性

### PopoverContent

| 属性 | 类型 | 默认值 | 描述 |
| --- | --- | --- | --- |
| `side` | `"top" \| "right" \| "bottom" \| "left"` | `"bottom"` | 首选出现方向。 |
| `align` | `"start" \| "center" \| "end"` | `"center"` | 相对 trigger 的对齐方式。 |
| `sideOffset` | `number` | `8` | 与 trigger 的距离。 |
| `alignOffset` | `number` | `0` | 对齐方向偏移。 |
| `showArrow` | `boolean` | `false` | 渲染 token 化箭头。 |
| `className` | `string` | — | 追加到 popup 的类名。 |

## 可访问性

- 基于 Base UI Popover 构建 —— `PopoverContent` 具有 `role="dialog"` 属性。
- 触发器具有 `aria-expanded` 和 `aria-haspopup="dialog"` 属性。
- 打开时焦点移入弹出框；关闭时焦点返回触发器。
- 按下 `Escape` 键关闭弹出框。
- 默认情况下，点击弹出框外部会将其关闭。

## 设计契约

- Popover 用于锚定在可见 trigger 上的非阻塞上下文详情或短控件。
- 内容保持紧凑；如果需要带主次按钮的 footer，考虑 Dialog 或 Sheet。
- 箭头应少用。只有 trigger 与浮层关系不够明确时才显示。

## 真实产品示例

- 价格行旁边的 plan details。
- 表格工具栏里的 quick filter 说明。
- 不打断当前流程的 entity metadata panel。

## 反模式

- 不要用 Popover 做全局命令搜索或导航菜单。
- 不要把必填表单校验隐藏在 Popover 内。
- 当任务必须阻塞页面并等待用户响应时，不要使用 Popover。
