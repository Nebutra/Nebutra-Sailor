## 使用方法 (Usage)

```tsx
import { ThemeProvider } from "@nebutra/tokens";
import { ThemeSwitcher } from "@nebutra/ui/primitives";

export function AppProviders({ children }: { children: React.ReactNode }) {
  return (
    <ThemeProvider attribute="class" defaultTheme="system">
      {children}
    </ThemeProvider>
  );
}

<ThemeSwitcher />;
```

当界面只需要紧凑的浅色/深色二态图标按钮时，使用 `ThemeToggle`。

## 属性 (Props)

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `size` | `"small" \| "medium"` | `"medium"` | 密集 chrome 中使用 `small`；设置页中使用默认尺寸。 |
| `disabled` | `boolean` | `false` | 用于只读预览。Provider 设置 `forcedTheme` 时也会自动禁用。 |
| `name` | `string` | 自动生成 | 原生 radio group 名称。 |
| `value` | `"system" \| "light" \| "dark"` | provider theme | 兼容受控值，主要用于测试或迁移期。 |
| `defaultValue` | `"system" \| "light" \| "dark"` | `"system"` | 在没有 `ThemeProvider` 时的 fallback 值。 |
| `onChange` | `(theme: ThemeSwitcherValue) => void` | — | 兼容回调。Provider 仍然是状态真相源。 |
| `className` | `string` | — | fieldset 外层额外类名。 |

## 最佳实践 (Best Practices)

ThemeSwitcher 只用于标准 Light / System / Dark 控制。每个 app 放一次，通常在 footer、账户菜单或设置页，不要每个页面重复放。

在 footer、dropdown 等密集 chrome 中传 `size="small"`；设置页使用默认尺寸，让标签有足够呼吸空间。

ThemeSwitcher 读写 `@nebutra/tokens` 的 `ThemeProvider`。该 Provider API 与 `next-themes` 接近，但避开了 React 19 inline script 警告。产品代码不要再把主题状态镜像到本地 React state。

当 Provider 设置 `forcedTheme` 时，控件会自动禁用。手动设置 `disabled` 只用于展示只读预览。

不要用 Switch 或三个图标按钮重造主题选择器。ThemeSwitcher 已处理图标、原生 radio 语义、焦点环和 System 检测。

组件会从主题 key 组合可见标签：`system`、`light`、`dark`。不要逐实例覆写标签，避免翻译和语义漂移。

## 可访问性 (Accessibility)

ThemeSwitcher 渲染原生 `fieldset` 与 radio group。可见 legend 是 “Select a display theme:”，每个选项的可访问名称稳定匹配主题 key。

键盘行为遵循原生 radio：Tab 进入控件，方向键在选项间移动，Space 激活当前选项。

forced 或 disabled 状态下会保留当前选中项，但禁用 radio 输入。
