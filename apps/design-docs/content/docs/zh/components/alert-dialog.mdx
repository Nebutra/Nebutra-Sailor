## 属性

### AlertDialog (根组件)

| 属性 | 类型 | 默认值 | 描述 |
| -------------- | ------------------------- | ------- | -------------------------------- |
| `open` | `boolean` | — | 受控的打开状态 |
| `defaultOpen` | `boolean` | `false` | 非受控的默认打开状态 |
| `onOpenChange` | `(open: boolean) => void` | — | 打开状态改变时的回调函数 |

### AlertDialogContent

| 属性 | 类型 | 默认值 | 描述 |
| ----------- | ----------- | ------- | ---------------------- |
| `className` | `string` | — | 额外的 CSS 类名 |
| `children` | `ReactNode` | — | 对话框内容 |

### AlertDialogAction

| 属性 | 类型 | 默认值 | 描述 |
| ----------- | ------------ | ------- | ------------------------------ |
| `className` | `string` | — | 额外的 CSS 类名 |
| `children` | `ReactNode` | — | 确认操作按钮标签 |
| `onClick` | `() => void` | — | 确认操作的处理函数 |

### AlertDialogCancel

| 属性 | 类型 | 默认值 | 描述 |
| ----------- | ----------- | ------- | ---------------------- |
| `className` | `string` | — | 额外的 CSS 类名 |
| `children` | `ReactNode` | — | 取消按钮标签 |

## 可访问性

- 基于 Base UI AlertDialog 构建 — 遵循 WAI-ARIA [警告和消息对话框模式 (Alert and Message Dialogs pattern)](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/)。
- 渲染时带有 `role="alertdialog"` 和 `aria-modal="true"`。
- 打开时焦点将被锁定在对话框内。
- 与 `Dialog` 不同，`AlertDialog` 在点击遮罩层 (overlay) 时不会关闭 — 它需要用户执行显式操作。

## 设计契约

- 只有下一步会造成数据丢失、安全影响或不可逆流程变化时，才使用 `AlertDialog`。
- `AlertDialogDescription` 必须先说明具体后果，不能只靠按钮文案表达风险。
- 取消动作保持可见，并在阅读顺序中位于确认动作之前，让键盘用户先获得退出路径。

## 真实产品示例

- 吊销 API key 前，确认活跃集成即将失去访问权限。
- 从组织移除成员，同时保留所有权和审计历史。
- 取消生产部署前，在说明中点明排队任务和待发送 webhook。

## 反模式

- 不要把 `AlertDialog` 用于普通保存、关闭或跳转确认，这些应优先内联处理。
- 不要隐藏取消动作，也不要让破坏性动作成为第一个焦点目标。
- 不要只写“是否确认”这类模糊说明；必须点名受影响资源和后果。
