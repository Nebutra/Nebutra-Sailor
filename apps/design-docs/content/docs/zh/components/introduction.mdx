## 分类法

侧边栏按消费者意图组织：

- **核心表单与操作**：收集或提交用户意图的 controls。
- **导航与命令**：页面移动、命令执行和大型界面定位。
- **弹层与展开**：在当前页面上方或内部条件性出现的内容。
- **反馈与状态**：系统状态、校验、进度、加载和空状态。
- **数据展示**：结构化信息、元数据、文件、代码和 cards。
- **布局与排版**：塑造产品密度和阅读层级的 primitives。
- **AI 与 Agent 表面**：chat、tool calls、agent plans 和 generated output。
- **动效与文本效果**：用于澄清层级或状态的效果，而不是默认装饰。
- **视觉系统与背景**：与运营型 SaaS surface 隔离的高表现视觉。
- **营销与内容区块**：获客或 editorial sections，不是 dashboard primitives。
- **媒体与样机**：产品截图、地图、视频和设备框的表达性 surface。

## 组件成熟度

| 状态 | 含义 |
| --- | --- |
| `stable` | Public API 预期保持兼容。Docs、stories、tokens 和 a11y contract 已对齐。 |
| `beta` | API 可用但仍在收敛。Breaking changes 必须有迁移说明。 |
| `experimental` | 视觉/API 方向仍在测试。不要未经 review 扩散到关键产品流。 |
| `deprecated` | 新工作禁用。页面必须说明替代方案。 |

## 治理规则

1. 选择能承载行为的最窄 primitive。
2. 除非 pattern 页面明确允许，不要把装饰组件放进运营工作流。
3. 组件进入 registry 时，docs 必须说明 package import 和 standalone install 在不同消费场景下的权威关系。
4. `src/components/previews` 下的每个 preview 都必须接入所属 MDX 页面；不属于 docs 契约的示例直接删除。
