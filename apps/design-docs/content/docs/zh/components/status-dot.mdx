## 安装

```tsx
import { StatusDot } from "@nebutra/ui/primitives";
```

独立 registry 安装：

```bash
npx shadcn@latest add https://ui.nebutra.com/r/status-dot.json
```

## 用法

`StatusDot` 只用于部署生命周期状态。不要把它复用到任意工作流、队列或计费状态。

```tsx
<StatusDot state="BUILDING" titlePrefix="生产部署" label />
```

## 状态

| 状态 | 动效 |
| --- | --- |
| `QUEUED` | 脉冲 |
| `BUILDING` | 脉冲 |
| `READY` | 静态 |
| `ERROR` | 静态 |
| `CANCELED` | 静态 |
| `DELETED` | 静态 |

## 可访问性

- 默认 `aria-label` 由 `titlePrefix` 和状态文案组合。
- 当旁边已有可见文字命名状态时，传入 `decorative`。
- 颜色不是唯一信号；`label` 会渲染 sentence-cased 状态文本。

## 属性

| 属性 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `state` | `"QUEUED" \| "BUILDING" \| "READY" \| "ERROR" \| "CANCELED" \| "DELETED"` | required | 部署生命周期状态。 |
| `label` | `boolean` | `false` | 在点旁边渲染可见状态文字。 |
| `titlePrefix` | `string` | `"Deployment"` | 用于组合可访问标签的前缀。 |
| `decorative` | `boolean` | `false` | 当旁边文案已经命名状态时，把状态点从辅助技术中隐藏。 |
| `className` | `string` | - | 额外布局类名。 |

## 设计契约

- `StatusDot` 只用于部署生命周期。通用实体状态需要独立状态原语和独立枚举。
- 脉冲表示活动中，不表示严重程度。只有 `QUEUED` 与 `BUILDING` 动起来。
- 如果同一行已有状态文案，传 `decorative`；否则渲染 `label` 或保留默认可访问名称。

## 真实产品示例

- 部署表格为每次发布展示 `QUEUED`、`BUILDING`、`READY`、`ERROR`、`CANCELED` 或 `DELETED`。
- 环境页头把部署状态和 commit SHA、生产 URL 放在一起。
- 构建详情时间线中，用状态点标记当前部署生命周期步骤。

## 反模式

- 不要把 `StatusDot` 复用到任意队列、计费状态、用户在线状态或集成健康度。
- 不要为了吸引注意力给 error 或 ready 状态加脉冲。动效只表示部署仍在进行。
- 在高密度表格里，如果旁边没有状态文字，不要只渲染一个无标签圆点。
