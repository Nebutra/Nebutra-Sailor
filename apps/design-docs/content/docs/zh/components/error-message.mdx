## 使用方法 (Usage)

```tsx
import { Error } from "@nebutra/ui/primitives";
```

```tsx
<Error
  title="Couldn’t Load Deployments"
  action="Try Again"
  onAction={refetch}
  errorId="iad1::r7h2p-1712f9cda5d8"
>
  The deployments list failed to load. Try again or check the request details.
</Error>
```

## 设计原则 (Design Principles)

- 当页面、路由边界、区块、面板或 dashboard card 加载失败时使用 `Error`。
- 短暂操作失败用 toast；字段校验错误交给对应 input/field primitive。
- 标题必须命名失败资源，不要使用 `Something went wrong`。
- 先说明发生了什么，再说明下一步怎么做；不要写道歉式或玩笑式文案。
- 系统错误要带稳定标识：request ID、trace ID、deployment ID 或 run ID。
- 恢复动作必须具体：`Try Again`、`Reconnect GitHub`、`Update Payment Method`。

## 属性 (Props)

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `title` | `string` | — | 命名失败资源的标题 |
| `children` | `ReactNode` | — | 消息正文 |
| `label` | `string` | — | 标题上方的紧凑标签 |
| `showLabel` | `boolean` | `true` | 为 false 时隐藏标签 |
| `size` | `"small" \| "medium" \| "large"` | `"medium"` | 错误面板密度 |
| `error` | `ErrorObject` | — | 结构化错误数据 |
| `errorId` | `string` | — | 稳定诊断标识 |
| `errorIdLabel` | `string` | `"Request ID"` | 稳定标识前的标签 |
| `live` | `"polite" \| "assertive" \| "off"` | `"polite"` | 异步错误播报模式 |
| `action` | `string` | — | 恢复动作文案 |
| `link` | `string` | — | 恢复动作链接 |
| `onAction` | `() => void` | — | 恢复按钮回调 |

### `ErrorObject`

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `title` | `string` | 可选资源标题 |
| `message` | `string` | 错误消息 |
| `action` | `string` | 恢复动作文案 |
| `link` | `string` | 恢复动作链接 |
| `id` | `string` | 稳定诊断标识 |
| `code` | `string` | 机器可读错误码 |

## 可访问性 (Accessibility)

- 异步错误默认使用 `aria-live="polite"` 播报。
- 只有阻断输入的错误才使用 `live="assertive"`。
- 诊断 ID 放在折叠的 `details` 内，便于复制，同时不干扰主要信息。
- 恢复按钮可键盘访问；外部链接会使用 `rel="noopener noreferrer"`。

## 旧版行内用法 (Legacy Inline Usage)

`ErrorMessage` 仍然导出，用于兼容既有行内校验文本；新的字段级错误应放在对应 field/input primitive 上。

```tsx
import { ErrorMessage } from "@nebutra/ui/primitives";

<ErrorMessage>This email address is already in use.</ErrorMessage>
```
