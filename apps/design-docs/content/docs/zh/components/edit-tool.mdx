## 安装

```tsx
import { EditTool } from "@nebutra/ui/primitives";
```

或通过 shadcn 注册表独立安装：

```bash
npx shadcn@latest add https://ui.nebutra.com/r/edit-tool.json
```

## 基本用法

`EditTool` 用于聊天界面中 AI 助手汇报文件修改结果。传 `oldContent` + `newContent`（`edit` variant）或仅 `newContent`（`write` variant）。

```tsx
import { EditTool } from "@nebutra/ui/primitives";

<EditTool
  filePath="/app/page.tsx"
  oldContent={previous}
  newContent={next}
  approval={{
    onApprove: applyEdit,
    onReject: discardEdit,
  }}
/>
```

## 状态机

| 状态         | 渲染                                                     |
| ------------ | -------------------------------------------------------- |
| `waiting`    | shimmer "Generating..." header —— 无 body               |
| `pending`    | shimmer "Editing X.tsx" header + 完整 diff               |
| `completed`  | 静态 "Edited X.tsx" header + 完整 diff + `+N -N` 统计    |

## 变体

| Variant  | 行为                                                              |
| -------- | ----------------------------------------------------------------- |
| `edit`   | `oldContent` vs `newContent` 的 LCS diff（红/绿行）              |
| `write`  | 仅 `newContent`——每行都作为新增渲染                              |

## 审批 footer

可选 `approval` prop 在 diff 下渲染 Approve / Reject 按钮。混合受控+非受控——可不传父级 state。

```tsx
const [decision, setDecision] = useState<ApprovalDecision>(null);

<EditTool
  state={decision === "approved" ? "pending" : "completed"}
  filePath="/app/page.tsx"
  oldContent={previous}
  newContent={next}
  approval={{
    decision,                       // 受控
    onDecisionChange: setDecision,  // 受控
    approveLabel: "Apply",
    rejectLabel: "Skip",
    onApprove: () => applyEdit(),
    onReject:  () => cancelEdit(),
  }}
/>
```

不传 `approval` 则不渲染 footer。

## Props

| Prop           | 类型                                            | 默认         | 说明                                                         |
| -------------- | ----------------------------------------------- | ------------ | ------------------------------------------------------------ |
| `state`        | `"completed" \| "pending" \| "waiting"`         | `"completed"`| 工具调用进度视觉                                             |
| `variant`      | `"edit" \| "write"`                             | `"edit"`     | diff 策略                                                    |
| `filePath`     | `string`                                        | —            | 头部显示 basename（`/foo/bar.ts` → `bar.ts`）                |
| `oldContent`   | `string`                                        | —            | `variant: "edit"` 必填                                       |
| `newContent`   | `string`                                        | —            | 两种 variant 都必填（如需渲染 body）                         |
| `approval`     | `EditToolApproval`                              | —            | 可选审批 footer 配置                                         |
| `maxDiffLines` | `number`                                        | `2000`       | LCS 上限，防 O(m·n) OOM；超出时显示占位                      |
| `className`    | `string`                                        | —            | 外层容器附加 class                                           |

## 安全：LCS 上限

LCS 行级 diff 是 O(m·n) 内存。一万行 diff = 一亿 cell = 浏览器 OOM。`EditTool` 在 `maxDiffLines`（默认 2000）截断，超出则显示占位。

## 无障碍

- 外层 `<section aria-label>` 地标，覆盖头部和 diff body
- 审批状态用 `<output aria-live="polite">`——屏读器自动播报 "Starting" / "Approved" / "Canceled"
- Loading dots 设 `aria-hidden`（装饰性）
- diff 行前缀符号（`+` / `-` / ` `）`aria-hidden`；语义由行背景色承载（这也是为什么 gutter 必须保持文本字符——见组件的设计 invariants）
- Esc 拒绝待批审批（业界 chat-tool 惯例）

## 复用关系

本组件复用现有 primitive，未重复造轮：

- [`TextShimmer`](/zh/docs/components/text-shimmer) —— 头部 shimmer
- [`LoadingDots`](/zh/docs/components/loader) —— 审批 "Starting…" 动画

定制以上任一 primitive，`EditTool` 自动继承。
