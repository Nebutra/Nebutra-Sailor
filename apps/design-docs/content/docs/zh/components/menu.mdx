## 概述

`Menu` 是基于 Nebutra `DropdownMenu` 的语义下拉 facade，底层由 Base UI Menu 承载。公开 API 是扁平且明确的：`MenuContainer`、`MenuButton`、`Menu`、`MenuItem`、`MenuLink`、`MenuItemLocked`、`MenuSection`。

当您需要原始构建块（如复选框项、单选组或子菜单）时，请直接使用 `DropdownMenu`。对于标准的导航和操作列表，请使用 `Menu`。

## 用法

```tsx
import {
  Menu,
  MenuButton,
  MenuContainer,
  MenuItem,
  MenuItemLocked,
  MenuSection,
} from "@nebutra/ui/primitives";

<MenuContainer position="bottom-start">
  <MenuButton type="secondary" showChevron>
    Workspace
  </MenuButton>
  <Menu width={220}>
    <MenuSection title="General" showDivider={false}>
      <MenuItem>Overview</MenuItem>
      <MenuItem href="/settings/members">Members</MenuItem>
      <MenuItemLocked>Billing</MenuItemLocked>
    </MenuSection>
  </Menu>
</MenuContainer>
```

### 锁定条目

## 链接条目

当提供 `href` 属性时，条目会自动渲染为 `<a>` 标签。键盘和鼠标导航通过 `DropdownMenu` 的 render-slot bridge 保留。

## 自定义触发器

头像、更多按钮这类触发器使用 `MenuButton variant="unstyled"`。如果需要 render slot、checkbox/radio 菜单项或多级 submenu，直接使用底层 `DropdownMenu`。

## 属性

该 API 与 Nebutra `DropdownMenu` content props 对齐，但 `.Item` 接受自定义渲染属性。

### `MenuContainer`

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `position` | `"bottom-start" \| "bottom-end" \| "top-start" \| "top-end" \| "right-start" \| "right-end" \| "left-start" \| "left-end"` | `"bottom-start"` | 相对触发器的弹层方向和对齐方式。 |
| `children` | `ReactNode` | — | `MenuButton` 与一个 `Menu`。 |

### `MenuButton`

继承 Nebutra `Button` 的交互属性，并将 Geist 命名映射到 Button variants。

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `showChevron` | `boolean` | `false` | 在标签后追加 chevron。 |
| `type` | `"primary" \| "secondary" \| "tertiary" \| "ghost" \| "warning" \| "destructive"` | `"primary"` | 将 Geist intent 映射为 Nebutra Button variant。 |
| `variant` | `"unstyled"` | — | 移除按钮外观，用于头像或纯图标触发器。 |
| `size` | `"tiny" \| "small" \| "medium" \| "large"` | `"medium"` | 触发器尺寸。 |
| `shape` | `"default" \| "square" \| "circle"` | `"default"` | 触发器形状。 |

### `Menu`

继承 Nebutra `DropdownMenuContent` 的弹层属性，但 `side` 和 `align` 由 `MenuContainer.position` 管理。

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `width` | `number \| string` | — | 固定弹层宽度。未设置时按内容自适应。 |
| `className` | `string` | — | 追加到弹层的类名。 |

### `Menu.Item`

| 属性 | 类型 | 默认值 | 描述 |
|------|------|---------|-------------|
| `prefix` | `ReactNode` | — | 左侧的图标/元素 |
| `suffix` | `ReactNode` | — | 右侧的图标/元素（当 `locked` 时被锁定图标覆盖） |
| `disabled` | `boolean` | `false` | 置灰条目，移除指针事件 |
| `href` | `string` | — | 将条目渲染为导航到该 URL 的 `<a>` 标签 |
| `onClick` | `() => void` | — | 条目激活时调用 |
| `type` | `"default" \| "error"` | `"default"` | 危险操作使用 `error`。 |
| `className` | `string` | — | 额外的 CSS 类名 |

### `MenuItemLocked`

`MenuItemLocked` 是权限受限但仍应被发现的菜单项。它保留 `MenuItem` 的视觉插槽，强制禁用，并注入锁定后缀。

## 可访问性

- `Menu` 继承 `DropdownMenu` 的菜单角色、roving focus、Escape 关闭和 typeahead 行为。
- 权限受限但需要被发现的动作使用 `locked`；临时不可用的动作使用 `disabled`。
- `prefix` 和 `suffix` 图标默认应为装饰性，除非它们表达了标签没有覆盖的信息。
- 链接条目仍应读起来像动作。不要把无关导航和危险命令混在同一个菜单里。

## 设计契约

- `Menu` 用于短动作列表或导航列表，其中每一行拥有相同密度和交互模型。
- 需要 checkbox、radio group、separator、级联 submenu 或自定义 item composition 时，直接使用底层 `DropdownMenu`。
- 菜单应保持稳定。如果用户需要扫描、比较或编辑多个字段，改用 Popover、Dialog 或页面级 settings surface。

## 真实产品示例

- Dashboard 顶栏里的账号菜单：Profile、Settings、Keyboard Shortcuts、Log out 保持同一行密度。
- Workspace 菜单里的 Billing、Security Logs 这类权限受限入口，用 `MenuItemLocked` 可见但不可交互。
- 表格行内的短动作列表，且动作少于七项、不包含表单控件。

## 反模式

- 不要在文档中使用不存在的 `Menu.Trigger`、`Menu.Content`，也不要把 `locked` 写成 `MenuItem` prop。
- 不要用 `Menu` 承载 checkbox、radio、嵌套 submenu 或筛选构建器；使用 `DropdownMenu` 或 `Popover`。
- 当用户需要理解升级或权限边界时，不要完全隐藏受限动作。
