## 先选择消费路径

| 场景 | 使用 | 原因 |
| --- | --- | --- |
| Nebutra monorepo 应用 | npm workspace package imports | 让 source、types、stories 和 docs 保持一致。 |
| 外部 Next.js/React 应用 | shadcn-compatible registry | 将 standalone source 复制到宿主项目。 |
| 品牌/VI 工作 | `@nebutra/brand` source data | 让身份数据和运行时 UI 样式分离。 |

## Monorepo 接入

<Steps>
  <Step title="安装 package 依赖">
    在 repo root 为目标应用添加依赖：

    ```bash
    pnpm add @nebutra/ui @nebutra/tokens @nebutra/icons --filter <app-name>
    ```
  </Step>

  <Step title="只在应用入口引入一次 token CSS">
    在 app-level CSS 入口添加：

    ```css
    @import "@nebutra/tokens/styles.css";
    ```
  </Step>

  <Step title="在应用根部接入主题状态">
    使用 `@nebutra/tokens` 的 `ThemeProvider`。它会把 resolved theme 写入 DOM，并保存偏好以支持 SSR-safe 渲染。

    ```tsx
    "use client";

    import { ThemeProvider } from "@nebutra/tokens";

    export function Providers({ children }: { children: React.ReactNode }) {
      return (
        <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
          {children}
        </ThemeProvider>
      );
    }
    ```
  </Step>

  <Step title="从最窄稳定路径导入">
    优先使用明确的 public subpath。需要受治理核心 primitive 子集时，使用 `@nebutra/ui/primitives/canonical`。

    ```tsx
    import { Button, Input, Select } from "@nebutra/ui/primitives";
    import { PageHeader } from "@nebutra/ui/layout";
    import { Search } from "@nebutra/icons";
    import { cn } from "@nebutra/ui/utils";
    ```
  </Step>
</Steps>

## Registry 接入

只有在外部项目复制 standalone component 时使用 registry：

```bash
npx shadcn@latest add https://ui.nebutra.com/r/button.json
```

Registry manifest 是 shadcn-compatible 分发产物。它可以携带复制出来的源码和 token fallback，但语义权威仍然是 package source 与 MDX docs。

## 导入路径策略

| Import | 用于 | 不适合 |
| --- | --- | --- |
| `@nebutra/ui/primitives` | 受治理 UI primitives 与产品表面 | 只需要 canonical core 子集时。 |
| `@nebutra/ui/primitives/canonical` | 只想暴露更小决策面的稳定 primitives | 需要 experimental 或装饰性 surfaces。 |
| `@nebutra/ui/layout` | Page shell 与重复 layout helpers | 正在写低层 primitive。 |
| `@nebutra/ui/patterns` | 有意保持高层的 docs/product patterns | 正在写可复用 primitive。 |
| `@nebutra/tokens` | ThemeProvider 与运行时主题状态 | 组件代码里只需要 CSS 变量时。 |
| `@nebutra/tokens/styles.css` | 运行时 CSS variables | 不要在组件文件里 import。 |

## 样式规则

```tsx
// Good: 通过组件 API 消费 semantic/component tokens。
<Button intent="primary">Deploy</Button>

// Good: 组合本地布局时使用 CSS variables。
<div className="border-[var(--border)] bg-[var(--background)] text-[var(--foreground)]" />

// Bad: 产品 UI 里硬编码漂移色。
<div className="bg-blue-600 text-white" />

// Bad: 从 docs 或 app code 穿透组件内部结构。
<Progress className="[&>div]:bg-green-500" />
```

如果组件无法通过公开 API 表达某个状态，就提升缺失的 semantic/component token 或 variant。不要把 workaround 写成文档范式。
