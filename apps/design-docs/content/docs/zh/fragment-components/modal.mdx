## 用法

`Modal` 是构建在 Nebutra `Dialog` 之上的复合 API。它保留 Geist modal 的使用模型，同时把焦点管理、标题关联、正文间距、内嵌面板和动作行收敛到统一原语中。

```tsx
import { Button, Input, Modal } from "@nebutra/ui/primitives";
import { useRef, useState } from "react";

export function CreateProjectModal() {
  const [active, setActive] = useState(false);
  const cancelRef = useRef<HTMLButtonElement>(null);

  return (
    <>
      <Button onClick={() => setActive(true)}>新建项目</Button>

      <Modal.Modal
        active={active}
        onClickOutside={() => setActive(false)}
        initialFocusRef={cancelRef}
      >
        <Modal.Body>
          <Modal.Header>
            <Modal.Title>新建项目</Modal.Title>
            <Modal.Subtitle>
              创建一个工作区级项目，并启用默认可观测性。
            </Modal.Subtitle>
          </Modal.Header>

          <Modal.Inset>
            <Input aria-label="项目名称" placeholder="Nebula Control Plane" />
          </Modal.Inset>
        </Modal.Body>

        <Modal.Actions>
          <Modal.Action ref={cancelRef} type="secondary" onClick={() => setActive(false)}>
            取消
          </Modal.Action>
          <Modal.Action onClick={() => setActive(false)}>创建项目</Modal.Action>
        </Modal.Actions>
      </Modal.Modal>
    </>
  );
}
```

## 属性

### `Modal.Modal`

| 属性 | 类型 | 默认值 | 描述 |
|---|---|---|---|
| `active` | `boolean` | — | 受控打开状态。 |
| `onClickOutside` | `() => void` | — | 用户通过外部点击或 Escape 请求关闭时调用。 |
| `sticky` | `boolean` | `false` | body 在面板内滚动，actions 固定在底部。 |
| `initialFocusRef` | `RefObject<HTMLElement \| null>` | — | 打开后聚焦的元素；危险流程应指向 Cancel。 |
| `className` | `string` | — | 对话框内容面板的额外类名。 |
| `children` | `ReactNode` | — | 复合模态框内容。 |

### 布局部件

| 部件 | 类型 | 描述 |
|---|---|---|
| `Modal.Body` | `HTMLAttributes<HTMLDivElement>` | 主内容区域；`sticky` 为 true 时在内部滚动。 |
| `Modal.Header` | `HTMLAttributes<HTMLDivElement>` | 标题和说明组合。 |
| `Modal.Title` | `HTMLAttributes<HTMLHeadingElement>` | 自动把 `aria-labelledby` 接到对话框内容。 |
| `Modal.Subtitle` | `HTMLAttributes<HTMLParagraphElement>` | 辅助说明文案。 |
| `Modal.Inset` | `HTMLAttributes<HTMLDivElement>` | 用于表单行、元数据或风险上下文的内嵌面板。 |
| `Modal.Actions` | `HTMLAttributes<HTMLDivElement>` | 底部动作行。 |

### `Modal.Action`

| 属性 | 类型 | 默认值 | 描述 |
|---|---|---|---|
| `type` | `"primary" \| "secondary"` | `"primary"` | 视觉动作优先级，映射到 Button variants。 |
| `buttonType` | `"button" \| "submit" \| "reset"` | `"button"` | 用于表单集成的原生 button 类型。 |
| `fullWidth` | `boolean` | `false` | 让动作按钮横向铺满。 |
| `prefix` | `ReactNode` | — | 可选前置图标。 |

## 可访问性

- 焦点锁定、Escape 关闭、关闭后回到触发器由底层 `Dialog` 提供。
- `Modal.Title` 会自动通过 `aria-labelledby` 关联对话框；不要手动重复标题 ID。
- 危险或高风险决策应通过 `initialFocusRef` 默认聚焦取消按钮。
- 主动作在源码顺序中放最后，让键盘和屏幕阅读器用户先经过 review/cancel 选项。
- 高风险删除动作使用 `DestructiveActionModal`，或在 `Modal.Inset` 内加入输入确认门。

## 设计契约

- 只有当页面其余区域必须被阻塞，直到用户完成决策或聚焦任务时，才使用 `Modal`。
- 周边页面上下文仍需可读时使用 `Sheet` 或 `Drawer`；字段很多的常规创建/编辑流程应放到独立页面。
- 标题使用简短陈述，不写问句。副标题说明后果、作用域或下一步。
- 普通流程保持两个动作按钮。超过两个动作通常说明这个流程应该升级为页面级表面。

## 真实产品示例

- 空工作区里创建项目，且只需要名称、区域和默认可观测性选项。
- 用户查看受影响集成后轮换 API key，并且可以安全取消。
- 从团队表格邀请成员，表单很短，提交后仍需要回到原列表上下文。

## 反模式

- 不要把 `Modal` 用于包含多个分区的长创建或编辑流程；这类流程应进入页面或路由级表单。
- 不要用它展示可以内联阅读的被动信息，避免无意义阻塞页面。
- 破坏性动作如果需要输入确认，不要直接使用普通 `Modal`；应加入专用确认 gate 或使用 `DestructiveActionModal`。
