Fragment components 是面向具体业务上下文预先组合好的原子组件集合。它不同于 UI Patterns 这类结构性指导原则；Fragment 是**具体、可导入、可复用的组件**。

<Info>
  Fragment components 由 `@nebutra/ui` 实现。每个组件页都会标明对应导入路径。
</Info>

## Fragment 的判定标准

Fragment 和 primitive atom 的区别在于**组合语义**。每个 Fragment 都应该：

- 把两个或更多原子组件（Button、Input、Badge、Icon 等）组合成一个一致的单元
- 编码领域语义，清楚表达自己代表什么，例如空状态、指标卡或确认对话框
- 提供合理默认值，让调用方用较少 props 就能落地
- 默认具备可访问性，包括 ARIA 角色、键盘导航和焦点管理

## 设计原则

**组合优先于配置。** Fragment 组合现有 atom，而不是重新实现它们。Fragment 内需要按钮时，应渲染 `Button` atom，而不是样式化的 `<button>`。

**通过 `className` 提供逃生口。** 每个 Fragment 都接受 `className`，用于一次性覆盖，而不需要 fork 组件。

**同时支持受控和非受控模式。** 涉及状态的 Fragment（如 modal、filter bar）应同时支持受控模式（`value` / `onChange`）和内部状态模式。
