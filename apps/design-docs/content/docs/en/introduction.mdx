## What This System Is

Nebutra Design System is a governed UI platform for AI-native SaaS products. It packages the decisions that should be shared across Nebutra applications: token semantics, primitive APIs, composition rules, accessibility contracts, and external registry distribution.

It is deliberately narrower than a design inspiration library. A surface belongs here only when it reduces product variance, gives downstream developers a better API, or turns a repeated production pattern into a reusable contract.

## Design Principles

| Principle | Operational meaning |
| --- | --- |
| Token truth over visual memory | Runtime UI consumes `@nebutra/tokens/styles.css`; component examples should not hard-code palette drift. |
| Public API over DOM piercing | Consumers extend variants, props, and documented slots; they do not target internal child selectors. |
| Native semantics first | Prefer native elements and proven primitives. If Base UI, custom logic, or another substrate owns behavior, docs say that explicitly. |
| Product density over decorative flourish | SaaS surfaces should be quiet, scannable, and precise. Motion and visual effects earn their place by clarifying state or hierarchy. |
| Storybook and docs converge | Stories prove states; docs explain contracts. If they disagree, one of them is stale. |

## Package Map

| Package | Role |
| --- | --- |
| `@nebutra/tokens` | Runtime CSS variables, theme provider, and light/dark token semantics. |
| `@nebutra/ui` | Public UI package, including primitives, components, layout, patterns, hooks, and utilities. |
| `@nebutra/icons` | Nebutra icon facade, with Geist icons preferred for product UI. |
| `@nebutra/brand` | Brand source data for VI and identity work, not app runtime styling. |

## Distribution Paths

Use package imports inside Nebutra apps:

```tsx
import { Button, Input } from "@nebutra/ui/primitives";
```

Use the registry only when installing a standalone copy into an external project:

```bash
npx shadcn@latest add https://ui.nebutra.com/r/button.json
```

The package source and MDX docs remain the design authority in both cases.
