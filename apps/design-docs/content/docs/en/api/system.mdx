## Endpoint Purpose

System endpoints drive health checks, readiness gates, liveness probes, and status surfaces. They are consumed by deployment automation, load balancers, and internal status dashboards.

## UI States Driven By API

- Health check success keeps the public status indicator green.
- Readiness failure should block rollout promotion while leaving the process observable.
- Liveness failure should trigger infrastructure restart policy, not a user-facing retry loop.

## Errors / Loading / Empty Contracts

- Loading: show a neutral checking state for status panels.
- Error: show the failing endpoint and request id when available.
- Empty: system endpoints should not produce empty states; missing data is an error.
