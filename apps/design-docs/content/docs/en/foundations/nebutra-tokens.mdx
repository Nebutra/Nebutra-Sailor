## What This Page Owns

`nebutra-tokens` is the registry-distributed bootstrap manifest for projects that install standalone Nebutra components. It drops the runtime CSS variables needed by registry components into the host app.

Inside this monorepo, the canonical path is still the package stylesheet:

```css
@import "@nebutra/tokens/styles.css";
```

External registry consumers can install the manifest:

```bash
npx shadcn@latest add https://ui.nebutra.com/r/nebutra-tokens.json
```

## Token Truth

The registry manifest is a delivery adapter, not the design authority. Token ownership stays in `packages/design/tokens/src/index.ts` and `packages/design/tokens/styles.css`; docs and registry JSON must describe that source instead of inventing another token layer.

## Usage

Use the package stylesheet in product apps and packages that already depend on the monorepo:

```css
@import "@nebutra/tokens/styles.css";
```

Use the registry manifest only when a standalone consumer installs Nebutra registry items without the package graph:

```bash
npx shadcn@latest add https://ui.nebutra.com/r/nebutra-tokens.json
```

## Token Families

| Family | Examples | Purpose |
| --- | --- | --- |
| Neutral | `--neutral-1`, `--neutral-12` | Surface and foreground ramps. |
| Brand | `--brand-primary`, `--brand-accent`, `--brand-gradient-start`, `--brand-gradient-end`, `--brand-gradient` | Nebutra identity anchors and contrast-safe product action gradient. |
| Accent scales | `--blue-9`, `--cyan-9` | Product interaction and accent rails. |
| Status | `--status-danger`, `--status-warning`, `--status-success` | Semantic state colors. |
| Containers | `--container-text`, `--container-content`, `--container-wide` | Layout width rails. |

## Anti-patterns

- Do not import registry JSON as an internal token source.
- Do not hardcode primitive color values inside component docs or previews when a semantic/component variable exists.
- Do not add token fallbacks to individual primitives. Promote missing variables into `@nebutra/tokens` first.
- Do not treat `nebutra-tokens.json` as a theme preset. It bootstraps runtime variables for registry consumers.

## Governance

- Runtime UI consumes `@nebutra/tokens/styles.css`.
- Component examples should use semantic/component variables instead of raw hex.
- Registry copies may include token fallback CSS, but they do not define the source of truth.
- Storybook must keep a same-name foundation story so token drift is visible in the docs surface.
- IA lint treats this page as a foundation template, not a registry exception.
