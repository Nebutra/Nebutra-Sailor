## Usage

`Modal` is a compound API layered on top of Nebutra `Dialog`. It keeps the public surface close to the Geist modal pattern while centralizing focus management, title wiring, body spacing, inset panels, and action rows.

```tsx
import { Button, Input, Modal } from "@nebutra/ui/primitives";
import { useRef, useState } from "react";

export function CreateProjectModal() {
  const [active, setActive] = useState(false);
  const cancelRef = useRef<HTMLButtonElement>(null);

  return (
    <>
      <Button onClick={() => setActive(true)}>New Project</Button>

      <Modal.Modal
        active={active}
        onClickOutside={() => setActive(false)}
        initialFocusRef={cancelRef}
      >
        <Modal.Body>
          <Modal.Header>
            <Modal.Title>Create Project</Modal.Title>
            <Modal.Subtitle>
              Create a workspace-scoped project with default observability.
            </Modal.Subtitle>
          </Modal.Header>

          <Modal.Inset>
            <Input aria-label="Project name" placeholder="Nebula Control Plane" />
          </Modal.Inset>
        </Modal.Body>

        <Modal.Actions>
          <Modal.Action ref={cancelRef} type="secondary" onClick={() => setActive(false)}>
            Cancel
          </Modal.Action>
          <Modal.Action onClick={() => setActive(false)}>Create Project</Modal.Action>
        </Modal.Actions>
      </Modal.Modal>
    </>
  );
}
```

## Props

### `Modal.Modal`

| Prop | Type | Default | Description |
|---|---|---|---|
| `active` | `boolean` | — | Controlled open state. |
| `onClickOutside` | `() => void` | — | Called when the dialog requests close through outside click or Escape. |
| `sticky` | `boolean` | `false` | Keeps actions pinned while the body scrolls inside the panel. |
| `initialFocusRef` | `RefObject<HTMLElement \| null>` | — | Element to focus after open; use Cancel for destructive flows. |
| `className` | `string` | — | Additional classes for the dialog content panel. |
| `children` | `ReactNode` | — | Compound modal content. |

### Layout Parts

| Part | Type | Description |
|---|---|---|
| `Modal.Body` | `HTMLAttributes<HTMLDivElement>` | Main content region; scrolls when `sticky` is true. |
| `Modal.Header` | `HTMLAttributes<HTMLDivElement>` | Title/subtitle group. |
| `Modal.Title` | `HTMLAttributes<HTMLHeadingElement>` | Auto-wires `aria-labelledby` to the dialog content. |
| `Modal.Subtitle` | `HTMLAttributes<HTMLParagraphElement>` | Secondary explanatory copy. |
| `Modal.Inset` | `HTMLAttributes<HTMLDivElement>` | Recessed panel for form rows, metadata, or risk context. |
| `Modal.Actions` | `HTMLAttributes<HTMLDivElement>` | Footer action row. |

### `Modal.Action`

| Prop | Type | Default | Description |
|---|---|---|---|
| `type` | `"primary" \| "secondary"` | `"primary"` | Visual action priority mapped to Button variants. |
| `buttonType` | `"button" \| "submit" \| "reset"` | `"button"` | Native button type for form integrations. |
| `fullWidth` | `boolean` | `false` | Stretches the action across the row. |
| `prefix` | `ReactNode` | — | Optional leading glyph. |

## Accessibility

- Focus trap, Escape-to-close, and return-focus behavior come from the underlying `Dialog`.
- `Modal.Title` automatically links to the dialog through `aria-labelledby`; do not manually duplicate title IDs.
- Use `initialFocusRef` to place focus on Cancel for destructive or high-risk decisions.
- Keep the primary action last in source order so keyboard and screen reader users encounter review/cancel options first.
- For high-stakes destructive actions, use `DestructiveActionModal` or add a typed confirmation gate inside `Modal.Inset`.

## Design Contract

- Use `Modal` only when the rest of the page must be blocked until the user decides or completes a focused task.
- Use `Sheet` or `Drawer` when surrounding page context should remain readable, and use a dedicated page for routine create/edit flows with many fields.
- Titles are short Title Case statements, not questions. Subtitles are sentence case and should explain consequence, scope, or next step.
- Keep actions to two buttons in normal flows. More than two actions usually means the flow belongs in a page-level surface.
