## Props

### AlertDialog (Root)

| Prop           | Type                      | Default | Description                      |
| -------------- | ------------------------- | ------- | -------------------------------- |
| `open`         | `boolean`                 | —       | Controlled open state            |
| `defaultOpen`  | `boolean`                 | `false` | Uncontrolled default open state  |
| `onOpenChange` | `(open: boolean) => void` | —       | Callback when open state changes |

### AlertDialogContent

| Prop        | Type        | Default | Description            |
| ----------- | ----------- | ------- | ---------------------- |
| `className` | `string`    | —       | Additional CSS classes |
| `children`  | `ReactNode` | —       | Dialog content         |

### AlertDialogAction

| Prop        | Type         | Default | Description                    |
| ----------- | ------------ | ------- | ------------------------------ |
| `className` | `string`     | —       | Additional CSS classes         |
| `children`  | `ReactNode`  | —       | Action button label            |
| `onClick`   | `() => void` | —       | Handler for the confirm action |

### AlertDialogCancel

| Prop        | Type        | Default | Description            |
| ----------- | ----------- | ------- | ---------------------- |
| `className` | `string`    | —       | Additional CSS classes |
| `children`  | `ReactNode` | —       | Cancel button label    |

## Accessibility

- Built on Base UI AlertDialog — follows the WAI-ARIA [Alert and Message Dialogs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/).
- Renders with `role="alertdialog"` and `aria-modal="true"`.
- Focus is trapped inside the dialog while open.
- Unlike `Dialog`, `AlertDialog` does not close on overlay click — requires explicit user action.

## Design Contract

- Use `AlertDialog` only when the next action can cause loss, security impact, or irreversible workflow change.
- Lead with a specific consequence in `AlertDialogDescription`; do not rely on the button label to explain risk.
- Keep the cancel action visible and first in reading order so keyboard users can leave the flow before reaching the confirm action.

## Real Product Examples

- Confirming that a user wants to revoke an API key before active integrations lose access.
- Removing a team member from an organization when ownership and audit history remain visible.
- Cancelling a production deployment after queued jobs and pending webhooks have been named in the description.

## Anti-patterns

- Do not use `AlertDialog` for routine save, close, or navigation confirmations that can be handled inline.
- Do not hide the cancel action or make the destructive action the first focus target.
- Do not use vague descriptions like "Are you sure?" without naming the affected resource and consequence.
