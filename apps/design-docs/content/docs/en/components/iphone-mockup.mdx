## Overview

`Phone` wraps captured mobile media in a restrained iPhone-style frame. The chrome is decorative; the captured screen supplies the accessible name through `imageAlt`, `videoLabel`, or a labelled child.

Use `Phone` for marketing pages, docs examples, changelog visuals, and launch screenshots. Do not render live product UI inside it unless the content is intentionally static and labelled as a captured screen.

## Usage

```tsx
import { Phone } from "@nebutra/ui/primitives";

export function Example() {
  return (
    <div className="w-full max-w-xs">
      <Phone
        imageSrc="/screenshots/mobile-dashboard.png"
        imageAlt="Nebutra mobile dashboard showing usage cards and recent activity"
      />
    </div>
  );
}
```

### Captured JSX

Use children only for static captured compositions. Interactive controls are blocked by the component because the device chrome implies a screenshot, not a live surface.

```tsx
<Phone>
  <div role="img" aria-label="Mobile onboarding confirmation screen">
    {/* static captured layout */}
  </div>
</Phone>
```

### Video

```tsx
<Phone
  videoSrc="/recordings/mobile-demo.mp4"
  videoPoster="/recordings/mobile-demo-poster.png"
  videoLabel="Mobile onboarding flow recording"
/>
```

`videoPoster` is the fallback for reduced motion. Always provide it in product usage.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `imageSrc` | `string` | — | Captured screenshot source. Requires `imageAlt`. |
| `imageAlt` | `string` | — | Accessible description of the captured screen. |
| `videoSrc` | `string` | — | Muted looping demo recording source. Requires `videoLabel`. |
| `videoLabel` | `string` | — | Accessible name for the recording. |
| `videoPoster` | `string` | — | Poster and `prefers-reduced-motion` fallback. |
| `children` | `ReactNode` | — | Static captured JSX. Mutually exclusive with image and video props. |
| `address` | `string` | — | Optional origin shown in the empty placeholder. |
| `chrome` | `"graphite" \| "silver" \| "titanium"` | `"graphite"` | Semantic chrome finish. |
| `fit` | `"cover" \| "contain"` | `"cover"` | Object fit for image and video media. |
| `position` | `CSSProperties["objectPosition"]` | `"top"` | Object position for image and video media. |
| `className` | `string` | — | Root class. Size the component with width constraints. |

## Migration

`IphoneMockup` remains as a deprecated compatibility alias. New code should import `Phone`.

```tsx
import { Phone } from "@nebutra/ui/primitives";
```

Legacy `src` still works when paired with `imageAlt`, but `imageSrc` is the canonical prop.

## Best Practices

Use `Phone` as marketing chrome around mobile screenshots, recordings, and demo images on landing pages and docs.

Do not render live mobile product UI inside the frame. The chrome implies a captured screen, not an interactive surface.

Pair with `Browser` when showing parallel desktop and mobile views, and keep both variants on the same theme.

Match `chrome` to the surrounding theme so the frame does not outshine the screenshot it is framing.

Lock the component with a stable width (`max-w-xs`, a grid column, or a media rail) so the inner 19.5:9 screen ratio does not crop unpredictably.

Avoid stacking additional shadows on the parent container. The component already owns its elevation token.

Treat the chrome as decorative. Accessible naming belongs on the captured screenshot or recording, not on the device frame.

For autoplay video, respect `prefers-reduced-motion` by providing `videoPoster`.
