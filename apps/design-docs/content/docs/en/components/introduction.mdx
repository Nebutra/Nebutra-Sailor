## Taxonomy

The sidebar groups components by consumer intent:

- **Core Forms & Actions**: controls that collect or submit user intent.
- **Navigation & Commands**: movement, command execution, and large-surface orientation.
- **Overlays & Disclosure**: content that appears conditionally above or within the current page.
- **Feedback & Status**: system state, validation, progress, loading, and empty states.
- **Data Display**: structured information, metadata, files, code, and cards.
- **Layout & Typography**: primitives that shape product density and reading hierarchy.
- **AI & Agent Surfaces**: chat, tool calls, agent plans, and generated output.
- **Motion & Text Effects**: effects that must clarify hierarchy or state, not decorate by default.
- **Visual Systems & Backgrounds**: high-touch visuals isolated from operational SaaS surfaces.
- **Marketing & Content Blocks**: acquisition or editorial sections, not dashboard primitives.
- **Media & Mockups**: representational surfaces for product screenshots, maps, video, and device frames.

## Component Maturity

| Status | Meaning |
| --- | --- |
| `stable` | Public API is expected to remain compatible. Docs, stories, tokens, and a11y contract are aligned. |
| `beta` | API is usable but still settling. Breaking changes require migration notes. |
| `experimental` | Visual/API direction is being tested. Avoid spreading into product-critical flows without review. |
| `deprecated` | Do not use for new work. The docs page must name the replacement. |

## Governance Rules

1. Pick the narrowest primitive that owns the behavior.
2. Do not use decorative components inside operational workflows unless the pattern page says so.
3. If a component is in the registry, docs must explain whether package imports or standalone install is canonical for the consuming context.
4. Every preview under `src/components/previews` must be attached to the owning MDX page. Remove examples that are not part of the docs contract.
