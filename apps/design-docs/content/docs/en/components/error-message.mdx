## Usage

```tsx
import { Error } from "@nebutra/ui/primitives";
```

```tsx
<Error
  title="Couldn’t Load Deployments"
  action="Try Again"
  onAction={refetch}
  errorId="iad1::r7h2p-1712f9cda5d8"
>
  The deployments list failed to load. Try again or check the request details.
</Error>
```

## Design Principles

- Use `Error` when a page, route boundary, section, panel, or dashboard card failed to load.
- Use toast errors for transient action failures and the owning input/field primitive for validation.
- Name the failed resource. Do not ship `Something went wrong`.
- State what happened and what to do next. Avoid apologetic or humorous copy.
- Include a stable identifier for system errors: request ID, trace ID, deployment ID, or run ID.
- Recovery actions must be concrete: `Try Again`, `Reconnect GitHub`, `Update Payment Method`.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `title` | `string` | — | Resource-specific title |
| `children` | `ReactNode` | — | Message body |
| `label` | `string` | — | Optional compact label above the title |
| `showLabel` | `boolean` | `true` | Hides the label when false |
| `size` | `"small" \| "medium" \| "large"` | `"medium"` | Surface density |
| `error` | `ErrorObject` | — | Structured error data |
| `errorId` | `string` | — | Stable diagnostic identifier |
| `errorIdLabel` | `string` | `"Request ID"` | Label rendered before the stable ID |
| `live` | `"polite" \| "assertive" \| "off"` | `"polite"` | Announcement mode for async errors |
| `action` | `string` | — | Recovery action label |
| `link` | `string` | — | Recovery action link |
| `onAction` | `() => void` | — | Recovery button handler |

### `ErrorObject`

| Field | Type | Description |
|-------|------|-------------|
| `title` | `string` | Optional resource title |
| `message` | `string` | Error message |
| `action` | `string` | Recovery action label |
| `link` | `string` | Recovery action href |
| `id` | `string` | Stable diagnostic identifier |
| `code` | `string` | Machine-readable error code |

## Accessibility

- Async errors announce with `aria-live="polite"` by default.
- Use `live="assertive"` only for blocking errors that interrupt input.
- Diagnostic IDs render inside collapsed `details` so users can copy them without making the error visually noisy.
- Button actions remain keyboard reachable; links use `rel="noopener noreferrer"` when external.

## Legacy Inline Usage

`ErrorMessage` remains exported for existing inline validation text, but new field-level errors should live on the field/input primitive.

```tsx
import { ErrorMessage } from "@nebutra/ui/primitives";

<ErrorMessage>This email address is already in use.</ErrorMessage>
```
