## Usage

```tsx
import { Textarea } from "@nebutra/ui/primitives";
```

```tsx
<Textarea
  id="message"
  label="Message"
  description="Keep the first sentence user-facing."
  placeholder="Customers can now..."
  rows={4}
/>
```

## Props

All native `<textarea>` props are supported, plus:

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | Tokenized density scale shared with form controls. |
| `label` | `string` | — | Visible field label. Requires an `id` at the type level. |
| `description` | `string` | — | Helper text linked with `aria-describedby`. Hidden when a string error is rendered. |
| `error` | `string \| boolean` | — | Marks the field invalid; string values render an inline error message. |
| `onValueChange` | `(value: string) => void` | — | Value-first change callback in addition to native `onChange`. |
| `fieldClassName` | `string` | — | Class name for the label/helper/error wrapper. |

## Design Contract

- Use Textarea for content that naturally wraps: release notes, descriptions, comments, and incident summaries.
- Keep the field visually flat: semantic border, background, text, muted placeholder, and tokenized focus ring only.
- Mouse and keyboard focus both use `:focus` for the component ring so native square browser outlines never leak around rounded controls.
- Use `ExpandingTextarea` only when the surface has vertical room for growth; fixed rows are safer inside dense forms and footers.

## Accessibility

`label`, `description`, and string `error` are wired to `id`, `aria-describedby`, and `aria-invalid`. Error text is rendered with `role="alert"`.

If composing labels externally, keep the same contract: `htmlFor` must match the textarea `id`, helper text should be one sentence, and validation should name the field and constraint.

## Tokens

Textarea consumes component geometry from `textareaTokens` and semantic runtime colors from CSS variables:

| Token | Purpose |
| ----- | ------- |
| `textareaTokens.sizes` | Min height, padding, font size, and radius per density. |
| `textareaTokens.focusRingWidth` | Tokenized focus ring width shared by focus and error focus states. |
| `textareaTokens.fieldGap` | Space between label, control, and field messages. |
| `--background`, `--foreground`, `--input`, `--ring`, `--destructive` | Semantic color contract. |

## Real Product Examples

- Release notes or changelog summaries.
- Incident postmortem notes with helper text and max-length validation.
- Comments and descriptions inside dense forms.

## Anti-patterns

- Do not use Textarea for a single scalar value such as a name, URL, or email.
- Do not grow the textarea until primary actions move below the fold.
- Do not rely on placeholder instructions instead of a visible label.
