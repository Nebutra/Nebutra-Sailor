## Group

## Props

### Avatar

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `size` | `"xs" \| "sm" \| "md" \| "lg" \| "xl" \| number` | `"md"` | Preset or pixel size. |
| `src` | `string` | — | Convenience image source. |
| `title` | `string` | — | Literal entity name used for fallback initials and labels. |
| `letter` | `string` | derived | 1-2 uppercase initials. |
| `placeholder` | `boolean` | `false` | Loading shell only. |

### AvatarGroup

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `members` | `AvatarGroupItem[]` | — | Geist-compatible member list. |
| `items` | `AvatarGroupItem[]` | — | Existing Nebutra member list. |
| `limit` | `number` | `4` | Geist-compatible max visible slot count. |
| `max` | `number` | `4` | Existing alias for `limit`. |
| `size` | `AvatarSize \| number` | `"sm"` | Size applied to every avatar. |

## Best Practices

- Use a single `Avatar` for one person, team, or organization.
- For two or more stacked avatars, use `AvatarGroup` so the cluster gets correct overlap, sizing, overflow, and a single accessible label.
- Pass `src` first and fall back to `letter` when the image is missing.
- Reserve `placeholder` for the loading shell; never use it as a permanent fallback.
- Keep `letter` uppercase and derived from the entity name. Use 1-2 letters.
- Pick a size that matches adjacent type: 20-24px next to compact labels, 32px next to standard labels, and 48-64px in headers or onboarding states.

## Accessibility

- `AvatarGroup` exposes one group label and hides individual stacked images from assistive tech to avoid noisy repetition.
- For individual image avatars, provide a useful `title` or `alt`.
- When an avatar triggers a menu or action, wrap it in a button with an explicit `aria-label`.
