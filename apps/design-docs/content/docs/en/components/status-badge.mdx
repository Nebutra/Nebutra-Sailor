## Overview

`StatusBadge` displays two labels separated by a thin vertical divider. The left side is bold (primary label) and the right side is muted (secondary label). Optional icons can precede each label and are colorized based on the `status` prop.

## Installation

```tsx
import { StatusBadge } from "@nebutra/ui/primitives";
```

## Usage

### Basic

```tsx
import { ShieldCheck, CrossCircle as XCircle } from "@nebutra/icons";

<StatusBadge
  leftIcon={ShieldCheck}
  rightIcon={XCircle}
  leftLabel="Protection"
  rightLabel="SSO disabled"
  status="success"
/>
```

### Multiple statuses

```tsx
import { CheckCircle as CheckCircle2, Warning as AlertCircle, CrossCircle as XCircle } from "@nebutra/icons";

<div className="flex gap-2 flex-wrap">
  <StatusBadge leftIcon={CheckCircle2} leftLabel="Live" rightLabel="v2.1.0" status="success" />
  <StatusBadge leftIcon={AlertCircle} leftLabel="Degraded" rightLabel="3 incidents" status="warning" />
  <StatusBadge leftIcon={XCircle} leftLabel="Outage" rightLabel="5 affected" status="error" />
</div>
```

### No icons

```tsx
<StatusBadge leftLabel="Region" rightLabel="us-east-1" status="info" />
```

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `leftLabel` | `string` | — | **Required.** Primary label (bold, foreground) |
| `rightLabel` | `string` | — | **Required.** Secondary label (muted) |
| `leftIcon` | `LucideIcon` | — | Icon before left label |
| `rightIcon` | `LucideIcon` | — | Icon before right label |
| `status` | `"success" \| "error" \| "warning" \| "info" \| "default"` | `"default"` | Determines icon color |
| `className` | `string` | — | Additional CSS classes |

## Status Icon Colors

| Status | Icon Color |
|--------|-----------|
| `success` | `text-emerald-600` (dark: `text-emerald-500`) |
| `error` | `text-red-600` (dark: `text-red-500`) |
| `warning` | `text-amber-600` (dark: `text-amber-500`) |
| `info` | `text-blue-600` (dark: `text-blue-500`) |
| `default` | `text-muted-foreground` |

## Notes

- The status only affects icon colors — the badge container always uses `bg-background` with a `border`.
- The divider between labels is a `1px` wide `bg-border` element.

## Accessibility

- The two labels must remain textual; icons and color are secondary signals.
- Keep each label short enough to wrap predictably in compact status rows.
- When the same state is already named in nearby copy, avoid repeating redundant icon-only badges.

## Design Contract

- Use `StatusBadge` for compact paired status copy, such as capability plus current condition.
- Keep the left label as the entity or capability and the right label as the current state or qualifier.
- Status color is an affordance, not the contract. The labels must still explain the state without color.

## Real Product Examples

- Security settings rows showing `Protection` plus `SSO disabled` or `SCIM active`.
- Region or environment headers pairing a location with its current rollout state.
- Integration cards summarizing provider connection health and the last successful sync label.

## Anti-patterns

- Do not use `StatusBadge` as a severity alert, toast, or validation error. Use the dedicated feedback component for those flows.
- Do not put long sentences in either side of the badge; switch to normal body copy when the state needs explanation.
- Do not use multiple badges as the only filterable status control in a dense table. Use a table column with text and an accessible filter.
