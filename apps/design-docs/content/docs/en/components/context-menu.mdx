## Overview

`ContextMenu` is the power-user shortcut surface for right-click and keyboard-menu interactions. It is built on Base UI and uses Nebutra item, overlay, and motion tokens. It must never be the only entry point for an action; mirror every item in a visible row action, toolbar menu, or details panel.

Use `CommandMenu` for global actions and search. Use a visible menu trigger when discoverability matters more than pointer-positioned speed.

## Usage

### Disabled items

Disabled items stay visible when the action exists but is temporarily unavailable.

```tsx
<ContextMenu.Item disabled value="promote">
  Promote to Production
</ContextMenu.Item>
```

### Link items

Use `href` for navigation. Link items render with Base UI's link item primitive instead of a simulated click handler.

```tsx
<ContextMenu.Item href="/docs" prefix={<Link className="size-4" />} value="docs">
  View Documentation
</ContextMenu.Item>
```

### Prefix and suffix

<ComponentPreview name="context-menu-with-icons-demo" className="min-h-[250px] flex justify-center items-center" />

```tsx
<ContextMenu.Item prefix={<Copy className="size-4" />} value="copy">
  Copy URL
  <ContextMenu.Shortcut>⌘C</ContextMenu.Shortcut>
</ContextMenu.Item>
```

### Checkbox, radio, and submenu items

```tsx
<ContextMenu.CheckboxItem defaultChecked value="status">
  Status
</ContextMenu.CheckboxItem>

<ContextMenu.RadioGroup defaultValue="comfortable">
  <ContextMenu.RadioItem value="compact">Compact</ContextMenu.RadioItem>
  <ContextMenu.RadioItem value="comfortable">Comfortable</ContextMenu.RadioItem>
</ContextMenu.RadioGroup>

<ContextMenu.Sub>
  <ContextMenu.SubTrigger>Move to Project</ContextMenu.SubTrigger>
  <ContextMenu.SubContent>
    <ContextMenu.Item value="core">Core Platform</ContextMenu.Item>
  </ContextMenu.SubContent>
</ContextMenu.Sub>
```

## Props

### ContextMenu

`ContextMenu` is callable as the root component and also exposes `ContextMenu.Root` for existing consumers.

### ContextMenu.Content

Accepts Base UI popup props plus `align`, `side`, `alignOffset`, and `sideOffset`.

### ContextMenu.Item

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `children` | `ReactNode` | — | Item label. Use Title Case Verb + Noun. |
| `onSelect` | `BaseContextMenu.Item["onClick"]` | — | Activation handler for non-link items. |
| `disabled` | `boolean` | `false` | Disables interaction. |
| `href` | `string` | — | Renders a link item. |
| `prefix` | `ReactNode` | — | Leading icon or avatar. |
| `suffix` | `ReactNode` | — | Trailing hint. Prefer `ContextMenu.Shortcut` for keys. |
| `variant` | `"default" \| "destructive"` | `"default"` | Destructive styling for irreversible actions. |
| `value` | `string` | — | Stable analytics/test value. |

## Design Principles

- Context menus accelerate secondary actions; they do not replace visible controls.
- Labels are Title Case Verb + Noun: `Copy URL`, `Delete Deployment`, `Open in New Tab`.
- Use an ellipsis only when the item opens a follow-up dialog, such as `Rename Deployment...`.
- Keep destructive items at the bottom after a separator. Do not hide destructive actions in submenus.
- Avoid more than one submenu level; keyboard navigation becomes fragile quickly.

## Accessibility

- Right-click, long-press, and keyboard menu flows should expose the same actions.
- Arrow keys move focus; `Enter`/`Space` activates; `Escape` closes and returns focus.
- Disabled items remain announced but are skipped for activation.
- The trigger region should be scoped to the row/object, not the whole page.
