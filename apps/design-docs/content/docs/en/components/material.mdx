## Overview

`Material` is a surface elevation primitive. It maps a semantic `type` prop to Tailwind's
theme-derived shadow and background utilities (`shadow-sm`, `bg-card`, etc.) via `class-variance-authority`
— no hand-crafted shadow or fill values. Use it wherever you need to express visual depth: cards,
dropdowns, dialogs, or full-screen overlays.

## Installation

```tsx
import { Material } from "@nebutra/ui/primitives";
```

## Usage

### Types

`Material` has 8 canonical elevation levels plus one deprecated alias — not 4. Defined in
`packages/design/ui/src/primitives/material.tsx`:

```tsx
<Material type="base">
  <div className="p-6">Resting card content</div>
</Material>

<Material type="menu">
  <div className="py-1">Menu items</div>
</Material>

<Material type="modal">
  <div className="p-6">Dialog content</div>
</Material>

<Material type="fullscreen">
  <div className="p-6">Full-screen content</div>
</Material>
```

### Base

Default surface for resting cards. Applies `shadow-sm` and `bg-card`.

```tsx
<Material type="base" className="w-80">
  <div className="p-6">
    <h2 className="text-sm font-medium">Card title</h2>
    <p className="text-xs text-muted-foreground mt-1">Supporting text</p>
  </div>
</Material>
```

`type="card"` still works as a **deprecated** alias of `base`, kept for existing call sites. New code
should use `base`.

### Small / Medium / Large

Raised content tiers, in ascending order. `small` matches `base` (`shadow-sm`); `medium` and `large`
both apply `shadow-md` and `bg-card`.

```tsx
<Material type="medium" className="w-80">
  <div className="p-6">Raised content</div>
</Material>
```

### Tooltip / Menu

Floating popover surfaces. Both apply `shadow-md` and `bg-popover`.

```tsx
<Material type="menu" className="w-56">
  <div className="py-1">
    <button type="button" className="w-full text-left px-3 py-2 text-sm hover:bg-muted">
      Profile
    </button>
    <button type="button" className="w-full text-left px-3 py-2 text-sm hover:bg-muted">
      Settings
    </button>
  </div>
</Material>
```

### Modal

Dialog and drawer surfaces. Applies `shadow-xl` and `bg-popover`.

```tsx
<Material type="modal" className="w-96">
  <div className="p-6 flex flex-col gap-4">
    <h2 className="text-sm font-semibold">Confirm action</h2>
    <p className="text-xs text-muted-foreground">This cannot be undone.</p>
    <div className="flex justify-end gap-2">
      <Button variant="outline">Cancel</Button>
      <Button>Confirm</Button>
    </div>
  </div>
</Material>
```

### Fullscreen

Full-screen overlay surface. Applies `shadow-none` and `bg-background`.

```tsx
<Material type="fullscreen" className="fixed inset-0">
  <div className="p-8">Full-screen content</div>
</Material>
```

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `type` | `"base" \| "small" \| "medium" \| "large" \| "tooltip" \| "menu" \| "modal" \| "fullscreen" \| "card"` (`"card"` deprecated, alias of `"base"`) | `"base"` | Surface elevation level |
| `className` | `string` | — | Additional CSS classes |
| `children` | `ReactNode` | — | Surface content |
| `ref` | `Ref<HTMLDivElement>` | — | Forwarded ref |

All standard `div` HTML attributes are also supported. Don't stack two `Material`s on the same
element — if a child needs more elevation, lift it into its own `Material` with a higher `type`.

## Token Reference

`--shadow-*` and `--color-card`/`--color-popover`/`--color-background` are declared in the `@theme
inline` block of `packages/design/tokens/styles.css` (a generated file — the editable source is the
DTCG token JSON under `packages/design/design-tokens/tokens/`). `packages/design/theme/themes.css`
carries no elevation tokens; it is five generated lines aliasing `keyframes.css`.

| type | Shadow token | Background token |
|------|-------------|-----------------|
| `base` / `small` / `card` (deprecated) | `--shadow-sm` | `--color-card` |
| `medium` / `large` | `--shadow-md` | `--color-card` |
| `tooltip` / `menu` | `--shadow-md` | `--color-popover` |
| `modal` | `--shadow-xl` | `--color-popover` |
| `fullscreen` | _(none)_ | `--color-background` |

## Accessibility

- `Material` renders a plain `<div>` — add semantic roles (`role="dialog"`, `role="menu"`, etc.) at the usage site as appropriate.
- Shadow is a visual-only affordance; do not rely on it alone to convey state or hierarchy to assistive technologies.

## Design Contract

- `Material` owns surface elevation only. It does not add semantic roles, focus management, dismissal behavior, or overlay stacking.
- Consumers choose the semantic element or role that matches the surface purpose.
- Elevation must stay token-driven through the theme layer. Do not add inline shadow, background, or border values to individual usages.
- Use `Card`, `Dialog`, `Popover`, or `Menu` primitives when behavior is required; use `Material` when only the surface treatment is needed.
