## Usage

```tsx
import { Tabs } from "@nebutra/ui/primitives";
```

```tsx
const [selected, setSelected] = useState("apple");

<Tabs
  aria-label="Fruit views"
  selected={selected}
  setSelected={setSelected}
  tabs={[
    { title: "Apple", value: "apple" },
    { title: "Orange", value: "orange" },
    { title: "Mango", value: "mango" },
  ]}
/>;
```

## Props

### Tabs

Built on Base UI Tabs. Use the `tabs` array API for simple same-scope view switching, and the compound API when each tab owns a panel.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `tabs` | `readonly TabsItem[]` | — | Optional array API for rendering a tab row without hand-writing triggers. |
| `selected` | `string` | — | Controlled active tab value. Alias for `value` in the array API. |
| `setSelected` | `(value: string) => void` | — | Controlled setter for the array API. Also calls `onValueChange` when provided. |
| `value` | `string` | — | Controlled active tab value for compound usage. |
| `defaultValue` | `string` | first enabled tab | Uncontrolled initial active tab. |
| `onValueChange` | `(value: string) => void` | — | Callback when active tab changes. |
| `variant` | `"default" \| "button" \| "line" \| "secondary"` | `"default"` | Visual style for array API and nested lists. |
| `size` | `"xs" \| "sm" \| "md" \| "lg"` | `"md"` | Component-token-backed control size. |
| `shape` | `"default" \| "pill"` | `"default"` | Trigger radius treatment. |
| `activationMode` | `"manual" \| "automatic"` | `"manual"` | Manual keeps arrows on focus movement and Enter/Space on activation. |
| `disabled` | `boolean` | `false` | Disables the whole tab set. |

### TabsItem

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `title` | `ReactNode` | — | Visible tab title. Keep it Title Case and one or two words. |
| `value` | `string` | — | Unique tab value. |
| `icon` | `ReactNode` | — | Optional leading icon. Mark decorative icons `aria-hidden`. |
| `badge` | `ReactNode` | — | Optional count/status badge. Drop it at zero instead of appending counts to titles. |
| `disabled` | `boolean` | `false` | Disables only this tab. Use for permission or unavailable states. |
| `tooltip` | `ReactNode` | — | Constraint explanation for a disabled tab. |
| `content` | `ReactNode` | — | Optional panel content rendered through `TabsContent`. |

### Compound API

```tsx
import { Tabs, TabsContent, TabsList, TabsTrigger } from "@nebutra/ui/primitives";
```

| Component | Required props | Notes |
|-----------|----------------|-------|
| `TabsList` | `aria-label` when no visible heading exists | Supports `variant`, `shape`, `loop`, and `activateOnFocus`. |
| `TabsTrigger` | `value` | Supports `icon`, `badge`, and native button props. |
| `TabsContent` | `value` | Supports `keepMounted`; `forceMount` remains as a compatibility alias. |

## Best Practices

Use Tabs to switch between sibling views inside a single page: Overview, Logs, Settings. For navigation between unrelated pages, use a sub-menu or side navigation.

Keep a row to 5–7 entries on desktop and 3–4 on mobile. Past that, consolidate views or move secondary surfaces behind a Menu.

Selecting a tab should be instant. Reflect the active tab in the URL when refresh or deep-link restoration matters, but do not toast or confirm tab changes.

Disable individual tabs only for permission or empty-state constraints. Pair disabled tabs with a tooltip that explains the constraint, such as "Only visible to project owners."

Tab titles are Title Case nouns, one or two words. Do not append counts to the title; use the `badge` slot and drop the badge at zero.

## Accessibility

Tabs render WAI-ARIA tablist/tab/tabpanel semantics through Base UI.

Manual activation is the default: Left/Right moves focus, Enter/Space activates. Set `activationMode="automatic"` only when each panel is already mounted and switching is effectively free.

Give `TabsList` or array-mode `Tabs` a stable `aria-label` when there is no visible heading above it.

Keep visible focus rings. Do not suppress focus styling on the active tab.

## Design Contract

- Tabs switch same-scope sibling panels; they are not route navigation.
- Keep tab rows compact and horizontally scrollable only as a fallback.
- Use manual activation unless every panel is already cheap to render.

## Real Product Examples

- Project Overview / Logs / Settings panels.
- Billing Monthly / Yearly view switch with the same surrounding content.
- Documentation preview/code/install surfaces.

## Anti-patterns

- Do not use Tabs for primary site navigation.
- Do not place more than seven top-level tabs in a single row.
- Do not hide destructive actions inside inactive tab panels without persistent context.
