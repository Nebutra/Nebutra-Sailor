## Overview

`Feedback` is a compact feedback primitive for the end of a page, doc, or completed flow. It is not a support form, bug intake, or NPS replacement.

Submit closes the panel and returns focus to the trigger. That close is the acknowledgment; do not replace the panel with a generic thank-you toast.

## Installation

```tsx
import { Feedback } from "@nebutra/ui/primitives"
```

## Usage

### Default

Use the default popover only on desktop-width surfaces.

```tsx
<Feedback label="Feedback" dryRun />
```

### Inline

```tsx
<Feedback dryRun label="Feedback" type="inline" />
```

### With Topics

Use `showTopics` for the default triage list, or pass `topics` for a product-specific list.

```tsx
<Feedback
  dryRun
  label="Report a Bug"
  showTopics
/>
```

### With Metadata

Attach non-PII context that helps reproduce the report.

```tsx
<Feedback
  dryRun
  label="Feedback on Checkout"
  metadata={{
    buildId: "build_12345",
    location: "post-checkout",
    plan: "pro",
    viewport: "desktop",
  }}
/>
```

### Custom Copy

```tsx
<Feedback
  copy="How did the import go?"
  label="Feedback on Imports"
  type="inline"
/>
```

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `label` | `string` | — | Visible trigger/title and payload label. Use Title Case |
| `type` | `"default" \| "inline"` | `"default"` | Display mode |
| `copy` | `string` | mode-specific | Prompt next to the emotion row |
| `topics` | `Array<string \| { value: string; label: string }>` | — | Product-specific triage topics |
| `showTopics` | `boolean` | `false` | Enables the default Bug/Pricing/Documentation/Performance/Other list |
| `metadata` | `FeedbackMetadata` | — | Non-PII context attached to the payload |
| `onSubmit` | `(payload: FeedbackPayload) => void \| Promise<void>` | — | Sends feedback to your backend |
| `dryRun` | `boolean` | `false` | Skips `onSubmit` for demos |
| `disabled` | `boolean` | `false` | Disables trigger and form controls |
| `className` | `string` | — | Root class override |

## FeedbackPayload

```ts
interface FeedbackPayload {
  label: string
  emotion?: "love" | "okay" | "not-great" | "hate"
  message: string
  topic?: string
  metadata?: Record<string, string | number | boolean | null | undefined>
}
```

## Best Practices

- Place Feedback after the user has formed an opinion: page end, docs footer, or completed flow.
- Use topics only when the team triages by category. Skip them when open text is enough.
- Keep `metadata` non-PII: route, build ID, plan, viewport.
- `label` is Title Case and short: `Feedback`, `Feedback on Imports`, `Report a Bug`.
- `copy` is sentence case. Avoid `please` and apology copy.
- The textarea placeholder is fixed as `Your feedback...`.

## Accessibility

- Emotion controls are exposed as a radio group with labelled options.
- The textarea is labelled by the prompt copy and receives focus when the form opens.
- Submit closes the panel and returns focus to the trigger.
- Failed submissions keep the form open and announce the inline error with `role="alert"`.
