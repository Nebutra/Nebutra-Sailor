## Installation

```tsx
import { QuestionTool } from "@nebutra/ui/primitives";
```

Or install standalone via the shadcn registry:

```bash
npx shadcn@latest add https://ui.nebutra.com/r/question-tool.json
```

## Usage

`QuestionTool` is the composed wrapper. `QuestionPrompt` (also exported) is the atomic single-question renderer if you need to build your own chrome.

```tsx
import { QuestionTool, type QuestionConfig } from "@nebutra/ui/primitives";

const questions: QuestionConfig[] = [
  {
    kind: "single",
    title: "What's your primary role?",
    options: [
      { id: "fe", label: "Frontend" },
      { id: "be", label: "Backend" },
      { id: "design", label: "Designer" },
    ],
    allowCustom: true,
  },
];

<QuestionTool
  questions={questions}
  onSubmitAnswer={(answer, index) => {
    // forward to your AI chat pipeline
  }}
/>
```

## Question kinds

| Kind     | Behavior                                                                  |
| -------- | ------------------------------------------------------------------------- |
| `single` | Renders as `<radiogroup>` — exactly one option selected (or custom write-in) |
| `multi`  | Renders as `<group aria-multiselectable>` — N options between `min`/`max` |
| `text`   | Free-text `<textarea>` — Cmd/Ctrl+Enter submits                           |

## QuestionConfig

| Field               | Type                                  | Description                                                |
| ------------------- | ------------------------------------- | ---------------------------------------------------------- |
| `kind`              | `"single" \| "multi" \| "text"`       | **Required.**                                              |
| `title`             | `string`                              | **Required.** Renders as `<h2>` for screen readers         |
| `description`       | `string`                              | Linked via `aria-describedby` to the option group          |
| `options`           | `QuestionOption[]`                    | Required for `single` / `multi`                            |
| `allowCustom`       | `boolean`                             | Append a write-in custom answer slot (option-based only)   |
| `customLabel`       | `string`                              | Accessible label for the custom input                      |
| `customPlaceholder` | `string`                              | Placeholder for the custom input                           |
| `minSelections`     | `number`                              | `multi` only. Default: `1`                                 |
| `maxSelections`     | `number`                              | `multi` only. No cap by default                            |
| `placeholder`       | `string`                              | `text` only. Placeholder for the textarea                  |

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `questions` | `QuestionConfig[]` | — | Stable ordered question set. |
| `questionIndex` | `number` | internal state | Controlled one-based active question index. |
| `totalQuestions` | `number` | `questions.length` | Progress denominator when the server owns the full flow. |
| `onPreviousQuestion` | `() => void` | — | Called from the previous chevron in controlled flows. |
| `onNextQuestion` | `() => void` | — | Called from the next chevron in controlled flows. |
| `submitLabel` | `string` | `"Send"` | Primary submit label. |
| `nextLabel` | `string` | `"Next"` | Label for the next affordance. |
| `skipLabel` | `string` | `"Skip"` | Label for the skip action. |
| `previousLabel` | `string` | `"Previous"` | Accessible label for previous navigation. |
| `allowSkip` | `boolean` | `true` | Allows a skip answer. |
| `onSubmitAnswer` | `(answer, questionIndex) => void` | — | Emits the discriminated answer and one-based index. |
| `output` | `{ answer?: QuestionAnswer }` | — | Renders the summary state for a completed tool call. |
| `toolCallId` | `string` | — | Resets internal answers when the tool call changes. |
| `headerLabel` | `string` | `"Question"` | Chrome bar label. |
| `className` | `string` | — | Outer wrapper class. |

## QuestionAnswer (discriminated union)

```ts
type QuestionAnswer =
  | { kind: "single"; selectedIds: string[]; text?: string }
  | { kind: "multi";  selectedIds: string[]; text?: string }
  | { kind: "text";   text: string }
  | { kind: "skip" };
```

When `allowCustom` is true and the user fills in the write-in slot, the answer carries `text` alongside any `selectedIds`.

## Controlled vs uncontrolled index

By default `QuestionTool` manages the current question index internally. Pass `questionIndex` + `onPreviousQuestion` / `onNextQuestion` to lift control to the parent — useful when an LLM picks the next question server-side based on the prior answer.

```tsx
<QuestionTool
  questions={questions}
  questionIndex={currentIdx}
  onPreviousQuestion={() => setIdx((i) => i - 1)}
  onNextQuestion={() => setIdx((i) => i + 1)}
  onSubmitAnswer={(answer, idx) => persistAndAdvance(answer, idx)}
/>
```

## Keyboard

| Key                                      | Behavior                                                          |
| ---------------------------------------- | ----------------------------------------------------------------- |
| `A`–`Z`                                  | Selects the corresponding option (option-based questions only)    |
| `Cmd`/`Ctrl` + `Enter`                   | Submits a `text` question                                         |
| `Tab` / `Shift+Tab`                      | Standard focus traversal                                          |

Letter shortcuts are suppressed while an `<input>` / `<textarea>` is focused.

## Accessibility

- Wrapper is a `<section aria-label>` landmark.
- Question title is rendered as `<h2>` and linked to the option group via `aria-labelledby`.
- Options carry proper `role="radio"` / `role="checkbox"` with `aria-checked`.
- Description (when present) is linked via `aria-describedby`.
- Header chevron buttons have `aria-label`s.
- Live progress (`{n} of {total}`) is announced via `aria-live="polite"`.
- Letter badges (`A`/`B`/…) are `aria-hidden` — the role+state carries semantics.

## When to use

Drop this into AI chat surfaces where the assistant needs structured input from the user — onboarding flows, clarification questions, persona profilers, follow-up dialogs. The visual identity reads "tool call result" so users implicitly understand it's an LLM-initiated form.

Avoid for:

- Standalone forms outside chat (use `Form` + `Field` primitives instead)
- Surveys with >26 options per question (alphabet limit)
- Async/streamed question generation — the component expects a stable `questions` array

## Design Contract

- `QuestionTool` is an AI tool-call surface. It should appear inside chat or assistant timelines, not as a generic survey card.
- `QuestionAnswer` is a discriminated union and is the API boundary. Do not collapse it to loose strings in downstream code.
- Option shortcuts are affordances, not the only interaction path. Pointer, keyboard focus, and textarea submit must all work.
- Keep question generation stable for the mounted instance; use `toolCallId` when a new tool call replaces the question set.
