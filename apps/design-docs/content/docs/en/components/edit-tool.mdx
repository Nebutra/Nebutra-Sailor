## Installation

```tsx
import { EditTool } from "@nebutra/ui/primitives";
```

Or install standalone via the shadcn registry:

```bash
npx shadcn@latest add https://ui.nebutra.com/r/edit-tool.json
```

## Usage

`EditTool` is designed for chat surfaces where an AI agent reports a file-modification result. Pass `oldContent` + `newContent` (variant `"edit"`) or just `newContent` (variant `"write"`).

```tsx
import { EditTool } from "@nebutra/ui/primitives";

<EditTool
  filePath="/app/page.tsx"
  oldContent={previous}
  newContent={next}
  approval={{
    onApprove: applyEdit,
    onReject: discardEdit,
  }}
/>
```

## State machine

| State        | Render                                                  |
| ------------ | ------------------------------------------------------- |
| `waiting`    | Shimmer "Generating..." header — no body                |
| `pending`    | Shimmer "Editing X.tsx" header + full diff              |
| `completed`  | Static "Edited X.tsx" header + full diff + `+N -N` stats |

```tsx
// Typical lifecycle: parent toggles state as the AI tool call progresses.
<EditTool state="waiting" />
<EditTool state="pending" filePath="..." oldContent="..." newContent="..." />
<EditTool state="completed" filePath="..." oldContent="..." newContent="..." />
```

## Variants

| Variant  | Behavior                                                     |
| -------- | ------------------------------------------------------------ |
| `edit`   | LCS diff of `oldContent` vs `newContent` (red/green lines)   |
| `write`  | `newContent` only — every line rendered as an addition       |

## Approval footer

Pass the optional `approval` prop to render Approve/Reject buttons under the diff. Hybrid controlled+uncontrolled — works with or without parent state.

```tsx
const [decision, setDecision] = useState<ApprovalDecision>(null);

<EditTool
  state={decision === "approved" ? "pending" : "completed"}
  filePath="/app/page.tsx"
  oldContent={previous}
  newContent={next}
  approval={{
    decision,                       // controlled
    onDecisionChange: setDecision,  // controlled
    approveLabel: "Apply",
    rejectLabel: "Skip",
    onApprove: () => applyEdit(),
    onReject:  () => cancelEdit(),
  }}
/>
```

When `approval` is omitted, no footer renders.

## Props

| Prop           | Type                                            | Default      | Description                                                  |
| -------------- | ----------------------------------------------- | ------------ | ------------------------------------------------------------ |
| `state`        | `"completed" \| "pending" \| "waiting"`         | `"completed"`| Visual progression of the tool call                          |
| `variant`      | `"edit" \| "write"`                             | `"edit"`     | Diff strategy                                                |
| `filePath`     | `string`                                        | —            | Shown by basename in header (`/foo/bar.ts` → `bar.ts`)       |
| `oldContent`   | `string`                                        | —            | Required for `variant: "edit"`                               |
| `newContent`   | `string`                                        | —            | Required for both variants when a body should render         |
| `approval`     | `EditToolApproval`                              | —            | Optional approval footer config                              |
| `maxDiffLines` | `number`                                        | `2000`       | LCS cap to avoid O(m·n) OOM. Larger inputs show a placeholder |
| `className`    | `string`                                        | —            | Outer wrapper class                                          |

## Safety: LCS cap

LCS line-diff is O(m·n) memory. A 10K-line diff = 100M cells = browser OOM. `EditTool` caps at `maxDiffLines` (default 2000) on either side and renders a placeholder instead.

## Accessibility

- Wrapper is `<section aria-label>` landmark — covers both header and diff body.
- Approval status uses `<output aria-live="polite">` — screen readers announce "Starting", "Approved", "Canceled" automatically.
- Loading dots are aria-hidden (decorative).
- Diff line gutters (`+` / `-` / ` `) are aria-hidden; row background color carries the semantics (this is also why the gutter MUST stay as text characters — see the component's design invariants).
- Esc rejects a pending approval (matches industry chat-tool convention).

## Design Contract

- `EditTool` owns chat-tool rendering only; it does not apply file changes, mutate editor state, or approve agent actions by itself.
- Diff computation stays bounded by `maxDiffLines`. If a parent needs very large diffs, it must summarize upstream rather than pushing unbounded text into the primitive.
- Approval UI is optional and must stay explicit. Never infer approval from completion state.
- Loading affordances compose `TextShimmer` and `LoadingDots`, so motion and reduced-motion behavior remain governed by the shared tool-family primitives.

## Reuses

This component composes existing primitives rather than re-implementing:

- [`TextShimmer`](/en/docs/components/text-shimmer) for header shimmer
- [`LoadingDots`](/en/docs/components/loader) for approval "Starting…" animation

If you customize either of those, `EditTool` inherits the change.
