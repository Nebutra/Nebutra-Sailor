## Installation

```tsx
import { ProjectBanner } from "@nebutra/ui/primitives";
```

Or install standalone via the shadcn registry:

```bash
npx shadcn@latest add https://ui.nebutra.com/r/project-banner.json
```

## Usage

Use `ProjectBanner` for project-wide states that need resolution: overdue billing, an active rollback, attack mitigation, an expiring trial blocking deploys.

```tsx
import { ShieldCheck } from "@nebutra/icons";
import { ProjectBanner } from "@nebutra/ui/primitives";

<ProjectBanner
  variant="success"
  icon={<ShieldCheck className="h-4 w-4 shrink-0" />}
  label="Attack Challenge Mode is enabled for this project"
  callToAction={{ label: "Disable", href: "/settings/security" }}
/>;
```

## When NOT to use this

- Inline contextual message tied to a single field or card → use `Note`.
- Transient acknowledgement → use `Toast`.
- Blocking confirmation → use `Modal` / `AlertDialog`.

## Variants

| Variant     | Use for                                                                       | Live region role |
| ----------- | ----------------------------------------------------------------------------- | ---------------- |
| `success`   | Positive temporary mitigation (e.g. Attack Challenge Mode active)             | `status`         |
| `warning`   | Exceptional state with non-immediate action (e.g. active rollback)            | `status`         |
| `error`     | Critical downtime or payment-blocking state                                   | `alert`          |
| `info`      | Routine project-wide notice (e.g. trial expiry)                               | `status`         |

The `role` prop overrides the default — pass `role="alert"` if you need a polite variant to interrupt screen readers, or `role="status"` to demote an error.

## Behavior

- **Non-dismissible by design.** If the message can be dismissed without resolving the state, it isn't banner-worthy. Move it to a `Note`.
- **One banner at a time.** Stacking competing banners drowns the most urgent state.
- **Always pass a `callToAction`** that resolves the state. A banner with no route is a dead end.

## CTA — link OR button, never both

`callToAction` is a discriminated union — either a link or a button, never both. The render path is decided by which field you pass.

```tsx
// Link CTA — for routes
<ProjectBanner
  variant="error"
  label="Payment failed, pay any open invoices before your account is shut down"
  callToAction={{ label: "Pay Invoices", href: "/billing/invoices" }}
/>

// Button CTA — for actions
<ProjectBanner
  variant="warning"
  label="This project was rolled back by @johnphamous"
  callToAction={{ label: "Undo Rollback", onClick: () => undoRollback() }}
/>
```

The TypeScript types prevent passing both `href` and `onClick` in the same CTA, so the bug class is unrepresentable.

## Content

- `label` is **one sentence in sentence case** that names the impact: `Your Pro trial expires in 3 days`. Don't open with "Heads up" or apologetic preambles.
- `callToAction.label` is **Title Case Verb + Noun** and points at the resolver: `Update Payment Method`, `Reactivate Project`, `Review Tokens`.
- Name the affected entity when the project context isn't obvious from the surrounding chrome: `Production deployments are paused on my-project`.
- Don't encode severity in the copy with emoji or interjections — the variant carries that signal.

## Props

| Prop           | Type                                                            | Default  | Description                                              |
| -------------- | --------------------------------------------------------------- | -------- | -------------------------------------------------------- |
| `variant`      | `"success" \| "warning" \| "error" \| "info"`                   | `"info"` | Severity mapping                                         |
| `label`        | `ReactNode`                                                     | —        | One-sentence impact statement                            |
| `icon`         | `ReactNode`                                                     | —        | Optional leading glyph (caller controls sizing)          |
| `callToAction` | `{ label, href } \| { label, onClick }`                         | —        | Resolver action — required by convention                 |
| `role`         | `"alert" \| "status"`                                           | auto     | Override the auto-picked live-region role                |
| `className`    | `string`                                                        | —        | Class on the outer `<aside>`                             |

## Accessibility

- The banner is an `<aside>` with a live-region `role` so screen readers announce it on render.
- `error` defaults to `role="alert"` (assertive). All other variants use `role="status"` (polite).
- The button CTA is a real `<button type="button">`, not a `<div onClick>` — Tab and Enter both activate.
- Icon glyphs render inside a `<span>` wrapper; the surrounding `<span>` for `label` is intentionally not `<p>`, so the label can contain inline interactive children (e.g. a `Tooltip`) without invalid HTML.

## Design Contract

- Use `ProjectBanner` for project-wide operational state with a resolver action. It is not a decorative alert or marketing callout.
- Render at most one banner in a project surface. If multiple conditions are active, resolve priority upstream and pass only the highest-impact state.
- Variant color is semantic. Do not override it with campaign, brand, or team-specific colors.
