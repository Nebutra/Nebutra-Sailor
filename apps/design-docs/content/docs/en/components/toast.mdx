## Usage

Mount the `Toaster` once at the app root, then trigger notifications through `useToasts` or the lower-level `toast` export.

```tsx
import { Toaster } from "@nebutra/ui/primitives";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        {children}
        <Toaster />
      </body>
    </html>
  );
}
```

```tsx
"use client";

import { Button, useToasts } from "@nebutra/ui/primitives";

export function SaveButton() {
  const toasts = useToasts();

  return (
    <Button onClick={() => toasts.success("Environment variable saved")}>
      Save
    </Button>
  );
}
```

## Props

### Toaster

`Toaster` extends Sonner's `ToasterProps` and applies Nebutra defaults.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `position` | Sonner `Position` | `"bottom-right"` | Keeps acknowledgements near the lower utility edge. |
| `visibleToasts` | `number` | `3` | Maximum visible stack depth. |
| `duration` | `number` | `3000` | Default auto-dismiss duration. |
| `closeButton` | `boolean` | `true` | Gives preserved or long messages an explicit exit. |
| `containerAriaLabel` | `string` | `"Notifications"` | Label for the live region container. |
| `toastOptions` | `ToastOptions` | Nebutra defaults | Overrides per-toast defaults and class names. |

### useToasts

| Method | Signature | Behavior |
| --- | --- | --- |
| `message` | `(message: ToastMessage) => ToastId` | Neutral acknowledgement with optional action or undo. |
| `success` | `(text, options?) => ToastId` | Completed user action. |
| `warning` | `(text, options?) => ToastId` | Partial completion or recoverable issue. |
| `error` | `(text, options?) => ToastId` | Transient action failure with recovery copy. |
| `dismiss` | `(id?) => ToastId` | Dismiss one toast or all toasts. |

## Examples

### Default

```tsx
toasts.message({
  text: "Deployment canceled",
});
```

### Preserve

```tsx
toasts.message({
  text: "Invite link copied",
  preserve: true,
});
```

### Action

```tsx
toasts.message({
  text: "Draft published",
  action: "View",
  onAction: () => router.push("/posts/draft"),
});
```

### Undo

```tsx
toasts.message({
  text: "Project archived",
  onUndoAction: () => restoreProject(),
});
```

### Status tones

```tsx
toasts.success("Domain added");
toasts.warning("Deployment completed with skipped routes");
toasts.error("Couldn’t verify domain. Try again.");
```

## Best practices

- Use a toast for non-blocking acknowledgements of user-initiated actions: Domain added, Project archived, Deployment canceled.
- Do not use a toast alone for billing failures, permission denials, or build failures the user must triage. Pair a short toast with persistent recovery UI.
- Field-level validation belongs on the input. Persistent configuration warnings belong in Note or Banner.
- Pick the method by how the user experienced the event, not by HTTP status.
- Default toasts auto-dismiss. Use `preserve` only when the user must read or act before dismissal.
- Undo snackbars use the literal label `Undo` and stay visible longer than standard toasts.
- Completion copy follows `{Noun} {past-participle}`: Blob deleted, Domain added, Environment variable saved.
- Error copy is two sentences with a recovery step: Couldn’t verify domain. Try again.

## Accessibility

- The region is announced as `Notifications` and uses Sonner's live-region behavior.
- Neutral, success, and warning toasts are polite announcements; reserve blocking recovery UI for interruptive failures.
- Do not put primary navigation inside a toast. Transient surfaces can vanish before keyboard users reach them.
