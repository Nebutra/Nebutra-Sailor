## Installation

```tsx
import { Scroller } from "@nebutra/ui/primitives";
```

## Overview

`Scroller` is a native overflow surface for peer-item lists: chip rows, tile rails, log streams,
code snippets, and command palettes. It keeps the browser's scroll and focus behavior intact while
adding edge affordances and optional buttons that jump to direct children.

It is not a carousel and it is not a virtualization layer. Use `Carousel` when every item is a
slide. Use a virtualization library inside `Scroller` for data sets larger than a few hundred rows.

## Usage

```tsx
<Scroller height={220} overflow="y" width="100%" contentLabel="deployment events">
  <div>Queued</div>
  <div>Building</div>
  <div>Ready</div>
</Scroller>
```

## Props

| Prop | Type | Default | Description |
|---|---|---|---|
| `overflow` | `"x" \| "y" \| "both"` | `"y"` | Scroll axis. Use `both` only for genuinely two-dimensional content. |
| `width` | `number \| string` | `"100%"` | Root width. Numbers resolve to px. |
| `height` | `number \| string` | `"auto"` | Viewport height. Numbers resolve to px. |
| `withButtons` | `boolean` | `false` | Adds directional buttons that scroll to the next direct child. |
| `buttonAxis` | `"x" \| "y"` | derived | Axis used by buttons. Defaults to x for horizontal, y otherwise. |
| `childrenContainerClassName` | `string` | — | Class applied to the direct-child container. |
| `contentLabel` | `string` | `"content"` | Accessible name for the scroll region and generated button labels. |
| `previousButtonLabel` | `string` | derived | Accessible label for the previous/up/left button. |
| `nextButtonLabel` | `string` | derived | Accessible label for the next/down/right button. |
| `edgeAffordance` | `"fade" \| "none"` | `"fade"` | Visual affordance on clipped edges. |
| `scrollBehavior` | `ScrollBehavior` | `"smooth"` | Programmatic button scroll behavior. |
| `className` | `string` | — | Additional classes on the root wrapper. |

## Examples

### Vertical

```tsx
<Scroller height={220} overflow="y" width="100%" contentLabel="activity feed">
  <ActivityCard />
  <ActivityCard />
</Scroller>
```

### Horizontal with buttons

```tsx
<Scroller
  contentLabel="customer logos"
  height={180}
  overflow="x"
  width="100%"
  withButtons
  childrenContainerClassName="gap-4"
>
  {logos.map((logo) => (
    <LogoTile key={logo.id} />
  ))}
</Scroller>
```

### Free scroll

```tsx
<Scroller height={220} overflow="both" width="100%" contentLabel="log matrix">
  <pre>{wideLogOutput}</pre>
</Scroller>
```

## Best Practices

- Use `Scroller` for overflowing peer items along a single axis: chip rows, tile rails, log streams,
  code snippets, and command palettes.
- Pick vertical for stacked feeds, horizontal for chip and tile rails, and free only when content
  genuinely scrolls in two dimensions.
- For paginated or virtualized data sets larger than a few hundred items, render a virtualization
  library inside `Scroller` instead of dumping every node into the DOM.
- Auto-scroll buttons target direct children only. If items are wrapped in extra layout nodes, the
  buttons will scroll to that wrapper rather than the nested item.
- Keep item widths and gaps consistent in horizontal scrollers so button stepping feels predictable.

## Accessibility

- The scroll viewport is a named section; keep focusable children inside it in reading order.
- Button labels include the direction and `contentLabel`, for example `Scroll customer logos left`.
- Tab order follows DOM order. Place items in reading order regardless of visual scroll direction.
- Focused off-screen descendants use the browser's default scroll-into-view behavior.
