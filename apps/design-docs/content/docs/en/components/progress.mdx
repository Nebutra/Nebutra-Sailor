## Usage

```tsx
import { Progress } from "@nebutra/ui/primitives"
```

## Props

Built on Base UI progress primitive.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `value` | `number \| null` | — | Progress value from `0` to `max`. `null` for indeterminate |
| `max` | `number` | `100` | Maximum value |
| `getValueLabel` | `(value: number, max: number) => string` | — | Custom label for screen readers |
| `className` | `string` | — | Additional CSS classes |

## Accessibility

- Built on Base UI Progress — has `role="progressbar"`.
- Sets `aria-valuemin="0"`, `aria-valuemax` (default 100), and `aria-valuenow` based on `value`.
- `aria-label` or `aria-labelledby` should be added for context.
- Indeterminate state (`value={null}`) omits `aria-valuenow`.

## Design Contract

- Use `Progress` for measurable task completion. Use `LoadingDots` or `Skeleton` when completion percentage is unknown.
- Do not encode business meaning in arbitrary colors. Use `type`, threshold colors, or stage stops tied to semantic state.
- Keep animated progress subtle and avoid per-frame announcements; the primitive throttles assistive updates so busy tasks do not spam screen readers.
