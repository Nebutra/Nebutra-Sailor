## Decision Model

| Product job | Start with | Avoid |
| --- | --- | --- |
| Single-value text entry | [Input](/en/docs/components/input) | Reusing Textarea for one-line data because it looks larger. |
| Multi-line authoring | [Textarea](/en/docs/components/textarea) | Custom editable divs without native form semantics. |
| Bounded choice | [Select](/en/docs/components/select) | Command menus when the options are short and static. |
| Destructive confirmation | [Alert Dialog](/en/docs/components/alert-dialog) | Generic Dialog without an explicit risk contract. |
| Background task feedback | [Progress](/en/docs/components/progress) or [Status Dot](/en/docs/components/status-dot) | Decorative loaders when the state is known. |
| Structured data | [Table](/en/docs/components/table) or [Description](/en/docs/components/description) | Card grids that make comparison harder. |

## Governance Contract

Every primitive in this section must make the same contract visible across source, docs, Storybook, and registry:

1. Public API and type names match the behavior consumers need.
2. Focus, keyboard, disabled, error, loading, empty, and dark-mode states are documented.
3. Examples consume semantic or component tokens, not raw colors or one-off spacing.
4. Registry previews demonstrate the real state matrix instead of a decorative demo.
5. Product teams should extend existing primitives before creating adjacent components.
