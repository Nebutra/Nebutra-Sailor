## Usage

```tsx
import { ThemeProvider } from "@nebutra/tokens";
import { ThemeSwitcher } from "@nebutra/ui/primitives";

export function AppProviders({ children }: { children: React.ReactNode }) {
  return (
    <ThemeProvider attribute="class" defaultTheme="system">
      {children}
    </ThemeProvider>
  );
}

<ThemeSwitcher />;
```

Use `ThemeToggle` instead when the surface only needs a compact binary light/dark icon button.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `size` | `"small" \| "medium"` | `"medium"` | Use `small` in dense chrome and `medium` on settings surfaces. |
| `disabled` | `boolean` | `false` | Renders the control read-only for previews. Provider `forcedTheme` also disables it. |
| `name` | `string` | generated id | Native radio group name. |
| `value` | `"system" \| "light" \| "dark"` | provider theme | Compatibility controlled value for tests or transitional integrations. |
| `defaultValue` | `"system" \| "light" \| "dark"` | `"system"` | Fallback value when rendered outside `ThemeProvider`. |
| `onChange` | `(theme: ThemeSwitcherValue) => void` | — | Compatibility callback. The provider remains the source of truth. |
| `className` | `string` | — | Additional classes for the fieldset wrapper. |

## Best Practices

Use ThemeSwitcher for the canonical Light / System / Dark control. Place it once per app, usually in a footer, account menu, or settings page. Do not duplicate it across every page.

Pass `size="small"` for dense chrome such as dropdowns or footers. Use the default size on a settings page where the labels have room to breathe.

ThemeSwitcher reads from and writes to `@nebutra/tokens` `ThemeProvider`, whose API mirrors `next-themes` while avoiding the React 19 inline-script warning. Do not mirror its state into local React state in product code.

The control auto-disables when `forcedTheme` is set on the provider. Setting `disabled` manually is for read-only previews of the control itself.

Do not rebuild a theme picker with Switch or three icon buttons. ThemeSwitcher already handles icons, native radio semantics, focus rings, and System detection.

The component composes its own visible labels from the theme keys: `system`, `light`, `dark`. Leave them alone so app-level localization can happen at the provider or docs layer rather than through per-instance label drift.

## Accessibility

ThemeSwitcher renders a native `fieldset` and radio group. The visible legend is “Select a display theme:” and each option has a stable accessible name matching its theme key.

Keyboard behavior follows native radio controls: Tab enters the group, arrow keys move between options, and Space activates the focused option.

Forced or disabled states keep the selected option visible while making the radio inputs non-interactive.
