## Installation

```tsx
import { FileAttachment } from "@nebutra/ui/primitives";
```

Or install standalone via the shadcn registry:

```bash
npx shadcn@latest add https://ui.nebutra.com/r/file-attachment.json
```

## Usage

`FileAttachment` renders an uploaded or pasted file inline in a chat composer, message bubble, or attachment list.

It is **not** a member of the chat tool-family (EditTool / McpTool / etc. — those render AI output). `FileAttachment` renders *user input*.

```tsx
import { FileAttachment } from "@nebutra/ui/primitives";

<FileAttachment
  filename="quarterly-report.pdf"
  size={245_000}
  onRemove={() => removeFile(id)}
/>
```

## File-type icon resolution

The icon is picked from the filename extension (or the `isImage` flag for image MIME types). All four icons come from `@nebutra/icons` (Geist).

| Category | Extensions                                                              | Icon         |
| -------- | ----------------------------------------------------------------------- | ------------ |
| image    | (any when `isImage` is true; thumbnail used when `url` is present)      | `Image`      |
| code     | `.js .ts .jsx .tsx .py .rb .go .rs .java .kt .swift .c .cpp .h .hpp .cs .php` | `Code`  |
| data     | `.json .yaml .yml .xml .toml`                                           | `Code`       |
| text     | (anything else — including `.pdf .docx .md .txt`)                       | `File`       |

The pasted-source convention of using a "JS file" icon for JSON / YAML was a misleading carryover from icon library packs; `Code` is honest for structured text.

## Display modes

| Mode          | Render                                                                  |
| ------------- | ----------------------------------------------------------------------- |
| `chip`        | Icon-or-thumbnail + filename + size (default)                           |
| `image-only`  | Just the thumbnail — for compact image grids. Falls back to chip when `isImage` or `url` is missing |

```tsx
// Chip with PDF icon
<FileAttachment filename="report.pdf" size={245_000} />

// Chip with image thumbnail
<FileAttachment filename="hero.png" size={86_000} isImage url="/hero.png" />

// Image-only thumbnail (for grids)
<FileAttachment display="image-only" filename="hero.png" isImage url="/hero.png" />
```

## Removable

Pass `onRemove` to render a small × button that surfaces on hover, focus-within, or focus-visible. Keyboard users can Tab to focus and Enter to remove — the original 21st.dev hover-only pattern was a blocker for non-mouse input.

```tsx
<FileAttachment
  filename="hero.png"
  size={86_000}
  isImage
  url="/hero.png"
  onRemove={() => handleRemove(id)}
/>
```

## Props

| Prop        | Type                            | Default  | Description                                                  |
| ----------- | ------------------------------- | -------- | ------------------------------------------------------------ |
| `filename`  | `string`                        | required | Displayed text + used for icon resolution                    |
| `size`      | `number` (bytes)                | —        | Rendered below filename when present                         |
| `isImage`   | `boolean`                       | `false`  | Pair with `url` to show a thumbnail                          |
| `url`       | `string`                        | —        | Preview URL — required for thumbnail rendering               |
| `onRemove`  | `() => void`                    | —        | When provided, renders the keyboard-accessible × button      |
| `display`   | `"chip" \| "image-only"`        | `"chip"` | Rendering mode                                               |
| `className` | `string`                        | —        | Outer wrapper class                                          |

## Accessibility

- Remove button uses `aria-label="Remove <filename>"` for unambiguous SR readout.
- Remove button is hidden by default but reveals on hover OR `focus-visible` OR `group-focus-within` — keyboard and touch users can still trigger removal.
- Image `<img>` uses `loading="lazy"` and `alt={filename}` for a meaningful description.

## Why `<img>` and not `next/image`?

`FileAttachment` is shipped as a framework-neutral shadcn primitive. Consumers may use Vite, Remix, or plain React — `next/image` would couple this primitive to Next.js. The `<img>` element is the honest framework-neutral choice; per-file `biome-ignore` directives document the intent.
