## Overview

`Menu` is a semantic dropdown facade built on top of Nebutra `DropdownMenu`, which currently uses Base UI Menu under the hood. The public API is flat and explicit: `MenuContainer`, `MenuButton`, `Menu`, `MenuItem`, `MenuLink`, `MenuItemLocked`, and `MenuSection`.

Use `DropdownMenu` directly when you need raw building blocks like checkbox items, radio groups, or sub-menus. Use `Menu` for standard navigation and action lists.

## Usage

```tsx
import {
  Menu,
  MenuButton,
  MenuContainer,
  MenuItem,
  MenuItemLocked,
  MenuSection,
} from "@nebutra/ui/primitives";

<MenuContainer position="bottom-start">
  <MenuButton type="secondary" showChevron>
    Workspace
  </MenuButton>
  <Menu width={220}>
    <MenuSection title="General" showDivider={false}>
      <MenuItem>Overview</MenuItem>
      <MenuItem href="/settings/members">Members</MenuItem>
      <MenuItemLocked>Billing</MenuItemLocked>
    </MenuSection>
  </Menu>
</MenuContainer>
```

## Permissions & States

### Locked Items

Locked items are permission-gated — visible but non-interactive, automatically rendering a lock icon. Semantically distinct from `disabled`.

## Props

The API mirrors Nebutra `DropdownMenu` content props, but the `.Item` accepts custom rendering props.

### `MenuContainer`

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `position` | `"bottom-start" \| "bottom-end" \| "top-start" \| "top-end" \| "right-start" \| "right-end" \| "left-start" \| "left-end"` | `"bottom-start"` | Popup side and alignment relative to the trigger. |
| `children` | `ReactNode` | — | `MenuButton` plus one `Menu`. |

### `MenuButton`

Extends Nebutra `Button` interaction props, but maps Geist naming to Button variants.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `showChevron` | `boolean` | `false` | Adds a chevron after the label. |
| `type` | `"primary" \| "secondary" \| "tertiary" \| "ghost" \| "warning" \| "destructive"` | `"primary"` | Maps Geist intent to Nebutra Button variants. |
| `variant` | `"unstyled"` | — | Removes button chrome for avatar/dots triggers. |
| `size` | `"tiny" \| "small" \| "medium" \| "large"` | `"medium"` | Trigger size. |
| `shape` | `"default" \| "square" \| "circle"` | `"default"` | Trigger shape. |

### `Menu`

Extends Nebutra `DropdownMenuContent` popup props except `side` and `align`, which come from `MenuContainer.position`.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `width` | `number \| string` | — | Fixed popup width. Otherwise the menu sizes to content. |
| `className` | `string` | — | Additional popup class. |

### `Menu.Item`

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `prefix` | `ReactNode` | — | Icon/element on the left |
| `suffix` | `ReactNode` | — | Icon/element on the right (overridden by lock icon when `locked`) |
| `disabled` | `boolean` | `false` | Grays out item, removes pointer events |
| `href` | `string` | — | Renders item as `<a>` navigating to this URL |
| `onClick` | `() => void` | — | Called on item activation |
| `type` | `"default" \| "error"` | `"default"` | Use `error` for destructive actions. |
| `className` | `string` | — | Additional CSS classes |

### `MenuItemLocked`

`MenuItemLocked` is a permission-gated row. It forwards the same visual slots as `MenuItem`, forces `disabled`, and injects a lock suffix.

## Accessibility

- `Menu` inherits menu roles, roving focus, Escape handling, and typeahead behavior from `DropdownMenu`.
- Use `locked` for permission-gated actions that should remain discoverable. Use `disabled` for temporarily unavailable actions.
- `prefix` and `suffix` icons must be decorative unless they add information not already present in the label.
- Link items must still read as actions. Avoid mixing unrelated navigation and destructive commands in the same menu.

## Design Contract

- Use `Menu` for short action or navigation lists where every row has the same density and interaction model.
- Use raw `DropdownMenu` when the menu needs checkbox items, radio groups, separators, nested submenus, or custom item composition.
- Keep menus stable. If users need to scan, compare, or edit multiple fields, use a Popover, Dialog, or page-level settings surface.

## Real Product Examples

- Account menus in the dashboard header where Profile, Settings, Keyboard Shortcuts, and Log out share one row density.
- Workspace menus where billing and security entries are visible but permission-gated through `MenuItemLocked`.
- Compact row actions in tables when the action list is shorter than seven items and does not need form controls.

## Anti-patterns

- Do not document `Menu.Trigger`, `Menu.Content`, or `locked` on `MenuItem`; those are not the public API.
- Do not use `Menu` for checkbox groups, radio menus, nested submenus, or filter builders. Use `DropdownMenu` or `Popover`.
- Do not hide gated actions completely when the user needs to understand upgrade or permission boundaries.
