## Installation

```tsx
import { TodoTool, type TodoItem } from "@nebutra/ui/primitives";
```

Or install standalone via the shadcn registry:

```bash
npx shadcn@latest add https://ui.nebutra.com/r/todo-tool.json
```

## Usage

`TodoTool` renders a flat, read-only checklist inside a chat reply when the assistant invokes the **TodoWrite** tool. The status enum (`pending` / `in_progress` / `completed`) is the **literal wire format** of that tool — no translation layer needed.

```tsx
const todos: TodoItem[] = [
  { content: "Audit components", status: "completed" },
  { content: "Tighten spacing",  status: "in_progress" },
  { content: "Ship updates",     status: "pending" },
];

<TodoTool todos={todos} />
```

## Relationship to AgentPlan

`TodoTool` and `AgentPlan` are **deliberately distinct** primitives. Pick by surface:

| Primitive    | Surface                                                                  |
| ------------ | ------------------------------------------------------------------------ |
| `TodoTool`   | Chat-inline. Flat, read-only, lightweight. Status enum `in_progress`     |
| `AgentPlan`  | Dashboard / planning page. Hierarchical, interactive, motion animations. Status enum `in-progress` (hyphenated) |

The enum mismatch (`in_progress` vs `in-progress`) is intentional — `TodoTool` mirrors the Claude TodoWrite wire format verbatim; `AgentPlan` uses the legacy dashboard enum. Do **not** unify.

## State machine

| State        | Render                                                            |
| ------------ | ----------------------------------------------------------------- |
| `loading`    | Shimmer header only — "Creating to-do list…" or "Updating to-dos…" per `mode` |
| `ready`      | Renders the list. Empty array renders `null`                      |

```tsx
<TodoTool state="loading" mode="creating" />
<TodoTool state="loading" mode="updating" />
<TodoTool state="ready"   todos={todos} />
```

## The `dimmed` modifier

When the AI is mid-revision of the list, set `dimmed` so the current snapshot looks softened — the "active" in-progress item is suppressed:

```tsx
<TodoTool todos={todos} dimmed />
```

## Stable keys

Keys derive from `id` (if provided) or a deterministic `${idx}-${content[0..16]}` fallback. Status transitions on the same item do **not** change the key — React reconciles in place rather than remounting.

## Props

| Prop        | Type                          | Default      | Description                                                     |
| ----------- | ----------------------------- | ------------ | --------------------------------------------------------------- |
| `state`     | `"loading" \| "ready"`        | `"ready"`    | Loading shimmer vs. rendered list                               |
| `mode`      | `"creating" \| "updating"`    | `"updating"` | Label variant when `state="loading"`                            |
| `todos`     | `readonly TodoItem[]`         | `[]`         | Task list. Empty in `ready` state renders nothing               |
| `dimmed`    | `boolean`                     | `false`      | When true, all items render in the muted treatment              |
| `className` | `string`                      | —            | Outer wrapper class                                             |

## Accessibility

- Container is `<ol aria-label="To-dos">`.
- The in-progress item carries `aria-current="step"` — assistive tech announces "current step".
- Completed items wrap in `<s>` for both visual line-through and screen-reader semantics.
- Status icons are `aria-hidden` (decorative; status is in text + `aria-current`).

## Reuses

- [`TextShimmer`](/en/docs/components/text-shimmer) for the loading-state header.

## Design Contract

- Use `TodoTool` only for flat chat-inline TodoWrite state. Interactive planning belongs in `AgentPlan`.
- Preserve the upstream `in_progress` wire enum; do not normalize it into dashboard status strings inside this primitive.
- Empty ready-state lists render nothing so chat streams do not show decorative empty shells.
