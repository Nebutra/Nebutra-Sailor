## Usage

Use `Input` for one line of free-form text: names, domains, tokens, URLs, and scoped search. Switch to `Textarea` when content can wrap. Use `Combobox` when the value comes from a known list.

```tsx
<Input
  id="project-name"
  label="Project Name"
  placeholder="my-awesome-project"
  description="Use lowercase letters, numbers, and hyphens."
/>
```

### File

Use `type="file"` for native uploads when the browser file picker is the right interaction. The file selector button inherits the same height, border, and typography scale as the rest of `Input`; avoid styling it as a custom upload zone unless the workflow needs drag-and-drop, progress, or validation previews.

## Props

`Input` extends native `React.InputHTMLAttributes<HTMLInputElement>`, except `prefix` and `size` are owned by the component API.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | Visual density tied to component tokens. |
| `label` | `string` | - | Visible label. Requires `id` at type level. |
| `id` | `string` | - | Required when `label` is provided. |
| `description` | `string` | - | Helper text wired through `aria-describedby`. |
| `error` | `string \| boolean` | - | Marks invalid state. A string also renders an inline error. |
| `prefix` | `ReactNode` | - | Non-interactive left affix. |
| `suffix` | `ReactNode` | - | Non-interactive right affix. Hidden by clear/shortcut/loading controls. |
| `clearable` | `boolean` | `false` | Shows a clear button when the field has a value. |
| `onClear` | `() => void` | - | Fires after the field is cleared. |
| `onValueChange` | `(value: string) => void` | - | Value-first callback for controlled inputs. |
| `shortcut` | `string` | - | Visual shortcut hint. Dirty fields show `Esc`. |
| `loading` | `boolean` | `false` | Shows a spinner without removing focusability. |
| `revealable` | `boolean` | `false` | Adds a password visibility button when `type="password"`. |
| `revealLabel` | `string` | `"Show password"` | Accessible label for the hidden-password state. |
| `hideLabel` | `string` | `"Hide password"` | Accessible label for the visible-password state. |
| `clearOnEscape` | `boolean` | `type === "search"` | Clears the field on Escape when dirty. |
| `wrapperClassName` | `string` | - | Applies to the control wrapper when affixes are present. |
| `fieldClassName` | `string` | - | Applies to the label/helper/error wrapper. |

## Design Contract

- Labels are Title Case nouns: Project Name, Domain, Environment Variable Name.
- Placeholders show example values, never instructions.
- Validate on blur and pass a string to `error` when the message is ready.
- Trim leading and trailing whitespace before submit in the calling form.
- Keep the input focusable while saving; use `loading` instead of disabling unless input is impossible.
- Do not use `suffix` for buttons. Use built-in controls such as `clearable` and `revealable`, or compose a dedicated field primitive when the right side needs custom interaction.

## Accessibility

- `label` cannot compile without `id`, preserving the label association.
- `description`, string text affixes, and string errors are merged into `aria-describedby`.
- Error text renders with `role="alert"`.
- Prefix and suffix icons are decorative; hide them from assistive technology.
- Search inputs clear with Escape only while dirty, so Escape can still close an outer dialog when the field is empty.
- Password reveal exposes `aria-pressed` and restores focus to the input after toggling.

## Tokens

`Input` consumes `inputTokens` for size, radius, padding, affix offsets, control sizes, icon sizes, and focus ring width. Runtime colors use semantic tokens: `background`, `foreground`, `input`, `ring`, `muted-foreground`, and `destructive`.

## Real Product Examples

- Workspace name fields with helper text and blur validation.
- Search inputs with a prefix icon, clear button, and keyboard shortcut hint.
- Password inputs with a reveal control and server-side error text.

## Anti-patterns

- Do not use Input for multi-line content. Use Textarea.
- Do not put actionable controls in both suffix and clear/reveal slots at the same time.
- Do not validate only through color; provide `error` text linked by `aria-describedby`.
