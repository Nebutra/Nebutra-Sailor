## Decision Criteria

Use `Checkbox` when users can select zero, one, or multiple independent options. Use `Switch` for immediate on/off settings, `RadioGroup` when exactly one option must be chosen, and `Choicebox` when the option itself needs a richer card surface.

## Usage

```tsx
import { Checkbox, CheckboxGroup } from "@nebutra/ui/primitives";

<Checkbox name="notifications" defaultChecked>
  Email notifications
</Checkbox>
```

## Anatomy

`Checkbox` renders a native `<input type="checkbox">` inside a label. The visual indicator is decorative; form submission, keyboard toggling, disabled behavior, and checked state stay on the native input.

```tsx
<CheckboxGroup label="Notification channels" orientation="vertical">
  <Checkbox name="email" defaultChecked>
    Email
  </Checkbox>
  <Checkbox name="slack">Slack</Checkbox>
</CheckboxGroup>
```

## States

| State | Prop contract | Behavior |
| --- | --- | --- |
| Unchecked | `checked={false}` or uncontrolled default | Space toggles to checked. |
| Checked | `checked` / `defaultChecked` | Indicator shows the check path. |
| Indeterminate | `indeterminate` | Indicator shows the mixed mark; the control does not toggle until the parent clears `indeterminate`. |
| Disabled | `disabled` | Native input is disabled and the visual label becomes non-interactive. |
| Grouped | `CheckboxGroup label="..."` | Group receives `role="group"` and an accessible label. |

## Props

### Checkbox

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `checked` | `boolean` | — | Controlled checked state. |
| `defaultChecked` | `boolean` | `false` | Initial unchecked/checked state for uncontrolled usage. |
| `onChange` | `(checked: boolean) => void` | — | Value-first callback fired by the native input change event. |
| `disabled` | `boolean` | `false` | Disables the native input and pointer interaction. |
| `indeterminate` | `boolean` | `false` | Shows the mixed visual state. |
| `children` | `ReactNode` | — | Visible label content. |
| `id` | `string` | — | Native input id. |
| `name` | `string` | — | Native form field name. |
| `className` | `string` | — | Applied to the label wrapper. |

### CheckboxGroup

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `label` | `string` | — | Accessible group label. |
| `orientation` | `"vertical" \| "horizontal"` | `"vertical"` | Layout direction for children. |
| `children` | `ReactNode` | — | Checkbox items. |
| `className` | `string` | — | Applied to the group wrapper. |

## Accessibility

- The native checkbox input owns form state and keyboard behavior.
- Pressing `Space` toggles the input when it is not disabled.
- Text labels are associated because the input and indicator live inside the wrapping `<label>`.
- `CheckboxGroup` uses `role="group"` with `aria-label` when `label` is provided.
- Do not use `indeterminate` as a third persisted value. It communicates mixed child state controlled by the parent.

## Design Contract

- Keep the checkbox row compact: one label, optional short helper text nearby, no nested controls inside the label.
- Use neutral chrome for unchecked and brand/foreground emphasis only for checked or mixed states.
- Use disabled for unavailable options, not for permission education. If the user should understand an upgrade path, pair the row with text or a tooltip icon.

## Real Product Examples

- Billing settings where multiple invoice recipients can be selected.
- Permission forms where several independent scopes can be granted.
- Bulk-selection headers using `indeterminate` while some child rows are selected.

## Anti-patterns

- Do not document HeroUI-style props such as `isSelected`, `isDisabled`, `color`, or `radius`; this primitive does not expose them.
- Do not use `Checkbox` for mutually exclusive options. Use `RadioGroup`.
- Do not rely on placeholder text or color alone to explain the option.
