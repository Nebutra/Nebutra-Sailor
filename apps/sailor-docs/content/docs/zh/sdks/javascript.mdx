## 没有 `@nebutra/sdk` 这回事

Nebutra-Sailor 不是一个带客户端 SDK 的托管 API——`create-sailor` 把整个后端作为代码交到你自己
的仓库里。没有什么额外要安装的东西，也没有 API key 去初始化一个客户端。

你实际要导入的是脚手架自带的 `@nebutra/*` workspace 包，直接在你自己的应用代码里用：

| 包 | 用途 |
|---|---|
| `@nebutra/auth` | Better Auth 服务端实例、给内部调用用的 `signServiceToken` / `verifyServiceToken` |
| `better-auth/react`（`createAuthClient`） | 客户端会话状态——见 [React 快速开始](/zh/quickstart/react) |
| `@nebutra/permissions` / `@nebutra/permissions/react` | `Can`、`usePermission`、`requirePermission`——RBAC/ABAC |
| `@nebutra/tenant` | `getCurrentTenant`、`withRls`——租户上下文与行级安全 |
| `@nebutra/billing` | 结账、权益检查（`checkEntitlement`、`FEATURES`）、用量计量 |
| `@nebutra/db` | `getSystemDb()` / `getTenantDb(tenantId)`——Prisma 客户端 |
| `@nebutra/logger` | 结构化日志 |

```typescript
import { getTenantDb } from "@nebutra/db";
import { getCurrentTenant } from "@nebutra/tenant";
import { checkEntitlement } from "@nebutra/billing";

const tenant = getCurrentTenant();
const db = getTenantDb(tenant.tenantId);
```

## 从 monorepo 之外调用网关

如果一个独立服务需要通过 HTTP 调用你项目的 `backends/gateway` REST API，同样没有对应的客户端
库——直接调用，用共享的 `SERVICE_SECRET` 认证（见 [Node.js 快速开始](/zh/quickstart/node)），
或者转发调用方的 Better Auth 会话。网关通过 OpenAPI 在 `/docs` 和 `/openapi.json` 自我记录。
