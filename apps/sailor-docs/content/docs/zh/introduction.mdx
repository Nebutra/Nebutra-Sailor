Nebutra-Sailor 是一个自托管的 SaaS **monorepo 模板**，面向 AI 原生产品，用一条命令
（`npx create-sailor`）生成，运行在你自己的基础设施上。它把现代 B2B SaaS 需要的一切都装好了——
多租户认证、基于角色的访问控制、计费、事务性邮件、AI 网关和可观测性——空的 `.env` 也能直接
`pnpm dev` 跑起来。

没有托管的 Nebutra API，没有按客户分发的 API key，也没有 `@nebutra/sdk` 这个包：`create-sailor`
生成的代码**就是**你产品的后端。你像调用自己仓库里的任何代码一样调用它——通过它自带的
`backends/gateway` Hono REST API，或者直接从应用里导入 `@nebutra/*` 包。

不要把前 6 个月浪费在构建基础设施上。从第一天起就专注于真正重要的事：你的产品。

## Nebutra 开箱即用的功能

<AccordionGroup>
  <Accordion title="多租户认证" icon="shield-check">
    **Better Auth**——唯一的认证服务商，含组织成员角色。生产使用独立登录中心 `auth.nebutra.com`，并在 `.nebutra.com` 上共享会话 Cookie。包含组织创建、成员邀请与会话管理。
  </Accordion>
  <Accordion title="基于角色的访问控制（RBAC）" icon="lock">
    4 个内置角色（`OWNER`、`ADMIN`、`MEMBER`、`VIEWER`）覆盖 17 个类型化权限范围。无需修改业务逻辑即可扩展权限矩阵。CASL 在进程内实现毫秒级检查。
  </Accordion>
  <Accordion title="计费与订阅" icon="credit-card">
    Creem 驱动的卡支付（面向全球，记录商户模式）加上面向中国大陆的微信支付/支付宝，预置 FREE、PRO 和 ENTERPRISE 三个套餐。通过 ClickHouse 聚合实现基于消耗的计量。在 API 网关层强制执行使用配额——无需修改应用代码。
  </Accordion>
  <Accordion title="AI 网关" icon="brain">
    `backends/gateway` 的 `/api/v1/ai` 路由代理你选择的模型提供商——经过认证、限流，并按租户范围隔离。用 `nebutra ai provider` / `nebutra ai gateway` 治理。
  </Accordion>
  <Accordion title="事务性邮件" icon="envelope">
    基于 Resend 的邮件系统，附带欢迎邮件、API 密钥创建、配额预警和团队邀请等开箱即用模板。可在几分钟内自定义的 React Email 组件。
  </Accordion>
  <Accordion title="可观测性" icon="chart-bar">
    30 天漏斗和收入图表。含租户上下文的 Sentry 错误追踪。通过 `@nebutra/logger` 结构化日志记录。
  </Accordion>
</AccordionGroup>

## 平台架构

Nebutra-Sailor 是一个 [Turborepo](https://turbo.build) monorepo。`backends/gateway`——唯一的业务
API，见 [ADR 2026-09-24](https://github.com/nebutra/nebutra-sailor/blob/main/docs/architecture/2026-09-24-sailor-convergence.md)——基于 [Hono](https://hono.dev) 和
OpenAPI 构建，默认挂载在 `apps/web` 内的 `app/api/[[...route]]`（`GATEWAY_MODE=embedded`），也可
独立运行（`GATEWAY_MODE=external`）。前端应用使用 Next.js 16 和 Tailwind v4。

默认脚手架包含：

| 应用 | 描述 |
|-----|------|
| `web` | 已认证的仪表板（Next.js 16），网关挂载在 `/api/[[...route]]` |
| `landing` | 公开营销站 |
| `auth` | Better Auth 登录中心 |
| `mail-preview` | 事务性邮件模板的本地预览服务 |
| `backends/gateway` | Hono REST API——业务端点唯一应该存在的地方 |
| `sailor-docs` | 本文档站（Fumadocs） |

Nebutra 自己的实例还额外跑着 `studio`（Sanity CMS）和 `storybook`（组件库 playground）——
默认脚手架不包含这两个。
