## 概览

Nebutra-Sailor 以**三个独立 Vercel 项目**的形式部署 — 每个公开面向的应用各一个。这为每个应用提供了独立的部署生命周期、环境变量、自定义域名和构建日志。

| Vercel 项目 | 应用 | 推荐域名 |
|------------|------|---------|
| `nebutra-web` | `apps/web` | `app.yourdomain.com` |
| `nebutra-landing` | `apps/landing-page` | `yourdomain.com` |
| `nebutra-api` | `backends/gateway` | `api.yourdomain.com` |

## 前置条件

- 一个 [Vercel 账号](https://vercel.com)
- 已安装 Vercel CLI：`npm install -g vercel`
- Vercel CLI 已认证：`vercel login`

## 分步指南：首次部署

<Steps>
  <Step title="安装 Vercel CLI">
    ```bash
    npm install -g vercel
    vercel login
    ```
  </Step>
  <Step title="将每个应用链接到 Vercel 项目">
    在每个应用目录中运行 `vercel link`。这会创建一个 `.vercel/project.json` 文件，将本地目录映射到 Vercel 项目。

    ```bash
    cd apps/web
    vercel link

    cd ../landing-page
    vercel link

    cd ../api-gateway
    vercel link
    ```
  </Step>
  <Step title="配置环境变量">
    为每个项目设置所有必填环境变量。可以在 Vercel 控制台或通过 CLI 完成：

    ```bash
    # 示例：为 web 应用设置密钥
    vercel env add CLERK_SECRET_KEY production --scope=nebutra-web
    ```

    对[环境变量参考](/zh/development/local-dev#环境变量)中列出的每个变量重复此操作。至少需要为 `production` 环境设置变量。
  </Step>
  <Step title="执行数据库迁移">
    首次部署前，对生产数据库执行迁移：

    ```bash
    DATABASE_URL=<your-production-db-url> pnpm db:migrate
    ```

    <Warning>
      务必在部署新版本应用**之前**执行迁移，而非之后。如果 Schema 过期，应用将无法启动。
    </Warning>
  </Step>
  <Step title="部署到生产环境">
    <Tabs>
      <Tab title="CLI">
        ```bash
        cd apps/web && vercel --prod
        cd ../landing-page && vercel --prod
        cd ../api-gateway && vercel --prod
        ```
      </Tab>
      <Tab title="GitHub（推荐）">
        将每个 Vercel 项目连接到 GitHub 仓库。Vercel 将在每次推送到 `main` 时自动部署。请参阅下方的 [GitHub 集成](#github-集成)。
      </Tab>
    </Tabs>
  </Step>
</Steps>

## `vercel.json` 配置

每个应用都包含一个 `vercel.json`，用于配置构建命令、输出目录和请求头。请勿删除这些文件。

`backends/gateway/vercel.json` 中的关键配置：

```json
{
  "buildCommand": "pnpm turbo run build --filter=backends/gateway",
  "outputDirectory": "dist",
  "functions": {
    "src/index.ts": {
      "maxDuration": 30
    }
  }
}
```

<Note>
  定时任务也在 `vercel.json` 中定义。如需配置定时函数，请查看每个应用中的该文件。
</Note>

## Turborepo 远程缓存

启用 Vercel Remote Cache，在本地机器、CI 和 Vercel 部署之间共享构建产物。对于未更改的包，这可以将构建时间缩短 50–90%。

<Steps>
  <Step title="使用 Vercel 认证 Turbo CLI">
    ```bash
    npx turbo login
    ```
  </Step>
  <Step title="将仓库链接到您的 Vercel 团队">
    ```bash
    npx turbo link
    ```
  </Step>
  <Step title="在 CI 中启用远程缓存">
    将 Vercel 团队的 `TURBO_TOKEN` 和 `TURBO_TEAM` 添加为 GitHub Actions 密钥，然后添加到您的工作流：
    ```yaml
    env:
      TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}
      TURBO_TEAM: ${{ secrets.TURBO_TEAM }}
    ```
  </Step>
</Steps>

## GitHub 集成

推荐的工作流是通过 Vercel 控制台将每个 Vercel 项目连接到 GitHub 仓库。连接后：

- **推送到 `main`** → 自动生产部署
- **创建 Pull Request** → 自动预览部署，生成唯一 URL
- **预览 URL** 作为 GitHub PR 评论发布，方便审查

`.github/workflows/deploy.yml` GitHub Actions 工作流还会在触发每次 Vercel 部署前运行 `pnpm db:migrate`，确保迁移始终在应用发布前完成。

## 预览部署

每个 PR 都会自动获得一个预览部署。预览环境使用 Vercel 中的 `preview` 环境变量范围 — 如果您希望预览指向测试数据库，请在那里设置单独的值。

<Tip>
  使用 Vercel 的[预览 URL 分享](https://vercel.com/docs/deployments/preview-deployments)功能，在合并前与团队分享实时预览。
</Tip>

## 自定义域名

<Steps>
  <Step title="在 Vercel 控制台添加域名">
    进入您的项目 → **设置 → 域名** → 添加您的自定义域名。
  </Step>
  <Step title="配置 DNS">
    添加指向 `cname.vercel-dns.com` 的 `CNAME` 记录，或为顶级域名添加指向 `76.76.21.21` 的 `A` 记录。
  </Step>
  <Step title="等待 SSL 证书配置">
    Vercel 自动配置 Let's Encrypt TLS 证书。通常在 2 分钟内完成。
  </Step>
</Steps>
