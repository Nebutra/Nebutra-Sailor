## 生成了什么

`create-sailor` 只为 Docker 写了两样东西：

| 文件 | 构建 | 用途 |
|------|------|------|
| `Dockerfile.web`（仓库根目录） | `apps/web`（Next `output: "standalone"`，网关进程内挂载） | 默认部署单元——一个镜像，一个进程 |
| `docker-compose.yml`（仓库根目录） | `web` + 本地 `postgres` + `redis` | 一条命令跑起本地或单机栈 |

如果你把网关独立跑（`GATEWAY_MODE=external`），`backends/gateway/Dockerfile` 会单独构建那个
镜像——它没有接进生成的 `docker-compose.yml`，后者假定的是内嵌的默认模式。

```yaml docker-compose.yml
services:
  web:
    build:
      context: .
      dockerfile: Dockerfile.web
    ports: ["3000:3000"]
    environment:
      - DATABASE_URL=postgresql://postgres:postgres@db:5432/nebutra
      - REDIS_URL=redis://redis:6379
    depends_on: [db, redis]

  db:
    image: postgres:15-alpine
    environment:
      - POSTGRES_USER=postgres
      - POSTGRES_PASSWORD=postgres
      - POSTGRES_DB=nebutra
    ports: ["5432:5432"]
    volumes: [pgdata:/var/lib/postgresql/data]

  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]
    volumes: [redisdata:/data]

volumes:
  pgdata:
  redisdata:
```

## 步骤

<Steps>
  <Step title="填好生产环境的密钥">
    把 `.env.example` 复制成 `.env.production`（或者按你的主机注入环境变量的方式），填入真实值
    ——见[环境变量](/zh/configuration/environment-variables)。
  </Step>
  <Step title="构建">
    ```bash
    docker compose build
    # 或者，单独构建：
    docker build -f Dockerfile.web -t my-app-web .
    ```
    构建上下文是仓库根目录，这样 Turborepo 才能访问共享的 `packages/`。
  </Step>
  <Step title="先启动数据库">
    ```bash
    docker compose up -d db redis
    ```
  </Step>
  <Step title="应用数据库，再启动应用">
    ```bash
    pnpm db:deploy    # 迁移 + platform.sql + 生成式 RLS，并校验
    docker compose up -d
    ```
    `pnpm db:deploy` 需要 `DATABASE_URL` 指向正在运行的 `db` 容器——可以在宿主机上跑，或者用
    `docker compose run --rm web pnpm --filter @nebutra/db db:deploy` 在容器网络内跑。
  </Step>
  <Step title="校验">
    ```bash
    docker compose ps
    docker compose logs web
    curl http://localhost:3000/api/misc/health
    ```
  </Step>
</Steps>

## web 的 Dockerfile

多阶段构建，最终产出一个 standalone 的 Next 服务：

```dockerfile Dockerfile.web
FROM node:22-alpine AS deps
# ... pnpm install --frozen-lockfile

FROM node:22-alpine AS builder
# ... pnpm run build

FROM node:22-alpine AS runner
ENV NODE_ENV production
COPY --from=builder /app/apps/web/.next/standalone ./
COPY --from=builder /app/apps/web/.next/static ./apps/web/.next/static
COPY --from=builder /app/apps/web/public ./apps/web/public
USER nextjs
EXPOSE 3000
CMD ["node", "apps/web/server.js"]
```

`.next/standalone/` 是自包含的——运行时不需要 `node_modules`。网关默认（`GATEWAY_MODE=embedded`）
就打包在这同一个镜像里，所以通常情况下 API 不需要额外构建或运行任何东西。

## 健康检查

网关自带一个真实的健康检查端点（同时挂载在 `/misc/health` 和 `/api/misc/health`）：

```
GET /api/misc/health
```

```json
{
  "status": "healthy",
  "version": "0.1.0",
  "uptime": 1234.5,
  "timestamp": "2026-09-29T00:00:00.000Z",
  "dependencies": {
    "database": { "status": "up", "latencyMs": 4 },
    "cache": { "status": "up", "latencyMs": 1 }
  }
}
```

`healthy` / `degraded` 返回 `200`，`unhealthy` 返回 `503`。把负载均衡器或容器编排系统的健康检查
指向这个路径。

## 反向代理

如果你自己在容器前面挂反向代理（nginx、Caddy 等），一个上游就够了——网关默认是同一个进程的
一部分：

```
yourdomain.com {
  reverse_proxy web:3000
}
```

只有切到 `GATEWAY_MODE=external`、把 `backends/gateway` 的镜像单独跑起来时，才需要第二个上游。

## 更新一个正在运行的部署

```bash
git pull origin main
docker compose build web
pnpm db:deploy
docker compose up -d --no-deps web
```

`--no-deps` 避免在只重建 web 时把 `db`/`redis` 也重启。
