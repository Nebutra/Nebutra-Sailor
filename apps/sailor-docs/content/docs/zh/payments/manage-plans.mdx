计划管理已经不再围绕单一的 `packages/commerce/billing/src/plans.ts` 文件。
当前 billing 包会把计划行为拆分到：

- `packages/commerce/billing/src/config/`
- `packages/commerce/billing/src/entitlements/`
- `packages/commerce/billing/src/usage/`
- `packages/commerce/billing/src/checkout/` 下的 provider checkout 模块

## 计划变更会影响什么

一次 plan 变更通常会同时影响：

- checkout price mapping
- feature entitlements
- usage limits / overage 行为
- web app 里的升级文案与账单页面

因此应把 plan 工作视作 billing package 级别的改动，而不是只改一个常量文件。

## 推荐工作流

1. 在 `packages/commerce/billing/src/config/` 更新计划配置源。
2. 在 `packages/commerce/billing/src/entitlements/` 审查权益映射。
3. 在 `packages/commerce/billing/src/usage/` 审查 usage / metering 行为。
4. 在 `packages/commerce/billing/src/checkout/` 检查 provider-specific checkout 假设。
5. 检查 `apps/web/src/app/[locale]/(app)/billing/` 下的用户可见账单页面。

## 添加新层级时

如果新增 `teams`、`growth` 这类 tier，至少要同时检查：

- checkout provider 的 price mapping
- feature entitlements
- usage limits
- web app 中的 upgrade 文案
- 下游 analytics / provisioning 假设

## 验证清单

- `pnpm --filter @nebutra/billing test`
- `pnpm --filter @nebutra/billing typecheck`
- 检查 `backends/gateway/src/routes/billing/` 下的 gateway billing route
- 检查 `apps/web/src/components/billing/` 下的 billing UI
