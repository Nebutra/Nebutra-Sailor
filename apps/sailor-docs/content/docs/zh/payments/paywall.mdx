## 概览

Nebutra 使用**按计划划分的功能权益**（`packages/commerce/billing/src/entitlements/`）来做访问控制，而不是一个独立的“计划对比”辅助函数：

| 机制 | 适用场景 |
|------|---------|
| `requireFeature(feature, quantity?)` | 服务端：API 网关中间件（Hono） |
| `checkEntitlement` / `requireEntitlement` | 服务端：其余任何位置（Server Components、Server Actions、后台任务） |
| `isPlanFeature(plan, feature)` | 纯静态查表（对 `PLAN_FEATURES`），不产生数据库往返 |

三者最终都会核对租户的计划（`FREE < PRO < ENTERPRISE`）及其 `PLAN_FEATURES` 条目；若该功能同时挂有用量额度，还会通过 `requireEntitlementUsage` 一并核对（网关中间件里的 `FEATURE_METER_MAP` 把 `ai.chat` / `ai.embeddings` / `ai.images` / `ai.reasoning` 映射到 `ai_tokens` 额度，`api.access` 映射到 `api_calls`）。

## API 路由门控

使用 `requireFeature` 作为中间件保护网关路由：

```typescript backends/gateway/src/middlewares/entitlements.ts
import { requireFeature } from "@nebutra/billing"; // 经网关中间件重新导出

app.post("/api/v1/ai/generate", requireFeature("ai.images", 1), async (c) => {
  // ... 处理请求
});
```

计划不满足或用量额度耗尽时返回结构化错误（`ENTITLEMENT_DENIED` 或 `USAGE_LIMIT_EXCEEDED`），由网关的错误处理器转换为 `403`/`429` JSON 响应。

## 网关之外的服务端检查

在 Hono 中间件链之外的地方，直接调用 `checkEntitlement` / `requireEntitlement`：

```typescript apps/web/src/app/dashboard/analytics/page.tsx
import { requireEntitlement, checkEntitlement } from "@nebutra/billing";
import { getCurrentTenant } from "@nebutra/tenant";
import { redirect } from "next/navigation";

export default async function AnalyticsPage() {
  const tenant = getCurrentTenant();

  const result = await checkEntitlement(tenant.tenantId, "ai.chat");
  if (!result.allowed) {
    redirect("/billing/upgrade");
  }

  return <AnalyticsDashboard />;
}
```

## 客户端 UI 门控

`@nebutra/billing` 并没有提供 `<PlanGate>` React 组件。请在服务端获取权益检查结果（一个 Server Component，或调用 `checkEntitlement` 的路由），再将纯布尔值 prop 传给下层组件——这与任何其他由服务端派生的鉴权状态的规则一样：真正需要拒绝的场景永远不能只依赖纯客户端检查。

```typescript
const { allowed } = await checkEntitlement(tenant.tenantId, "ai.chat");

return allowed ? <AdvancedAnalytics /> : <UpgradeBanner feature="高级分析" />;
```

## 升级重定向目标

`/billing/upgrade` 路由会创建订阅结账会话并重定向用户。该路由已内置，仅需配置环境变量，无需额外设置。计划订阅目前仍运行在 Stripe 上（历史遗留，根据 [ADR 2026-09-26](https://github.com/Nebutra/Nebutra-Sailor/blob/main/docs/architecture/2026-09-26-creem-global-payments.md)）——这与 Creem 是两回事，Creem 负责一次性卡支付购买（面向全球，记录商户模式），中国大陆则由微信支付/支付宝负责。完整的服务商组合参见[账单概览](/zh/payments/overview)。

如需自定义升级页面（例如在重定向前展示计划对比表），请编辑：

```
apps/web/src/app/billing/upgrade/page.tsx
```

## 升级提示与硬拦截的选择

参考以下原则选择软提示或硬拦截：

| 场景 | 建议 |
|------|------|
| 功能可被发现但需付费解锁（如导出按钮） | 软提示 — `checkEntitlement` 拒绝时渲染升级 CTA |
| 路由仅对付费计划有意义（如 SSO 设置） | 在 Server Component 中通过 `requireEntitlement` 硬重定向 |
| 敏感数据绝对不能被 FREE 用户访问 | 同时在 Server Component **和** 网关路由（`requireFeature`）上硬拦截 |
| 功能预览 / 预告 | 渲染禁用/锁定版本，仍需服务端校验 |

<Warning>
切勿仅依赖客户端的计划检查。务必在服务端使用 `requireEntitlement`（其他场景）或 `requireFeature`（网关路由）执行访问控制。有经验的用户可以绕过任何客户端守卫。
</Warning>
