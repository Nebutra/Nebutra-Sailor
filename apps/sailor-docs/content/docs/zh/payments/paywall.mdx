description: 使用当前 tenant context、billing state 与 entitlements 限制敏感功能访问。
---

旧文档里的 `requirePlan()` / `PlanGate` 示例已经不再匹配当前 app surface。
今天的 Nebutra-Sailor 主要通过以下组合实现付费墙：

- `apps/web/src/lib/auth.ts` 提供的服务端 tenant context
- `@nebutra/billing` 提供的 billing / entitlement 检查
- `backends/gateway/src/routes/billing/` 或调用它的产品 route 上的服务端强制执行

## app 页面中的 UI 门控

在服务端渲染页面中，先从共享 tenant context 开始：

```typescript
import { getTenantContext, requireAuth } from "@/lib/auth";

export default async function BillingAwarePage() {
  await requireAuth();
  const { tenantId, plan } = await getTenantContext();

  if (!tenantId || plan === "FREE") {
    return <UpgradePrompt />;
  }

  return <AdvancedFeature />;
}
```

UI 门控应该贴近页面，但它只是第一层保护。

## API 与后端强制执行

敏感功能必须在服务端再次检查：

```typescript
import { checkEntitlement } from "@nebutra/billing";

const result = checkEntitlement("org_123", "ai.chat");

if (!result.allowed) {
  throw new Error("当前计划不可用此功能。");
}
```

在 gateway 中，也要在真正执行受保护操作前做同类检查。

## 当前 billing UI 所在位置

```text
apps/web/src/app/[locale]/(app)/billing/
apps/web/src/components/billing/
```

如果需要升级提示，请从这里已有的 billing surface 出发，而不是继续沿用旧文档中
过时的 `/billing/upgrade` 例子。

## 推荐经验法则

- 仅做 UI 可发现性：页面级提示或禁用态
- 会触发 mutation / export / usage 消耗：服务端再次强制执行
- 涉及跨租户或财务副作用：在 gateway 统一强制执行并记录审计/账单后果
