## 服务商

根据 [ADR 2026-09-26](https://github.com/Nebutra/Nebutra-Sailor/blob/main/docs/architecture/2026-09-26-creem-global-payments.md)，支付服务商组合为：

- **Creem** —— 全球卡支付，记录商户模式（自行代收代缴销售税/增值税）。这是当前一次性卡支付结账的通道。参见 [Creem 集成](/zh/integrations/creem)。
- **微信支付 / 支付宝** —— 面向中国大陆。

**订阅目前仍运行在 Stripe 上**（历史遗留）——即下文描述的计划同步架构。Stripe 已不再承接新工作；不会在其上构建任何新功能。订阅迁移时，将变为通过同一套支付订单与履约机制运作的 Creem 订阅（`subscription.*` 事件）。仍依赖 Stripe 的部分参见 [Stripe 集成](/zh/integrations/stripe)。

## 架构（订阅，Stripe——历史遗留）

Nebutra 的订阅账单流水线由三层协同工作，根据计划控制访问权限并实时执行使用配额。

```
用户
 └─▶ Stripe 结账
       └─▶ Stripe 发送 webhook
             └─▶ /api/webhooks/stripe
                   └─▶ 数据库计划更新（租户记录）
                         └─▶ @nebutra/metering 执行配额限制
```

所有账单集成代码（Creem、Stripe、微信支付/支付宝）都位于 `packages/commerce/billing/`。应用代码调用 `@nebutra/billing` 中的辅助函数——不直接使用任何服务商的 SDK。

## 计划同步原理（订阅，Stripe——历史遗留）

<Steps>
  <Step title="用户完成 Stripe 结账">
    用户被重定向至 Stripe 托管的结账页面。支付成功后，Stripe 触发 `checkout.session.completed` 事件。
  </Step>
  <Step title="接收并验证 Webhook">
    API 网关端点 `POST /api/webhooks/stripe` 接收事件，使用 `STRIPE_WEBHOOK_SECRET` 验证签名，并将事件路由到 `@nebutra/billing` 中对应的处理程序。
  </Step>
  <Step title="租户计划记录更新">
    处理程序更新数据库中租户的 `plan` 和 `planExpiresAt` 字段，使 Stripe 订阅状态与本地保持同步。
  </Step>
  <Step title="配额执行生效">
    此后每次 API 请求时，`@nebutra/metering` 从数据库读取租户当前计划的限额，并与 ClickHouse 中累积的用量进行比较。超出配额的请求将收到 `429 Too Many Requests` 响应。
  </Step>
</Steps>

## 一次性卡支付结账原理（Creem——当前）

<Steps>
  <Step title="用户发起 Creem 结账">
    一次性卡支付购买（例如积分、附加包）会打开共享的 Creem 产品，并将 `custom_price` 设为该报价的价格。订单 id 作为 `request_id` 随结账一起传递。
  </Step>
  <Step title="接收并验证 Webhook">
    `POST /api/webhooks/creem` 验证 `creem-signature` 请求头（对原始请求体做 HMAC-SHA256，密钥为 `CREEM_WEBHOOK_SECRET`），并查找 `checkout.completed` 事件。
  </Step>
  <Step title="结算支付订单">
    将订单的税前金额（Creem 作为记录商户在其上另加税费）与锁定的报价价格进行比对，然后结算该笔支付订单。
  </Step>
  <Step title="对账丢失的 Webhook">
    对账任务可以直接用 `GET /v1/checkouts?checkout_id=…` 查询一笔待处理的结账，因此丢失的 Webhook 只损失几分钟，而不会损失一笔订单。
  </Step>
</Steps>

## 服务商配置位置

| 位置 | 用途 |
|------|------|
| `packages/commerce/billing/src/creem/index.ts` | Creem 客户端——结账、对账、退款、Webhook 签名 |
| `packages/commerce/billing/src/stripe/` | Stripe 客户端、客户、结账/账单门户会话（历史遗留——订阅） |
| `packages/commerce/billing/src/config/plan-config.ts` | 数据库驱动的计划配置（`PlanConfig`、限额、功能） |
| `packages/commerce/billing/src/entitlements/` | 按计划划分的功能权益（`FEATURES`、`PLAN_FEATURES`、`checkEntitlement`） |
| `backends/gateway/src/routes/webhooks/stripe.ts` | Stripe Webhook 处理程序（内联 Hono 路由，不是可复用的导出函数） |
| `backends/gateway/src/routes/webhooks/creem.ts` | Creem Webhook 处理程序 |
| `packages/commerce/billing/src/checkout/` | 结账会话创建辅助函数（Stripe、Creem、ChinaPay、manual） |
| `packages/commerce/billing/src/orders/` | 支付订单——offer → order → fulfillment（ADR 2026-09-25） |

## 环境变量

在 `.env` 文件（或部署平台的密钥管理器）中设置以下变量：

```bash
# Creem — 当前的卡支付通道（记录商户模式）
CREEM_API_KEY=creem_xxxxxxxxxxxxxxxxxxxx
CREEM_PRODUCT_ID=prod_xxxxxxxxxxxxxxxxxxxx
CREEM_WEBHOOK_SECRET=whsec_xxxxxxxxxxxxxxxxxxxx
CREEM_TEST_MODE=true   # 指向 test-api.creem.io

# Stripe（历史遗留）— 开发环境使用 sk_test_，生产环境使用 sk_live_。
# 仅供订阅、计费门户和切换前的历史结账使用。
STRIPE_SECRET_KEY=sk_live_xxxxxxxxxxxxxxxxxxxx

# Webhook 签名密钥 — 从 Stripe Dashboard 或 Stripe CLI 获取
STRIPE_WEBHOOK_SECRET=whsec_xxxxxxxxxxxxxxxxxxxx

# 前端可公开使用的发布密钥
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_live_xxxxxxxxxxxxxxxxxxxx

# 各付费计划的价格 ID（从 Stripe Dashboard → Products → Prices 获取）
STRIPE_PRICE_ID_PRO_MONTHLY=price_xxxxxxxxxxxxxxxxxxxx
STRIPE_PRICE_ID_ENTERPRISE_MONTHLY=price_xxxxxxxxxxxxxxxxxxxx
```

<Warning>
切勿将真实的 Creem 或 Stripe 密钥提交到源代码仓库。本地开发请使用 `.env.local`，生产部署请通过 CI/CD 环境注入密钥。
</Warning>

## Stripe Dashboard 配置（历史遗留——订阅）

<Steps>
  <Step title="创建 Stripe 账户">
    在 [stripe.com](https://stripe.com) 注册并激活账户。
  </Step>
  <Step title="创建产品和价格">
    进入 **Stripe Dashboard → Products → Add product**。分别为 PRO（$49/月循环计费）和 ENTERPRISE（自定义）创建产品，并将价格 ID 填入环境变量。
  </Step>
  <Step title="注册 Webhook 端点">
    进入 **Developers → Webhooks → Add endpoint**，将 URL 设为 `https://api.yourdomain.com/api/webhooks/stripe`，并选择 [Webhooks](/zh/payments/webhooks) 页面中列出的事件。
  </Step>
  <Step title="复制 Webhook 签名密钥">
    创建端点后，展开并复制 **Signing secret**（`whsec_...`），填入 `STRIPE_WEBHOOK_SECRET`。
  </Step>
</Steps>

<Tip>
本地开发时，使用 [Stripe CLI](https://stripe.com/docs/stripe-cli) 将实时事件转发到本地服务器，无需配置公开端点。
</Tip>
