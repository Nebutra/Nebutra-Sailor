Nebutra-Sailor 的计费系统已经不再是“单 Stripe + 单文件配置”的模式。当前
`@nebutra/billing` 是一个 **面向多 provider 的 billing core**。

## 当前架构

```text
apps/web billing surfaces
  └─▶ typed gateway calls
        └─▶ backends/gateway/src/routes/billing/*
              ├─▶ @nebutra/billing/checkout
              ├─▶ @nebutra/billing/subscriptions
              ├─▶ @nebutra/billing/credits
              ├─▶ @nebutra/billing/entitlements
              └─▶ @nebutra/billing/usage
```

Webhook handler 则位于：

```text
backends/gateway/src/routes/webhooks/stripe.ts
```

## 当前包布局

当前 billing 包按职责拆分：

| 模块 | 当前位置 |
| --- | --- |
| provider checkout orchestration | `packages/commerce/billing/src/checkout/` |
| Stripe provider helpers | `packages/commerce/billing/src/stripe/` |
| 订阅 | `packages/commerce/billing/src/subscriptions/` |
| Credits | `packages/commerce/billing/src/credits/` |
| Usage / metering | `packages/commerce/billing/src/usage/` |
| Entitlements | `packages/commerce/billing/src/entitlements/` |
| Plan configuration | `packages/commerce/billing/src/config/` |

旧文档里指向 `src/plans.ts`、`src/handlers/`、`src/portal.ts` 或单体
`src/checkout.ts` 的描述已经过时。

## Provider

当前代码库中可以看到这些 provider 模块：

- Stripe
- Polar
- LemonSqueezy
- ChinaPay
- manual / credit purchase flow

实际启用哪个 provider，取决于运行时配置以及调用 checkout abstraction
的 gateway route。

## Web 应用 surface

已认证应用已经提供账单页面：

```text
apps/web/src/app/[locale]/(app)/billing/
apps/web/src/components/billing/
```

在修改“套餐、权益、升级流程”等文案前，应先以这些产品 surface 为事实来源。

## Entitlements 与 usage

`@nebutra/billing` 不只是 checkout：

- feature entitlements
- credits
- usage metering
- overage calculation

这意味着 plan 变更会同时影响 UI gating、API limit 与后台 usage 记账，而不
只是 subscription 状态。

## 配置建议

当前 billing 配置横跨以下维度：

- provider credentials
- checkout readiness
- plan / limit configuration
- webhook secrets

因此不要再假设只有一对固定的 `STRIPE_*_PRICE_ID` 变量就能描述整个账单系统。
应结合包入口与部署环境一起查看。
