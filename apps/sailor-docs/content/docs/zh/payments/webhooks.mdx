## 两个端点，两个服务商

根据 [ADR 2026-09-26](https://github.com/Nebutra/Nebutra-Sailor/blob/main/docs/architecture/2026-09-26-creem-global-payments.md)，Nebutra 有两个支付 Webhook 端点：

| 端点 | 服务商 | 覆盖范围 |
|----------|----------|--------|
| `POST /api/webhooks/creem` | Creem（当前） | 一次性卡支付购买，面向全球，记录商户模式 |
| `POST /api/v1/webhooks/stripe` | Stripe（历史遗留） | 订阅、计费门户、切换前的历史结账 |

两者都已预先构建——你无需自行编写路由逻辑，仅在需要时为新事件添加处理程序。

## Creem Webhook（当前）

`POST /api/webhooks/creem`，实现于 `backends/gateway/src/routes/webhooks/creem.ts`。`creem-signature` 请求头是对**原始**请求体做 HMAC-SHA256（十六进制），密钥为 `CREEM_WEBHOOK_SECRET`——必须在任何解析之前，按收到的原始字节验证：

```typescript backends/gateway/src/routes/webhooks/creem.ts
import { verifyCreemSignature } from "@nebutra/billing";

const rawBody = await c.req.text();
if (!verifyCreemSignature(rawBody, c.req.header("creem-signature"))) {
  return c.json({ ok: false }, 401);
}

const event = JSON.parse(rawBody) as CreemWebhookEvent;
if (event.eventType === "checkout.completed" && event.object.order?.status === "paid") {
  // order.amount 是税前金额 —— Creem 作为记录商户在其上另加税费
  await settlePaymentOrder({
    orderId: event.object.request_id!,
    paidMinor: event.object.order.amount,
    currency: event.object.order.currency,
    providerRef: event.object.order.id,
  });
}
```

| Creem 事件 | 处理动作 |
|-------------|------------|
| `checkout.completed` | 结算支付订单 |
| `refund.created` | 仅用于可见性——表示某笔退款是从别处（Creem 控制台）发起的，而不是通过 `refundPaymentOrder` |

如果某次 Webhook 丢失，可以直接用 `GET /v1/checkouts?checkout_id=…`（`getCreemCheckout`）对账一笔待处理的结账。完整配置流程参见 [Creem 集成指南](/zh/integrations/creem)。

## Stripe Webhook（历史遗留——订阅）

所有 Stripe 事件均发送至 API 网关的单一端点：

```
POST /api/v1/webhooks/stripe
```

该端点已预置于 `backends/gateway/src/routes/webhooks/stripe.ts`。它仅供尚未迁移至 Creem 的表面使用：订阅、计费门户、许可证 Webhook 以及历史遗留的积分购买会话。不会在其上构建任何新功能。

## 签名验证

<Warning>
在处理任何事件之前，务必验证 Stripe Webhook 的签名。跳过验证将允许任何人向您的端点发送伪造事件，从而操纵账单状态。
</Warning>

Stripe 使用 `Stripe-Signature` 请求头对每个请求进行签名。处理程序使用 `STRIPE_WEBHOOK_SECRET` 进行验证：

```typescript backends/gateway/src/routes/webhooks/stripe.ts
import Stripe from "stripe";
import { PLANS } from "@nebutra/billing";
import { db } from "@nebutra/db";

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);

export async function POST(req: Request) {
  const body = await req.text();
  const sig = req.headers.get("stripe-signature");

  if (!sig) {
    return new Response("Missing stripe-signature header", { status: 400 });
  }

  let event: Stripe.Event;

  try {
    event = stripe.webhooks.constructEvent(
      body,
      sig,
      process.env.STRIPE_WEBHOOK_SECRET!
    );
  } catch {
    return new Response("Invalid signature", { status: 400 });
  }

  await handleStripeEvent(event);

  return new Response("OK", { status: 200 });
}
```

## 已处理事件

| Stripe 事件 | 处理程序动作 |
|------------|------------|
| `customer.subscription.updated` | 更新数据库中租户的 `plan`、`status` 和 `currentPeriodEnd` |
| `customer.subscription.deleted` | 将租户降级至 FREE 计划 |
| `invoice.payment_succeeded` | 记录支付成功；清除 `past_due` 标记 |
| `invoice.payment_failed` | 将租户状态设为 `past_due`；触发支付失败邮件 |

### 事件处理程序实现

<CodeGroup>
```typescript subscription.updated
async function handleSubscriptionUpdated(
  subscription: Stripe.Subscription
) {
  const orgId = subscription.metadata.orgId;
  const priceId = subscription.items.data[0]?.price.id;

  const plan = Object.values(PLANS).find(
    (p) => p.stripePriceId === priceId
  );

  await db.tenant.update({
    where: { id: orgId },
    data: {
      plan: plan?.id ?? "free",
      subscriptionStatus: subscription.status,
      currentPeriodEnd: new Date(subscription.current_period_end * 1000),
      cancelAtPeriodEnd: subscription.cancel_at_period_end,
    },
  });
}
```
```typescript subscription.deleted
async function handleSubscriptionDeleted(
  subscription: Stripe.Subscription
) {
  const orgId = subscription.metadata.orgId;

  await db.tenant.update({
    where: { id: orgId },
    data: {
      plan: "free",
      subscriptionStatus: "canceled",
      currentPeriodEnd: null,
    },
  });
}
```
```typescript invoice.payment_failed
async function handlePaymentFailed(invoice: Stripe.Invoice) {
  const customerId = invoice.customer as string;

  const tenant = await db.tenant.findFirst({
    where: { stripeCustomerId: customerId },
  });

  if (!tenant) return;

  await db.tenant.update({
    where: { id: tenant.id },
    data: { subscriptionStatus: "past_due" },
  });

  // 通过 @nebutra/notifications 通知用户
  await notifications.send({
    id: crypto.randomUUID(),
    type: "billing.payment_failed",
    recipientId: tenant.ownerId,
    tenantId: tenant.id,
    channels: ["email"],
    data: { invoiceUrl: invoice.hosted_invoice_url },
  });
}
```
</CodeGroup>

## 在 Stripe Dashboard 中注册事件（历史遗留）

设置生产环境 Webhook 端点时，只需启用以下事件：

```
customer.subscription.updated
customer.subscription.deleted
invoice.payment_succeeded
invoice.payment_failed
checkout.session.completed
```

进入 **Stripe Dashboard → Developers → Webhooks → Add endpoint**，填写 API URL 并选择上述事件。

## 使用 Stripe CLI 进行本地测试（历史遗留）

<Steps>
  <Step title="安装 Stripe CLI">
    ```bash
    # macOS
    brew install stripe/stripe-cli/stripe

    # npm（跨平台）
    npm install -g stripe
    ```
  </Step>
  <Step title="身份验证">
    ```bash
    stripe login
    ```
  </Step>
  <Step title="将事件转发至本地服务器">
    ```bash
    stripe listen --forward-to localhost:3001/api/v1/webhooks/stripe
    ```

    CLI 会打印本地 Webhook 签名密钥（`whsec_...`）。在本地开发时，将其设置为 `.env.local` 中的 `STRIPE_WEBHOOK_SECRET`。
  </Step>
  <Step title="触发测试事件">
    在另一个终端中，触发单个事件以测试您的处理程序：

    ```bash
    # 模拟订阅更新成功
    stripe trigger customer.subscription.updated

    # 模拟支付失败
    stripe trigger invoice.payment_failed
    ```
  </Step>
</Steps>

<Info>
Stripe CLI 的签名密钥与生产环境的 Webhook 签名密钥不同。本地开发时在 `.env.local` 中使用 CLI 提供的密钥，生产环境中使用 Dashboard 中的密钥。
</Info>

## 幂等性

两个服务商都可能多次发送同一事件（至少一次投递语义）。请确保您的处理程序具备幂等性——处理同一事件两次的结果应与处理一次相同。

Creem 的处理程序会在执行任何副作用之前先将事件记录进 Webhook 收件箱，因此重复投递只是空操作。上述 Stripe `subscription.updated` 和 `subscription.deleted` 处理程序已具备幂等性，因为它们使用了 upsert 式的数据库更新操作。
