## 套餐

`@nebutra/billing` 自带 `DEFAULT_PLAN_LIMITS` 和 `DEFAULT_PRICING`（三层，定义在
`packages/commerce/billing/src/types.ts`）——这是一个默认起点，不是固定不变的产品；改配置即可
重命名、重新定价、增删功能。

## 计量工作原理

使用量通过 `@nebutra/metering` 追踪，与具体存储无关——生产环境用 ClickHouse，开发/测试用内存
实现。标准计量项预先定义好了（`API_CALLS`、`AI_TOKENS`、`STORAGE_BYTES`、`BANDWIDTH`，以及
`ALL_STANDARD_METERS` 里的其他项）；标准集合覆盖不到的指标可以自己定义。

```typescript
import { getMetering, API_CALLS } from "@nebutra/metering";

const metering = await getMetering(); // 自动识别 provider
await metering.defineMeter(API_CALLS);

await metering.ingest({
  meterId: "api_calls",
  tenantId: "org_123",
  value: 1,
  properties: { endpoint: "/api/v1/ai/chat", method: "POST" },
});
```

## 配额强制执行

`evaluateUsageLimit`（来自 `@nebutra/metering`）检查租户用量是否超出套餐限制——接入网关中间件，
在业务逻辑运行之前完成检查。`QUOTA_EXCEEDED` / `FEATURE_DISABLED` 错误码和错误封装来自
`@nebutra/errors`——具体形状见[错误参考](/zh/api-reference/errors)：

```json
{
  "error": {
    "code": "QUOTA_EXCEEDED",
    "message": "月度 API 调用配额已超出。",
    "details": { "limit": 1000, "used": 1001 }
  },
  "requestId": "req_..."
}
```

## 查询配额

```typescript
const metering = await getMetering();

const quota = await metering.getQuota("org_123", "api_calls", "monthly");
// → { meterId, tenantId, limit, used, remaining, percentage, period, periodStart, periodEnd }
```

## 支付服务商

根据 [ADR 2026-09-26](https://github.com/Nebutra/Nebutra-Sailor/blob/main/docs/architecture/2026-09-26-creem-global-payments.md)，一次性卡支付购买（例如直接买断的计划升级、积分充值）通过 **Creem** 处理——全球卡支付，记录商户模式——中国大陆则使用 **微信支付 / 支付宝**。上文描述的循环计划订阅目前仍运行在 **Stripe** 上（历史遗留）：不会在其上构建任何新功能，仅保留至订阅迁移为 Creem 订阅（`subscription.*` 事件）为止。

API 网关为两者都预置了 Webhook 处理程序：

| Stripe 事件（历史遗留，订阅） | 处理动作 |
|--------------|--------|
| `checkout.session.completed` | 开通计划，发送欢迎邮件 |
| `customer.subscription.updated` | 更新租户计划和配额 |
| `customer.subscription.deleted` | 降级至 FREE |
| `invoice.payment_failed` | 发送支付失败邮件 |
| `invoice.paid` | 记录支付，更新计费周期 |

| Creem 事件（当前，一次性卡支付购买） | 处理动作 |
|--------------|--------|
| `checkout.completed` | 结算支付订单（税前金额与锁定的报价价格比对） |
