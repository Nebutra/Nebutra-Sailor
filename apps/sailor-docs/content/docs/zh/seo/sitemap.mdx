## 网站地图的工作原理

网站地图通过 Next.js App Router 文件系统约定生成，但它**按路由语言分片，每个语言一个子文件**，而不是单一的扁平文件——在 34 个产品语言下，一个巨大的网站地图会让 Search Console 把索引健康状况报告成一整团无法区分的数据。`generateSitemaps()` 从路由的唯一事实来源（SSOT）为每个语言返回一个分片 id，Next 会将其分别提供在 `/sitemap/<locale>.xml`。

**文件位置：**
```
apps/landing/src/app/sitemap.ts
```

## 分片、按语言的网站地图

```typescript apps/landing/src/app/sitemap.ts（节选）
import type { MetadataRoute } from "next";
import { routing } from "@/i18n/routing";
import { SEO_ROUTE_REGISTRY, localesForPath } from "@/lib/seo/route-registry";
import { getSiteUrl } from "@/lib/seo/site-routes";

// 每个路由语言一个分片——Next 会将它们提供在 /sitemap/<locale>.xml。
export function generateSitemaps(): Array<{ id: string }> {
  return routing.locales.map((id) => ({ id }));
}

// Next 16 会以 Promise 的形式传入分片 id——如果当作裸字符串读取，
// 每个分片都会悄悄返回空结果。
export default async function sitemap({
  id,
}: {
  id: Promise<string | undefined> | string | undefined;
}): Promise<MetadataRoute.Sitemap> {
  const locale = await id;
  if (!locale || !routing.locales.includes(locale)) return [];

  const baseUrl = getSiteUrl();
  const entries: MetadataRoute.Sitemap = [];

  for (const route of SEO_ROUTE_REGISTRY) {
    if (!localesForPath(route.pattern).includes(locale)) continue;
    entries.push({
      url: `${baseUrl}/${locale}${route.pattern}`,
      changeFrequency: route.changeFrequency,
      priority: route.priority,
    });
  }

  return entries;
}
```

静态路由元数据（`changeFrequency`、`priority`，以及某个路由发布在哪些语言下）保存在 `SEO_ROUTE_REGISTRY`（`apps/landing/src/lib/seo/route-registry.ts`）中，而不是在 `sitemap.ts` 里按路由硬编码——新增页面时应在那里添加，而不是修改网站地图函数。

博客文章来自 `@/lib/blog` 中的 `getAllPosts()`（而不是直接使用 Sanity 客户端），并汇入上面由注册表驱动的条目，而不是作为单独的静态列表附加。

对于分片网站地图，Next **不会**生成索引——`/sitemap.xml` 处的 `<sitemapindex>` 是在 `app/sitemap-index.xml/route.ts` 中手写的，并由 `next.config.ts` 重写到该路径，因为在那里放一个路由文件会与 `sitemap.ts` 这个元数据文件冲突。

## robots.txt

`robots.ts` 文件控制爬虫可以访问哪些路径。它还为指定的 AI/答案引擎爬虫（GPTBot、ClaudeBot、Google-Extended、Applebot-Extended、CCBot、Bytespider）声明了一份更窄的允许列表，这些爬虫只能看到产品相关的页面，而不是整个站点：

```typescript apps/landing/src/app/robots.ts（节选）
import type { MetadataRoute } from "next";
import { getSiteUrl } from "@/lib/seo/site-routes";

export default function robots(): MetadataRoute.Robots {
  const baseUrl = getSiteUrl();
  return {
    rules: [
      {
        userAgent: "*",
        allow: "/",
        disallow: ["/api/", "/_next/", "/sign-in", "/sign-up", "/admin/", "/settings/"],
      },
      ...(["GPTBot", "ClaudeBot", "Google-Extended", "Applebot-Extended", "CCBot", "Bytespider"] as const).map(
        (userAgent) => ({
          userAgent,
          allow: ["/", "/blog/", "/features", "/features/", "/pricing", "/llms.txt"],
          disallow: ["/api/", "/_next/", "/sign-in", "/sign-up", "/admin/", "/settings/"],
        })
      ),
    ],
    sitemap: `${baseUrl}/sitemap.xml`,
    host: baseUrl,
  };
}
```

<Warning>
  切勿在网站地图中包含已认证的应用路由（如 `app.nebutra.com/dashboard`）。只有公开落地页（`nebutra.com`）会被索引。`apps/web` 和 `apps/sailor-docs` 各自都有自己的 `robots.ts`。
</Warning>

## 在本地验证网站地图

```bash
pnpm --filter @nebutra/landing dev
# 访问：http://localhost:3000/sitemap/en.xml
# 访问：http://localhost:3000/robots.txt
```

在开发环境中，网站地图按需渲染；在生产环境中，网站地图会在 CDN 边缘缓存。

## 向 Google Search Console 提交

<Steps>
  <Step title="验证域名所有权">
    在 [Google Search Console](https://search.google.com/search-console) 中，添加您的资源（`https://nebutra.com`），并通过 DNS TXT 记录或 HTML 文件方式验证所有权。
  </Step>
  <Step title="提交网站地图">
    在 Search Console 中，点击左侧边栏的 **Sitemaps**。在 URL 字段中输入 `sitemap.xml`，然后点击 **Submit**。
  </Step>
  <Step title="监控索引状态">
    提交后，Search Console 会显示已发现和已索引的 URL 数量。新网站地图通常需要 24–72 小时才能被处理。
  </Step>
  <Step title="重大内容更新后重新提交">
    Google 会自动重新爬取网站地图，但在重大版本发布后（新增语言、大量新博客文章），手动重新提交可以加快重新索引速度。
  </Step>
</Steps>

## 网站地图大小限制

Google 支持每个文件最多 50,000 个 URL 或 50 MB（未压缩）——按语言分片（如上所述）已经让每个分片在 34 个语言的页面规模下远低于这个限制。如果某个语言的分片接近这个限制（例如博客文章非常多），可以用同样的方式对该语言进一步分片：让嵌套的 `generateSitemaps()` 除了语言 id 之外，再按一个次级 id（如文章批次）分片，并更新 `app/sitemap-index.xml/route.ts` 中手写的索引，列出新增的子文件。
