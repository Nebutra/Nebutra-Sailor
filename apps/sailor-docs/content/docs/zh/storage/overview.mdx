根据 ADR 2026-09-24（Sailor 收敛），对象存储只有**一个**服务商：单一的 S3 兼容客户端（`S3UploadProvider`），Cloudflare R2、AWS S3、阿里云 OSS 或任何其他 S3 兼容端点都走同一条代码路径——不存在独立的 "R2 服务商" 或 "S3 服务商" 实现，已删除的 Vercel Blob 适配器也不会回归。`@nebutra/uploads` 恰好暴露两种服务商类型：`"s3"` 与 `"local"`（供开发环境使用的本地文件系统回退）。在 R2、AWS S3、OSS 之间切换只是环境变量的变化；它们之间没有任何代码路径差异。

## 架构

```
┌──────────────────────────────────────┐
│           浏览器 / 客户端             │
│  (React、移动应用、CLI)               │
└──────────────┬───────────────────────┘
               │ 1. 请求上传 URL
┌──────────────▼───────────────────────┐
│         API Route / Server Action    │
│   getUploadProvider() → 预签名 URL   │
│   或分片上传会话                       │
└──────────────┬───────────────────────┘
               │ 2. 签名 URL 返回给客户端
┌──────────────▼───────────────────────┐
│         客户端直接上传                │
│   PUT {presignedUrl} — 不经过代理     │
└──────────────┬───────────────────────┘
               │ 3. 文件进入存储桶
┌──────────────▼───────────────────────┐
│  R2 / AWS S3 / OSS / 任意 S3 兼容端点 │
│    （同一个适配器 S3UploadProvider）  │
└──────────────┬───────────────────────┘
               │ 4. 通过 CDN 提供服务
┌──────────────▼───────────────────────┐
│        CloudFront / R2 公共 URL      │
│      (私有文件使用 getDownloadUrl)    │
└──────────────────────────────────────┘
```

客户端直接向存储提供商上传文件，文件不经过你的应用服务器。这样可以保持高上传吞吐量并降低服务器成本。

## 文件上传策略

根据文件大小和可靠性要求选择合适的策略：

| 策略 | 适用场景 | 大小限制 | 可续传 |
|------|---------|---------|--------|
| 预签名 URL | 文档、图片、小文件 | 最大约 100 MB | 否 |
| 分片上传 | 视频、大型压缩包 | 无限制 | 部分 |
| Tus 断点续传 | 不稳定连接、大文件 | 无限制 | 是 |

### 预签名 URL

最简单的方案。服务端生成一个短期有效的签名 URL，客户端通过单次 `PUT` 请求直接上传，不经过你的服务器。适用于 100 MB 以下的文件。

### 分片上传

将大文件拆分为若干小分片（每片最小 5 MB）并行上传。失败的分片可单独重试。AWS S3 上超过 5 GB 的文件必须使用此方式。

### Tus 断点续传

一种开放的断点续传协议。如果连接断开，上传将从最后确认的字节处继续。最适合在不稳定网络环境下上传大文件。

<Note>
S3 兼容服务商上的 `getTusEndpoint()` 会开启一个分片上传并返回可续传的配置（endpoint、chunk size、retry delays）——它不是一个可以让现成的 `tus-js-client` 直接对接的完整 Tus 协议服务端。详情及更直接的分片续传方式请参阅[文件上传](/zh/storage/uploads)。
</Note>

## 租户隔离

每个文件的存储键都包含租户标识符前缀：

```
{tenantId}/{文件路径}

# 示例
org_acme/docs/q4-report.pdf
org_beta/avatars/user_123.jpg
org_acme/videos/demo.mp4
```

这种约定确保在共享存储桶中实现租户文件的逻辑隔离。结合 IAM 策略或 Cloudflare R2 访问控制，还可在基础设施层面强制执行访问隔离。

<Warning>
始终从服务端经过身份验证的会话中获取 `tenantId`。绝对不要接受来自客户端请求体中的 `tenantId`，因为它可以被伪造。
</Warning>

## 快速开始

```typescript
import { getUploadProvider } from "@nebutra/uploads";

const uploads = await getUploadProvider();

// 生成客户端上传的预签名 URL
const { url, headers } = await uploads.createPresignedUpload({
  bucket: "nebutra-uploads",
  key: `${tenantId}/docs/report.pdf`,
  contentType: "application/pdf",
  tenantId,
  expiresIn: 3600, // 秒
});

// 客户端直接上传到存储提供商
// PUT url  (携带 headers)

// 获取已签名的下载 URL
const downloadUrl = await uploads.getDownloadUrl("nebutra-uploads", key);

// 删除文件
await uploads.deleteFile("nebutra-uploads", key);
```

## 环境变量

没有单独的存储桶名称环境变量——存储桶始终是调用时传入的参数（`createPresignedUpload({ bucket, key, … })` 等），对所有 S3 兼容端点都一样。

| 变量 | 是否必填 | 说明 |
|------|---------|------|
| `UPLOAD_PROVIDER` | 否 | 显式指定：`"s3"` \| `"local"` \| `"r2"`（别名，解析为使用下方 `R2_*` 变量的 `"s3"`） |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | AWS S3 用 | 未设置时回退到 `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`——本质是同一个客户端 |
| `AWS_REGION` | 否 | 默认为 `"auto"` |
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | R2 用 | R2 API 令牌 ID / 密钥 |
| `R2_ENDPOINT` / `S3_ENDPOINT` | 自定义端点用 | Cloudflare R2、阿里云 OSS、MinIO、Backblaze 等——两者都设置时 `S3_ENDPOINT` 优先 |
| `R2_PUBLIC_URL` / `S3_PUBLIC_URL` | 否 | 提供服务的公共 CDN 基础 URL |
| `S3_FORCE_PATH_STYLE` | 否 | `"true"` 表示使用路径风格 URL（自托管 MinIO 等） |

提供商自动检测（`createUploadProvider()`，未显式设置 `UPLOAD_PROVIDER` 时）优先级：

1. `UPLOAD_PROVIDER` 环境变量（若已设置，`"r2"` 会解析为使用 `R2_*` 变量配置的 S3 服务商）
2. 存在 `R2_ACCESS_KEY_ID` 或 `R2_SECRET_ACCESS_KEY` → S3 服务商，使用 `R2_*` 变量配置
3. 存在 `AWS_ACCESS_KEY_ID` 或 `AWS_SECRET_ACCESS_KEY` → S3 服务商，使用 `AWS_*` 变量配置（未设置的字段回退到 `R2_*`）
4. 存在 `S3_ENDPOINT` → S3 服务商，自定义端点（阿里云 OSS、MinIO、Backblaze 等）
5. 兜底 → 本地文件系统（仅限开发环境）
