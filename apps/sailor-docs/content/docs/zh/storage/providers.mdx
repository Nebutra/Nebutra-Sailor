---
title: 存储服务商
description: 为 @nebutra/uploads 配置唯一的 S3 兼容适配器——支持 Cloudflare R2、AWS S3、阿里云 OSS 或任意 S3 兼容端点。
---

`@nebutra/uploads` 只有**一个**云端服务商——单一的 S3 兼容客户端（`S3UploadProvider`）——外加一个用于开发环境的本地文件系统回退。根据 ADR 2026-09-24（Sailor 收敛），Cloudflare R2 与阿里云 OSS 复用同一个适配器（"one S3-compatible adapter for R2 and OSS"），这个适配器同样可以对接 AWS S3、MinIO、Backblaze B2 及任何其他 S3 兼容端点——它们走的是完全相同的代码路径，只是环境变量不同。这里不存在独立的 "AWS S3 服务商" 或 "R2 服务商" 实现，也没有 `STORAGE_PROVIDER` 环境变量——真正的变量名是 `UPLOAD_PROVIDER`。

<Note>
服务商自动检测（`createUploadProvider()`，未显式设置 `UPLOAD_PROVIDER` 时）优先级：显式 `UPLOAD_PROVIDER` → 存在 `R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY`（使用 `R2_*` 变量）→ 存在 `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`（使用 `AWS_*` 变量，未设置的字段回退到 `R2_*`）→ 存在 `S3_ENDPOINT`（自定义端点）→ 本地文件系统兜底。
</Note>

## Cloudflare R2（主力）

R2 是 Nebutra 生产环境实际使用的存储。它兼容 S3 协议，且**零出口流量费用**。

### 环境变量

```bash
UPLOAD_PROVIDER=r2
R2_ACCESS_KEY_ID=...
R2_SECRET_ACCESS_KEY=...
R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
R2_PUBLIC_URL=https://assets.nebutra.com
```

<Tip>
`UPLOAD_PROVIDER=r2` 只是一个别名，最终解析为使用 `R2_*` 变量配置的 S3 服务商——与本文档中其它端点使用的是同一个 `S3UploadProvider` 类。不设置 `UPLOAD_PROVIDER`，仅设置 `R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY` 也会自动检测出同样的结果。
</Tip>

### 设置步骤

<Steps>
  <Step title="创建 R2 存储桶">
    在 Cloudflare 控制台中，进入 **R2 → Create bucket**。存储桶名称是每次调用时传入的参数（`createPresignedUpload({ bucket, key, … })`），不是从环境变量读取的。
  </Step>

  <Step title="创建 API 令牌">
    进入 **R2 → Manage R2 API tokens → Create API token**。

    - **权限：** Object Read & Write
    - **存储桶：** 限定到你创建的存储桶

    将 **Access Key ID** 和 **Secret Access Key** 保存为 `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`。
  </Step>

  <Step title="配置 CORS">
    在 R2 存储桶设置中，进入 **Settings → CORS Policy**：

    ```json
    [
      {
        "AllowedOrigins": ["https://app.nebutra.com"],
        "AllowedMethods": ["GET", "PUT", "HEAD", "DELETE"],
        "AllowedHeaders": ["*"],
        "ExposeHeaders": ["ETag"],
        "MaxAgeSeconds": 3600
      }
    ]
    ```
  </Step>

  <Step title="启用公共访问（可选）">
    如需公共 CDN URL（头像、公开文档），进入 **R2 bucket → Settings → Public access**，绑定自定义域名或启用 `r2.dev` 子域名，并将其设为 `R2_PUBLIC_URL`。
  </Step>
</Steps>

## AWS S3

如果你已经在使用 AWS 生态，或需要 AWS 原生 IAM 策略，可以直接用 S3。仍是同一个适配器，只是把 `R2_*` 换成 `AWS_*`：

```bash
AWS_ACCESS_KEY_ID=AKIA...
AWS_SECRET_ACCESS_KEY=...
AWS_REGION=us-east-1
```

`UPLOAD_PROVIDER` 可以不设置——只要存在 `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`（且没有设置 `R2_*` 凭据），就会自动检测为使用这些变量的 S3 服务商。为你的存储桶附加一条 IAM 策略：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject", "s3:ListBucket"],
      "Resource": ["arn:aws:s3:::nebutra-uploads", "arn:aws:s3:::nebutra-uploads/*"]
    }
  ]
}
```

CORS 配置方式与上面的 R2 示例相同，在你自己的存储桶控制台中设置即可。

## 阿里云 OSS、MinIO、Backblaze B2 及其他 S3 兼容端点

任何 S3 兼容服务都可以通过同一个适配器接入，只需将 `S3_ENDPOINT`（其次是 `R2_ENDPOINT`）指向它。这正是 ADR 2026-09-24 中为满足中国大陆 PIPL 数据驻留要求而给出的 OSS 接入路径：

```bash
AWS_ACCESS_KEY_ID=...          # 或 S3_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY=...      # 或 S3_SECRET_ACCESS_KEY
AWS_REGION=us-east-1
S3_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
S3_PUBLIC_URL=https://assets.example.com
```

### MinIO（自托管、本地开发）

<Steps>
  <Step title="启动 MinIO">
    ```bash
    docker run -p 9000:9000 -p 9001:9001 \
      -e MINIO_ROOT_USER=admin \
      -e MINIO_ROOT_PASSWORD=password \
      quay.io/minio/minio server /data --console-address ":9001"
    ```
  </Step>

  <Step title="创建存储桶和访问密钥">
    打开 `http://localhost:9001` 的 MinIO 控制台，创建一个存储桶并生成一对访问密钥。
  </Step>

  <Step title="设置环境变量">
    ```bash
    AWS_ACCESS_KEY_ID=<minio-access-key>
    AWS_SECRET_ACCESS_KEY=<minio-secret-key>
    AWS_REGION=us-east-1
    S3_ENDPOINT=http://localhost:9000
    S3_FORCE_PATH_STYLE=true
    ```
  </Step>
</Steps>

<Warning>
本地 MinIO 需要设置 `S3_FORCE_PATH_STYLE=true`，以避免虚拟主机风格 URL 解析问题。
</Warning>

## 本地文件系统（无凭据时的默认值）

在没有设置以上任何变量的情况下，`createUploadProvider()` 会回退到 `LocalUploadProvider`——文件落到本地磁盘。这是零配置脚手架（ADR 2026-09-24）的默认行为：空 `.env` 下 `pnpm dev` 依然可以工作。

## 切换端点

因为每个端点都走同一个 `S3UploadProvider`，从 R2 切到 AWS S3（或 OSS）只是环境变量的变化，不需要改代码：

```bash
# 从 R2 切换到 AWS S3 —— 只需更新环境变量
AWS_ACCESS_KEY_ID=AKIA...
AWS_SECRET_ACCESS_KEY=...
AWS_REGION=us-east-1
```
