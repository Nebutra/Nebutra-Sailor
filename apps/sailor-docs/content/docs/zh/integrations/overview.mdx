title: 集成概览
description: 当前由用户管理的 integration surface，以及围绕它们运作的平台服务。
---

Nebutra-Sailor 当前会明确区分：

- **用户可管理的 integrations**：在产品 UI 中暴露
- **平台服务**：支撑整个栈，但并不是通过某个通用 `defineIntegration()`
  API 注册出来的

## 用户可管理的 integrations

当前 web app 的 integrations 页面围绕这些类型工作：

- `SHOPIFY`
- `SHOPLINE`
- `STRIPE`
- `CUSTOM`

对应的产品页面位于：

```text
apps/web/src/app/[locale]/(app)/integrations/page.tsx
```

后端 API 位于：

```text
backends/gateway/src/routes/integrations/index.ts
```

## 平台服务

这些服务很重要，但它们 **不是** 通过一个虚构的
`@nebutra/integrations` 包注册出来的：

| 服务 | 作用 |
| --- | --- |
| Resend / email | 事务性邮件基础设施 |
| Sanity | 内容管理与编辑数据 |
| Sentry | 错误监控 |
| Vercel | 部署目标 |

应把它们视为 platform dependency 或 provider-specific package，而不是一个
抽象 integration registry 中的记录，除非代码里真的这样建模。

## 当前 route / API 模型

gateway 在 `/api/v1/integrations` 下暴露 integration CRUD，并通过加密的
integration model 持久化 credentials / settings。

浏览器调用示例：

```typescript
import { browserApiClient } from "@/lib/api/client";

const { data } = await browserApiClient.GET("/api/v1/integrations");
```

## 添加新的 managed integration

今天新增一个 integration，需要修改的是真实 gateway + UI surface：

1. 扩展 `backends/gateway/src/routes/integrations/index.ts` 中的 schema/type
2. 更新 `apps/web/src/app/[locale]/(app)/integrations/page.tsx` 中的 UI catalog
3. 如果需要 secrets，使用 DB 层已支持的 `integration.credentials` /
   `integration.settings` 加密字段

不要继续文档化或导入以下旧接口：

- `@nebutra/integrations`
- `defineIntegration(...)`
- 某个独立的 web app integration registry 文件
