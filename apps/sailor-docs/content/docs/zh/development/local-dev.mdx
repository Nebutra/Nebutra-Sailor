## 前置条件

开始之前，请确保已安装以下工具：

- **Node.js 22+** — [nodejs.org](https://nodejs.org) 或使用 [nvm](https://github.com/nvm-sh/nvm)
- **pnpm 10.32+** — `npm install -g pnpm`
- **Docker Desktop 24+** — [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/)
- **Git 2.40+** — [git-scm.com](https://git-scm.com)

## 分步配置

<Steps>
  <Step title="安装 Node.js 22">
    ```bash
    # 使用 nvm（推荐）
    nvm install 22
    nvm use 22

    # 验证
    node --version   # v22.x.x
    ```
  </Step>
  <Step title="安装 pnpm">
    ```bash
    npm install -g pnpm@latest

    # 验证
    pnpm --version   # 10.32.x 或更高
    ```
  </Step>
  <Step title="克隆仓库">
    ```bash
    git clone https://github.com/nebutra/nebutra-sailor.git
    cd nebutra-sailor
    ```
  </Step>
  <Step title="安装依赖">
    ```bash
    pnpm install
    ```
    此命令安装所有应用和包的 workspace 依赖。首次运行可能需要 2–3 分钟。
  </Step>
  <Step title="启动基础设施服务">
    ```bash
    pnpm infra:up
    ```
    此命令会对根目录的 `docker-compose.yml` 执行 `docker-compose up -d`，其中包含：
    - **PostgreSQL 16**（pgvector），端口 `5432`
    - **Redis 7**，端口 `6379`
    - **ClickHouse 24**，端口 `8123`

    如果只需要 Postgres 和 Redis（不需要 ClickHouse），请改用 `pnpm infra:lite`——它使用 `docker-compose.lite.yml`。注意 `infra:lite` 仍然会启动 Redis，它只是跳过了 ClickHouse。

    严格来说，开发并不必须依赖以上任何一项：未设置 `DATABASE_URL` 时，`@nebutra/db` 会自动回退到零配置的 PGlite（WASM 中的 Postgres 17）预览数据库。
  </Step>
  <Step title="配置环境变量">
    为您计划运行的每个应用复制示例文件：
    ```bash
    cp apps/web/.env.example           apps/web/.env.local
    cp backends/gateway/.env.example   backends/gateway/.env.local
    cp apps/landing/.env.example  apps/landing/.env.local
    ```
    然后打开每个 `.env.local` 文件并填写您的密钥。完整的变量参考请参阅下方的[环境变量](#环境变量)章节。
  </Step>
  <Step title="生成 Prisma 客户端">
    ```bash
    pnpm db:generate
    ```
    此命令使用 `packages/platform/db/prisma/schema.prisma` 中的 Schema 运行 `prisma generate`。
  </Step>
  <Step title="执行数据库迁移">
    ```bash
    pnpm db:migrate
    ```
    此命令将所有待执行的 Prisma 迁移应用到您的本地 PostgreSQL 实例。
  </Step>
  <Step title="填充开发数据">
    ```bash
    pnpm db:seed
    ```
    向数据库填充测试组织、用户和示例数据，让您可以立即登录。
  </Step>
  <Step title="启动开发服务器">
    <Tabs>
      <Tab title="轻量预览">
        ```bash
        pnpm dev
        ```
        只启动三个核心应用——`apps/landing`（站点，端口 3000）、`apps/web`（应用，端口 3001）和 `backends/gateway`（API，端口 3002）——无需任何密钥、Docker 或数据库设置。若默认端口被占用会自动挑选空闲端口。
      </Tab>
      <Tab title="所有应用">
        ```bash
        pnpm dev:all
        ```
        通过 Turborepo（`turbo run dev --concurrency=64`）并行启动每一个应用、Storybook 以及文档站点。
      </Tab>
      <Tab title="仅控制台">
        ```bash
        pnpm dev:dashboard
        ```
        启动 `apps/web`、`apps/admin` 和 `backends/gateway`。
      </Tab>
      <Tab title="仅营销网站">
        ```bash
        pnpm dev:marketing
        ```
        启动 `apps/landing`、`packages/commerce/blog` 和 `apps/studio`。
      </Tab>
    </Tabs>
    所有应用均支持**热模块替换（HMR）**。对源文件的修改无需完整页面刷新即可立即生效。
  </Step>
</Steps>

## 端口映射

| 服务 | URL | 备注 |
|------|-----|------|
| 营销网站 | http://localhost:3000 | 34 种语言（中文按脚本区分为 zh-Hans/zh-Hant），默认为 `/en` |
| SaaS 控制台 | http://localhost:3001 | 需要 Better Auth 认证 |
| API 网关 | http://localhost:3002 | REST API，OpenAPI 文档位于 `/doc` |
| Sailor 文档（本站点） | http://localhost:3004 | `apps/sailor-docs` |
| 内部设计文档 | http://localhost:3109 | `apps/design`，仅内部使用 |
| Storybook | http://localhost:6006 | 组件库 |
| Sanity Studio | http://localhost:3333 | 内容管理 |
| PostgreSQL | localhost:5432 | 数据库 |
| Redis | localhost:6379 | 缓存和队列 |
| ClickHouse | localhost:8123 | 使用量计量 |

## 环境变量

### `backends/gateway`

| 变量 | 是否必填 | 说明 |
|------|---------|------|
| `DATABASE_URL` | 是 | PostgreSQL 连接字符串，例如 `postgresql://postgres:postgres@localhost:5432/nebutra` |
| `REDIS_URL` | 是 | Redis 连接字符串，例如 `redis://localhost:6379` |
| `AUTH_PROVIDER` | 否 | 认证提供商：`better-auth`（唯一的真实选项）或 `dev`（本地兜底） |
| `NEXT_PUBLIC_AUTH_PROVIDER` | 否 | 客户端可见的认证提供商；应与 `AUTH_PROVIDER` 保持一致 |
| `CREEM_API_KEY` | 使用 Creem 结账时 | Creem API 密钥——当前的卡支付通道（记录商户模式） |
| `CREEM_PRODUCT_ID` | 使用 Creem 结账时 | 每次结账都会打开的一次性 Creem 产品 |
| `CREEM_WEBHOOK_SECRET` | 需要 Creem Webhook 验证时 | 为 Creem Webhook 投递的 `creem-signature` 签名 |
| `STRIPE_SECRET_KEY` | 用于订阅（历史遗留） | Stripe 密钥 |
| `STRIPE_WEBHOOK_SECRET` | 用于订阅（历史遗留） | Stripe Webhook 签名密钥 |
| `CLICKHOUSE_URL` | 是 | ClickHouse HTTP 接口 URL |
| `QUEUE_PROVIDER` | 否 | `qstash` 或 `memory`（自动检测；没有自托管替代方案） |

### `apps/web`

| 变量 | 是否必填 | 说明 |
|------|---------|------|
| `AUTH_PROVIDER` | 否 | 服务端路由选择的认证提供商 |
| `NEXT_PUBLIC_AUTH_PROVIDER` | 否 | 客户端代码和 Landing One Tap 选择的认证提供商 |
| `BETTER_AUTH_SECRET` | 若要启用真实的认证后端 | Better Auth 自托管签名密钥 |
| `GOOGLE_CLIENT_ID` | 使用 Google OAuth 时 | Google OAuth Web Client ID |
| `GOOGLE_CLIENT_SECRET` | 使用 Google OAuth 时 | Google OAuth Web Client Secret |
| `NEXT_PUBLIC_API_URL` | 是 | API 网关的基础 URL，例如 `http://localhost:3002` |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | 用于订阅（历史遗留） | 客户端计费所用的 Stripe 可发布密钥 |
| `DATABASE_URL` | 是 | PostgreSQL 连接字符串（用于 Server Actions） |

### `apps/landing`

| 变量 | 是否必填 | 说明 |
|------|---------|------|
| `NEXT_PUBLIC_SANITY_PROJECT_ID` | 是 | Sanity 项目 ID |
| `NEXT_PUBLIC_SANITY_DATASET` | 是 | Sanity 数据集名称，例如 `production` |
| `NEXT_PUBLIC_AUTH_PROVIDER` | 否 | 用于选择 Landing One Tap 行为的认证提供商 |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | 启用 Google One Tap 时 | 公开 Google OAuth Web Client ID |
| `SANITY_API_TOKEN` | 否 | Sanity 读取 Token（草稿预览时需要） |

<Note>
  所有环境变量在启动时由 `@nebutra/config` 验证。如果缺少必填变量，进程会立即崩溃并显示详细的错误信息 — 不会有静默失败。
</Note>

## 首次运行常见问题

### "Cannot find module '@prisma/client'"

您需要先生成 Prisma 客户端：

```bash
pnpm db:generate
```

### "Error: connect ECONNREFUSED 127.0.0.1:5432"

PostgreSQL 未运行。启动基础设施容器：

```bash
pnpm infra:up
```

### "Error: connect ECONNREFUSED 127.0.0.1:6379"

Redis 未运行。运行 `pnpm infra:up` 或 `pnpm infra:lite` 都可以——两者都会启动 Redis，`infra:lite` 只是跳过 ClickHouse。

### 端口已被占用

`pnpm dev` 在默认端口被占用时会自动挑选空闲端口，但对于其他 dev 命令，你可以自行释放端口：

```bash
lsof -ti:3000 | xargs kill   # 释放端口 3000（landing）
lsof -ti:3001 | xargs kill   # 释放端口 3001（web）
lsof -ti:3002 | xargs kill   # 释放端口 3002（gateway）
```

### pnpm 版本不匹配

本仓库要求 pnpm 10.32+。请升级：

```bash
npm install -g pnpm@latest
```

## 运行单独的命令

```bash
pnpm typecheck          # 跨所有包进行 TypeScript 检查
pnpm lint               # Biome 代码检查
pnpm lint:fix           # Biome 代码检查并自动修复
pnpm test               # Vitest 单元测试
pnpm test:coverage      # 带覆盖率报告的单元测试
pnpm test:arch          # 架构边界测试
pnpm e2e                # Playwright E2E（无界面模式）
pnpm e2e:ui             # 带交互界面的 Playwright E2E
pnpm build              # 生产构建（所有应用）
```
