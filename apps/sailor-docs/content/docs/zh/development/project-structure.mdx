Nebutra-Sailor 在顶层按**用途**组织，在 `packages/` 内按**领域**组织。

## 顶层布局

```text
nebutra-sailor/
├── apps/
├── backends/
├── packages/
├── infra/
├── workflows/
├── e2e/
├── tests/
├── scripts/
├── package.json
└── pnpm-workspace.yaml
```

## `apps/`

当前仓库中存在的 app 包括：

| 应用 | 用途 |
| --- | --- |
| `apps/landing-page` | 公开营销站 |
| `apps/web` | 已认证 SaaS 应用 |
| `apps/storybook` | 组件文档 / stories |
| `apps/design-docs` | 内部设计系统文档 |
| `apps/sailor-docs` | 产品文档 |
| `apps/studio` | Sanity Studio |
| `apps/idp` | 身份提供方应用 |
| `apps/mail-preview` | 邮件预览界面 |
| `apps/sleptons`、`apps/tsekaluk-dev` | 辅助产品界面 |

旧文档里提到的 Mintlify 风格 docs app 并不属于当前仓库，不应再作为公开
docs app 引用。

## `backends/`

```text
backends/
├── gateway/   TypeScript / Hono
├── go/
├── python/
└── rust/
```

根据仓库契约，新产品后端工作默认进入 `backends/gateway/`，除非有明确原因
迁移到其他 runtime。

## `packages/`

workspace 包按领域分组：

| 领域 | 示例 |
| --- | --- |
| `ai/` | `agents`、`agent-runtime`、`mcp`、`browser-control` |
| `commerce/` | `billing`、`marketing`、`metering`、`blog` |
| `design/` | `ui`、`tokens`、`brand`、`icons`、`theme` |
| `iam/` | `auth`、`identity`、`permissions`、`tenant`、`vault` |
| `integrations/` | `email`、`event-bus`、`queue`、`notifications`、`webhooks` |
| `ops/` | `cli`、`create-sailor`、`preset`、`sanity`、`supabase` |
| `platform/` | `db`、`logger`、`errors`、`config`、`rate-limit` |

## 当前 web app route 结构

已认证 app shell 是 locale-aware 的：

```text
apps/web/src/app/
  [locale]/
    (app)/
    (auth)/
    (public)/
  api/
```

新增产品页面时，应放到 `[locale]/(app)` 下，而不是旧文档中的 `(dashboard)`
路径。

## Workflows、tests 与 infra

```text
workflows/
  inngest/
  n8n/
  pusher/

e2e/
  playwright.config.ts
  playwright.golden.config.ts
  playwright.sleptons.config.ts

tests/
  architecture/
```

当前 `e2e/` 是 config-first 结构，而不是旧文档中描述的 `smoke/` /
`golden/` / `sleptons/` 子目录布局。

## 新内容应放在哪里

| 需求 | 当前位置 |
| --- | --- |
| 新的已认证页面 | `apps/web/src/app/[locale]/(app)/` |
| 新的营销页 | `apps/landing-page/src/app/[lang]/` |
| 新的 gateway 路由 | `backends/gateway/src/routes/` |
| 新的可复用 UI 组件 | `packages/design/ui/src/` |
| 新的 DB 合约 | `packages/platform/db/` |
| 新的 workflow scaffold | `workflows/<provider>/` |
