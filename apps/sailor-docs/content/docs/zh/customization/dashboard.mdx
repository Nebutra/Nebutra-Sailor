---

已认证产品 shell 当前位于：

```text
apps/web/src/app/[locale]/(app)/
```

它由 `apps/web/src/app/[locale]/(app)/layout.tsx` 挂载，layout 本身已经负责
auth guard，并通过 `DesignSystemShell` 包裹所有页面。

## 当前 app 页面结构

```text
apps/web/src/app/[locale]/(app)/
  layout.tsx
  analytics/
    page.tsx
    loading.tsx
  billing/
    page.tsx
    loading.tsx
```

旧文档里假定“非 locale dashboard route group”的写法已经过时。

## 创建新的板块

```bash
mkdir -p 'apps/web/src/app/[locale]/(app)/my-section'
```

```typescript
// apps/web/src/app/[locale]/(app)/my-section/page.tsx
import { PageHeader } from "@nebutra/ui/layout";
import { requireAuth } from "@/lib/auth";

export default async function MySectionPage() {
  await requireAuth();

  return (
    <div className="space-y-6">
      <PageHeader
        title="My Section"
        description="A new section inside the shared app shell."
      />
    </div>
  );
}
```

## Loading 与 error 状态

```typescript
// apps/web/src/app/[locale]/(app)/my-section/loading.tsx
import { LoadingState } from "@nebutra/ui/layout";

export default function Loading() {
  return <LoadingState message="Loading section…" />;
}
```

如果需要客户端错误恢复，可增加 route-local `error.tsx` 并使用标准
`ErrorState`。

## 共享 shell 行为

页面 chrome、通知区与 product capability 由以下文件拥有：

- `apps/web/src/app/[locale]/(app)/layout.tsx`
- `apps/web/src/app/[locale]/providers/design-system-shell.tsx`
- `apps/web/src/lib/product-capabilities.ts`

当新页面依赖 billing、workspace mode 或 notifications 时，应在这些能力
假设上做收敛，而不是再发明一套平行 dashboard 约定。

## 导航

旧文档依赖的 sidebar item registry 已不存在。当前导航由 shell 与这些组件
组合而成：

```text
apps/web/src/components/navigation/
```

新增主导航板块前，先读当前 shell / navigation wiring，并与活跃的 product
capability model 保持一致。

## 布局原语

```tsx
import { Card, EmptyState, ErrorState, LoadingState, PageHeader } from "@nebutra/ui/layout";
```

优先复用这些共享 layout 组件，而不是再写一套私有 dashboard 变体。

## tenant-aware 页面逻辑

当页面依赖租户状态时，通过共享服务端 helper 获取：

```typescript
import { getTenantContext, requireAuth } from "@/lib/auth";

await requireAuth();
const { tenantId, plan } = await getTenantContext();
```

建议在页面和后端路由中显式做 plan / capability 判断，不要继续依赖已经不在
当前 app surface 中的旧 `PlanGate` 例子。
