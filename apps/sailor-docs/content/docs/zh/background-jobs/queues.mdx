## 概述

`@nebutra/queue` 是每个 Sailor 项目使用的队列：**QStash**（Upstash）——Serverless、基于 HTTP,无需管理任何基础设施。根据 Sailor Convergence ADR（2026-09-24）,自托管的 BullMQ + Redis 后端已被移除;QStash 是唯一的队列后端。

## Provider 自动检测

| 优先级 | 条件 | Provider |
|----------|-----------|----------|
| 1 | 设置了 `QUEUE_PROVIDER` | 按指定值（`qstash` / `memory`） |
| 2 | 存在 `QSTASH_TOKEN` | `qstash` |
| 3 | 都没有 | `memory`（仅限开发/测试——不持久化；`nebutra status` 会将其报告为 `local-fallback`） |

## 配置步骤

<Steps>
  <Step title="设置环境变量">
    ```bash
    QSTASH_TOKEN=""
    QSTASH_CURRENT_SIGNING_KEY=""
    QSTASH_NEXT_SIGNING_KEY=""

    # 你的 API 网关的公网 Base URL
    # QStash 会调用这个 URL 来投递任务
    QSTASH_CALLBACK_BASE_URL="https://api.yourdomain.com"
    ```
  </Step>

  <Step title="注册 Webhook 路由">
    API 网关已经在以下地址暴露了 QStash Webhook：

    ```
    POST /api/queue/:queue/:type
    ```

    当 `report.generate` 任务就绪时,QStash 会向 `https://api.yourdomain.com/api/queue/report/generate` 发起 POST。

    <Warning>
      QStash 需要一个**可公网访问的 HTTPS 地址**,无法投递到 `localhost`。本地开发时请使用隧道工具（如 `ngrok`）。
    </Warning>
  </Step>

  <Step title="将任务加入队列">
    ```typescript
    import { getQueue, createJob } from "@nebutra/queue";

    const queue = await getQueue();

    await queue.enqueue(
      createJob("report", "generate", {
        tenantId: "org_123",
        reportType: "monthly",
      })
    );
    ```
  </Step>

  <Step title="注册处理器">
    ```typescript
    import { getQueue } from "@nebutra/queue";

    const queue = await getQueue();

    queue.registerHandler("report", "generate", async (job) => {
      await generateReport(job.data);
    });
    ```
  </Step>
</Steps>

未设置 `QSTASH_TOKEN` 时,`getQueue()` 会返回内存兜底实现——同样的入队/处理器 API 依旧可用,但任务不会跨进程投递,重启后也不会保留。它存在的意义是让 `pnpm dev` 和单元测试在没有配置队列的情况下也能跑起来,而不是一个生产替代方案。

## 入队与处理模式

```typescript
import { getQueue, createJob } from "@nebutra/queue";

// --- 生产者（入队）---
const queue = await getQueue();

await queue.enqueue(
  createJob(
    "email",        // 队列名
    "send",         // 任务类型
    {               // 任务数据（可序列化）
      to: "user@example.com",
      template: "invoice-paid",
      data: { invoiceId: "inv_123", amount: 99.99 },
    },
    {               // 选项（可选）
      tenantId: "org_123",
      delay: 5000,  // 投递前延迟的毫秒数
    }
  )
);

// --- 消费者（处理器）---
queue.registerHandler("email", "send", async (job) => {
  await sendEmail(job.data.to, job.data.template, job.data.data);
});
```

## 任务选项

```typescript
createJob(queueName, jobType, data, {
  tenantId: "org_123",   // 将任务限定在某个租户
  delay: 60_000,         // 60 秒后投递
  jobId: "unique-id",    // 按 ID 去重（防止重复入队）
})
```

## QStash 的特点

**优点：**
- 零基础设施——完全由 Upstash 托管
- 适用于任意部署目标,包括 Serverless / 边缘环境
- 内置带指数退避的重试
- 基于 HTTP——便于检查和调试
- 签名 Webhook——投递经过认证

**权衡：**
- 需要一个公网 Webhook 地址（不能直接用 `localhost`）
- 不支持优先级队列
- 单条消息最大 1 MB

如果你需要自托管、支持优先级调度、长驻 Worker 进程的高吞吐队列,`@nebutra/queue` 并不提供这些——按照它的接口自己写一个适配器即可（参见 ADR 的结论部分：想要已删除服务商的买家,针对保留的接口自己写适配器）。

## 死信队列（DLQ）

QStash 默认对失败的投递做指数退避重试（最多 3 次）。所有重试耗尽后,任务会被丢弃。可在 [Upstash 控制台](https://console.upstash.com) 中查看失败的投递。

```typescript
// 入队时配置重试次数
await queue.enqueue(
  createJob("report", "generate", data, { maxRetries: 5 })
);
```

## Python 支持

`@nebutra/queue` 也为微服务提供了 Python 客户端：

```python
from _shared.queue import get_queue, create_job

queue = await get_queue()

# 入队
await queue.enqueue(create_job("report", "generate", {"tenant_id": "org_123"}))

# 处理
@queue.handler("report", "generate")
async def handle_report(job):
    await generate_report(job.data["tenant_id"])
```
