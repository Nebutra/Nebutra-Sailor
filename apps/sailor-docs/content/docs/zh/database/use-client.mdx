title: 使用数据库客户端
description: 当前 `getTenantDb()`、`getSystemDb()` 与 tenant context helper 的数据库访问模式。
---

`@nebutra/db` 已不再导出裸 `db` 客户端。当前契约是显式区分：

- `getTenantDb(organizationId)` 用于 tenant-scoped 查询
- `getSystemDb()` 用于跨租户或 bootstrap 场景

这样可以让行级安全的决策直接体现在调用点上。

## 当前包面

```typescript
import { getSystemDb, getTenantDb } from "@nebutra/db";
```

实现入口位于 [`packages/platform/db/src/index.ts`](../../../packages/platform/db/src/index.ts)，
底层 lazy Prisma client 位于 `client.ts`。

## tenant-scoped 查询

当请求已经解析出 tenant 时，请使用 `getTenantDb()`：

```typescript
import { getCurrentTenant } from "@nebutra/tenant";
import { getTenantDb } from "@nebutra/db";

export async function listProjects() {
  const tenant = getCurrentTenant();
  const db = getTenantDb(tenant.id);

  return db.project.findMany({
    orderBy: { createdAt: "desc" },
  });
}
```

`getTenantDb()` 会为查询注入仓库当前 RLS 策略需要的 PostgreSQL session state，
因此应优先于到处手写 `where: { organizationId }`。

## system-scoped 查询

只有在还没有可信 tenant 上下文时才使用 `getSystemDb()`：

```typescript
import { getSystemDb } from "@nebutra/db";

export async function findOrganizationByStripeCustomer(customerId: string) {
  const db = getSystemDb();
  return db.organization.findFirst({
    where: { stripeCustomerId: customerId },
  });
}
```

典型场景：

- webhook bootstrap 阶段还未解析 tenant
- admin / 跨租户报表
- 涉及多个组织的后台作业

## Web 应用中的服务端页面

在 `apps/web` 中，页面级状态通常先通过 auth helper 推导：

```typescript
import { getTenantContext, requireAuth } from "@/lib/auth";

export default async function BillingPage() {
  await requireAuth();
  const { tenantId, plan } = await getTenantContext();

  if (!tenantId) {
    return null;
  }

  const db = getTenantDb(tenantId);
  const subscriptions = await db.subscription.findMany();

  return <pre>{JSON.stringify({ plan, count: subscriptions.length }, null, 2)}</pre>;
}
```

## Client Component

Client Component 不得直接导入 `@nebutra/db`。应通过 HTTP 边界访问：

```typescript
import { browserApiClient } from "@/lib/api/client";

const { data } = await browserApiClient.GET("/api/v1/integrations");
```

如果需要浏览器端 hook，应构建在 API client 或 route handler 之上，而不是
直接套 Prisma。

## 事务

基于 `getTenantDb()` 或 `getSystemDb()` 返回的 scoped client 执行事务：

```typescript
import { getTenantDb } from "@nebutra/db";

export async function createProject(organizationId: string, userId: string) {
  const db = getTenantDb(organizationId);

  return db.$transaction(async (tx) => {
    const project = await tx.project.create({
      data: { organizationId, name: "New project" },
    });

    await tx.auditLog.create({
      data: {
        organizationId,
        actorId: userId,
        action: "project.created",
      },
    });

    return project;
  });
}
```

## 错误处理

优先将 Prisma 失败映射到共享 API error，而不是抛裸字符串：

```typescript
import { Prisma } from "@nebutra/db";
import { ConflictError } from "@nebutra/errors";

export function mapDbError(error: unknown): never {
  if (
    error instanceof Prisma.PrismaClientKnownRequestError &&
    error.code === "P2002"
  ) {
    throw new ConflictError("该唯一字段对应的记录已存在。");
  }

  throw error;
}
```
