---
title: Node.js 快速开始
description: 在 Node.js 或 Hono 后端中组合 Nebutra 当前的服务端包面。
---

仓库里已经没有独立的 `@nebutra/sdk` Node 包。服务端集成的方式是组合若干
聚焦包，例如 `@nebutra/logger`、`@nebutra/agents`、`@nebutra/permissions`
和 `@nebutra/db`。

## 第一步：安装聚焦的服务端包

```bash
pnpm add @nebutra/logger @nebutra/agents @nebutra/permissions @nebutra/db
```

只安装你的服务真正需要的部分。

## 第二步：先接入结构化日志

```typescript
import { logger } from "@nebutra/logger";

logger.info("worker.started", { service: "reporting" });
```

长期运行的服务不要使用 `console.log`，否则日志路由与租户元数据会和平台
其余部分脱节。

## 第三步：AI 生成通过 `@nebutra/agents`

```typescript
import { generateText } from "@nebutra/agents";

const result = await generateText({
  model: "openai/gpt-4.1-mini",
  prompt: "总结最近 24 小时的用量异常。",
});
```

## 第四步：显式做权限判断

```typescript
import { createPermissionChecker } from "@nebutra/permissions";

const checker = createPermissionChecker({
  role: "admin",
});

const allowed = checker.can("billing:manage");
```

要与 UI 暴露的 permission model 保持一致，不要把客户端门控当成服务端授权。

## 第五步：区分 tenant-scoped 与 system-scoped DB 访问

```typescript
import { getSystemDb, getTenantDb } from "@nebutra/db";

const tenantDb = getTenantDb("org_123");
const systemDb = getSystemDb();
```

- `getTenantDb()` 适用于 request-scoped tenant 数据
- `getSystemDb()` 适用于管理任务、webhook bootstrap、跨租户作业

## 第六步：优先把后端代码放进 Hono gateway

在这个仓库中，新产品后端工作默认进入 `backends/gateway/`：

```typescript
import { OpenAPIHono } from "@hono/zod-openapi";

const app = new OpenAPIHono();
```

当前 gateway 已经承载 auth、tenancy、billing、integrations 与 webhooks，
应优先扩展这里，而不是再平行造一套运行时。
