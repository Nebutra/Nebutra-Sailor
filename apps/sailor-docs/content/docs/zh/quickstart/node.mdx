没有托管的 Nebutra API，也没有 `@nebutra/sdk` 包。如果你有一个 `apps/web` 之外的 Node.js 服务
需要跟脚手架项目的网关通信，像调用任何其他内部服务一样直接走 HTTP。

## 服务间认证

内部调用用一个短期有效的 HS256 JWT（`x-service-token`），由 `@nebutra/auth` 的
`signServiceToken` / `verifyServiceToken` 签发和校验，背后是共享的 `SERVICE_SECRET`。这不是终端
用户的会话 token——它认证的是一个受信任的内部调用方。

```typescript
import { signServiceToken } from "@nebutra/auth";

const token = signServiceToken({ service: "my-node-worker" });

const res = await fetch("https://your-gateway-host/api/v1/ai/models", {
  headers: { "x-service-token": token },
});
```

如果你的 Node 服务在 monorepo 之外，没法直接导入 `@nebutra/auth`，就用同样的
`SERVICE_SECRET` 和 claim 结构手动签一个 HS256 JWT——网关的 `verifyServiceToken` 只要签名正确
就认，不要求 token 必须由这个包签发。

## 代表终端用户调用网关

如果请求是代表某个已登录用户发起的（而不是受信任的内部服务），转发 Better Auth 的会话
Cookie 或 bearer token，跟 `apps/web` 的做法一样——这里没有单独的 API key 方案。
