---
title: React 快速开始
description: 在 React 应用中复用 Nebutra 的权限与 UI 包，而不是依赖一个并不存在的浏览器 SDK。
---

Nebutra-Sailor 当前 **不会** 发布独立的 `@nebutra/react` 包。对于纯 React
应用，推荐模式是：

- 由宿主应用自己维护 auth / session
- 通过你自己的后端或类型化客户端调用 Nebutra HTTP surface
- 复用 `@nebutra/permissions`、`@nebutra/ui` 这类聚焦包

## 第一步：安装真正需要的包

```bash
pnpm add @nebutra/ui @nebutra/permissions
```

如果你的 React 应用还要承载服务端 AI 功能，请在服务端 runtime 中加入
`@nebutra/agents`，不要放进浏览器 bundle。

## 第二步：渲染共享 UI 原语

```tsx
import { Button } from "@nebutra/ui/components";
import { EmptyState, PageHeader } from "@nebutra/ui/layout";

export function BillingPage() {
  return (
    <div className="space-y-6">
      <PageHeader title="Billing" description="管理用量与订阅状态。" />
      <Button>Upgrade</Button>
      <EmptyState title="暂无发票" description="完成结账后会在这里看到发票。" />
    </div>
  );
}
```

## 第三步：用权限感知组件门控 UI

`@nebutra/permissions` 暴露了 React 子路径，可用于 UI 层的权限检查：

```tsx
import { PermissionGate } from "@nebutra/permissions/react";

export function DeleteButton() {
  return (
    <PermissionGate require="project:delete">
      <button type="button">删除项目</button>
    </PermissionGate>
  );
}
```

这只是一层展示逻辑。真正的写操作仍需在服务端再次验证权限。

## 第四步：通过服务端拥有的边界拉取数据

客户端 React 代码应通过你自己的 route handler / API 层获取数据，而不是
调用一个虚构的 Nebutra 浏览器 SDK：

```tsx
import { useEffect, useState } from "react";

export function useIntegrations() {
  const [items, setItems] = useState([]);

  useEffect(() => {
    fetch("/api/integrations")
      .then((res) => res.json())
      .then((payload) => setItems(payload.integrations ?? []));
  }, []);

  return items;
}
```

## 第五步：tenant 与权限状态放在服务端

如果 React 应用后端由 Nebutra-Sailor 提供，请在服务端解析 tenant / scope，
只把最小必要 UI 状态传给浏览器：

```tsx
type ViewerState = {
  tenantId: string;
  plan: string;
  scopes: string[];
};
```

这样可以避免把内部 auth / data-access 假设泄露到前端。
