没有一个独立的 Nebutra 产品需要你去"集成"——`create-sailor` 生成的 `apps/web` 就是一个
Next.js 16 App Router 项目，它**就是你的应用**。这页讲的是已经接好的那些部分。

## 生成项目

```bash
npx create-sailor my-app
cd my-app
pnpm install
pnpm dev
```

`pnpm dev` 会在 `localhost:3001` 启动零 key 预览（本地 PGlite 数据库，演示登录
`admin@example.com` / `preview-demo`），营销站在 `localhost:3000`。见[安装](/zh/getting-started/installation)。

## 在 Server Component 里读取当前会话

Better Auth 是唯一的认证服务商（没有 Clerk/NextAuth/Supabase 适配器——
[ADR 2026-09-24](https://github.com/nebutra/nebutra-sailor/blob/main/docs/architecture/2026-09-24-sailor-convergence.md)）。Server Component 直接读会话：

```typescript app/dashboard/page.tsx
import { redirect } from "next/navigation";
import { auth } from "@/lib/auth"; // 你项目里的 Better Auth 实例
import { headers } from "next/headers";

export default async function DashboardPage() {
  const session = await auth.api.getSession({ headers: await headers() });

  if (!session) {
    redirect("/sign-in");
  }

  return <h1>Welcome, {session.user.name}</h1>;
}
```

## 用权限控制 UI 和操作

`@nebutra/permissions` 在进程内包了一层 CASL，做 RBAC/ABAC 检查：

```tsx
import { Can } from "@nebutra/permissions/react";

<Can action="delete" resource="Project" subject={project}>
  <DeleteButton />
</Can>
```

```typescript app/actions/delete-project.ts
"use server";
import { requirePermission } from "@nebutra/permissions";

export async function deleteProject(projectId: string) {
  await requirePermission("delete", "Project"); // 没有对应权限就抛 403
  // ...
}
```

## 调用网关

业务端点都在 `backends/gateway`（Hono）里，默认挂载在 `app/api/[[...route]]`
（`GATEWAY_MODE=embedded`）。像调用同源 API 路由一样调用它：

```typescript
const res = await fetch("/api/v1/ai/models");
```

新增端点用 CLI 而不是新建 Next 路由处理器——`apps/web` 的路由处理器被冻结在"Next 本身需要的"
范围内（认证回调、OG 路由等）：

```bash
nebutra generate route projects
```
