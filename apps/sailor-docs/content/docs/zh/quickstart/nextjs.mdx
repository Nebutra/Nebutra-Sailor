title: Next.js 快速开始
description: 使用当前认证、UI 和类型化 API surface 构建 Nebutra 风格的 Next.js 16 应用。
---

本页反映的是 **当前** Nebutra-Sailor 接入方式。仓库里已经没有单一的
`@nebutra/sdk` 浏览器包。现代 Next.js 集成通常使用：

- `@nebutra/auth` 负责认证 runtime
- `@nebutra/ui` 提供 UI 原语和布局
- `apps/web/src/lib/api/client.ts` 中的生成型 API 客户端
- `requireAuth()`、`getTenantContext()` 这类应用层 helper

## 第一步：从正确的结构开始

在这个 monorepo 中，已认证应用位于：

```text
apps/web/src/app/[locale]/(app)/
```

共享 app shell 挂载在：

```text
apps/web/src/app/[locale]/(app)/layout.tsx
```

## 第二步：使用共享认证 helper

服务端页面保护由 `apps/web/src/lib/auth.ts` 提供：

```typescript
import { requireAuth, getTenantContext } from "@/lib/auth";

export default async function WorkspacePage() {
  await requireAuth();
  const { tenantId, plan } = await getTenantContext();

  return (
    <div>
      <h1>Workspace</h1>
      <p>Tenant: {tenantId}</p>
      <p>Plan: {plan}</p>
    </div>
  );
}
```

## 第三步：用共享 UI 原语渲染页面

```tsx
import { Card, PageHeader } from "@nebutra/ui/layout";

export default function Example() {
  return (
    <div className="space-y-6">
      <PageHeader title="Analytics" description="增长与使用情况指标。" />
      <Card className="p-6">Dashboard content</Card>
    </div>
  );
}
```

## 第四步：通过类型化客户端调用网关

支持的客户端位于 `apps/web/src/lib/api/client.ts`：

```typescript
import { getTypedApi } from "@/lib/api/client";

export default async function ModelsPage() {
  const api = await getTypedApi();
  const { data, error } = await api.GET("/api/v1/ai/models");

  if (error) {
    throw new Error("Failed to load models");
  }

  return <pre>{JSON.stringify(data, null, 2)}</pre>;
}
```

对于 Client Component，请使用 `browserApiClient`，而不是调用一个虚构的
SDK 对象：

```typescript
import { browserApiClient } from "@/lib/api/client";

const response = await browserApiClient.GET("/api/v1/integrations");
```

## 第五步：在当前 route group 中添加页面

在 `[locale]/(app)` 下创建新页面：

```bash
mkdir -p 'apps/web/src/app/[locale]/(app)/my-section'
```

```typescript
// apps/web/src/app/[locale]/(app)/my-section/page.tsx
import { PageHeader } from "@nebutra/ui/layout";
import { requireAuth } from "@/lib/auth";

export default async function MySectionPage() {
  await requireAuth();

  return (
    <div className="space-y-6">
      <PageHeader title="My Section" description="Built on the shared app shell." />
    </div>
  );
}
```

## 第六步：遵守 feature flag 与 product capability

app shell 会通过 `resolveWebProductCapabilities()` 推导 workspace、billing、
notifications 等行为：

```typescript
import { resolveWebProductCapabilities } from "@/lib/product-capabilities";

const capabilities = resolveWebProductCapabilities();
```

如果新页面依赖 billing、notifications 或 workspace mode，请在页面逻辑中
显式处理这些前提，而不是假设所有租户共享同一种 dashboard 结构。

## 第七步：网关契约变化时重新生成 API 类型

```bash
pnpm --filter @nebutra/gateway generate:spec
pnpm generate:api-types
```

这会刷新 `getTypedApi()` 与 `browserApiClient` 所依赖的 `paths` 合约。
