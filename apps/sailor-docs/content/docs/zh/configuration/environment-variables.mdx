## 验证机制

所有变量在启动时由 `@nebutra/config` 进行验证（`packages/platform/config/src/index.ts`）。缺失或为空的必填变量会导致立即退出，并输出描述性错误信息。缺失的可选变量将使用文档中记录的默认值。

<Note>
  以 `NEXT_PUBLIC_` 为前缀的变量会被打包进客户端 JavaScript 中，对终端用户可见。切勿在 `NEXT_PUBLIC_` 变量中存放密钥。
</Note>

## 数据库

| 变量 | 是否必填 | 默认值 | 说明 |
|------|----------|--------|------|
| `DATABASE_URL` | 是 | — | 完整的 PostgreSQL 连接字符串。格式：`postgresql://user:pass@host:5432/nebutra` |

```bash .env.local
DATABASE_URL=postgresql://postgres:password@localhost:5432/nebutra
```

<Tip>
  在本地开发中，`pnpm infra:up` 会在端口 5432 上启动 PostgreSQL 16 实例，用户名为 `postgres`，密码为 `password`。
</Tip>

## 身份验证

Better Auth 是唯一的认证服务商——Sailor Convergence ADR（2026-09-24）移除了 Clerk、NextAuth 和 Supabase 认证适配器。未设置 `BETTER_AUTH_SECRET` 时,认证会降级为开发环境兜底(`nebutra status` 会将其报告为 `local-fallback`),而不是切换到另一个服务商。

| 变量 | 是否必填 | 默认值 | 说明 |
|------|----------|--------|------|
| `AUTH_PROVIDER` | 否 | `better-auth` | 服务端认证提供商。`better-auth` 是唯一的真实选项(或本地兜底的 `dev`)。 |
| `NEXT_PUBLIC_AUTH_PROVIDER` | 否 | `better-auth` | 客户端可见的认证提供商。应与 `AUTH_PROVIDER` 保持一致。 |
| `BETTER_AUTH_SECRET` | 若要启用真实的认证后端 | — | Better Auth 自托管签名密钥。可用 `openssl rand -base64 32` 生成。**auth 与各 RP 必须一致**。 |
| `BETTER_AUTH_URL` | 若要启用真实的认证后端 | — | 提供 `/api/auth/*` 的登录中心源站。生产：`https://auth.nebutra.com`。 |
| `NEXT_PUBLIC_AUTH_URL` | 拆分登录中心时 | — | 客户端跳转 / SDK baseURL 使用的登录中心 URL，通常与 `BETTER_AUTH_URL` 相同。 |
| `AUTH_COOKIE_DOMAIN` | 多子域生产 | — | 共享 Cookie 父域（如 `.nebutra.com`），使 `app` 与 `auth` 共享会话。 |
| `SERVICE_SECRET` | 是（网关 / S2S） | — | 内部 `x-service-token` HS256 JWT 密钥。不是终端用户会话密钥。 |
| `AUTH_SSO_DISCOVERY_PROVIDERS` | 启用企业 SSO 发现时 | — | 将邮箱域名映射到 SSO provider 的 JSON 数组。Feishu 条目使用 `/api/auth/oauth/feishu`；generic 条目必须定义内部 `loginUrl`。 |
| `FEISHU_APP_ID` | 启用飞书/Lark SSO 时 | — | Better Auth generic OAuth 使用的飞书/Lark App ID。 |
| `FEISHU_APP_SECRET` | 启用飞书/Lark SSO 时 | — | 飞书/Lark App Secret。切勿暴露为 `NEXT_PUBLIC_`。 |
| `FEISHU_OAUTH_SCOPES` | 否 | `contact:user.email contact:user.base:readonly` | 向飞书/Lark 请求的 OAuth scope，支持空格或逗号分隔。 |
| `FEISHU_ALLOWED_TENANT_KEYS` | 否 | — | 可选的飞书 tenant key 白名单，用于限制本部署接受的租户。 |
| `FEISHU_REDIRECT_URI` | 否 | — | 可选覆盖。Better Auth 默认回调为 `/api/auth/oauth2/callback/feishu`。 |
| `GOOGLE_CLIENT_ID` | 启用 Google OAuth 时 | — | Better Auth 使用的 Google OAuth Web Client ID。 |
| `GOOGLE_CLIENT_SECRET` | 启用 Google OAuth 时 | — | Better Auth 使用的 Google OAuth Web Client Secret。 |
| `GITHUB_CLIENT_ID` | 启用 GitHub OAuth 时 | — | Better Auth 使用的 GitHub OAuth App Client ID。 |
| `GITHUB_CLIENT_SECRET` | 启用 GitHub OAuth 时 | — | GitHub OAuth App Client Secret。 |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | 启用 Google One Tap 时 | — | Landing 页 One Tap 提示使用的公开 Google OAuth Web Client ID。 |
| `NEXT_PUBLIC_ENABLE_GOOGLE_ONE_TAP` | 否 | `true` | 设置为 `false` 可关闭 Landing 页 One Tap 提示。 |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | 展示 Turnstile 时 | — | 登录中心表单使用的 Cloudflare Turnstile site key。 |
| `TURNSTILE_SECRET_KEY` / `TURNSTILE_SECRET` | 强制 Turnstile 时 | — | `siteverify` 服务端密钥。未配置时跳过校验。 |
| `NEXT_PUBLIC_AUTH_MAGIC_LINK` | 否 | 关闭 | 设为 `1` / `true` 时在登录中心展示魔法链接入口。 |
| `NEXT_PUBLIC_AUTH_PASSKEYS` | 否 | 关闭 | 设为 `1` / `true` 时展示 Passkey 按钮与条件 UI。 |
| `PASSKEY_RP_ID` | 否 | auth 主机名 | WebAuthn RP ID 覆盖（默认登录中心主机）。 |
| `PASSKEY_ORIGIN` | 否 | auth 源站 | WebAuthn origin 覆盖（默认登录中心源站）。 |
| `NEBUTRA_LANDING_ORIGIN` | Landing 页 One Tap 启用时 | — | 允许 POST 到 `/api/auth/google-one-tap` 的 Landing 源站。 |
| `NEBUTRA_SESSION_HINT_DOMAIN` | 否 | — | 可选的跨子域轻量会话提示 Cookie 域。 |

<CodeGroup>
```bash .env.local（开发环境）
AUTH_PROVIDER=better-auth
NEXT_PUBLIC_AUTH_PROVIDER=better-auth
BETTER_AUTH_SECRET=local-dev-secret
BETTER_AUTH_URL=http://localhost:3101
NEXT_PUBLIC_AUTH_URL=http://localhost:3101
GOOGLE_CLIENT_ID=xxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=xxx
NEXT_PUBLIC_GOOGLE_CLIENT_ID=xxx.apps.googleusercontent.com
```
```bash .env（生产 — Nebutra.com / Better Auth）
AUTH_PROVIDER=better-auth
NEXT_PUBLIC_AUTH_PROVIDER=better-auth
BETTER_AUTH_SECRET=...                 # apps/auth 与 apps/web 相同
BETTER_AUTH_URL=https://auth.nebutra.com
NEXT_PUBLIC_AUTH_URL=https://auth.nebutra.com
AUTH_COOKIE_DOMAIN=.nebutra.com
DATABASE_URL=postgresql://...
SERVICE_SECRET=...
GOOGLE_CLIENT_ID=xxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=xxx
GITHUB_CLIENT_ID=...
GITHUB_CLIENT_SECRET=...
NEXT_PUBLIC_TURNSTILE_SITE_KEY=0x4AAAAA...
TURNSTILE_SECRET_KEY=0x4AAAAA...
# 可选 UX 开关：
# NEXT_PUBLIC_AUTH_MAGIC_LINK=1
# NEXT_PUBLIC_AUTH_PASSKEYS=1
# PASSKEY_RP_ID=auth.nebutra.com
# PASSKEY_ORIGIN=https://auth.nebutra.com
```
```bash .env（飞书/Lark SSO）
AUTH_PROVIDER=better-auth
NEXT_PUBLIC_AUTH_PROVIDER=better-auth
BETTER_AUTH_SECRET=...
BETTER_AUTH_URL=https://auth.nebutra.com
NEXT_PUBLIC_AUTH_URL=https://auth.nebutra.com
AUTH_COOKIE_DOMAIN=.nebutra.com
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_OAUTH_SCOPES="contact:user.email contact:user.base:readonly"
AUTH_SSO_DISCOVERY_PROVIDERS='[{"domain":"example.cn","id":"example-feishu","name":"Example Feishu","type":"oidc","provider":"feishu"}]'
```
</CodeGroup>

<Note>
  OAuth 回调 URI 必须指向**登录中心**源站，例如
  `https://auth.nebutra.com/api/auth/callback/google` 与
  `https://auth.nebutra.com/api/auth/callback/github`。
  `GET https://auth.nebutra.com/health` 会返回当前启用的 `oauth.callbackUrls`。
</Note>

## 存储

一个 S3 兼容客户端同时覆盖 R2 和阿里云 OSS——两者不需要分别配置独立的 provider。`UPLOAD_PROVIDER` 用来显式指定后端;不设置时会根据下面哪些凭据存在自动检测(优先 R2,其次 AWS,再其次自定义 S3 兼容端点),最后兜底为本地磁盘。

| 变量 | 是否必填 | 默认值 | 说明 |
|------|----------|--------|------|
| `UPLOAD_PROVIDER` | 否 | 自动检测 | `s3`(或其别名 `r2`)强制使用 S3 兼容 provider;不设置时按下方凭据自动检测;否则兜底为 `local`。 |
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | 否 | — | Cloudflare R2 凭据——最先检查。 |
| `R2_ENDPOINT` / `R2_PUBLIC_URL` | 否 | — | R2 端点与公开 CDN URL 覆盖项。 |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | 否 | — | AWS S3 凭据——仅在未设置 R2 凭据时检查。 |
| `AWS_REGION` | 否 | `us-east-1` | S3 的 AWS 区域。 |
| `S3_ENDPOINT` / `S3_PUBLIC_URL` | 否 | — | 自定义 S3 兼容端点(阿里云 OSS、MinIO 等)及其公开 URL。 |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | 否 | — | 兜底凭据名,仅在 `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` 未设置且设置了 `S3_ENDPOINT` 时使用。 |

<Info>
  完全没有配置存储凭据时,上传的文件会写入服务器文件系统的 `./uploads` 目录(`nebutra status` 会将其报告为 `local-fallback`)。这仅适用于本地开发——本地存储在部署间不会持久化。
</Info>

<Note>
  Vercel Blob 已根据 Sailor Convergence ADR(2026-09-24)移除——不存在 `blob` provider。任何对象存储形态的需求都走上面的 S3 兼容客户端。
</Note>

## Redis

| 变量 | 是否必填 | 默认值 | 说明 |
|------|----------|--------|------|
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | 否 | — | 通过 Upstash REST 协议使用 Redis——生产环境的缓存路径,最先检查。 |
| `REDIS_URL` | 否 | — | 直连 `ioredis` 的连接字符串——自托管 Redis(例如放在 Serverless Redis HTTP 代理后面)。在未设置 Upstash REST 变量时用于缓存和限流。示例：`redis://localhost:6379`。 |

<Tip>
  `pnpm infra:up` 会在端口 6379 上启动 Redis 7。`pnpm infra:lite` 仅启动 PostgreSQL，不包含 Redis。
</Tip>

## 队列（QStash）

QStash 是唯一的队列后端——BullMQ 已根据 Sailor Convergence ADR(2026-09-24)移除。未设置 `QSTASH_TOKEN` 时,队列会降级为内存兜底(`nebutra status` 会将其报告为 `local-fallback`),而不是切换到自托管的消息代理。

| 变量 | 是否必填 | 默认值 | 说明 |
|------|----------|--------|------|
| `QSTASH_TOKEN` | 若要启用真实队列 | — | Upstash QStash REST 令牌。 |
| `QSTASH_CURRENT_SIGNING_KEY` | 若要启用真实队列 | — | 用于载荷验证的当前 Webhook 签名密钥。 |
| `QSTASH_NEXT_SIGNING_KEY` | 若要启用真实队列 | — | 密钥轮换期间使用的下一个签名密钥。 |
| `QSTASH_CALLBACK_BASE_URL` | 若要启用真实队列 | — | QStash 投递 Webhook 回调的公开基础 URL。示例：`https://api.nebutra.com`。 |

## 生成密钥

对于需要加密随机值的密钥：

```bash
openssl rand -base64 32
```

每个环境（开发、预览、生产）请使用独立的密钥值，切勿跨环境复用。
