## 配置的工作原理

Nebutra-Sailor 在应用启动时通过 `@nebutra/config` 包对每个环境变量进行验证。如果某个**必填**变量缺失或格式错误，进程会立即退出，并输出清晰的错误信息，明确指出有问题的变量名——不存在静默回退。

```
Error: [config] Missing required environment variable: DATABASE_URL
  at validateConfig (packages/platform/config/src/index.ts:42)
```

这种快速失败的模式确保部署问题在数秒内暴露，而不是在生产环境运行数小时后才出现运行时错误。

验证的唯一来源位于 `packages/platform/config/src/index.ts`。每个应用都从此包导入，因此配置变更会自动同步到所有应用。

## 三类变量

<Tabs>
  <Tab title="必填">
    缺少这些变量时，**应用将无法启动**。它们涵盖核心基础设施：数据库连接、身份验证提供商、支付处理器和事务性邮件。

    完整列表请参见[环境变量](/zh/configuration/environment-variables)。
  </Tab>
  <Tab title="可选">
    这些变量提供合理的默认值，可用于本地开发。在生产环境中，应使用真实的服务凭据覆盖它们。

    示例包括：存储提供商选择、AI 模型密钥、Redis URL 和分析令牌。
  </Tab>
  <Tab title="功能开关">
    脚手架中不存在功能开关这项能力。此前的 `--feature-flags` 脚手架标志及其服务商选项已被移除,也没有任何东西替代——可替代方案见[功能开关](/zh/configuration/feature-flags)。
  </Tab>
</Tabs>

## 变量的设置位置

<Steps>
  <Step title="本地开发 — .env.local">
    在仓库根目录（或各应用目录）创建 `.env.local` 文件。该文件默认已被 gitignore。

    ```bash
    cp .env.example .env.local
    # 填入您的值
    ```

    <Warning>
      切勿将 `.env`、`.env.local` 或任何包含真实密钥的文件提交到 git。仓库的 `.gitignore` 已排除这些文件，但每次提交前请务必再次确认。
    </Warning>
  </Step>
  <Step title="生产 / 预览环境 — 由具体部署目标自己的机制管理">
    模板不内置任何部署目标——它产出的是可移植的构建结果（Next `standalone` 构建 +
    `Dockerfile.web` + `docker-compose.yml`）。无论把这份产物跑在哪里，都通过那个平台自己的环境变量机制
    （控制台、密钥管理服务、`--env-file` 等）设置生产环境的值。
  </Step>
  <Step title="自托管 / Docker">
    通过 Docker Compose env 文件或 Kubernetes Secret 传入变量：

    ```yaml docker-compose.yml
    services:
      web:
        env_file:
          - .env.production
    ```

    或直接注入：

    ```bash
    docker run --env-file .env.production nebutra/web:latest
    ```
  </Step>
</Steps>

## 生成密钥

对于需要加密随机值的密钥（如 `BETTER_AUTH_SECRET`、`SERVICE_SECRET`、签名密钥）：

```bash
openssl rand -base64 32
```

请勿在不同环境中复用同一密钥。

<Info>
  以 `NEXT_PUBLIC_` 为前缀的变量会在构建时嵌入到客户端包中，对终端用户可见。切勿在 `NEXT_PUBLIC_` 变量中存放密钥。
</Info>
