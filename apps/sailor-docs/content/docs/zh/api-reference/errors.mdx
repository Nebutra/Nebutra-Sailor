## 错误封装

网关的 `app.onError` 处理器（`backends/gateway/src/app.ts`）用 `@nebutra/errors` 的
`toApiError()` 转换每一个抛出的错误：

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Human-readable description of what went wrong.",
    "details": { "suggestion": "..." }
  },
  "requestId": "req_..."
}
```

只有调用方发了 `x-request-id` 请求头时才会有 `requestId`。只有底层 `AppError` 带了 metadata
或 suggestion 时才会有 `details`。这里没有 `success` 字段——2xx 状态码就是成功，非 2xx 加上这个
封装就是失败。

没有匹配路由的 404（而不是主动抛出的 `NOT_FOUND` 错误）返回的是 Hono `notFound` 处理器给的更
简单的形状：`{ "error": "Not Found", "path": "..." }`。

## 错误码

来自 `@nebutra/errors` 的 `ERROR_CODES`（`packages/platform/errors/src/index.ts`）：

### 4xx——客户端错误

| 错误码 | 常见状态码 |
|------|------|
| `BAD_REQUEST` | 400 |
| `VALIDATION_ERROR` | 400/422（取决于抛出位置） |
| `UNAUTHORIZED` | 401 |
| `FORBIDDEN` | 403 |
| `NOT_FOUND` | 404 |
| `CONFLICT` | 409 |
| `RATE_LIMITED` | 429 |
| `QUOTA_EXCEEDED` | 429 |

### 5xx——服务端错误

| 错误码 | 常见状态码 |
|------|------|
| `INTERNAL_ERROR` | 500 |
| `DATABASE_ERROR` | 500 |
| `SERVICE_UNAVAILABLE` | 503 |
| `EXTERNAL_SERVICE_ERROR` | 502 |
| `TIMEOUT` | 504 |

### 业务错误

| 错误码 | 含义 |
|------|------|
| `PAYMENT_REQUIRED` | 需要先完成计费操作才能继续 |
| `SUBSCRIPTION_EXPIRED` | 租户订阅已过期 |
| `FEATURE_DISABLED` | 当前套餐不包含此权益（见 `@nebutra/billing` 的 `checkEntitlement`） |
| `TENANT_SUSPENDED` | 租户已被暂停 |

每个错误实际的 HTTP 状态码来自 `getStatusCode(error)`，它读的是 `AppError` 自己的
`statusCode`——上表只是典型情况，不是对某个错误码的硬性保证。

## 支持

在 [GitHub](https://github.com/nebutra/nebutra-sailor/issues) 上带着 `requestId` 和请求
路径/方法提 issue。作为自托管模板，没有单独的 Nebutra 支持台——部署出去的服务归你自己管理。
