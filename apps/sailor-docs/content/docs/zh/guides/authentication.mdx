## 认证服务商

Better Auth 是 Sailor 技术栈中唯一的认证服务商。Sailor Convergence ADR(2026-09-24)移除了此前 `@nebutra/auth` 可切换的 Clerk、NextAuth/Auth.js 和 Supabase Auth 适配器——现在没有别的可选,`AUTH_PROVIDER` 除了 `better-auth`(或未设置 `BETTER_AUTH_SECRET` 时的本地兜底 `dev`)之外没有其他值。

请保持 `AUTH_PROVIDER` 与 `NEXT_PUBLIC_AUTH_PROVIDER` 一致,这样服务端路由、中间件、React hooks 和 Landing 页会解析到同一个服务商。

```bash
# .env
AUTH_PROVIDER=better-auth
NEXT_PUBLIC_AUTH_PROVIDER=better-auth
```

未设置 `BETTER_AUTH_SECRET` 时,应用会运行在 `dev` 兜底上——合成用户和工作区,适合本地预览,生产环境会被硬性禁用。`nebutra status` 会将其报告为 `local-fallback`。

## Google One Tap

Landing 页的 One Tap 实现是 Better Auth 自带的客户端 `oneTapClient`,会 POST 到 `/api/auth/one-tap/callback`。需要设置 `NEXT_PUBLIC_GOOGLE_CLIENT_ID`。

设置 `NEXT_PUBLIC_ENABLE_GOOGLE_ONE_TAP=false` 可关闭 Landing 页提示。
当 `ACCESS_GATE_MODE=invite` 时，OAuth 与 One Tap 入口会被封住，直到邀请码门禁放开。

## Better Auth 配置

生产 Nebutra 使用独立**登录中心**（`apps/auth` → `https://auth.nebutra.com`）：

| 变量 | 示例 |
|------|------|
| `AUTH_PROVIDER` | `better-auth` |
| `BETTER_AUTH_URL` / `NEXT_PUBLIC_AUTH_URL` | `https://auth.nebutra.com` |
| `AUTH_COOKIE_DOMAIN` | `.nebutra.com` |
| `BETTER_AUTH_SECRET` | auth 与 web 相同 |

### 单一登录入口

产品应用是 **RP**：会把认证相关路由 soft-redirect 到登录中心。Better Auth
**只有一套 UI**，不要在 `app` 上再维护第二套登录页。

| 表面 | 行为 |
|------|------|
| `app.nebutra.com/sign-in` | `307` → `auth.nebutra.com/sign-in?returnTo=…` |
| `app.nebutra.com/sign-up` | `307` → `auth.nebutra.com/sign-up?returnTo=…` |
| `auth.nebutra.com/*` | 规范登录 UI（账密、OAuth、可选魔法链接 / Passkey） |

### OAuth 回调 URI

在 IdP 中注册**登录中心**回调（不要写 `app`）：

```
https://auth.nebutra.com/api/auth/callback/google
https://auth.nebutra.com/api/auth/callback/github
```

登录中心 `GET /health` 会返回当前启用的 `oauth.callbackUrls`。

### 验证码 / 魔法链接 / Passkey

| 开关 / 环境变量 | 作用 |
|-----------------|------|
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` + `TURNSTILE_SECRET_KEY` | 表单 Cloudflare Turnstile（`x-captcha-response`） |
| `NEXT_PUBLIC_AUTH_MAGIC_LINK=1` | 登录页展示魔法链接入口 |
| `NEXT_PUBLIC_AUTH_PASSKEYS=1` | Passkey 按钮与条件 UI |
| `PASSKEY_RP_ID` / `PASSKEY_ORIGIN` | WebAuthn RP 覆盖（默认 auth 主机） |

各 RP 的 `BETTER_AUTH_SECRET` 必须一致。

### 设备授权流程（CLI 登录）

登录中心还挂载了 Better Auth 的 `deviceAuthorization` + `bearer` 插件,供 `nebutra login` 使用(参见 [nebutra CLI](/zh/cli/nebutra-cli))——这是一个独立、按需开启的表面,与上面基于 Cookie 的会话流程分开,通过 `AuthConfig.options.deviceAuthorization` 门控,因此只存在于 `apps/auth`,而不是每个构建 Better Auth 实例的应用都有。

## 网关令牌校验

Hono API 网关在受保护请求上校验 Better Auth 的会话 / Bearer 令牌。
Better Auth 使用共享密钥与数据库会话；服务间调用使用短时 **HS256**
`x-service-token`（`SERVICE_SECRET`），旧版 hex-HMAC 会被拒绝。

```typescript
app.use("/api/*", authMiddleware());

app.get("/api/projects", async (c) => {
  const { userId, orgId } = c.get("auth");
  // userId 和 orgId 已经过校验,可以安全使用
});
```

## JWT 声明内容

经过验证的用户令牌通常包含：

```json
{
  "sub": "user_2a8bXXXXXXXXX",
  "org_id": "org_2a8bXXXXXXXXX",
  "org_role": "org:admin",
  "scopes": ["project:read", "project:create"],
  "plan": "pro"
}
```

`scopes` 声明由 Nebutra 的 RBAC 层在签发令牌时设置。

## 会话管理

- 会话 Cookie 在 `auth.nebutra.com` 签发,`AUTH_COOKIE_DOMAIN=.nebutra.com`
- 仪表板等 RP 经 `returnTo` 回跳后共享同一 Cookie
- 通过登录中心的 Better Auth 会话 API 撤销 / 登出

## 多因素认证

MFA 可在组织层面强制启用(产品设置)：

- TOTP(身份验证器 App)
- 短信一次性密码(如已配置)
- Passkey(WebAuthn)——在登录中心设置 `NEXT_PUBLIC_AUTH_PASSKEYS=1` 启用

## 登录 / 注册 UI

使用 `apps/auth` 下的登录中心页面(`/sign-in`、`/sign-up`、`/forgot-password` 等)。产品应用只做跳转——不需要为每个应用单独构建或维护登录页。

## 组织创建流程

注册后没有组织的用户会被重定向到组织创建流程(Nebutra 仪表板 onboarding)。

<Warning>
  缺少组织创建路径时，用户可能长期处于 `orgId: null` 并在落地页与仪表板之间循环跳转。多租户应用务必实现该流程。
</Warning>
