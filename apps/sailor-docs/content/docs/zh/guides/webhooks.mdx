## 概述

Nebutra 的 Webhook 系统（`@nebutra/webhooks`）允许你：

1. **接收**来自 Nebutra 的事件（入站 Webhook——如 Creem、GitHub）
2. **发送**事件到你客户的系统（出站 Webhook——当产品中发生事情时）

## 出站 Webhook

### 注册端点

客户从**设置 → Webhooks → 添加端点**中注册 Webhook 端点。这里没有单独的客户端 SDK——设置页面会直接调用网关路由，由 `@nebutra/webhooks` 存储端点及其事件订阅。

### 发送事件

```typescript
import { getWebhooks } from "@nebutra/webhooks";

const webhooks = await getWebhooks();

await webhooks.sendEvent({
  id: crypto.randomUUID(),
  eventType: "invoice.paid",
  payload: { invoiceId: "inv_123", amount: 9900 },
  timestamp: new Date().toISOString(),
  tenantId: "org_123",
});
```

Nebutra 会自动处理投递、重试（指数退避）和签名。

### 投递保证

| 属性 | 值 |
|------|-----|
| 投递方式 | 至少一次 |
| 重试次数 | 6 次（指数退避，初始延迟 5 秒） |
| 签名算法 | HMAC-SHA256 |
| 负载格式 | JSON |
| 单次尝试超时 | 30 秒 |

## 入站 Webhook（接收事件）

### 验证签名

接收 Webhook 时，始终先验证签名。Nebutra 自己当前的卡支付通道（Creem，根据 [ADR 2026-09-26](https://github.com/Nebutra/Nebutra-Sailor/blob/main/docs/architecture/2026-09-26-creem-global-payments.md)）会在解析请求体之前先验证原始字节——同样的模式适用于你接收的任何入站 Webhook：

```typescript backends/gateway/src/routes/webhooks/creem.ts
import { verifyCreemSignature } from "@nebutra/billing";

export async function POST(req: Request) {
  // 按收到的原始字节验证——先解析会改变这些字节。
  const rawBody = await req.text();
  const signature = req.headers.get("creem-signature");

  if (!verifyCreemSignature(rawBody, signature)) {
    return new Response("Invalid signature", { status: 401 });
  }

  const event = JSON.parse(rawBody);

  switch (event.eventType) {
    case "checkout.completed":
      await handleCheckoutCompleted(event.object);
      break;
    case "refund.created":
      await handleRefundCreated(event.object);
      break;
  }

  return new Response("OK", { status: 200 });
}
```

<Note>
订阅相关的 Webhook（`customer.subscription.*`、`invoice.*`）目前仍从 **Stripe**（历史遗留）投递到另一个独立端点——参见[支付 Webhooks](/zh/payments/webhooks)。
</Note>

## Webhook 事件参考

| 事件 | 触发时机 |
|------|---------|
| `org.created` | 新组织创建时 |
| `member.joined` | 成员接受邀请时 |
| `member.removed` | 成员被移除时 |
| `invoice.paid` | 计费发票支付时 |
| `quota.warning` | 使用量达到配额 80% 时 |
| `quota.exceeded` | 使用量超出配额 100% 时 |

## 本地测试 Webhook

对于 Creem，设置 `CREEM_TEST_MODE=true` 并将 Webhook 指向你的本地隧道，或者使用 [ngrok](https://ngrok.com) 暴露本地服务器：

```bash
ngrok http 3000
```
