---
title: nebutra CLI
description: 统一的 Nebutra 命令行工具——在已脚手架的 Sailor 项目里查看状态、跑 dev、管数据库、做代码生成。
---

`nebutra` CLI 是在 [`create-sailor`](/docs/cli/create-sailor) 脚手架出来的项目里日常使用的工具。根据 Sailor Convergence ADR（2026-09-24），公开发布的这个包现在只服务模板购买者——运营方工具(`admin`、`community`、`growth`、`stats`)以及尚未完工的 `ecosystem` 已被移除,`create` 不再包一层 `create-sailor`(只有一个创建入口),`add` 被替换为针对声明式能力清单的 `sync`。

## 安装

```bash
# 在 monorepo 内——无需安装
pnpm exec nebutra --help

# 全局安装
npm install -g nebutra@latest
```

## 全局标志

```
--verbose            输出详细信息
--quiet              抑制非必要输出
--format <type>      输出格式：json、table、plain
--yes                跳过所有交互式提示(Agent 模式)
--no-interactive      --yes 的别名
--no-color           关闭彩色输出
```

在非 TTY 环境(CI、管道输出、agent 沙箱)下会自动隐含 `--yes`。

## 生命周期：login、status、sync

### `nebutra login`

通过设备授权流程(参照 `gh`/`vercel`)授权本机使用你的 Nebutra 账号——这不是模板项目自身的功能,而是用于模板更新与授权的**购买者身份**认证。

```bash
nebutra login                 # 打开浏览器,打印用户码,阻塞直到确认
nebutra login --json          # 打印 {verification_uri, verification_uri_complete, user_code,
                               #   expires_in, interval} 并立即以 0 退出——不阻塞
nebutra login --poll --json   # 恢复上面 --json 调用留下的待处理设备码,并阻塞直到完成
nebutra login --no-browser    # 只打印链接,不尝试打开浏览器
```

会话令牌存储在操作系统的密钥链中(找不到密钥链工具时回退到 `~/.config/nebutra/credentials.json`,权限 `0600`)。设置 `NEBUTRA_TOKEN` 可以完全跳过本地存储的令牌(用于 CI)。没有静默刷新——存储令牌过期后,重新运行 `nebutra login` 即可。

```bash
nebutra whoami                # 显示本机当前授权的身份
nebutra logout                # 清除存储的令牌
nebutra logout --all          # 清除所有本地 nebutra 配置,不止认证令牌
```

### `nebutra link` / `nebutra unlink`

```bash
nebutra link [project-id]     # 将当前项目关联到一个 Nebutra 项目 id
nebutra unlink                # 从 nebutra.config.json 中移除项目关联
nebutra unlink --force        # 删除整个 nebutra.config.json
```

### `nebutra status`

能力就绪状态的机器接口。读取 `nebutra.config.json` 中声明的 `capabilities` 列表,对每一项检查其某个可用服务商所需的环境变量是否齐全:

```bash
nebutra status
nebutra status --json
```

每项能力会汇报以下三种状态之一:

| 状态 | 含义 |
|------|------|
| `live` | 某个真实服务商所需的环境变量已全部设置 |
| `local-fallback` | 未配置服务商;正在运行本地实现(dev/console/内存) |
| `missing-key` | 未配置服务商,也没有本地兜底——该能力不可用 |

输出还包含尚未 `live` 的能力的 `next` 提示(该设置哪个环境变量)。Agent 应当读取 `status`、按 `next` 提示行动、再重新读取。

### `nebutra sync`

按 `nebutra.config.json` 中声明的能力清单,校正 `.env.example` / `.env.local`——**只涉及能力,不涉及服务商**;服务商由运行时哪些环境变量存在来决定。这取代了旧版直接写入服务商选择的 `nebutra add`。

```bash
nebutra sync              # 为已声明的能力,把缺失的环境变量键加进 .env.example;
                           #   .env.local 不存在则创建
nebutra sync --dry-run    # 预览将要添加的内容,不写入(退出码 10)
nebutra sync --json
```

`sync` 是幂等的——`.env.example` 中任何位置已存在的键都不会被改动。

## 项目初始化

### `nebutra init`

```bash
nebutra init
nebutra init --dry-run          # 预览而不写入文件(退出码 10)
nebutra init --if-not-exists    # nebutra.config.json 已存在则跳过
```

### `nebutra doctor`

检查 Node 版本、`nebutra.config.json`/`package.json` 是否存在、`.env` 是否存在,以及 monorepo 布局漂移(旧版 `apps/api-gateway/` vs `backends/gateway/`、未分类的 `packages/<name>/`)。

```bash
nebutra doctor
```

## 数据库

```bash
nebutra db generate                # 重新生成 Prisma 客户端
nebutra db migrate                 # 运行待执行的迁移
nebutra db push                    # 将 schema 推送到数据库(不生成迁移文件)
nebutra db seed                    # 填充测试数据
nebutra db studio                  # 启动 Prisma Studio GUI
nebutra db reset --yes             # ⚠️ 重置整个数据库
nebutra db status                  # 显示迁移状态
```

**标志：** `--dry-run`、`--yes`、`--format <json|plain>`

## 基础设施

Docker Compose 基础设施管理(PostgreSQL、Redis,以及任何按 profile 门控的附加服务):

```bash
nebutra infra up                    # 启动完整栈
nebutra infra up --lite             # 仅 PostgreSQL + Redis
nebutra infra up --profile <name>
nebutra infra down
nebutra infra status
nebutra infra logs [service]
nebutra infra reset --yes           # ⚠️ 移除所有容器和卷
```

**标志：** `--dry-run`、`--yes`、`--lite`、`--profile <name>`、`--format <json|plain>`

## 环境变量

```bash
nebutra env validate       # 检查 .env.example 要求的变量是否已设置
nebutra env template       # 基于 .env.example 交互式生成 .env.local
nebutra env template --yes # 非交互模式
nebutra env diff           # 对比 .env.local 与 .env.example
nebutra env show            # 显示当前变量(KEY/TOKEN/SECRET/PASSWORD 会被打码)
```

**标志：** `--dry-run`、`--yes`、`--format <json|plain>`

## Dev、build、lint、typecheck

```bash
nebutra dev                     # 启动 dev 服务器(turbo dev)
nebutra dev --app=web           # 只启动单个 app
nebutra build                   # 构建所有 app
nebutra build --strict          # 附带 UI 治理校验的构建
nebutra lint                    # Biome lint
nebutra lint --fix
nebutra typecheck
```

以上四个命令均支持 `--app <name>` 和 `--dry-run`(退出码 10)。

## 测试

```bash
nebutra test                    # 单元测试(Vitest)
nebutra test --watch
nebutra test --coverage
nebutra test e2e                # Playwright 端到端测试
nebutra test e2e --ui
nebutra test e2e --ci
nebutra test size                # 检查产物体积
nebutra test size --why          # 详细体积构成分析
nebutra test arch                # 架构一致性测试
```

另有一个独立的顶层命令 `nebutra e2e <suite>`,对应各自配置文件的具名 Playwright 套件:

```bash
nebutra e2e smoke        # e2e/playwright.config.ts
nebutra e2e golden       # e2e/playwright.golden.config.ts
nebutra e2e sleptons     # e2e/playwright.sleptons.config.ts
nebutra e2e smoke --dry-run
```

## 代码生成

```bash
nebutra generate app my-blog                 # 生成 Next.js app
nebutra generate package notifications       # 生成 @nebutra/<name> 包
nebutra generate route projects              # 在 backends/gateway 生成 Hono 路由
nebutra generate component PricingCard \
  --variants "primary,outlined" --sizes "sm,md,lg"
```

别名：`nebutra gen`。均支持 `--dry-run` 与 `--yes`。

nebutra ui component <name>         # 打印单个组件的契约
nebutra ui validate [name]          # 校验生产证据

## 平台

```bash
nebutra services status
nebutra services logs <service>
nebutra services restart <service>
nebutra services scale <service> <n>

nebutra secrets list --tenant org_123
nebutra secrets set <key> --tenant org_123 --value ...
nebutra secrets get <key> --tenant org_123
nebutra secrets rotate <key> --tenant org_123
nebutra secrets audit --tenant org_123
nebutra secrets verify --tenant org_123
```

`secrets` 通过 `@nebutra/vault`(AWS KMS + HKDF 信封加密)管理应用层加密密钥。

## 授权许可

```bash
nebutra license activate <key>
nebutra license status
```

`license` 是对已登录身份的内部检查(见 `nebutra login`),而不是一个独立的授权流程。

## 工具类

```bash
nebutra completions bash|zsh|fish     # 安装 shell 补全
nebutra mcp                           # 为 Cursor/Windsurf/Claude Code 启动 MCP 上下文服务器
nebutra schema                        # 命令 schema(对 Agent 友好)
nebutra schema --all                  # 完整 JSON schema
nebutra schema --list                 # 列出所有命令名
nebutra schema --exit-codes           # 退出码参考
nebutra upgrade                       # 升级 CLI 本身(别名：self-update)
```

## Agent 模式

每个命令都支持 `--yes` 实现非交互执行：

```bash
nebutra init --yes
nebutra db migrate --yes
nebutra generate app analytics --yes
```

在非 TTY 环境(管道输出、CI)下 `--yes` 会自动隐含。

## Dry-run 模式

`--dry-run` 预览而不产生副作用,并以退出码 `10` 结束：

```bash
nebutra init --dry-run
nebutra sync --dry-run
nebutra generate app my-blog --dry-run
nebutra db migrate --dry-run
nebutra infra up --dry-run
```
