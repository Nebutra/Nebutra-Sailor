所有脚本均由 [Turborepo](https://turbo.build/repo) 编排，除特别说明外，均从 monorepo 根目录运行。

```bash
# 从 monorepo 根目录运行任意脚本
pnpm <script>

# 为特定包运行脚本
pnpm --filter @nebutra/ui typecheck
pnpm --filter apps/web dev
```

## 开发

| 脚本 | 说明 |
|------|------|
| `pnpm dev` | 零 key 预览环境（`scripts/dev/preview.ts`）：本地 PGlite 数据库，演示登录 `admin@example.com` / `preview-demo`，站点在 `:3000`，产品应用在 `:3001`（端口冲突时各自往后跳一千位） |
| `pnpm dev:all` | `turbo run dev`，跑所有应用——"全部启动"版本 |
| `pnpm dev:web` | 只启动产品应用（`@nebutra/web`） |
| `pnpm dev:landing` | 只启动营销站 |
| `pnpm dev:api` | 只独立启动网关 |
| `pnpm dev:auth` | 只启动 Better Auth 登录中心 |
| `pnpm dev:storybook` / `pnpm dev:docs` | 组件库 playground / 本文档站 |

<Note>
  `dev:dashboard`、`dev:ai-saas`、`dev:marketing` 这类预设过滤脚本存在于这个 monorepo 自己的
  `package.json` 里（它们指向 `@nebutra/admin`、`@nebutra/blog` 这类应用），但这些应用是
  Nebutra 自己的产品，不属于 `create-sailor` 默认脚手架——新项目里不要指望它们存在。
</Note>

## 数据库

| 脚本 | 说明 |
|------|------|
| `pnpm db:deploy` | **部署命令。** 依次跑迁移、`platform.sql` + 生成式 RLS，最后校验。 |
| `pnpm db:check` | 只读的漂移检查——`db:deploy` 的另一半 |
| `pnpm db:generate` | 重新生成 Prisma 客户端（以及 `generated/rls.sql`） |
| `pnpm db:migrate` | 创建并应用一个迁移（本地开发） |
| `pnpm db:push` | 直接推送 schema（不生成迁移，仅限本地原型开发） |
| `pnpm db:studio` | 启动 Prisma Studio GUI |

## 常用命令组合

```bash
# 完全重置（全新开始）
pnpm infra:down
pnpm infra:up
pnpm db:migrate

# 提交前检查
pnpm typecheck && pnpm lint && pnpm test

# 拉取代码后
pnpm install
pnpm db:generate
pnpm db:migrate

# Storybook 开发
pnpm --filter @nebutra/storybook dev

# 生产就绪检查
pnpm build && pnpm test && pnpm e2e
```

## Filter 语法

使用 `--filter` 定向到特定应用或包：

```bash
# 按包名
pnpm --filter @nebutra/ui typecheck
pnpm --filter @nebutra/billing test

# 按应用名（不含 @）
pnpm --filter landing dev
pnpm --filter web build

# 多个过滤器
pnpm --filter @nebutra/ui --filter @nebutra/tokens build

# 在所有包中运行脚本
pnpm -r typecheck
```

## Turborepo 缓存

Turborepo 会在本地（可选远程）缓存任务输出。缓存命中时显示 `cache hit, replaying output`。

```bash
# 强制重新执行，绕过缓存
pnpm build --force

# 远程缓存（需要 Vercel 账号）
pnpm dlx turbo login
pnpm dlx turbo link
```
