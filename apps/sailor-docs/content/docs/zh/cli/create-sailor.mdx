---

`create-sailor` 是一次性脚手架工具。它除了项目目录之外不问任何问题，直接写出收敛后的完整 Sailor 技术栈——空的 `.env` 也能直接运行。

<Note>
  Sailor Convergence ADR（2026-09-24）移除了所有“选服务商”的标志。现在只有一套栈，不再是菜单——脚手架时已经没有可配置的东西，自然也就不会配错。
</Note>

## 用法

```bash
npx create-sailor [名称]
# 或者在一个空目录里
npx create-sailor .
```

若省略 `[名称]`，向导会提示你输入项目目录（默认：`my-app`）。这个目录——或者非交互模式下的 `--yes`——是 `create-sailor` 会为你做的**唯一**决定。

## 生成内容

没有可选项，每个项目都是同一套栈：

- **前端**：Next.js 16 + Tailwind v4，Hono 网关默认以进程内挂载方式接在 `app/api/[[...route]]`（`GATEWAY_MODE=embedded`）
- **数据库**：Postgres + Prisma
- **认证**：Better Auth
- **支付**：Stripe，外加并行的微信支付 / 支付宝（ChinaPay）
- **邮件**：Resend（附带仅用于开发环境的 `console` 兜底）
- **存储**：S3 兼容对象存储（同时覆盖 R2 与阿里云 OSS）
- **队列**：QStash
- **缓存**：通过 Upstash REST 协议使用 Redis
- **监控 / 分析 / 验证码**：Sentry、PostHog、Turnstile
- **MCP**：内置上下文服务器

每项能力开箱即用本地实现——控制台打印邮件、内存队列、本地存储——所以空 `.env` 下 `pnpm dev` 就能直接跑起来。之后想让某项能力上线，加一个服务商密钥即可；`nebutra status`（见 [nebutra CLI](/docs/cli/nebutra-cli)）会报告哪些已上线、哪些在跑本地兜底、哪些还缺密钥。

面向中国大陆的部署是运行时的 locale，而不是脚手架标志：设置 `NEBUTRA_LOCALE=cn` 即可打开 ICP 备案页脚、AIGC 生成内容标识、手机号优先登录——这些能力在每个脚手架里都存在,只是运行时门控。

`foundation` 层的包（vault、audit、tenant、permissions、metering……）**不**包含在默认脚手架中。需要时显式添加；在添加之前 `nebutra status` 会将它们显示为 `preview`。

## 标志

剩下的标志都是机械性的——没有一个用来选服务商：

| 标志 | 作用 |
|------|------|
| `-p, --pm <id>` | `npm` \| `pnpm` \| `yarn` \| `bun`（根据 `PATH` 自动检测） |
| `--no-install` | 跳过依赖安装 |
| `--no-git` | 跳过 `git init` |
| `-y, --yes` | 非交互模式——采用默认项目名，跳过所有提示 |
| `--dry-run` | 只打印计划，不写入文件 |
| `--json` | 机器可读的 NDJSON 事件流 |
| `--no-color` | 关闭彩色输出 |

以前存在的每一个服务商标志——`--auth`、`--payment`、`--email`、`--storage`、`--queue`、`--search`、`--cache`、`--sms`、`--cms`、`--captcha`、`--monitoring`、`--analytics`、`--notifications`、`--webhooks`、`--feature-flags`、`--metering`、`--mcp`、`--region`,以及旧版 43 个标志中的其余部分——都已移除。克隆整个 monorepo 之后再做减法的裁剪流水线（`prune.ts`、`prune-schema.ts`、`prune-migrations.ts`）同样已移除：脚手架现在只写出收敛后的这一套栈，没有什么需要裁剪。

需要 Node.js >= 22 和 pnpm 10+（脚手架生成的项目是 pnpm + Turborepo workspace）。除非传入 `--pm`，CLI 会检查 `PATH` 上是否有 `pnpm`。

## 示例会话

```
npx create-sailor my-saas

✔ 项目创建在哪里？ … ./my-saas

⠋ 正在克隆 Nebutra-Sailor 模板到 ./my-saas...
✔ 项目 my-saas 初始化成功！

  后续步骤：
  cd my-saas
  pnpm install
  pnpm dev
```

## 脚手架后的操作

```bash
cd my-saas
pnpm install
pnpm dev
```

`pnpm dev` 在没有任何外部服务的情况下,靠本地兜底就能跑起来。要接入真实服务商,把密钥加到 `.env.local`,再跑一次 `nebutra status` 确认每项能力都已上线。

<Note>
  `create-sailor` 是一次性工具——不存在再包一层的 `nebutra create`,这就是唯一的创建入口。项目创建之后的日常任务(查看能力状态、跑迁移、管理基础设施)请使用 [`nebutra` CLI](/docs/cli/nebutra-cli)。
</Note>
