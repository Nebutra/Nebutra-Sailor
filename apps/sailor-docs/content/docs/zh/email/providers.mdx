---
title: 邮件提供商
description: 为 @nebutra/email 配置 Resend 凭证和已验证发件域名。
---

`@nebutra/email` 有两个 provider：用于真实投递的 **Resend**，以及内置的 **console** provider（`ConsoleEmailProvider`），后者只打印渲染出的邮件而不真正发送——按 ADR 2026-09-24（Sailor 收敛）保留的开发/测试兜底（Nodemailer 已被删除，console 被保留）。选择方式是自动探测：设置了 `EMAIL_PROVIDER`（`"resend"` | `"console"`）就用它，否则存在 `RESEND_API_KEY` 就选 Resend，否则用 console。测试和预览校验可以无凭证导入包——发送函数真正通过 Resend 投递时才需要 `RESEND_API_KEY`。

## Resend 配置

<Steps>
  <Step title="创建 Resend 账号">
    在 [resend.com](https://resend.com) 注册账号。免费额度足够本地开发和早期 staging 验证。
  </Step>

  <Step title="添加并验证发件域名">
    进入 **Resend dashboard → Domains → Add Domain**。

    建议使用 `mail.nebutra.com` 这类子域名，把邮件信誉和主产品域名隔离。
  </Step>

  <Step title="创建 API key">
    进入 **Resend dashboard → API Keys → Create API Key**。

    - **Name:** `nebutra-production` 或 `nebutra-staging`
    - **Permission:** sending access
    - **Domain:** 限制到已验证发件域名
  </Step>

  <Step title="设置环境变量">
    ```bash
    RESEND_API_KEY=re_...
    EMAIL_FROM=Nebutra <noreply@nebutra.com>
    ```
  </Step>

  <Step title="真实投递前验证">
    ```bash
    pnpm --filter @nebutra/email test
    pnpm mail:check
    ```

    然后使用 Resend test key 做受控投递日志验证。
  </Step>
</Steps>

## Resend test key

```bash
# .env.local — 仅开发环境
RESEND_API_KEY=re_test_...
EMAIL_FROM=Nebutra <noreply@nebutra.com>
```

<Warning>
不要在生产环境使用 test key。测试邮件不会投递给真实收件人。
</Warning>

## Console provider（开发/测试）

没有设置 `RESEND_API_KEY`——或显式设置 `EMAIL_PROVIDER=console`——时，每个发送函数都会把渲染出的主题/HTML 打印到标准输出，而不是调用 Resend。这正是 `pnpm --filter @nebutra/email test` 和 `pnpm mail:check` 能在空 `.env` 下运行的原因。

```bash
EMAIL_PROVIDER=console
```

## 域名排错

| 现象 | 可能原因 | 处理方式 |
|------|----------|----------|
| 域名一直未验证 | DNS 记录缺失或还在传播 | 检查 DNS 记录并等待传播 |
| 邮件进垃圾箱 | SPF、DKIM 或 DMARC 不完整 | 按 Resend 给出的记录补齐 |
| 运行时发送失败 | `RESEND_API_KEY` 缺失或无效 | 检查环境变量和 key 权限 |
| 发件人不对 | `EMAIL_FROM` 不属于已验证域名 | 使用已验证域名下的地址 |
