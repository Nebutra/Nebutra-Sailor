Nebutra 通过 `@nebutra/email` 发送事务邮件。当前实现以
`packages/integrations/email/src/index.ts` 里的 `EMAIL_TEMPLATE_CATALOG` 为中心：它把每个公开发送函数映射到对应的预览产物。服务商是自动探测的：显式的 `EMAIL_PROVIDER` 环境变量优先，其次是存在 `RESEND_API_KEY` 时选用 Resend，两者都没有时回退到 **console** 服务商（`ConsoleEmailProvider`），只把渲染出的邮件打印出来而不真正发送——这是 ADR 2026-09-24 收敛方案保留的开发环境兜底。

## 架构

```
Server action / route / job / webhook
  -> @nebutra/email 具名发送函数
  -> 品牌 HTML 邮件
  -> getEmailProvider() —— Resend，或开发/测试环境下的 console
  -> 用户收件箱（或 console 情况下的标准输出）
```

没有 `RESEND_API_KEY` 时，仍然可以导入包、运行契约测试和校验本地预览——它们会自动落到 console 服务商。真实投递需要 Resend 凭证。

## 快速开始

```typescript
import { sendWelcomeEmail, sendMagicLinkEmail } from "@nebutra/email";

await sendWelcomeEmail({
  to: user.email,
  firstName: user.firstName,
  orgName: org.name,
  dashboardUrl: "https://app.nebutra.com",
});

await sendMagicLinkEmail({
  to: user.email,
  magicLinkUrl: "https://app.nebutra.com/login/magic-link/abc123",
});
```

## 环境变量

| 变量 | 真实发送是否必需 | 说明 |
|------|------------------|------|
| `EMAIL_PROVIDER` | 否 | 显式覆盖：`"resend"` \| `"console"` |
| `RESEND_API_KEY` | 使用 Resend 时 | Resend API key，只在发送时读取 |
| `EMAIL_FROM` | 否 | 发件人地址，默认使用品牌配置的邮件发件人 |

<Warning>
`RESEND_API_KEY` 是密钥，不要提交到代码仓库。请放在 CI secrets 或密钥管理器中。
</Warning>

## 本地预览

用 mail-preview 工作区校验预览，不要手工改生成 HTML：

```bash
pnpm mail:check
pnpm mail:export
```

`mail:check` 校验每个目录项都有预览产物；`mail:export` 根据目录重新生成预览索引和 manifest。
