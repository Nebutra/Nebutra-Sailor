Nebutra-Sailor's theming system has three independent layers that compose together:

| Layer | Package | Responsibility |
|-------|---------|---------------|
| **Runtime tokens** | `@nebutra/tokens` | CSS variables — colors, spacing, typography |
| **Light/dark mode** | `@nebutra/tokens` (next-themes) | `ThemeProvider` + `useTheme` |
| **Brand Packages** | `@nebutra/theme` | 7 built-in design languages via the `data-brand` attribute |

## Editing CSS variables

Don't hand-edit `packages/design/tokens/styles.css` — it's a **generated build artifact**. An edit there survives until the next token build of anything depending on the package, then silently disappears (the file still parses, the token is just gone, with no error).

The single source of truth is the DTCG token source:

```
packages/design/design-tokens/tokens/
├── core.json           # primitive scales
├── themes/light.json   # ┐ semantic + elevation — always edit as a pair
└── themes/dark.json    # ┘
```

Edit there, then rebuild so the change propagates:

```bash
pnpm --filter @nebutra/design-tokens build && pnpm --filter @nebutra/tokens build
```

### Key token reference

<Tabs>
  <Tab title="Brand">
    ```css
    :root {
      --brand-primary:   var(--blue-9);    /* VI identity lock — logo, favicon, print. NOT a CTA fill */
      --brand-accent:    var(--cyan-9);    /* Accent, success highlight */
      --brand-tertiary:  #8b5cf6;          /* Infrastructure, tertiary viz */
      --brand-gradient:  135deg, var(--blue-9) 0%, var(--cyan-9) 100%;

      --primary:            225 7.7% 10.2%; /* ink — the action fill: buttons, links, focus */
      --primary-foreground: 0 0% 100%;
    }
    ```
    `--brand-primary` (`--blue-9`, `#0033FE`) is reserved for the logo, favicon, and print — its saturation is far beyond what a comfortable UI fill needs. Buttons, links, and focus rings use `--primary` (ink, near-black) instead; see the root `CLAUDE.md` for the full history of why this distinction exists.
  </Tab>
  <Tab title="Neutral scale">
    ```css
    :root {
      --neutral-1:  #ffffff;   /* App background */
      --neutral-2:  #f8fafc;   /* Subtle background */
      --neutral-7:  #d1d5db;   /* Default border */
      --neutral-11: #374151;   /* Secondary text */
      --neutral-12: #0a0a0a;   /* Primary text */
    }
    ```
  </Tab>
  <Tab title="Status colors">
    ```css
    :root {
      --status-danger:  #ef4444;              /* Errors, breaking changes */
      --status-warning: #f59e0b;              /* Improvements, pending */
      --status-success: #10b981;              /* Fixes, completed */
      --status-info:    var(--brand-primary); /* Informational */
    }
    ```
  </Tab>

## Rebrand with the palette generator

The fastest way to change the entire brand palette is the generator script. It derives both scales from two colours and hands them to the token source through `brand:apply`, so every generated file follows:

<Steps>
  <Step title="Run the palette generator">
    ```bash
    node scripts/generate-palette.mjs --primary=#7C3AED --secondary=#F59E0B
    ```
    Pass any valid hex color for `--primary` (main brand) and `--secondary` (accent).
  </Step>
  <Step title="Apply it to the token source">
    Paste the printed `colors` block into `brand.config.ts`, then run:
    ```bash
    pnpm brand:apply
    ```
  </Step>
  <Step title="Restart the dev server">
    ```bash
    pnpm --filter @nebutra/landing dev
    # or
    pnpm --filter @nebutra/web dev
    ```
    Hot reload does not pick up changes to `styles.css` in all cases; a full restart is safer.
  </Step>
  <Step title="Verify in Storybook">
    ```bash
    pnpm --filter @nebutra/storybook dev
    ```
    Navigate to **Design Tokens** → **Brand Colors** to confirm the new palette rendered correctly across all scales.
  </Step>
</Steps>

### Manual rebranding example

If you prefer to edit tokens by hand:

```json
// packages/design/design-tokens/tokens/core.json (excerpt)
{
  "blue": { "9": { "$value": "#7C3AED", "$type": "color" } },
  "cyan": { "9": { "$value": "#F59E0B", "$type": "color" } }
}
```

Then rebuild the token pipeline (`pnpm --filter @nebutra/design-tokens build && pnpm --filter @nebutra/tokens build`) so `styles.css` regenerates with the new palette.

<Warning>
  When editing the neutral scale, always update both light (`:root`) and dark (`.dark` / `[data-theme]`) blocks. Skipping the dark block causes contrast issues in dark mode.
</Warning>

## Light/dark mode

Light/dark mode is managed by `next-themes` re-exported from `@nebutra/tokens`.

### Setup

The `ThemeProvider` is already configured in `apps/web/src/app/layout.tsx` and `apps/landing/src/app/layout.tsx`. No additional setup is required.

```tsx
// apps/web/src/app/layout.tsx
import { ThemeProvider } from "@nebutra/tokens";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
          {children}
        </ThemeProvider>
      </body>
    </html>
  );
}
```

### Switching themes programmatically

```tsx
"use client";
import { useTheme } from "@nebutra/tokens";

export function ThemeToggle() {
  const { theme, setTheme } = useTheme();

  return (
    <button
      type="button"
      onClick={() => setTheme(theme === "dark" ? "light" : "dark")}
      aria-label="Toggle dark mode"
      className="rounded-md p-2"
    >
      {theme === "dark" ? "Light" : "Dark"}
    </button>
  );
}
```

### Resolved theme

`useTheme` returns `"system"` when the user hasn't explicitly chosen a theme. Use `resolvedTheme` for the actual computed value:

```tsx
const { resolvedTheme } = useTheme();
// → "light" | "dark"
```

## Brand Packages

`@nebutra/theme` ships 7 built-in **Brand Packages** — complete design languages (roles + chrome recipe + elevation + zones + fonts, applied as a whole, not a colour swap): `gsap`, `linear`, `notion`, `raycast`, `stripe`, `vanta`, `vercel`. Each is applied via the `data-brand` attribute on `<html>`, scoped through `skins.css` (generated by `emit-skins.mjs` from each package's `emit-css.ts`).

### Switching Brand Packages

```tsx
// Static — set in layout
<html data-brand="linear">

// Dynamic
"use client";
import { applyLanguage, LANGUAGE_REGISTRY } from "@nebutra/theme";

export function BrandPackageSelector() {
  return (
    <div className="flex gap-2">
      {Object.keys(LANGUAGE_REGISTRY).map((id) => (
        <button key={id} type="button" onClick={() => applyLanguage(id)} className="rounded px-3 py-1 text-sm bg-neutral-2">
          {id}
        </button>
      ))}
    </div>
  );
}
```

In a Sailor project, the easier path is [Sailor Studio](https://nebutra.com/sailor/studio): pick a Brand Package as your base language, turn the knobs, and apply the resulting preset with `nebutra apply --preset <code>` — see [Customization Overview](/customization/overview).

## Adding a new Brand Package

<Steps>
  <Step title="Add the brand definition">
    ```
    packages/design/tokens/brands/<id>/brand.json
    ```
  </Step>
  <Step title="Register it">
    Add an entry in `packages/design/theme/src/languages.meta.json`, then run:

    ```bash
    node packages/design/theme/scripts/sync-languages.mjs
    ```

    This writes the generated `languages.json` — never hand-edit it.
  </Step>
  <Step title="Apply and verify">
    ```tsx
    <html data-brand="your-id">
    ```

    Open Storybook and check the **Design Tokens** section to verify contrast ratios meet WCAG AA.
  </Step>
</Steps>

## Typography

Fonts are loaded via `next/font` and injected as CSS variables. No external font requests. The type scale itself lives in `core.json:type` — every `text-*` step carries its own line-height and tracking.

```css
/* packages/design/tokens/styles.css — generated */
:root {
  --font-sans: var(--font-geist-sans), "Geist", system-ui, sans-serif;       /* UI text */
  --font-mono: var(--font-geist-mono), "Geist Mono", ui-monospace, monospace; /* Code, metrics */
}
```

To change the font family, update the `next/font` configuration in the app layout, then update the source fallbacks in `packages/design/design-tokens/tokens/core.json` and rebuild — never edit `styles.css` directly.

- Semantic palette (neutral scale)
- Brand gradients
- Status colors
- Typography scale
- Motion presets
- Shadow/elevation system
