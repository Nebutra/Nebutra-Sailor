---
title: Dashboard Customization
description: Add new app pages inside the current `[locale]/(app)` shell and compose them with shared layout primitives.
---

The authenticated product shell now lives under:

```text
apps/web/src/app/[locale]/(app)/
```

It is mounted by the shared layout in
`apps/web/src/app/[locale]/(app)/layout.tsx`, which already applies the auth
guard and wraps pages in `DesignSystemShell`.

## Anatomy of a current app page

```text
apps/web/src/app/[locale]/(app)/
  layout.tsx
  analytics/
    page.tsx
    loading.tsx
  billing/
    page.tsx
    loading.tsx
```

Older docs that assume a non-locale dashboard route group are obsolete.

## Create a new section

```bash
mkdir -p 'apps/web/src/app/[locale]/(app)/my-section'
```

```typescript
// apps/web/src/app/[locale]/(app)/my-section/page.tsx
import { PageHeader } from "@nebutra/ui/layout";
import { requireAuth } from "@/lib/auth";

export default async function MySectionPage() {
  await requireAuth();

  return (
    <div className="space-y-6">
      <PageHeader
        title="My Section"
        description="A new section inside the shared app shell."
      />
    </div>
  );
}
```

## Loading and error states

```typescript
// apps/web/src/app/[locale]/(app)/my-section/loading.tsx
import { LoadingState } from "@nebutra/ui/layout";

export default function Loading() {
  return <LoadingState message="Loading section…" />;
}
```

For client-side error recovery, add a route-local `error.tsx` with the standard
`ErrorState` component.

## Shared shell behavior

The page chrome, notifications surface, and product capabilities are owned by:

- `apps/web/src/app/[locale]/(app)/layout.tsx`
- `apps/web/src/app/[locale]/providers/design-system-shell.tsx`
- `apps/web/src/lib/product-capabilities.ts`

If your new page depends on billing, workspace mode, or notifications, update
the capability assumptions there instead of inventing a parallel dashboard
contract.

## Navigation

The previous sidebar item registry used by older docs no longer exists.
Current navigation behavior is composed from the shell and navigation
components under:

```text
apps/web/src/components/navigation/
```

When adding a new primary section, inspect the current shell/navigation wiring
first and keep it aligned with the active product capability model.

## Layout primitives

```tsx
import { Card, EmptyState, ErrorState, LoadingState, PageHeader } from "@nebutra/ui/layout";
```

Use these shared layout components rather than building one-off dashboard
variants.

## Tenant-aware page logic

When a page depends on tenant state, derive it from the shared server helpers:

```typescript
import { getTenantContext, requireAuth } from "@/lib/auth";

await requireAuth();
const { tenantId, plan } = await getTenantContext();
```

Prefer explicit plan or capability checks in the page and backing route logic.
Do not rely on a stale `PlanGate` example if the actual component is not part of
the current app surface.
