## Overview

The Sailor template doesn't bake in a deploy target. `create-sailor` produces portable output — a
Next `standalone` build and a `Dockerfile.web` + `docker-compose.yml` — and says nothing about
where it runs. Vercel is one option among several (`vercel`, `standalone`, `cloudflare-pages`,
`railway`, `fly` for frontend surfaces) selectable per service via the `DEPLOY_TARGET_*`
env-var/preset mechanism — it is not provisioned automatically and nothing in the scaffold assumes
it.

<Note>
  Nebutra's own production (`nebutra.com`) does not run on Vercel — that surface was retired on
  2026-09-22 in favor of Fly Machines for frontends/origin and Cloudflare Workers for the gateway.
  This page is about using Vercel as a deploy target for a project you scaffold from Sailor, not
  about how Nebutra itself deploys.
</Note>

## Deploying an app to Vercel

Each app deploys as a separate Vercel project:

```bash
cd apps/landing
vercel link

cd ../web
vercel link
# Repeat for each app you want on Vercel
```

### Set environment variables

```bash
# Pull env vars for local development
vercel env pull .env.local

# Add a new env var
vercel env add DATABASE_URL production
```

## Turborepo remote cache

Enable shared build cache across CI and local machines:

```bash
npx turbo link
```

This uses your Vercel account as the remote cache backend — cache misses are eliminated across the team, independent of which deploy target you actually run on.

## Environment variables

The converged stack has one provider per capability — the env vars are the same regardless of
where you deploy:

```bash
# Auth — Better Auth is the only provider
AUTH_PROVIDER=better-auth
NEXT_PUBLIC_AUTH_PROVIDER=better-auth
BETTER_AUTH_SECRET=...
BETTER_AUTH_URL=https://auth.yourdomain.com
NEXT_PUBLIC_AUTH_URL=https://auth.yourdomain.com
AUTH_COOKIE_DOMAIN=.yourdomain.com

# Database
DATABASE_URL=postgresql://...

# Creem — current card rail (merchant of record)
CREEM_API_KEY=creem_...
CREEM_PRODUCT_ID=prod_...
CREEM_WEBHOOK_SECRET=whsec_...

# Stripe (legacy — subscriptions only)
STRIPE_SECRET_KEY=sk_live_...
STRIPE_WEBHOOK_SECRET=whsec_...

# Email
RESEND_API_KEY=re_...

# Redis (Upstash REST protocol)
UPSTASH_REDIS_REST_URL=https://...
UPSTASH_REDIS_REST_TOKEN=...

# Error tracking
SENTRY_DSN=https://...

# Internal S2S
SERVICE_SECRET=... # HS256 for x-service-token
```

## Preview deployments

Every pull request gets an automatic preview URL. Vercel automatically sets the correct `VERCEL_URL` so API calls work in preview environments.
