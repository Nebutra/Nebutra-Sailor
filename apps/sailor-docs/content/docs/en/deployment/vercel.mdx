## Overview

Nebutra uses **separate Vercel projects** per public surface. That isolates env,
domains, and deploy quotas.

| Vercel project (examples) | App path | Domain (nebutra.com) | Steady state |
|---------------------------|----------|----------------------|--------------|
| `nebutra-sailor-landing-page` / landing | `apps/landing-page` | `nebutra.com` | **Production on Vercel** |
| `docs` | `apps/sailor-docs` | `docs.nebutra.com` | **Production on Vercel** |
| `nebutra-web` | `apps/web` | `app.nebutra.com` | Optional; **ECS is production today** |
| `nebutra-auth` | `apps/auth` | `auth.nebutra.com` | Optional; **ECS is production today** |

**Do not** treat `backends/gateway` as a default Vercel Functions deploy for
nebutra.com production — API stays on ECS (or Cloudflare Workers gateway target).

Web must build with **Next**, not the package default Vite script:

```bash
# apps/web vercel.json / project buildCommand
cd ../.. && pnpm turbo run build:next --filter=@nebutra/web
```

## Prerequisites

- [Vercel](https://vercel.com) account + CLI (`pnpm dlx vercel login`)
- Monorepo linked with correct **Root Directory** (`apps/web`, `apps/auth`, …)
- Production secrets: `BETTER_AUTH_*`, `DATABASE_URL`, OAuth clients, etc.

## Step-by-step: first link

<Steps>
  <Step title="Install / login CLI">
    ```bash
    pnpm dlx vercel login
    ```
  </Step>
  <Step title="Link each frontend app">
    From the monorepo root, or from each app directory:

    ```bash
    cd apps/landing-page && vercel link
    cd ../sailor-docs && vercel link
    # optional cutover targets:
    cd ../web && vercel link
    cd ../auth && vercel link
    ```

    Paths are under `apps/*` or `backends/gateway` — there is **no**
    `apps/api-gateway` directory.
  </Step>
  <Step title="Configure environment variables">
    Prefer Better Auth for production parity:

    ```bash
    vercel env add BETTER_AUTH_SECRET production
    vercel env add BETTER_AUTH_URL production   # https://auth.nebutra.com
    vercel env add AUTH_COOKIE_DOMAIN production  # .nebutra.com
    ```

    Use the [environment variables reference](/configuration/environment-variables).
  </Step>
  <Step title="Deploy">
    ```bash
    cd apps/landing-page && vercel --prod
    cd ../sailor-docs && vercel --prod
    ```

    Or rely on Git integration on `main` (watch **Hobby daily deploy quotas** on
    monorepos — disable auto-deploy on non-critical projects if you hit limits).
  </Step>
</Steps>

## Optional web / auth cutover

Production traffic for `app` / `auth` remains on ECS until DNS is flipped.
Checklist + preflight (no DNS mutation):

```bash
node scripts/preflight-web-auth-vercel.mjs
node scripts/redeploy-web-auth-vercel.mjs   # after green buildCommand + quota
```

See monorepo `docs/ops/web-auth-vercel-cutover.md`.
