---
title: Using the Database Client
description: Current database access patterns with `getTenantDb()`, `getSystemDb()`, and tenant context helpers.
---

`@nebutra/db` no longer exports a bare shared `db` client. The current contract
is explicit:

- `getTenantDb(organizationId)` for tenant-scoped queries
- `getSystemDb()` for cross-tenant or bootstrap work

This keeps row-level-security decisions visible at the call site.

## The current package surface

```typescript
import { getSystemDb, getTenantDb } from "@nebutra/db";
```

The implementation lives in [`packages/platform/db/src/index.ts`](../../../packages/platform/db/src/index.ts)
and delegates to the lazy Prisma client in `client.ts`.

## Tenant-scoped queries

Use `getTenantDb()` whenever the request already has a resolved tenant:

```typescript
import { getCurrentTenant } from "@nebutra/tenant";
import { getTenantDb } from "@nebutra/db";

export async function listProjects() {
  const tenant = getCurrentTenant();
  const db = getTenantDb(tenant.id);

  return db.project.findMany({
    orderBy: { createdAt: "desc" },
  });
}
```

`getTenantDb()` wraps every query with the PostgreSQL session state required by
the repo's row-level security policy. Prefer it over hand-rolling `where:
{ organizationId }` guards everywhere.

## System-scoped queries

Use `getSystemDb()` only when there is no trustworthy tenant context yet:

```typescript
import { getSystemDb } from "@nebutra/db";

export async function findOrganizationByStripeCustomer(customerId: string) {
  const db = getSystemDb();
  return db.organization.findFirst({
    where: { stripeCustomerId: customerId },
  });
}
```

Typical uses:

- webhook bootstrap before tenant resolution
- admin / cross-tenant reporting
- background jobs spanning many organizations

## Web app server components

In `apps/web`, you often derive page-level state through the auth helpers first:

```typescript
import { getTenantContext, requireAuth } from "@/lib/auth";

export default async function BillingPage() {
  await requireAuth();
  const { tenantId, plan } = await getTenantContext();

  if (!tenantId) {
    return null;
  }

  const db = getTenantDb(tenantId);
  const subscriptions = await db.subscription.findMany();

  return <pre>{JSON.stringify({ plan, count: subscriptions.length }, null, 2)}</pre>;
}
```

## Client components

Client Components must not import `@nebutra/db`. Go through an HTTP boundary:

```typescript
import { browserApiClient } from "@/lib/api/client";

const { data } = await browserApiClient.GET("/api/v1/integrations");
```

If you need app-local browser hooks, build them on top of the API client or a
route handler, not on top of Prisma.

## Transactions

Use the scoped client returned by `getTenantDb()` or `getSystemDb()` and run
transactions there:

```typescript
import { getTenantDb } from "@nebutra/db";

export async function createProject(organizationId: string, userId: string) {
  const db = getTenantDb(organizationId);

  return db.$transaction(async (tx) => {
    const project = await tx.project.create({
      data: { organizationId, name: "New project" },
    });

    await tx.auditLog.create({
      data: {
        organizationId,
        actorId: userId,
        action: "project.created",
      },
    });

    return project;
  });
}
```

## Error handling

Prefer translating Prisma failures into shared API errors instead of throwing
raw strings:

```typescript
import { Prisma } from "@nebutra/db";
import { ConflictError } from "@nebutra/errors";

export function mapDbError(error: unknown): never {
  if (
    error instanceof Prisma.PrismaClientKnownRequestError &&
    error.code === "P2002"
  ) {
    throw new ConflictError("A record with that unique value already exists.");
  }

  throw error;
}
```
