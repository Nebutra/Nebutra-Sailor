Plan management is no longer centered on a single `packages/commerce/billing/src/plans.ts`
file. The current billing package splits plan behavior across:

- `packages/commerce/billing/src/config/`
- `packages/commerce/billing/src/entitlements/`
- `packages/commerce/billing/src/usage/`
- provider checkout modules under `packages/commerce/billing/src/checkout/`

## What a plan change can affect

A plan change may update all of these at once:

- checkout price mapping
- feature entitlements
- usage limits / overage behavior
- billing page copy and upgrade prompts

That is why plan work should be treated as a package-level billing change, not
just an edit to one constants file.

## Recommended workflow

1. Update the plan configuration source in `packages/commerce/billing/src/config/`.
2. Review entitlements in `packages/commerce/billing/src/entitlements/`.
3. Review usage and metering behavior in `packages/commerce/billing/src/usage/`.
4. Verify any provider-specific checkout assumptions in `packages/commerce/billing/src/checkout/`.
5. Check the user-facing billing pages under `apps/web/src/app/[locale]/(app)/billing/`.

## When adding a new tier

For a new tier such as `teams` or `growth`, review:

- checkout provider price mapping
- feature entitlements
- usage limits
- upgrade copy in the web app
- any downstream analytics or provisioning assumptions

## Verification checklist

- `pnpm --filter @nebutra/billing test`
- `pnpm --filter @nebutra/billing typecheck`
- verify the gateway billing routes under `backends/gateway/src/routes/billing/`
- verify the billing UI under `apps/web/src/components/billing/`
