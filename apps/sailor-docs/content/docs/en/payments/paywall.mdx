The old `requirePlan()` / `PlanGate` examples in earlier docs no longer match
the current app surface. Today, paywalls in Nebutra-Sailor are enforced through
a mix of:

- server-side tenant context from `apps/web/src/lib/auth.ts`
- billing/entitlement checks from `@nebutra/billing`
- route-level enforcement in `backends/gateway/src/routes/billing/` or the
  calling product route

## UI gating in app pages

In server-rendered app pages, start from the shared tenant context:

```typescript
import { getTenantContext, requireAuth } from "@/lib/auth";

export default async function BillingAwarePage() {
  await requireAuth();
  const { tenantId, plan } = await getTenantContext();

  if (!tenantId || plan === "FREE") {
    return <UpgradePrompt />;
  }

  return <AdvancedFeature />;
}
```

Keep UI gating close to the page, but remember it is only the first layer.

## API and backend enforcement

Sensitive features must also be enforced on the server:

```typescript
import { checkEntitlement } from "@nebutra/billing";

const result = checkEntitlement("org_123", "ai.chat");

if (!result.allowed) {
  throw new Error("Feature not available on the current plan.");
}
```

In the gateway, perform the same class of check before executing the protected
operation.

## Where the current billing UI lives

```text
apps/web/src/app/[locale]/(app)/billing/
apps/web/src/components/billing/
```

If you need an upgrade prompt, start from the current billing surfaces there
instead of wiring a stale `/billing/upgrade` example from older docs.

## Recommended rule of thumb

- UI discoverability: page-level prompt or disabled state
- mutation / export / usage-consuming action: enforce again on the server
- cross-tenant or financial side effects: enforce in the gateway and record
  audit/billing consequences there
