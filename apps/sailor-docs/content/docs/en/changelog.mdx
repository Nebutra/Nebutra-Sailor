## Recent releases

### create-sailor 2.0.x — September 2026

**One stack, zero questions** (ADR 2026-09-24 Sailor convergence)
- `create-sailor` no longer asks anything but where to put the project — every stack flag (`--region`, `--auth`, `--payment`, `--email`, `--storage`, `--queue`, `--search`, `--deploy`, …) is gone. Every project is the same converged stack, and each capability goes live when its key is set.
- `nebutra status [--json]` replaces the old grab-bag of `create` / `add` / `auth` / `billing` / `search` / … subcommands, reporting what's live and what each capability still needs.
- A fresh project carries its own brand from the first render — `create-sailor` runs the template's brand pipeline on scaffold so the welcome page, header, and sign-in show your project name instead of Nebutra's.
- 2.0.2 fixed root resolution for the CLI running from inside a scaffolded project, non-interactive `db status`, and removed references to services and scripts that no longer exist.

### Database convergence — September 2026

- One database source: `packages/platform/db/prisma/schema.prisma` is the only file a schema change touches — tables plus each table's `/// @rls` access rule. Row-level security is generated (`prisma/generated/rls.sql`), never hand-written, and every deploy runs `pnpm db:deploy` before the apps start.
- Zero-key preview database: with no `DATABASE_URL` set, `@nebutra/db` runs on PGlite (Postgres 17 in WASM) automatically — no external Postgres needed to start developing.

### @nebutra/* design packages 4.0.0 / 4.0.1

- `@nebutra/ui`, `@nebutra/tokens`, `@nebutra/brand`, `@nebutra/icons`, `@nebutra/graph-model`, and `@nebutra/design-tokens` moved together to 4.0.0, then 4.0.1 for a font-dependency fix — coordinated release across the design package group.

### Payments — Creem card rail

- `nebutra status`/`sync` check `CREEM_API_KEY` and `CREEM_PRODUCT_ID` for the `billing` capability's card provider; scaffold copy and docs describe Creem (cards worldwide, merchant of record) paired with WeChat Pay/Alipay as the current payments stack (ADR 2026-09-26).
