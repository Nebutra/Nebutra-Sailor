## Overview

`@nebutra/queue` is the queue used by every Sailor project: **QStash** (Upstash) — serverless,
HTTP-based, no infrastructure to manage. Per the Sailor Convergence ADR (2026-09-24), the
self-hosted BullMQ + Redis backend was deleted; QStash is the only queue backend.

## Provider auto-detection

| Priority | Condition | Provider |
|----------|-----------|----------|
| 1 | `QUEUE_PROVIDER` is set | As specified (`qstash` / `memory`) |
| 2 | `QSTASH_TOKEN` exists | `qstash` |
| 3 | Neither | `memory` (dev/test only — not persistent; `nebutra status` reports this as `local-fallback`) |

## Setup

<Steps>
  <Step title="Set environment variables">
    ```bash
    QSTASH_TOKEN=""
    QSTASH_CURRENT_SIGNING_KEY=""
    QSTASH_NEXT_SIGNING_KEY=""

    # Public base URL of your API gateway
    # QStash calls this URL to deliver jobs
    QSTASH_CALLBACK_BASE_URL="https://api.yourdomain.com"
    ```
  </Step>

  <Step title="Register the webhook route">
    The API gateway already exposes the QStash webhook at:

    ```
    POST /api/queue/:queue/:type
    ```

    QStash will POST to `https://api.yourdomain.com/api/queue/report/generate` when a `report.generate` job is ready.

    <Warning>
      QStash requires a **publicly reachable HTTPS endpoint**. It cannot deliver to `localhost`. Use a tunnel (e.g. `ngrok`) during local development.
    </Warning>
  </Step>

  <Step title="Enqueue a job">
    ```typescript
    import { getQueue, createJob } from "@nebutra/queue";

    const queue = await getQueue();

    await queue.enqueue(
      createJob("report", "generate", {
        tenantId: "org_123",
        reportType: "monthly",
      })
    );
    ```
  </Step>

  <Step title="Register a handler">
    ```typescript
    import { getQueue } from "@nebutra/queue";

    const queue = await getQueue();

    queue.registerHandler("report", "generate", async (job) => {
      await generateReport(job.data);
    });
    ```
  </Step>
</Steps>

Without `QSTASH_TOKEN` set, `getQueue()` returns the in-memory fallback — the same
enqueue/handler API works, but nothing is delivered across processes and nothing survives a
restart. It exists so `pnpm dev` and unit tests work without a queue configured, not as a
production alternative.

## Enqueue and handle pattern

```typescript
import { getQueue, createJob } from "@nebutra/queue";

// --- Producer (enqueue) ---
const queue = await getQueue();

await queue.enqueue(
  createJob(
    "email",        // queue name
    "send",         // job type
    {               // job data (serializable)
      to: "user@example.com",
      template: "invoice-paid",
      data: { invoiceId: "inv_123", amount: 99.99 },
    },
    {               // options (optional)
      tenantId: "org_123",
      delay: 5000,  // delay in ms before delivery
    }
  )
);

// --- Consumer (handler) ---
queue.registerHandler("email", "send", async (job) => {
  await sendEmail(job.data.to, job.data.template, job.data.data);
});
```

## Job options

```typescript
createJob(queueName, jobType, data, {
  tenantId: "org_123",   // scopes the job to a tenant
  delay: 60_000,         // deliver after 60 seconds
  jobId: "unique-id",    // deduplicate by ID (prevents duplicate enqueues)
})
```

## QStash characteristics

**Pros:**
- Zero infrastructure — fully managed by Upstash
- Works on any deploy target, including serverless/edge
- Built-in retry with exponential backoff
- HTTP-based — easy to inspect and debug
- Signed webhooks — delivery is authenticated

**Trade-offs:**
- Requires a public webhook endpoint (cannot use `localhost` directly)
- No priority queues
- Maximum message size: 1 MB

If you need self-hosted, high-throughput queueing with priority scheduling and long-running
worker processes, that is outside what `@nebutra/queue` provides — write your own adapter against
its interface (see the ADR's consequences: buyers who wanted the deleted providers write their own
adapter against the kept interface).

## Dead letter queue (DLQ)

QStash retries failed deliveries with exponential backoff (up to 3 times by default). After all retries are exhausted, the job is discarded. Monitor failed deliveries in the [Upstash Console](https://console.upstash.com).

```typescript
// Configure retry count when enqueuing
await queue.enqueue(
  createJob("report", "generate", data, { maxRetries: 5 })
);
```

## Python support

`@nebutra/queue` also has a Python client for microservices:

```python
from _shared.queue import get_queue, create_job

queue = await get_queue()

# Enqueue
await queue.enqueue(create_job("report", "generate", {"tenant_id": "org_123"}))

# Handle
@queue.handler("report", "generate")
async def handle_report(job):
    await generate_report(job.data["tenant_id"])
```
