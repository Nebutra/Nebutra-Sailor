## Base URL

```
https://api.nebutra.com
```

All API requests are made over HTTPS. HTTP requests are redirected to HTTPS.

## Versioning

The API is versioned via URL path prefix:

```
https://api.nebutra.com/api/v1/...
```

The current stable version is `v1`. Breaking changes are introduced in new major versions with at minimum 6 months of deprecation notice.

## Request format

All `POST`, `PUT`, and `PATCH` requests accept JSON bodies:

```http
POST /api/v1/projects HTTP/1.1
Host: api.nebutra.com
Authorization: Bearer nbk_live_xxxxxxxxxxxxxxxxxxxx
Content-Type: application/json

{
  "name": "My Project",
  "description": "A new project"
}
```

## Response envelope

All responses follow this envelope:

```json
{
  "success": true,
  "data": { ... },
  "meta": {
    "total": 142,
    "page": 1,
    "limit": 20
  }
}
```

Error responses use the same envelope with `success: false`:

```json
{
  "success": false,
  "error": {
    "code": "RESOURCE_NOT_FOUND",
    "message": "Project proj_123 not found.",
    "request_id": "req_2a8bXXXXXXXXX"
  }
}
```

## Pagination

List endpoints support cursor-based pagination via `limit` and `cursor` parameters:

```http
GET /api/v1/projects?limit=20&cursor=crs_xxxx
```

Response:

```json
{
  "success": true,
  "data": [...],
  "meta": {
    "total": 142,
    "limit": 20,
    "next_cursor": "crs_yyyy",
    "has_more": true
  }
}
```

## Filtering & sorting

List endpoints accept `filter` and `sort` query parameters:

```http
GET /api/v1/projects?filter[status]=active&sort=-createdAt&limit=10
```

- Prefix field names with `-` for descending sort
- Nested filters use bracket notation: `filter[field]=value`

## Idempotency

Pass `Idempotency-Key` for mutation requests to prevent duplicate operations:

```http
POST /api/v1/invoices
Idempotency-Key: inv-2026-03-31-01
Content-Type: application/json
```

The same key within 24 hours returns the cached response.
