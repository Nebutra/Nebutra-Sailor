title: Testing Emails

---

Before emails reach real inboxes, test them at three levels: local visual preview, safe delivery with a test API key, and automated rendering unit tests.

<Warning>
Never send real emails in test or CI environments. Use the preview server or Resend's test API key instead.
</Warning>

## Local preview server

React Email provides a browser-based preview that hot-reloads as you edit templates.

<Steps>
  <Step title="Start the preview server">
    ```bash
    pnpm --filter @nebutra/email dev
    ```

    The preview server starts at **http://localhost:3100**.
  </Step>

  <Step title="Browse and inspect templates">
    The left sidebar lists all registered templates. Click a template to preview it.

    - **Desktop / mobile toggle** — check responsive layout
    - **HTML / Plain text tabs** — verify both render formats
    - **Source view** — inspect the generated HTML
  </Step>

  <Step title="Pass test data">
    Templates are rendered with default fixture data defined in each template file's `defaultProps`. To preview with custom data, edit the `defaultProps` export:

    ```typescript
    // packages/email/src/templates/welcome.tsx

    WelcomeEmail.defaultProps = {
      userName: "Alex Chen",
      orgName: "Acme Corp",
      dashboardUrl: "https://app.nebutra.com/dashboard",
    } satisfies WelcomeEmailProps;
    ```
  </Step>
</Steps>

## Resend test mode

Resend's test API key (`re_test_...`) accepts API calls and logs them in the dashboard without delivering to real inboxes.

<Steps>
  <Step title="Get a test API key">
    In the Resend dashboard, go to **API Keys → Create API Key** and select **Test** mode. The key will start with `re_test_`.
  </Step>

  <Step title="Set the test key in your local environment">
    ```bash
    # .env.local — never commit this file
    RESEND_API_KEY=re_test_...
    EMAIL_FROM=Nebutra <noreply@mail.nebutra.com>
    ```
  </Step>

  <Step title="Send a test email">
    Use your normal application flow to trigger an email. The email will appear in the Resend dashboard under **Logs** with a `test` badge — no email is delivered.

    ```typescript
    // Quick test script — run with tsx
    // scripts/test-email.ts
    import { getEmailProvider } from "@nebutra/email";

    const email = await getEmailProvider();

    await email.send({
      to: "delivered@resend.dev", // Resend's special test address
      template: "welcome",
      data: {
        userName: "Test User",
        orgName: "Test Org",
        dashboardUrl: "https://app.nebutra.com/dashboard",
      },
    });

    console.log("Test email sent — check Resend dashboard");
    ```

    ```bash
    npx tsx scripts/test-email.ts
    ```

    <Tip>
      `delivered@resend.dev` is a Resend-provided test address that always returns a successful delivery status.
    </Tip>
  </Step>
</Steps>

## Vitest rendering tests

Write unit tests to verify that templates render without errors and contain expected content.

<Steps>
  <Step title="Install test dependencies">
    ```bash
    pnpm --filter @nebutra/email add -D vitest @vitejs/plugin-react @react-email/render
    ```
  </Step>

  <Step title="Write a rendering test">
    ```typescript
    // packages/email/src/templates/welcome.test.tsx
    import { render } from "@react-email/render";
    import { describe, expect, it } from "vitest";
    import { WelcomeEmail } from "./welcome";

    describe("WelcomeEmail", () => {
      const props = {
        userName: "Alex Chen",
        orgName: "Acme Corp",
        dashboardUrl: "https://app.nebutra.com/dashboard",
      };

      it("renders without throwing", () => {
        expect(() => render(<WelcomeEmail {...props} />)).not.toThrow();
      });

      it("includes the user name", () => {
        const html = render(<WelcomeEmail {...props} />);
        expect(html).toContain("Alex Chen");
      });

      it("includes the org name", () => {
        const html = render(<WelcomeEmail {...props} />);
        expect(html).toContain("Acme Corp");
      });

      it("includes the dashboard URL", () => {
        const html = render(<WelcomeEmail {...props} />);
        expect(html).toContain("https://app.nebutra.com/dashboard");
      });

      it("renders a plain-text version", () => {
        const text = render(<WelcomeEmail {...props} />, { plainText: true });
        expect(text).toContain("Alex Chen");
        expect(text.length).toBeGreaterThan(0);
      });
    });
    ```
  </Step>

  <Step title="Run the tests">
    ```bash
    pnpm --filter @nebutra/email test
    ```
  </Step>
</Steps>

## Testing in CI

Add email rendering tests to your CI pipeline to catch template regressions before they reach production. No real email delivery happens in CI — the tests only render templates to HTML strings.

```yaml
# .github/workflows/ci.yml (excerpt)
- name: Test email templates
  run: pnpm --filter @nebutra/email test --run
```

<Note>
Do not set `RESEND_API_KEY` in CI. Template rendering tests use `@react-email/render` directly and do not call the Resend API.
</Note>

## Checklist before launch

Before your first production deployment, verify every template manually:

- [ ] All six templates render without errors (`pnpm --filter @nebutra/email test`)
- [ ] Each template looks correct in the preview server on desktop and mobile
- [ ] Sending domain is verified in Resend
- [ ] `EMAIL_FROM` address matches your verified domain
- [ ] `RESEND_API_KEY` in production uses a production key (not `re_test_...`)
- [ ] At least one real delivery test per template has been performed from staging
