## Overview

Nebutra is a **Turborepo monorepo** with 7 apps and 33 packages, all sharing a common design system, type-safe API contract, and runtime token system. Every component is independently deployable and replaceable.

```
Browser / Mobile Client
        │
        ▼
┌─────────────────────────────┐
│       Vercel Edge Network   │  (CDN, WAF, DDoS protection)
└─────────────┬───────────────┘
              │
    ┌─────────┴─────────┐
    │                   │
    ▼                   ▼
┌────────────┐   ┌──────────────┐
│ landing-   │   │    web app   │  Next.js 16 (App Router)
│ page       │   │ app.nebutra  │  Authenticated dashboard
└────────────┘   └──────┬───────┘
                        │ fetch / Server Actions
                        ▼
              ┌──────────────────┐
              │   API Gateway    │  Hono + OpenAPI
              │ api.nebutra.com  │  auth middleware, RBAC, rate limiting
              └────────┬─────────┘
                       │
          ┌────────────┼────────────┐
          │            │            │
          ▼            ▼            ▼
   ┌────────────┐ ┌─────────┐ ┌──────────┐
   │  Supabase  │ │  Redis  │ │  AI      │
   │ PostgreSQL │ │ (cache) │ │  Service │
   │ + pgvector │ │         │ │  Proxy   │
   └────────────┘ └─────────┘ └──────────┘
```

|---------|-------------|

## Request flow

Every API request passes through this chain:

```
Request
  │
  ├─ 1. Vercel WAF        (IP allowlist, rate limit rules)
  │
  ├─ 2. Hono middleware
  │     ├─ CORS           (origin validation)
  │     ├─ Auth           (JWT verification via Clerk / Better Auth)
  │     ├─ Tenant         (resolve orgId → tenant context)
  │     ├─ RBAC           (scope check for the route)
  │     └─ Rate limit     (per-tenant quota via Redis)
  │
  ├─ 3. Route handler     (business logic)
  │
  └─ 4. Response          (JSON envelope: { success, data, error })
```

## Database isolation

Nebutra supports three multi-tenant data isolation strategies — choose based on your scale and compliance requirements:

| Strategy | Isolation | Recommended for |
|----------|-----------|-----------------|
| **Shared schema** | Row-level security (RLS) via `tenant_id` column | Most SaaS (default) |
| **Separate schema** | PostgreSQL schema per tenant | Mid-market with data residency needs |
| **Separate database** | Full DB per tenant | Enterprise with strict compliance (SOC2, HIPAA) |

The default configuration uses shared schema with automatic RLS via `@nebutra/tenant`.

## AI layer

The API gateway exposes three AI routes, authenticated and tenant-scoped:

- `POST /api/v1/ai/chat` — proxied chat completions (any provider)
- `POST /api/v1/ai/embeddings` — vector embedding generation
- `GET /api/v1/ai/models` — available model list

All AI routes enforce per-tenant rate limits and log usage to the metering pipeline for billing.

## Provider swap pattern

Every infrastructure dependency in Nebutra is swappable at the environment variable level:

```bash
# Swap auth provider
AUTH_PROVIDER=better-auth  # or "clerk"

# Swap queue backend
QUEUE_PROVIDER=bullmq      # or "qstash" | "memory"

# Swap search backend
SEARCH_PROVIDER=typesense  # or "meilisearch" | "algolia"

# Swap permissions backend
PERMISSIONS_PROVIDER=openfga  # or "casl"
```

Your application code doesn't change — only the environment variable.
