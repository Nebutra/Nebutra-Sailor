`create-sailor` is a one-time scaffolding tool. It asks for nothing but a project directory and
writes out the full converged Sailor stack, ready to run with an empty `.env`.

<Note>
  The Sailor Convergence ADR (2026-09-24) removed every provider-choice flag. There is one stack
  now, not a menu — the scaffold cannot be misconfigured because there is nothing left to
  configure at scaffold time.
</Note>

## Usage

```bash
npx create-sailor [name]
# or, inside an existing empty directory
npx create-sailor .
```

If you omit `[name]`, the wizard prompts you for a project directory (default: `my-app`). That
directory — or, non-interactively, `--yes` — is the **only** decision `create-sailor` makes for you.

## What it generates

There is nothing to choose. Every project gets the same stack:

- **Frontend**: Next.js 16 + Tailwind v4, with the Hono gateway mounted in-process at
  `app/api/[[...route]]` (`GATEWAY_MODE=embedded` by default)
- **Database**: Postgres + Prisma
- **Auth**: Better Auth
- **Payments**: Creem (cards, worldwide, merchant of record), plus WeChat Pay / Alipay (ChinaPay) side by side
- **Email**: Resend (with a `console` dev-only fallback)
- **Storage**: S3-compatible object storage (covers both R2 and Aliyun OSS)
- **Queue**: QStash
- **Cache**: Redis via the Upstash REST protocol
- **Monitoring / analytics / captcha**: Sentry, PostHog, Turnstile
- **MCP**: built-in context server

Every capability runs locally out of the box — console email, an in-memory queue, local storage —
so `pnpm dev` works immediately with an empty `.env`. Add a provider key later to take a capability
live; `nebutra status` (see [nebutra CLI](/docs/cli/nebutra-cli)) reports what's live, what's
running on a local fallback, and what still needs a key.

China deployments are a runtime locale, not a scaffold flag: set `NEBUTRA_LOCALE=cn` to turn on the
ICP footer, AIGC disclosure text, and phone-first login — present in every scaffold, gated at
runtime.

`foundation`-tier packages (vault, audit, tenant, permissions, metering, …) are **not** part of the
default scaffold. Add them explicitly; `nebutra status` shows them as `preview` until you do.

## Flags

The remaining flags are mechanical — none of them pick a provider:

| Flag | Effect |
|------|--------|
| `-p, --pm <id>` | `npm` \| `pnpm` \| `yarn` \| `bun` (auto-detected from what's on `PATH`) |
| `--no-install` | Skip package install |
| `--no-git` | Skip `git init` |
| `-y, --yes` | Non-interactive — accept the default project name, skip all prompts |
| `--dry-run` | Print the plan without writing files |
| `--json` | Machine-readable NDJSON event stream |
| `--no-color` | Disable color output |

Every provider flag that used to exist — `--auth`, `--payment`, `--email`, `--storage`, `--queue`,
`--search`, `--cache`, `--sms`, `--cms`, `--captcha`, `--monitoring`, `--analytics`,
`--notifications`, `--webhooks`, `--feature-flags`, `--metering`, `--mcp`, `--region`, and the rest
of the old 43-flag surface — is gone. So is the subtractive prune pipeline (`prune.ts`,
`prune-schema.ts`, `prune-migrations.ts`) that used to cut the monorepo down after cloning it: the
scaffold now writes only the converged stack, so there's nothing left to prune.

Requires Node.js >= 22 and pnpm 11.28.5+ (the scaffolded project is a pnpm + Turborepo workspace). The
CLI checks for `pnpm` on `PATH` unless you pass `--pm`.

## Example session

```
npx create-sailor my-saas

✔ Where should we create your project? … ./my-saas

⠋ Cloning Nebutra-Sailor template into ./my-saas...
✔ Project my-saas successfully initialized!

  Next steps:
  cd my-saas
  pnpm install
  pnpm dev
```

## After scaffolding

```bash
cd my-saas
pnpm install
pnpm dev
```

`pnpm dev` runs against local fallbacks with no external services required. To wire real
providers, add keys to `.env.local` and run `nebutra status` to confirm each capability came up
live.

<Note>
  `create-sailor` is a one-time tool — there is no `nebutra create` that wraps it; this is the
  single creation entry point. For day-to-day tasks inside the scaffolded project (checking
  capability status, running migrations, managing infra), use the [`nebutra` CLI](/docs/cli/nebutra-cli).
</Note>
