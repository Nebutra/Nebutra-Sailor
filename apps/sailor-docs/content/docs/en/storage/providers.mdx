title: Storage Providers
description: Configure the single S3-compatible adapter behind @nebutra/uploads for Cloudflare R2, AWS S3, Aliyun OSS, or any other S3-compatible endpoint.
---

`@nebutra/uploads` has exactly **one** cloud provider — a single S3-compatible client
(`S3UploadProvider`) — plus a local filesystem fallback for development. Per ADR 2026-09-24
(Sailor convergence), the same adapter is used for Cloudflare R2 and Aliyun OSS ("one S3-compatible
adapter for R2 and OSS"), and it also happens to work against AWS S3, MinIO, Backblaze B2, and any
other S3-compatible endpoint — they are all the same code path, distinguished only by which
environment variables you set. There is no separate "AWS S3 provider" or "R2 provider"
implementation, and no `STORAGE_PROVIDER` env var — the real var is `UPLOAD_PROVIDER`.

<Note>
Provider auto-detection (`createUploadProvider()`, no explicit `UPLOAD_PROVIDER`): explicit
`UPLOAD_PROVIDER` → `R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY` present (uses `R2_*` vars) →
`AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` present (uses `AWS_*` vars, falling back to `R2_*` for
anything unset) → `S3_ENDPOINT` present (custom endpoint) → local filesystem fallback.
</Note>

## Cloudflare R2 (primary)

R2 is what Nebutra production runs. It is S3-compatible and charges **zero egress fees**.

### Environment variables

```bash
UPLOAD_PROVIDER=r2
R2_ACCESS_KEY_ID=...
R2_SECRET_ACCESS_KEY=...
R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
R2_PUBLIC_URL=https://assets.nebutra.com
```

<Tip>
`UPLOAD_PROVIDER=r2` is an alias resolved to the S3 provider, configured from the `R2_*` vars — it
is the same `S3UploadProvider` class as every other endpoint here. Omitting `UPLOAD_PROVIDER` and
just setting `R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY` auto-detects the same result.
</Tip>

### Setup steps

<Steps>
  <Step title="Create an R2 bucket">
    In the Cloudflare dashboard, go to **R2 → Create bucket**. The bucket name is passed as a
    parameter on every call (`createPresignedUpload({ bucket, key, … })`) — it is not read from an
    env var.
  </Step>

  <Step title="Create an API token">
    Go to **R2 → Manage R2 API tokens → Create API token**.

    - **Permissions:** Object Read & Write
    - **Bucket:** restrict to the bucket you created

    Save the **Access Key ID** and **Secret Access Key** as `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`.
  </Step>

  <Step title="Configure CORS">
    In R2 bucket settings, go to **Settings → CORS Policy**:

    ```json
    [
      {
        "AllowedOrigins": ["https://app.nebutra.com"],
        "AllowedMethods": ["GET", "PUT", "HEAD", "DELETE"],
        "AllowedHeaders": ["*"],
        "ExposeHeaders": ["ETag"],
        "MaxAgeSeconds": 3600
      }
    ]
    ```
  </Step>

  <Step title="Enable public access (optional)">
    For a public CDN URL (avatars, public documents), go to **R2 bucket → Settings → Public
    access** and connect a custom domain or enable the `r2.dev` subdomain. Set `R2_PUBLIC_URL` to
    it.
  </Step>
</Steps>

## AWS S3

Use plain S3 when you are already invested in the AWS ecosystem or need AWS-native IAM policies.
Same adapter, `AWS_*` env vars instead of `R2_*`:

```bash
AWS_ACCESS_KEY_ID=AKIA...
AWS_SECRET_ACCESS_KEY=...
AWS_REGION=us-east-1
```

`UPLOAD_PROVIDER` can be left unset — `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` present (with no
`R2_*` credentials set) auto-detects the S3 provider using these vars. Attach an IAM policy scoped
to your bucket:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject", "s3:ListBucket"],
      "Resource": ["arn:aws:s3:::nebutra-uploads", "arn:aws:s3:::nebutra-uploads/*"]
    }
  ]
}
```

Configure CORS the same way as the R2 example above, with your bucket's console.

## Aliyun OSS, MinIO, Backblaze B2, and other S3-compatible endpoints

Any S3-compatible service works through the same adapter by pointing `S3_ENDPOINT` (or
`R2_ENDPOINT`, checked second) at it. This is the path ADR 2026-09-24 names for OSS under mainland
China's PIPL data-residency requirement:

```bash
AWS_ACCESS_KEY_ID=...          # or S3_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY=...      # or S3_SECRET_ACCESS_KEY
AWS_REGION=us-east-1
S3_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
S3_PUBLIC_URL=https://assets.example.com
```

### MinIO (self-hosted, local development)

<Steps>
  <Step title="Start MinIO">
    ```bash
    docker run -p 9000:9000 -p 9001:9001 \
      -e MINIO_ROOT_USER=admin \
      -e MINIO_ROOT_PASSWORD=password \
      quay.io/minio/minio server /data --console-address ":9001"
    ```
  </Step>

  <Step title="Create a bucket and access key">
    Open the MinIO console at `http://localhost:9001`. Create a bucket and generate an access key
    pair.
  </Step>

  <Step title="Set environment variables">
    ```bash
    AWS_ACCESS_KEY_ID=<minio-access-key>
    AWS_SECRET_ACCESS_KEY=<minio-secret-key>
    AWS_REGION=us-east-1
    S3_ENDPOINT=http://localhost:9000
    S3_FORCE_PATH_STYLE=true
    ```
  </Step>
</Steps>

<Warning>
For local MinIO, set `S3_FORCE_PATH_STYLE=true` to avoid virtual-hosted-style URL resolution
issues.
</Warning>

## Local filesystem (default with no credentials)

With none of the above set, `createUploadProvider()` falls back to `LocalUploadProvider` — files
land on local disk. This is the zero-question scaffold's default (ADR 2026-09-24): `pnpm dev`
works with an empty `.env`.

## Switching endpoints

Because every endpoint runs through the same `S3UploadProvider`, moving from R2 to AWS S3 (or to
OSS) is an environment variable change, not a code change:

```bash
# Switch from R2 to AWS S3 — just update env vars
AWS_ACCESS_KEY_ID=AKIA...
AWS_SECRET_ACCESS_KEY=...
AWS_REGION=us-east-1
```
