---
title: Node.js Quickstart
description: Compose Nebutra's current server-side packages in a Node.js or Hono backend.
---

There is no standalone `@nebutra/sdk` package for Node backends in this repo.
Server integrations are built by composing focused packages such as
`@nebutra/logger`, `@nebutra/agents`, `@nebutra/permissions`, and `@nebutra/db`.

## Step 1: Install focused server packages

```bash
pnpm add @nebutra/logger @nebutra/agents @nebutra/permissions @nebutra/db
```

Add only what your service actually needs.

## Step 2: Start with structured logging

```typescript
import { logger } from "@nebutra/logger";

logger.info("worker.started", { service: "reporting" });
```

Avoid `console.log` in long-lived services so log routing and tenant metadata
stay consistent with the rest of the platform.

## Step 3: Use the AI runtime where generation belongs

```typescript
import { generateText } from "@nebutra/agents";

const result = await generateText({
  model: "openai/gpt-4.1-mini",
  prompt: "Summarize the last 24 hours of usage anomalies.",
});
```

## Step 4: Resolve permissions explicitly

```typescript
import { createPermissionChecker } from "@nebutra/permissions";

const checker = createPermissionChecker({
  role: "admin",
});

const allowed = checker.can("billing:manage");
```

Mirror the same permission model your UI exposes; do not rely on browser-only
gates for server mutations.

## Step 5: Choose tenant-scoped vs system-scoped database access

```typescript
import { getSystemDb, getTenantDb } from "@nebutra/db";

const tenantDb = getTenantDb("org_123");
const systemDb = getSystemDb();
```

- `getTenantDb()` for request-scoped tenant data
- `getSystemDb()` for admin jobs, webhook bootstrap, or cross-tenant tasks

## Step 6: Prefer Hono routes inside the gateway

In this repo, new backend work defaults to `backends/gateway/`:

```typescript
import { OpenAPIHono } from "@hono/zod-openapi";

const app = new OpenAPIHono();
```

The current gateway already owns auth, tenancy, billing, integrations, and
webhook surfaces, so add server code there before inventing a parallel runtime.
