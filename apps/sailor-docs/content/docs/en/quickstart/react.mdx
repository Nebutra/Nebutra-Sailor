---
title: React Quickstart
description: Reuse Nebutra permission and UI packages in a React application without relying on a nonexistent browser SDK.
---

Nebutra-Sailor does **not** currently publish a standalone `@nebutra/react`
package. In plain React applications, the supported pattern is:

- keep auth/session state in your host app
- call Nebutra HTTP surfaces through your own backend or typed client layer
- reuse focused packages like `@nebutra/permissions` and `@nebutra/ui`

## Step 1: Install the packages you actually need

```bash
pnpm add @nebutra/ui @nebutra/permissions
```

If your React app also hosts server-side AI features, add `@nebutra/agents` on
the server runtime rather than in the browser bundle.

## Step 2: Render shared UI primitives

```tsx
import { Button } from "@nebutra/ui/components";
import { EmptyState, PageHeader } from "@nebutra/ui/layout";

export function BillingPage() {
  return (
    <div className="space-y-6">
      <PageHeader title="Billing" description="Manage usage and subscription state." />
      <Button>Upgrade</Button>
      <EmptyState title="No invoices yet" description="Invoices will appear after checkout." />
    </div>
  );
}
```

## Step 3: Gate UI with permission-aware components

`@nebutra/permissions` exposes a React subpath for UI-facing access checks:

```tsx
import { PermissionGate } from "@nebutra/permissions/react";

export function DeleteButton() {
  return (
    <PermissionGate require="project:delete">
      <button type="button">Delete project</button>
    </PermissionGate>
  );
}
```

Use this only as a presentation guard. Enforce the same permission again on the
server before mutating data.

## Step 4: Fetch data through a server-owned boundary

Client-side React code should fetch from your own route handlers or API layer,
not from a fictional Nebutra browser SDK:

```tsx
import { useEffect, useState } from "react";

export function useIntegrations() {
  const [items, setItems] = useState([]);

  useEffect(() => {
    fetch("/api/integrations")
      .then((res) => res.json())
      .then((payload) => setItems(payload.integrations ?? []));
  }, []);

  return items;
}
```

## Step 5: Keep tenant and permission state on the server

If your React app is backed by Nebutra-Sailor services, resolve tenant context
server-side and pass down the minimum UI state you need:

```tsx
type ViewerState = {
  tenantId: string;
  plan: string;
  scopes: string[];
};
```

This avoids leaking internal auth and data-access assumptions into the browser.
