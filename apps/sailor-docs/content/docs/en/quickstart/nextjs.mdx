---
title: Next.js Quickstart
description: Build a Nebutra-style Next.js 16 app using the current auth, UI, and typed API surfaces.
---

This quickstart reflects the **current** Nebutra-Sailor app shape. There is no
single `@nebutra/sdk` browser package. A modern Next.js integration uses:

- `@nebutra/auth` for auth runtime
- `@nebutra/ui` for UI primitives and layouts
- the generated API client in `apps/web/src/lib/api/client.ts`
- app-level helpers such as `requireAuth()` and `getTenantContext()`

## Step 1: Start from the right structure

Inside this monorepo, the authenticated app lives under:

```text
apps/web/src/app/[locale]/(app)/
```

Protected pages are rendered inside the shared app shell at:

```text
apps/web/src/app/[locale]/(app)/layout.tsx
```

## Step 2: Use the shared auth helpers

Server-side route protection is handled by `apps/web/src/lib/auth.ts`:

```typescript
import { requireAuth, getTenantContext } from "@/lib/auth";

export default async function WorkspacePage() {
  await requireAuth();
  const { tenantId, plan } = await getTenantContext();

  return (
    <div>
      <h1>Workspace</h1>
      <p>Tenant: {tenantId}</p>
      <p>Plan: {plan}</p>
    </div>
  );
}
```

## Step 3: Render with shared UI primitives

```tsx
import { Card, PageHeader } from "@nebutra/ui/layout";

export default function Example() {
  return (
    <div className="space-y-6">
      <PageHeader title="Analytics" description="Growth and usage metrics." />
      <Card className="p-6">Dashboard content</Card>
    </div>
  );
}
```

## Step 4: Call the gateway through the typed client

The supported client lives at `apps/web/src/lib/api/client.ts`:

```typescript
import { getTypedApi } from "@/lib/api/client";

export default async function ModelsPage() {
  const api = await getTypedApi();
  const { data, error } = await api.GET("/api/v1/ai/models");

  if (error) {
    throw new Error("Failed to load models");
  }

  return <pre>{JSON.stringify(data, null, 2)}</pre>;
}
```

For Client Components, use `browserApiClient` instead of calling a fictional
SDK object:

```typescript
import { browserApiClient } from "@/lib/api/client";

const response = await browserApiClient.GET("/api/v1/integrations");
```

## Step 5: Add a new app page in the current route group

Create the page inside `[locale]/(app)`:

```bash
mkdir -p 'apps/web/src/app/[locale]/(app)/my-section'
```

```typescript
// apps/web/src/app/[locale]/(app)/my-section/page.tsx
import { PageHeader } from "@nebutra/ui/layout";
import { requireAuth } from "@/lib/auth";

export default async function MySectionPage() {
  await requireAuth();

  return (
    <div className="space-y-6">
      <PageHeader title="My Section" description="Built on the shared app shell." />
    </div>
  );
}
```

## Step 6: Respect feature flags and tenant capabilities

The app shell derives workspace, billing, and notifications behavior from
`resolveWebProductCapabilities()`:

```typescript
import { resolveWebProductCapabilities } from "@/lib/product-capabilities";

const capabilities = resolveWebProductCapabilities();
```

When you add a page that depends on billing, notifications, or workspace mode,
make those assumptions explicit in the page logic rather than hardcoding a
universal dashboard shape.

## Step 7: Regenerate API types when gateway contracts change

```bash
pnpm --filter @nebutra/gateway generate:spec
pnpm generate:api-types
```

This refreshes the client-side `paths` contract used by `getTypedApi()` and
`browserApiClient`.
