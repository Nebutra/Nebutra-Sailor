## What is Nebutra-Sailor?

Nebutra-Sailor is a **Turborepo monorepo** that ships a complete AI-native SaaS product as working code. It contains 7 deployable apps and 20+ shared packages, all typed end-to-end, sharing a common design system, API contract, and runtime token system.

The monorepo is the source of truth for everything that runs at `nebutra.com`, `app.nebutra.com`, and `api.nebutra.com`.

## Apps at a glance

| App | Port | Purpose | Framework |
|-----|------|---------|-----------|
| `apps/web` | 3000 | Authenticated SaaS dashboard | Next.js 16 + Clerk |
| `backends/gateway` | 3001 | REST API — auth, RBAC, billing, AI proxy | Hono + OpenAPI |
| `apps/landing-page` | 3002 | Public marketing site (7 locales) | Next.js 16 + next-intl |
| `apps/design-docs` | 3003 | Internal design system documentation | Next.js 16 + Fumadocs |
| `apps/storybook` | 6006 | Component library playground | Storybook 8.x |
| `apps/studio` | 3333 | Content management | Sanity Studio v5 |
| `apps/sailor-docs` | 3004 | Public product documentation (this site) | Next.js 16 + Fumadocs |

## Prerequisites

Before you can run the monorepo locally you need the following tools installed on your machine.

| Tool | Minimum version | Why |
|------|----------------|-----|
| Node.js | 22.x | Runtime for all apps and tooling |
| pnpm | 10.32+ | Workspace package manager |
| Docker | 24+ | Local PostgreSQL, Redis, and ClickHouse |
| Git | 2.40+ | Source control |

<Note>
  The repo uses pnpm workspaces. Running `npm install` or `yarn install` will produce incorrect results and is not supported.
</Note>

## Quick start

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/nebutra/nebutra-sailor.git
    cd nebutra-sailor
    ```
  </Step>
  <Step title="Install dependencies">
    ```bash
    pnpm install
    ```
  </Step>
  <Step title="Start infrastructure services">
    ```bash
    pnpm infra:up
    ```
    This starts PostgreSQL 16, Redis 7, and ClickHouse 24 via Docker Compose.
  </Step>
  <Step title="Configure environment variables">
    Copy the example env files and fill in your secrets:
    ```bash
    cp apps/web/.env.example apps/web/.env.local
    cp backends/gateway/.env.example backends/gateway/.env.local
    cp apps/landing-page/.env.example apps/landing-page/.env.local
    ```
  </Step>
  <Step title="Set up the database">
    ```bash
    pnpm db:generate   # generate Prisma client
    pnpm db:migrate    # run all pending migrations
    pnpm db:seed       # seed development data
    ```
  </Step>
  <Step title="Start the development servers">
    ```bash
    pnpm dev           # start all apps in parallel
    ```
    Or start only what you need:
    ```bash
    pnpm dev:dashboard   # web (3000) + api-gateway (3001)
    pnpm dev:marketing   # landing-page (3002) + studio (3333)
    ```
  </Step>
</Steps>

<Tip>
  For a full walkthrough with environment variable descriptions, common issues, and port assignments, see the [Local Development](/development/local-dev) guide.
</Tip>

## Key conventions

- **Package manager:** pnpm 10.32+ with workspaces. Always run `pnpm` at the repo root.
- **Linter + formatter:** Biome (replaces ESLint + Prettier). Run `pnpm lint:fix` to auto-fix.
- **Type checking:** `pnpm typecheck` runs `tsc --noEmit` across all packages via Turbo.
- **Testing:** Vitest for unit tests, Playwright for E2E. Run `pnpm test` and `pnpm e2e`.
- **Build system:** Turborepo with Vercel Remote Cache. Tasks are defined in `turbo.json`.
