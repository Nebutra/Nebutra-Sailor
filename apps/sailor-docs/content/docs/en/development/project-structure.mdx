Nebutra-Sailor is organized by **purpose** at the top level and by **domain**
inside `packages/`.

## Top-level layout

```text
nebutra-sailor/
├── apps/
├── backends/
├── packages/
├── infra/
├── workflows/
├── e2e/
├── tests/
├── scripts/
├── package.json
└── pnpm-workspace.yaml
```

## `apps/`

Current checked-in apps include:

| App | Purpose |
| --- | --- |
| `apps/landing-page` | Public marketing site |
| `apps/web` | Authenticated SaaS app |
| `apps/storybook` | Component docs / stories |
| `apps/design-docs` | Internal design system docs |
| `apps/sailor-docs` | Product documentation |
| `apps/studio` | Sanity Studio |
| `apps/idp` | Identity provider app |
| `apps/mail-preview` | Email preview surface |
| `apps/sleptons`, `apps/tsekaluk-dev` | Auxiliary product surfaces |

The old Mintlify-style docs app described by earlier documentation is not part
of the current repository and should not be referenced as the public docs app.

## `backends/`

```text
backends/
├── gateway/   TypeScript / Hono
├── go/
├── python/
└── rust/
```

Per the repo contract, new product backend work defaults to
`backends/gateway/` unless there is a clear reason to move to another runtime.

## `packages/`

Workspace packages are grouped by domain:

| Domain | Examples |
| --- | --- |
| `ai/` | `agents`, `agent-runtime`, `mcp`, `browser-control` |
| `commerce/` | `billing`, `marketing`, `metering`, `blog` |
| `design/` | `ui`, `tokens`, `brand`, `icons`, `theme` |
| `iam/` | `auth`, `identity`, `permissions`, `tenant`, `vault` |
| `integrations/` | `email`, `event-bus`, `queue`, `notifications`, `webhooks` |
| `ops/` | `cli`, `create-sailor`, `preset`, `sanity`, `supabase` |
| `platform/` | `db`, `logger`, `errors`, `config`, `rate-limit` |

## Current web app route structure

The authenticated app shell is locale-aware:

```text
apps/web/src/app/
  [locale]/
    (app)/
    (auth)/
    (public)/
  api/
```

When you add new product pages, place them inside `[locale]/(app)` rather than
the old `(dashboard)` path shown in earlier docs.

## Workflows, tests, and infra

```text
workflows/
  inngest/
  n8n/
  pusher/

e2e/
  playwright.config.ts
  playwright.golden.config.ts
  playwright.sleptons.config.ts

tests/
  architecture/
```

The current `e2e/` folder is config-first; it is not partitioned into the old
`smoke/` / `golden/` / `sleptons/` subdirectories described by earlier docs.

## Where to add new things

| Need | Current home |
| --- | --- |
| New authenticated page | `apps/web/src/app/[locale]/(app)/` |
| New marketing page | `apps/landing-page/src/app/[lang]/` |
| New gateway route | `backends/gateway/src/routes/` |
| New reusable UI component | `packages/design/ui/src/` |
| New DB contract | `packages/platform/db/` |
| New workflow scaffold | `workflows/<provider>/` |
