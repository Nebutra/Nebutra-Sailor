title: Feature Flags
description: There is no feature-flags capability in the Sailor scaffold — what changed and what to use instead.
---

## This capability does not currently exist

Earlier versions of `create-sailor` offered a `--feature-flags` flag with a choice of providers
(Vercel Flags, GrowthBook, ConfigCat). The Sailor Convergence ADR (2026-09-24) removed that flag
along with the rest of the scaffold's provider-choice surface, and **nothing replaces it** — there
is no runtime feature-flags package in the converged stack, no `FEATURE_*` environment-variable
convention wired up by the scaffold, and no `nebutra` command for managing flags.

If you need feature flags in a project scaffolded from Sailor, you'll need to add your own
provider (e.g. GrowthBook, LaunchDarkly, or a simple env-var convention) — this is not a gap the
template fills in for you.

## What to use in the meantime

- **Plan-gated features** — check `tenant.plan` in your `@nebutra/permissions` policies and return
  `403` for capabilities the plan doesn't include. See [Permissions](/concepts/permissions).
- **Capability readiness** — `nebutra status` reports whether a given integration (auth, billing,
  email, storage, queue, cache, ai, monitoring, analytics, captcha, notifications, webhooks, mcp)
  is `live`, running on a `local-fallback`, or `missing-key`. This is about which providers are
  configured, not application-level feature toggles, but it's often what teams reach for
  feature-flag tooling to answer. See [nebutra CLI](/docs/cli/nebutra-cli).
