# AI provider governance

`create-sailor` asks nothing about AI providers at scaffold time — per
[ADR 2026-09-24 Sailor convergence](https://github.com/nebutra/nebutra-sailor/blob/main/docs/architecture/2026-09-24-sailor-convergence.md), every provider-choice
flag was removed from the scaffold. Every project ships the same AI gateway
(`backends/gateway`'s `/api/v1/ai` routes); which model provider is actually live is a runtime
decision, governed after scaffolding with the `nebutra ai` CLI.

## Managing providers

```bash
nebutra ai provider list                  # supported and currently enabled providers
nebutra ai provider enable openai anthropic
nebutra ai provider disable openai

nebutra ai gateway init                   # initialize the local AI gateway governance block
nebutra ai gateway status

nebutra ai route set <name> ...           # routing policy (which provider serves which route)
nebutra ai route list

nebutra ai models                         # list configured models
nebutra ai test "hello world"             # test the current provider through the gateway
```

`nebutra status` reports the `ai` capability as `live`, `local-fallback`, or `missing-key`
depending on whether a provider's env keys are set.

## Adding a provider adapter

The gateway's AI routes are not locked to a single vendor SDK. Add a new provider by wiring its
client into the AI route handlers in `backends/gateway/src/routes/ai/` and enabling it with
`nebutra ai provider enable <name>` — there is no scaffold-time provider list to edit.
