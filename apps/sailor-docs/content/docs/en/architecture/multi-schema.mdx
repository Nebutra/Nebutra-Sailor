Per [ADR 2026-09-25 database convergence](https://github.com/nebutra/nebutra-sailor/blob/main/docs/architecture/2026-09-25-database-convergence.md),
`packages/platform/db/prisma/schema.prisma` is the **single source** for the database: every
table, and every table's access rule as an `/// @rls` comment. There is no scaffold-time choice
about database structure — `create-sailor` writes the same schema every time.

## Two Postgres schemas, not one per domain

```prisma packages/platform/db/prisma/schema.prisma
datasource db {
  provider   = "postgresql"
  extensions = [vector, uuid_ossp(map: "uuid-ossp")]
  schemas    = ["public", "better_auth"]
}
```

- **`public`** — every application table, each carrying its own `@@schema("public")` and an
  `/// @rls` access-rule annotation.
- **`better_auth`** — the tables Better Auth's own plugins (`organization`, `passkey`, …) manage.
  Kept separate because the device-authorization flow's own table
  (`public.auth_device_codes`) has to live in `public` instead, where a Kysely-based edge runtime
  (no Prisma) can address it by literal name — see ADR 2026-09-24 §8.

This is **not** a "microservice-per-schema" pattern, and there is no `stripe` or `ai` schema to
prune based on a scaffold choice — the old provider-choice flags that implied one don't exist.

## Row-level security is generated, not hand-written

A model's access rule is **inferred automatically** from a `tenantId` / `organizationId` column,
or from its single tenant-scoped parent relation — no annotation needed for the common case. Any
other model must declare one explicitly, or `prisma generate` fails:

```prisma
/// @rls self
model Session {
  // ... only the owning user's row is visible
  @@schema("public")
}
```

The full vocabulary: `global | deny | off | self | via(field) | using(sql) | read(sql) write(sql)`.

`prisma generate` runs a custom generator (`prisma/generators/rls.mjs`) that turns every `/// @rls`
comment into a policy in `generated/rls.sql`. See [Row-Level Security](/database/rls) for the full
annotation vocabulary and the `pnpm db:deploy` flow that applies it.
