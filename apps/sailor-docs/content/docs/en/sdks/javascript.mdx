Nebutra-Sailor no longer ships a single catch-all `@nebutra/sdk` package.
The current JavaScript / TypeScript integration model is **package-first**:
pick the focused surface that matches the job you are doing.

## What to use today

| Need | Current surface | Notes |
| --- | --- | --- |
| App authentication | `@nebutra/auth` | Provider-agnostic auth runtime used by `apps/web` |
| Typed gateway calls | `apps/web/src/lib/api/client.ts` | OpenAPI-generated `openapi-fetch` client |
| AI generation | `@nebutra/agents` | `generateText`, `streamText`, embeddings, provider helpers |
| Permission checks | `@nebutra/permissions` | IAM rules, middleware, optional React helpers |
| Multi-tenant context | `@nebutra/tenant` | Tenant resolution and RLS helpers |
| UI primitives / layouts | `@nebutra/ui` | Components, layout wrappers, utilities |

## Typed API client

Inside the web app, the supported way to call the API gateway is the generated
OpenAPI client:

```typescript
import { browserApiClient, getTypedApi } from "@/lib/api/client";

// Server Component / Server Action
const api = await getTypedApi();
const { data } = await api.GET("/api/v1/ai/models");

// Client Component
const response = await browserApiClient.GET("/api/v1/integrations");
```

Types come from the committed/generated `types.generated.ts` contract, sourced
from `backends/gateway/openapi.json`.

## Authentication

`apps/web` uses the shared auth abstraction from `@nebutra/auth`, while
server-side route protection lives in `apps/web/src/lib/auth.ts`:

```typescript
import { requireAuth, getTenantContext } from "@/lib/auth";

export default async function Page() {
  await requireAuth();
  const { tenantId, plan } = await getTenantContext();
  return <div>{tenantId} · {plan}</div>;
}
```

If you need the lower-level provider runtime directly, import from
`@nebutra/auth` / `@nebutra/auth/server` rather than a fictional SDK wrapper.

## AI runtime

AI features are exposed from `@nebutra/agents`:

```typescript
import { generateText, streamText } from "@nebutra/agents";

const completion = await generateText({
  model: "openai/gpt-4.1-mini",
  prompt: "Summarize this tenant's weekly funnel performance.",
});

const stream = await streamText({
  model: "openai/gpt-4.1-mini",
  prompt: "Draft release notes for the newest billing changes.",
});
```

## Permissions

Authorization logic is provided by `@nebutra/permissions` and the app-level
helpers layered on top of it:

```typescript
import { hasPermission } from "@/lib/permissions";

const allowed = hasPermission("admin", "billing:manage");
```

For reusable UI gates in a standalone React surface, use the package's React
subpath rather than an old `@nebutra/react` package:

```typescript
import { PermissionGate } from "@/components/permission-gate";
```

## UI and layout packages

```tsx
import { Button } from "@nebutra/ui/components";
import { PageHeader, EmptyState, LoadingState } from "@nebutra/ui/layout";
import { cn } from "@nebutra/ui/utils";
```

`@nebutra/design-system` has already been absorbed into `@nebutra/ui`.

## What not to use

- Do not document or import `@nebutra/sdk`.
- Do not document or import `@nebutra/react`.
- Do not document or import `@nebutra/integrations`.
- Do not treat `@nebutra/db` as a browser-safe client library.
